How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1419 votes

I still remember the first time I set up a fresh Ubuntu box for a side project, feeling like a total pro until I tried to run my first container. I spent a good hour staring at my terminal, convinced I’d somehow broken the entire Docker installation because every time I typed docker run, I got slapped with a "permission denied" error. It’s one of those classic "welcome to Linux" moments that makes you want to throw your keyboard out the window, especially when you realize you’re just one group assignment away from it working perfectly.

The reason this happens is actually quite logical once you look under the hood. By default, the Docker daemon binds to a Unix socket owned by the root user, which means only users with root privileges—or those using sudo—can talk to it. It’s a security feature to keep random processes from messing with your containers, but honestly, typing sudo before every single command gets old fast. You don't want to run your entire development workflow with root privileges, and you certainly don't want to clutter your history with unnecessary sudo calls.

To fix this, I always add my user to the docker group, which grants me the permissions needed to interact with the daemon without needing elevated privileges. First, I create the group if it doesn’t exist by running sudo groupadd docker. Then, I add my current user to that group using sudo usermod -aG docker $USER. After running that, the most important part—which I’ve forgotten more times than I care to admit—is to refresh my shell. You can either log out and log back in, or just run newgrp docker to apply the changes to your current terminal session immediately. Once that’s done, you can verify it by running a simple command without the sudo prefix:


docker run hello-world

If you see that "Hello from Docker!" message without any permission errors, you’re golden. If you’re still getting the error, a quick reboot usually clears out any lingering session issues that the group change didn't pick up.

To prevent this from becoming a recurring headache, my biggest tip is to always handle your group permissions as part of your initial machine setup script. Whenever I provision a new dev environment, I include the usermod command in my setup.sh file so I never have to manually troubleshoot permissions again. It’s a small bit of automation that saves me a massive amount of frustration down the road.

Hope this saves you some time and keeps your terminal sessions stress-free. Happy coding!

為什麼每次跑 Docker 都要加 sudo？教你一招徹底告別 Permission Denied

來源：Stack Overflow ↗ · 1419 票

剛開始學 Docker 的時候，我真的被這個錯誤訊息搞到快崩潰。記得那天我正趕著要在本地端跑一個微服務測試，心急如焚地輸入 docker run，結果螢幕直接噴出一大串紅字，顯示什麼 permission denied。當下我心想：「我不是剛剛才裝好嗎？為什麼還要我加 sudo？」最痛苦的是，每次打指令都要多加一個 sudo，手指都要敲爛了，而且有時候寫腳本時，因為權限問題一直跑不起來，真的會讓人想直接把電腦關了。

其實會發生這種狀況，是因為 Docker 的守護行程（Daemon）預設是綁定在 unix socket 上的，而這個 socket 的擁有者是 root。換句話說，當你沒有用 root 權限去呼叫 Docker 時，系統就會覺得你「不夠格」去存取這個 socket，所以直接把你拒於門外。這雖然是為了系統安全著想，但對於我們這種天天要跟容器打交道的開發者來說，實在是太不方便了。

要解決這個問題，其實不用每次都這麼麻煩。我們只要把當前的使用者加進 docker 這個群組裡就好。首先，你先在終端機輸入這行指令來建立群組：sudo groupadd docker，接著把你的使用者加進去：sudo usermod -aG docker $USER。做完這兩步後，最關鍵的步驟來了，你必須登出再登入，或者直接執行 newgrp docker，這樣權限才會生效。你可以試著跑一下 docker run hello-world，如果沒出現權限錯誤，那就代表大功告成了！

至於怎麼預防這種惱人的情況再次發生？其實這就是環境設定的一環。我建議以後只要在新機器安裝完 Docker，第一件事就是把這幾行設定寫進你的個人筆記或自動化腳本裡。畢竟，省下每次打 sudo 的時間，長久下來真的能多喝好幾杯咖啡呢。

以後再看到這個錯誤，記得直接把這套流程跑一遍就好，別再浪費時間跟它生悶氣啦！
