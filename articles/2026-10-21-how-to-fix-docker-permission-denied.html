How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1420 votes

I still remember the first time I set up Docker on a fresh Ubuntu install, feeling like a total pro until I tried to run my first container. I spent a good two hours convinced I had botched the entire installation, fruitlessly reinstalling packages and restarting my machine, only to realize I was just missing a simple user group configuration. It’s one of those classic "welcome to Linux" moments that makes you want to throw your keyboard out the window when you realize the fix is literally a one-liner.

The reason you’re running into this is actually about security. By default, the Docker daemon binds to a Unix socket owned by the root user, not your standard user account. When you try to run docker run without sudo, the Docker client tries to communicate with that socket, but the system stops you because your user doesn't have the necessary permissions to access it. It’s the OS’s way of ensuring that only users with administrative privileges can control the engine that manages your containers.

Fixing this is straightforward, and you don’t need to keep typing sudo every single time you want to spin up a container. First, you need to create the docker group if it doesn't already exist, then add your current user to that group. Run these commands in your terminal:


# Create the docker group
sudo groupadd docker

# Add your user to the group
sudo usermod -aG docker $USER

Once you’ve run those, the changes won't take effect immediately. You’ll need to either log out and log back in, or run newgrp docker to refresh your group membership without a full session restart. You can verify it worked by running docker run hello-world without the sudo prefix. If the output shows the "Hello from Docker!" message, you're officially back in business.

To keep this from biting you again, make it a habit to check your group permissions whenever you set up a new environment or jump onto a new server. Adding your user to the Docker group is the industry standard for development machines, but just remember that this effectively grants your user root-level privileges to the system. It’s totally fine for your local dev machine, but be careful if you're ever doing this on a shared production server.

Hope this saves you the headache I went through! Happy coding and enjoy your containerized workflow.

為什麼執行 Docker 指令老是卡在 Permission denied？教你一招徹底擺脫 sudo

來源：Stack Overflow ↗ · 1420 票

記得我剛開始接觸 Docker 時，那天為了趕一個 demo，整個人焦慮到不行，偏偏在執行 docker run 時一直跳出那串惱人的 permission denied。我當時的第一反應是：「拜託，我明明就是這台機器的管理員，為什麼還要我一直打 sudo？」更痛苦的是，每次寫腳本測試都要在那邊敲密碼，只要一打錯，整個開發節奏就被打斷，那種「明明只是一個指令，為什麼卻像在跟電腦吵架」的無力感，真的會讓人想直接把鍵盤摔了。

其實這背後的原因一點都不神秘，說穿了就是 Linux 的權限控管機制在作祟。當我們安裝完 Docker 後，預設情況下，Docker 的守護進程（daemon）會透過 Unix socket 來監聽指令，而這個檔案預設只有 root 權限才能存取。所以當你不用 sudo 時，系統就像個嚴格的警衛，因為你的使用者帳號沒有權限去觸碰那個 socket，直接把你擋在門外，這也是為什麼加了 sudo 就能跑的原因。

解決這個問題的方法其實很簡單，就是把你的使用者帳號加進 docker 這個群組裡。這等於是給了你的帳號一塊「通行證」，以後不用每次都向系統證明你是 root 也能操作 Docker。你可以先執行 sudo groupadd docker 確保群組存在，接著用 sudo usermod -aG docker $USER 把自己加進去。搞定這步之後，最重要的一點是：請記得登出再重新登入，或者直接重開機，讓權限生效。如果你懶得重開，也可以用 newgrp docker 指令先讓當前的終端機階段生效。

為了防止下次換了台新機器又被這個問題卡住，我現在的習慣是，每當我在 Ubuntu 上裝好 Docker，第一件事就是把這個權限設定寫進我的環境建置腳本裡。這樣以後只要新開開發環境，執行一次腳本，這些惱人的權限設定就會自動處理好，再也不用為了這點小事浪費我的腦細胞。

以後看到這串錯誤訊息，別再傻傻地一直加 sudo 了，把權限設好，開發體驗真的會順暢很多！
