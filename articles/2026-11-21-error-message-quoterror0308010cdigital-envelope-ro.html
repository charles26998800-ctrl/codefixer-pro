Fixing the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2573 votes

I remember the exact moment I first ran into this error. I had just spun up a fresh project in IntelliJ, expecting to see that comforting "Welcome to React" screen, but instead, my terminal exploded with a wall of red text ending in error:0308010C:digital envelope routines::unsupported. I spent three hours staring at my package.json and reinstalling node_modules like a madman before realizing my Node version was simply too new for the aging Webpack version the project was using. It’s one of those bugs that makes you want to throw your laptop out the window, especially when you’re just trying to get a simple "Hello World" off the ground.

The reason this happens is actually quite straightforward once you peel back the layers. When Node.js bumped up to version 17 and beyond, they upgraded the underlying OpenSSL library to version 3.0. This new version is much stricter about the cryptographic algorithms it allows, and it effectively deprecated the older MD4 hashing algorithm that many legacy Webpack builds—and by extension, older Create React App templates—rely on. Essentially, your Node environment is saying, "I refuse to run this old, insecure code," leaving your build process hanging in the balance.

The quickest way I’ve found to resolve this without needing to downgrade your entire Node installation is to force your terminal to use the legacy OpenSSL provider. You can do this by setting an environment variable before you run your start script. If you’re on a Mac or Linux machine, you’ll want to run this in your terminal:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is a bit different, so you’ll want to use this command instead:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

If you don’t want to type that out every single time you spin up your project, you can simply edit your package.json file. Just look for the scripts section and modify the start command to include the variable directly, like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To keep this from biting you in the future, my best advice is to keep an eye on your Node version compared to your project dependencies. Whenever I start a new project, I always use a version manager like nvm (Node Version Manager) to ensure I’m running a stable LTS version that matches what the project expects. It’s a total lifesaver for avoiding these version-mismatch headaches.

Hope this gets your project up and running again so you can get back to building. Happy coding!

Node.js 升級後 React 專案直接炸開？解決 error:0308010C 的崩潰經驗

來源：Stack Overflow ↗ · 2573 票

那天我剛換了台新電腦，想說要把擱置已久的 React 舊專案拿出來跑一下，結果 npm start 才剛敲下去，終端機就噴出一大串紅通通的錯誤訊息，重點還是那個看都看不懂的 error:0308010C:digital envelope routines::unsupported。當時我真的差點崩潰，明明上週在舊電腦還跑得好好的，怎麼換個環境就變成這樣，甚至一度懷疑是不是新電腦的晶片有問題，害我浪費了一整個下午在重灌 Node.js。

其實這背後的原因沒那麼恐怖，單純是因為我把 Node.js 升級到了 v17 以上的版本。Node.js 在這之後改用了 OpenSSL 3.0 作為加密演算法的標準，但很多舊的 Webpack 版本還在用舊版的加密演算法（MD4），兩邊版本兜不攏，Node.js 就會覺得你不安全，直接給你亮紅燈拒絕執行。說真的，這種「版本更新導致舊程式碼原地爆炸」的痛苦時刻，相信每個前端工程師都經歷過，那種明明程式碼沒改，世界卻變了的無力感，真的是會讓人想把鍵盤砸了。

要解決這個問題其實很簡單，既然是加密演算法的相容性問題，我們只要在啟動專案時，告訴 Node.js 允許使用舊版的演算法就好。最快的方法就是直接修改 package.json 裡的 scripts 設定。你只需要在 start 的指令前面加上 SET NODE_OPTIONS=--openssl-legacy-provider（如果你是用 Windows 的話），或者在 Mac/Linux 下寫成這樣：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

改完之後再跑一次 npm start，你會發現原本那些惱人的錯誤訊息瞬間消失，專案又活過來了。如果你不想每次都改指令，也可以在終端機直接執行 export NODE_OPTIONS=--openssl-legacy-provider (Mac/Linux) 來設定全域環境變數，不過我個人還是比較喜歡直接寫進 package.json，這樣團隊其他人同步代碼時也不會踩坑。

為了避免這種狀況以後又突然跑出來搗亂，我強烈建議大家平時開發專案時，一定要養成使用 nvm (Node Version Manager) 的習慣。透過 nvm，你可以針對不同的舊專案切換到對應的 Node.js 版本，不用為了遷就某個舊專案而強迫整個開發環境升級，這絕對是保護自己心臟最好的方式。

希望這篇筆記能救回你那寶貴的開發時間，以後看到這串錯誤碼就別再驚慌失措啦！
