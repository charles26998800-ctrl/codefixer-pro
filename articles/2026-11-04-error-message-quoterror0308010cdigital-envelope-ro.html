How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the first time I saw that cryptic error:0308010C message pop up in my terminal. I had just spun up a fresh React project to test a quick UI component, and my build process crashed before it even started. I spent a good two hours convinced that my entire Node.js installation was corrupted, frantically reinstalling packages and deleting my node_modules folder, only to end up right back where I started with that same wall of red text.

The reason this happens is actually quite straightforward, even if the error message makes it sound like a catastrophic failure. It boils down to a fundamental change introduced in OpenSSL 3.0, which Node.js v17 and later versions started using by default. Older versions of Webpack and other build tools rely on legacy algorithms for hashing that OpenSSL 3.0 now considers insecure. Since your project is trying to use those older, "unsupported" algorithms, Node.js simply refuses to execute the task, leaving you staring at a broken build.

The fastest way I’ve found to resolve this—and the one I use whenever I'm working with older codebases—is to force Node.js to use the legacy OpenSSL provider. You don't need to downgrade your entire environment; you just need to set an environment variable before you run your build script. If you're on a Mac or Linux machine, you can patch your package.json file like this:


"scripts": {
  "start": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

If you happen to be on Windows using Command Prompt, you'll want to use set instead of export:


"scripts": {
  "start": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

If you prefer not to touch your package.json files, you can also run the command directly in your terminal before starting your development server, though I usually forget to do that and end up getting the error again. For a more permanent fix that doesn't involve editing scripts, you can set the environment variable globally in your shell profile, like your .bashrc or .zshrc, but I generally prefer the package.json method because it keeps the configuration local to the project.

To prevent this headache in the future, my best advice is to keep your dependencies updated. This error is almost exclusively a symptom of using outdated versions of react-scripts or Webpack with a modern version of Node. If you have the luxury of time, run an audit and bump your dependencies to versions that officially support OpenSSL 3.0, which is always the cleaner, more professional path forward.

Hope this saves you the hours of frustration I went through when I first hit this wall. Happy coding!

崩潰！啟動 React 專案卻噴出 Node.js 加密錯誤？這樣解就對了

來源：Stack Overflow ↗ · 2572 票

那天我正準備接手一個舊專案，打開終端機自信滿滿地敲下 npm start，結果螢幕上瞬間跳出一長串紅通通的錯誤訊息，重點還是那個看都看不懂的 error:0308010C:digital envelope routines::unsupported。當下我真的差點崩潰，明明幾分鐘前才剛從 Git 把程式碼拉下來，環境也裝好了，結果連個開發伺服器都跑不起來，那一刻我真的是對著螢幕翻了個大白眼，內心瘋狂 OS：「這到底是誰寫的鬼東西？」

其實這錯誤會跳出來，是因為我當時電腦裡的 Node.js 版本升級到了 v17 以上，而專案裡用的 Webpack 版本比較舊。簡單來說，Node.js 更新後換了一套更嚴格的加密演算法（OpenSSL 3.0），但舊版的 Webpack 還在用人家已經不支援的舊語法，兩邊「語言不通」，所以 Node.js 就直接拒絕執行，擺出一副「我不認識你這套過時的演算法」的姿態。這種感覺就像你拿著舊時代的鑰匙想去開新鎖，結果當然是怎麼轉都轉不開，還差點把鑰匙弄斷。

當時我在網路上翻了好幾頁 Stack Overflow，試過各種奇怪的降版大法，最後發現最快、最不傷身的方法，就是直接在啟動指令前面塞一個環境變數，告訴 Node.js：「嘿，拜託你先暫時退回到舊模式幫我跑一下」。如果你是在 Mac 或 Linux，直接修改 package.json 裡的 scripts 就行了：


"scripts": {
  "start": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

如果你是用 Windows 的話，記得指令要改成 set NODE_OPTIONS=--openssl-legacy-provider 喔。改完之後再跑一次 npm start，那個熟悉的編譯畫面就會乖乖出現了。

至於要怎麼預防這種地雷再次炸開？我覺得最穩的方法還是乖乖用 nvm (Node Version Manager) 來管理版本。畢竟每個舊專案對 Node 的脾氣都不一樣，以後遇到這種「古董級」專案，第一件事就是先查一下它的 engines 設定，直接用 nvm use 切換到該專案當初開發時的 Node 版本，通常就能省下大半天找錯誤的時間，畢竟工程師的肝可是很珍貴的，能少踩一個坑是一個。

希望這篇筆記能救到正在螢幕前抓狂的你，趕快去把專案跑起來繼續搬磚吧！
