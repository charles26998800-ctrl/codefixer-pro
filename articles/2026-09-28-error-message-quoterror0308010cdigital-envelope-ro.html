How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I remember exactly where I was when I first hit this error—it was a Sunday afternoon, and I was just trying to spin up a fresh React project to prototype a new feature. I had just run npm start with total confidence, only to be met with a wall of red text screaming about "digital envelope routines." I spent a good three hours convinced I’d somehow broken my entire Node installation or corrupted my local environment, only to realize I was just a victim of a major version bump in Node.js.

The reason this happens is actually quite straightforward, even if it feels cryptic at first. When Node.js upgraded to version 17, they bumped the underlying OpenSSL library to version 3.0. This new version enforces stricter security standards, and it turns out that some older Webpack configurations—or even newer ones that haven't been updated—rely on algorithms that OpenSSL 3.0 now considers legacy or insecure. It’s a classic case of your development tools being "too safe" for the older dependencies your project is trying to run.

The fastest way I found to fix this is by telling Node to use the legacy OpenSSL provider, which effectively tells the system to stop being so picky about those older cryptographic routines. If you’re on a Mac or Linux machine, you can patch this temporarily by setting an environment variable in your terminal right before you run your start command:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax changes slightly. You’ll want to run this in your command prompt:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

To make this permanent so you don’t have to type it every single time you sit down to code, I usually just add it directly to my package.json file. You can modify the scripts section like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

Moving forward, the best way to prevent this from ruining your flow is to keep your dependencies updated. Most of the time, this error pops up because you're using an older version of react-scripts that hasn't been maintained to support the newer Node environments. If you’re starting a new project, always check that you’re using the latest versions of your build tools, as the community has largely patched these issues in newer releases.

Hopefully, this saves you the headache it caused me that Sunday afternoon. Happy coding, and don't let the build errors get you down!

React 專案啟動就報錯？搞定這該死的 digital envelope routines 錯誤

來源：Stack Overflow ↗ · 2572 票

那天我剛升級了電腦的 Node.js 版本，想說趁週末把一個擱置已久的 React 舊專案拿出來跑一下，結果 npm start 一敲下去，終端機直接噴出一大串紅通通的 error:0308010C:digital envelope routines::unsupported。我當下真的差點把咖啡噴到螢幕上，心想明明昨天還好好的，怎麼今天連開發伺服器都起不來？那種「明明程式碼沒改，環境卻原地爆炸」的無力感，真的是每個工程師心裡的痛，感覺像被整個世界針對了一樣。

其實這問題的罪魁禍首就是 Node.js 17 之後的版本。簡單來說，Node.js 為了資安考量，把 OpenSSL 從 1.1.1 升級到了 3.0，而舊版的 Webpack（特別是 React CRA 常用到的那些版本）還在使用舊的加密演算法，結果兩邊就像雞同鴨講，新版 Node 不認帳，這才跳出這個令人抓狂的錯誤。說穿了就是新環境跟舊套件在「鬧彆扭」，誰也不讓誰。

解決方法其實意外地單純，我們只要告訴 Node.js 暫時恢復一下舊版的加密標準就好。如果你是 macOS 或 Linux 使用者，在終端機輸入這行指令就能立刻搞定：


export NODE_OPTIONS=--openssl-legacy-provider

若是 Windows 的 PowerShell，則是用這行：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

如果你不想每次重開終端機都要打一次，最推薦的做法是直接改 package.json 裡的 scripts 設定。找到 start 那一行，把它改成這樣：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

這樣一來，每次執行指令時都會自動帶上這個參數，保證不會再跳出錯誤。

為了避免以後再被這種環境問題搞到心態崩潰，我現在強烈建議大家導入 nvm（Node Version Manager）來管理 Node.js 版本。畢竟專案一多，每個專案依賴的環境根本不一樣，用 nvm 可以輕鬆切換，甚至在專案目錄下放一個 .nvmrc 檔案，這樣下次換電腦或是同事接手時，只要敲一下 nvm use 就能完美重現開發環境，省下不少除錯的時間。

希望這篇能幫你省下寶貴的週末，別再為了這個報錯在電腦前發呆啦！
