How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1420 votes

I still remember the first time I set up Docker on a fresh Ubuntu install, feeling like a total pro until I tried to run my first container without sudo. I spent a solid 30 minutes convinced I’d somehow broken my entire Linux installation or that I’d botched the daemon setup, only to realize I was just fighting a standard permissions wall. It’s one of those classic "welcome to the club" moments that every dev hits eventually, and honestly, typing sudo before every single Docker command gets old real fast.

The reason you’re seeing that "Permission denied" error is actually a security feature, not a bug. By default, the Docker daemon binds to a Unix socket owned by the root user, which means only users with root privileges can talk to it. When you run a command without sudo, your standard user account simply doesn't have the permission to access /var/run/docker.sock. Linux is just doing its job by keeping your user from touching processes that require elevated rights, but since you're the one managing the containers, you need a way to bypass this without chaining sudo to everything you type.

To fix this, I always add my user to the docker group, which grants the necessary permissions to interact with the daemon without needing root access. First, you need to create the group if it doesn't exist yet by running sudo groupadd docker. Once that's ready, go ahead and add your current user to that group using the following command:


sudo usermod -aG docker $USER

After you run that, the changes won't take effect immediately. You’ll need to refresh your group membership, which you can do by logging out and logging back in, or by running newgrp docker in your current terminal session to apply the changes right away. Once that’s done, try running docker run hello-world again. If it works, you’re golden.

If you find that the permissions didn't stick or you're still hitting a wall, a quick reboot of your machine is the nuclear option that almost always clears out any lingering session issues. Moving forward, the best way to prevent this from ruining your flow is to always handle your user permissions immediately after installing the Docker engine. Just add that usermod command to your setup checklist, and you’ll never have to deal with that annoying "Permission denied" error on a new machine again.

Hope this saves you some of the headache I dealt with back in the day. Happy containerizing!

Docker 權限被拒？別再每次都打 sudo 了！

來源：Stack Overflow ↗ · 1420 票

記得剛開始碰 Docker 的時候，我正為了趕一個專案進度忙得焦頭爛額，好不容易設定好環境，滿心期待地輸入 docker run hello-world 想驗證一下成果，結果螢幕直接噴出一大串紅通通的 Permission denied。當時我心想：「蛤？我剛才明明才剛安裝好啊，該不會是安裝壞了吧？」最痛苦的是，我為了求快，被迫在每個指令前面都加上 sudo，結果後來打到手痠不說，還因為權限問題搞壞了幾個掛載的目錄，那種「明明程式沒錯，卻死在權限設定」的無力感，真的會讓人想直接把電腦關了去睡覺。

其實這問題的根本原因很單純，Docker 的 daemon 進程預設是綁定在 unix socket 上的，而這個 socket 檔案預設只有 root 使用者才有讀寫權限。所以當你不用 sudo 的時候，Docker client 想要跟後端的 daemon 溝通，直接被作業系統擋在門外，它當然就只能回報「我不認識你，不准進來」了。

要解決這個問題其實不用搞得那麼複雜，我們只需要把當前的使用者加入到 docker 這個使用者群組裡就行了。首先，你可以透過 sudo groupadd docker 確保群組存在（通常安裝時會自動建立），接著用這行指令把你的帳號加進去：


sudo usermod -aG docker $USER

加進去之後，重點來了，你需要讓這個變更生效。最簡單的方法就是直接登出再登入，或者是執行 newgrp docker 強制更新當前 shell 的群組權限。你可以試著輸入 docker run hello-world，如果看到那段熟悉的「Hello from Docker!」，恭喜你，以後再也不用為了這點小事打 sudo 了！

至於要怎麼預防下次又踩雷？其實這就是 Linux 權限管理的日常。下次你在新機器上安裝 Docker 時，養成好習慣，安裝完就順手執行一次加入群組的步驟。另外，如果你是剛加入團隊的新手，記得提醒自己，以後遇到這種「權限被拒」的狀況，先檢查一下自己是不是在正確的群組裡，而不是一味地依賴 sudo，這才是資深工程師該有的處理節奏。

搞定之後心情真的會舒暢很多，趕快去把你的專案跑起來吧，別讓這種小 bug 耽誤了你的開發進度！
