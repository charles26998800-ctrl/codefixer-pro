How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the first time I ran into this error. I had just spun up a fresh React project to prototype a quick dashboard, confident that I’d have the skeleton ready before my coffee went cold. Instead, I spent three hours staring at my terminal, convinced I’d somehow corrupted my entire Node environment, only to realize that my shiny new version of Node.js was essentially playing "hard to get" with my older build tools.

The reason you’re seeing this error:0308010C:digital envelope routines::unsupported message is pretty straightforward, even if it feels like a total roadblock. Essentially, Node.js version 17 and above upgraded to OpenSSL 3.0, which tightened up security standards. Many older Webpack versions and libraries still rely on older, less secure hashing algorithms that OpenSSL 3.0 simply refuses to run by default. It's basically a mismatch between your modern Node installation and the legacy code living inside your project's node_modules.

To get things moving again, the most common fix is to force Node.js to use the legacy OpenSSL provider. You can do this by setting an environment variable called NODE_OPTIONS to --openssl-legacy-provider. If you're on a Mac or Linux machine, you can just run this command in your terminal before starting your development server:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is a little different—you'll want to use set instead of export. If you want to make this change stick so you don't have to remember it every time you open a new terminal tab, I recommend adding it directly to your package.json file. Just update your scripts section like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

Moving forward, the best way to prevent this headache is to keep your dependencies updated. This error is almost always a sign that your react-scripts package is outdated and isn't playing nice with your current Node environment. Whenever you start a new project, run a quick audit or check if there’s a newer version of your build tools available; it’ll save you a lot of time in the long run.

Hope this gets your project back on track without any more cryptic errors. Happy coding, and don't let the build tools win!

遇到 error:0308010C？別慌，這只是 Node.js 版本跟舊專案鬧脾氣而已

來源：Stack Overflow ↗ · 2572 票

那天我剛接手一個放了有點久的 React 舊專案，想說先 npm install 再 npm start 跑跑看，結果終端機直接噴出一大串紅通通的錯誤，最顯眼的就是那行 error:0308010C:digital envelope routines::unsupported。我當下心裡真的罵了一句髒話，明明剛剛才裝好環境，怎麼連個 Hello World 都跑不起來？那一刻我盯著螢幕發呆，甚至懷疑自己是不是把 Node.js 的設定弄壞了，差點把整個專案砍掉重練。

其實這問題一點也不複雜，說穿了就是 Node.js 版本更新帶來的「副作用」。簡單來說，從 Node.js v17 開始，為了安全性，官方把 OpenSSL 升級到了 3.0 版本，這導致許多舊版的 Webpack 或其他依賴套件使用的加密演算法被視為「不安全」或是「不支援」。這就像是你拿著一把舊時代的鑰匙，想去開一扇裝了新式生物辨識系統的門，門鎖當然不認你這把舊鑰匙，直接拒絕讓你進去。

我當時試了一堆方法，最後發現最快也最不傷身的方法，就是告訴 Node.js：「嘿，別管那麼多，先讓我用舊的加密方式跑吧！」最直接的解法就是在執行 npm start 之前，設定一個環境變數 NODE_OPTIONS。如果你是用 macOS 或 Linux，直接在終端機輸入這行：


export NODE_OPTIONS=--openssl-legacy-provider
npm start

如果你是 Windows 的 PowerShell 使用者，指令長這樣：


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

如果你不想每次跑專案都要打一遍，也可以直接把它寫進 package.json 的 scripts 區塊裡，把 "start": "react-scripts start" 改成 "start": "react-scripts --openssl-legacy-provider start"，這樣以後只要打 npm start 就會自動生效，省事多了。

至於怎麼預防這種鬼打牆的情況發生？我覺得最根本的方法還是「版本控制」。如果你在團隊開發，強烈建議在專案根目錄放一個 .nvmrc 檔案，裡面寫上該專案指定的 Node.js 版本（比如 16.14.0），然後強迫大家用 nvm 來管理版本。這樣就不會發生你用最新的 Node.js 去跑一個兩年前的舊專案，然後在那邊懷疑人生的慘劇了。

希望這招能救你脫離苦海，別再為了這種環境設定浪費寶貴的開發時間啦！
