How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1419 votes

I remember the first time I set up my dev environment on a fresh Ubuntu install and felt like a total pro until I ran my first container. I sat there staring at my screen for a good twenty minutes, convinced I’d somehow broken the entire Docker installation because the terminal kept spitting back "permission denied" errors. I spent way too much time obsessing over my user permissions and reinstalling the whole engine before realizing it was just a simple socket access issue that every engineer hits at least once.

The reason you’re running into this is actually pretty straightforward once you peel back the layers. By default, the Docker daemon binds to a Unix socket owned by the root user, not your standard user account. When you run a command without sudo, your terminal tries to talk to that socket, but the system shuts it down because your user doesn't have the required group privileges. It’s a standard security measure to prevent unprivileged users from having root-level control over the system, but it gets annoying fast when you're just trying to spin up a local database.

To fix this, you need to add your user to the docker group, which grants you the necessary permissions to interact with the daemon without needing to type sudo every single time. First, you’ll want to create the group if it doesn't already exist by running sudo groupadd docker. Once that's ready, go ahead and add your current user to that group with this command:


sudo usermod -aG docker $USER

After you’ve run that, the changes won't take effect immediately. You’ll need to either log out and log back in or run newgrp docker to refresh your group membership in the current shell. I usually just restart my terminal session entirely to be safe. You can verify it worked by running docker run hello-world without the sudo prefix; if everything went according to plan, you’ll see that satisfying confirmation message from Docker instead of the dreaded permission error.

Moving forward, the best way to prevent this headache is to make it a part of your standard "new machine" setup script. Whenever I provision a new dev box, I include the group assignment as an automated step in my bash profile or Ansible playbook. It saves me the trouble of remembering the command six months down the line when I’m inevitably setting up a new laptop and feeling too lazy to troubleshoot basic permissions again.

Hope this gets you back to shipping code without the constant password prompts. Happy containerizing!

每次下指令都要打 sudo？教你優雅解決 Docker 權限報錯

來源：Stack Overflow ↗ · 1419 票

還記得剛開始學 Docker 那會兒，為了趕在截止日前部署一個小 demo，我在終端機裡瘋狂輸入指令。結果每次打完 docker run 就跳出那個該死的 Permission denied，搞得我心態直接崩掉，心想：「這不是才剛裝好嗎？為什麼全世界都在跟我作對？」最痛苦的是，當你寫好一長串複雜的參數，按下 Enter 才發現忘了加 sudo，那種必須重打一遍或是按方向鍵重來、甚至還要補上密碼的無力感，真的是工程師的一大夢魘。

其實這個問題的原因很單純，就是 Unix 權限設定在搞鬼。Docker 的服務端（Daemon）會建立一個 /var/run/docker.sock 的 socket 檔案，而這個檔案預設只有 root 使用者有權限存取。當我們不用 sudo 執行指令時，我們只是以一般使用者的身份去存取它，理所當然就會被拒之門外。這就像是你要進公司的機房，結果門禁卡權限不夠，系統當然會冷冷地拒絕你。

解決方法其實非常簡單，我們只需要把當前的使用者加入到 docker 這個群組裡就行了。首先，你要先建立這個群組（雖然通常安裝 Docker 時已經自動建立了，但保險起見還是可以跑一下）：


sudo groupadd docker

接著，把你的帳號加進去：


sudo usermod -aG docker $USER

這裡的 $USER 會自動帶入你目前的帳號名稱。重點來了，做完這個步驟後，一定要記得登出再重新登入系統，或者直接重開機，因為群組權限的更新要在新的 session 才會生效。如果你不想重登，也可以先用 newgrp docker 指令暫時切換一下，但為了確保環境變數都更新到位，我還是強烈建議直接登出登入比較乾脆。

為了預防下次又遇到這種鳥事，或是哪天重灌系統後忘記怎麼設，我通常會把這串指令寫成一個設定環境的腳本檔，放在自己的 GitHub dotfiles 倉庫裡。其實只要養成習慣，在設定新環境的當下就順手把權限處理好，以後就不會再因為這種小問題中斷開發節奏了。

搞定這個權限問題後，總算可以順暢地一鍵啟動容器，不用再當那個整天跟 sudo 搏鬥的苦命工程師啦！
