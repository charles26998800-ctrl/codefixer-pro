How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I upgraded my Node.js version right before a major client demo, only to have my entire project crash with the dreaded error:0308010C:digital envelope routines::unsupported message. I spent three hours frantically digging through node_modules and questioning my life choices, convinced I’d somehow broken my entire local environment. It turns out, I was just a victim of an update that didn't play nice with my legacy build tools, and I’m sure you’ve felt that same surge of panic if you’re reading this.

The reason this happens is actually quite straightforward once you look under the hood. When Node.js bumped up to version 17 and beyond, they switched to a newer version of OpenSSL. This new version enforces stricter security standards, specifically regarding the hashing algorithms used in older versions of Webpack. Since many React projects—especially those created with older versions of Create React App—rely on these legacy hashing methods, Node.js throws a fit and refuses to run the build process because it considers those old algorithms "unsupported." It’s essentially a security mismatch between your modern Node environment and your slightly older project dependencies.

To fix this, you don't need to rebuild your entire project or downgrade your Node installation. The most reliable way I’ve found to resolve this is by telling Node.js to enable the legacy OpenSSL provider explicitly. You can do this by setting an environment variable called NODE_OPTIONS to --openssl-legacy-provider. If you're on a Mac or Linux machine, you can patch your package.json file to apply this fix automatically every time you run a script. Just find your scripts section and modify your start and build commands like this:


"scripts": {
  "start": "NODE_OPTIONS=--openssl-legacy-provider react-scripts start",
  "build": "NODE_OPTIONS=--openssl-legacy-provider react-scripts build"
}

If you’re working on a Windows machine, the syntax is a bit different because Windows doesn't handle the NODE_OPTIONS assignment the same way in the terminal. In that case, you should install a package called cross-env to ensure your commands work regardless of the operating system:


npm install --save-dev cross-env

Then, update your scripts to use it:


"scripts": {
  "start": "cross-env NODE_OPTIONS=--openssl-legacy-provider react-scripts start",
  "build": "cross-env NODE_OPTIONS=--openssl-legacy-provider react-scripts build"
}

Moving forward, the best way to prevent this kind of headache is to keep your project dependencies updated. Tools like npm-check-updates or simply keeping your react-scripts version current will ensure you're using modern build configurations that don't rely on deprecated security protocols. It’s definitely a pain in the neck when things break after an update, but once you've patched it, you'll be back to coding in no time.

Hope this gets your project back on track and saves you from the same frustration I dealt with. Happy coding, and don't let the build errors get you down!

救命！React 專案噴出 error:0308010C，害我以為電腦壞了

來源：Stack Overflow ↗ · 2572 票

那天我正準備要接手一個舊專案，想說先跑個 npm start 看看環境有沒有問題，結果終端機瞬間噴出一大串紅通通的錯誤，上面寫著什麼 digital envelope routines::unsupported。我當下心臟漏了一拍，想說該不會是剛更新完 Node.js 就把系統搞掛了吧？那天為了修這個 bug，我盯著螢幕盯到眼睛快脫窗，明明前幾分鐘還好好的專案，一轉眼就變成無法啟動的廢鐵，那種「我明明什麼都沒改，為什麼就是跑不動」的無力感，真的是工程師最想原地離職的時刻之一。

其實會跳出這個錯誤，簡單說就是 Node.js 的版本升級惹的禍。從 Node.js 17 版本開始，開發團隊為了安全性，改用了 OpenSSL 3.0，結果這傢伙對一些舊的加密演算法管得很嚴，偏偏我們用的 Webpack 4 或者一些老舊的套件，還在使用舊版的加密方式。簡單講，就是你的新版 Node.js 覺得這些舊套件的加密方式太老派、不安全，所以直接把門鎖起來不讓它們通過，導致你的 React 專案還沒啟動就先崩潰。

我當時試過重新安裝 node_modules，甚至還想過要把 Node.js 降級回去，結果發現根本不需要這麼麻煩。最快也最直接的解法，就是告訴 Node.js：「嘿，請暫時放寬一點標準，讓我把這些老舊套件跑起來」。如果你是用 Mac 或 Linux，只要在啟動專案前，設定一下環境變數 NODE_OPTIONS 就可以了。我當時是直接修改 package.json 裡的 scripts，把啟動指令改成這樣：


"scripts": {
  "start": "NODE_OPTIONS=--openssl-legacy-provider react-scripts start",
  "build": "NODE_OPTIONS=--openssl-legacy-provider react-scripts build"
}

如果你是用 Windows 的 PowerShell，直接打指令會報錯，建議直接安裝 cross-env 這個套件，讓指令可以跨平台執行，改寫成 cross-env NODE_OPTIONS=--openssl-legacy-provider react-scripts start 就搞定了。

為了避免以後又踩到這種雷，我現在養成了習慣，在接手任何舊專案時，第一件事就是先檢查 .nvmrc 檔案。如果專案沒有這玩意兒，我會強烈建議團隊加上去，並規定大家統一使用 LTS 版本。畢竟與其每次升級環境都在跟這些加密演算法搏鬥，不如從源頭管理好 Node.js 版本，這樣開發起來心情真的會平靜很多。

希望這招能救到正在螢幕前崩潰的你，下次遇到這種紅字別怕，通常只是環境版本沒對上而已！
