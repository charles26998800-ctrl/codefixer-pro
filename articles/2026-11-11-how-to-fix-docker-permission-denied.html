Why You Keep Getting "Permission Denied" With Docker on Ubuntu

Source: Stack Overflow ↗ · 1420 votes

I remember setting up my first development environment on a fresh Ubuntu install a few years back, feeling like a total pro until I hit the dreaded docker: Got permission denied error. I spent a good three hours convinced I’d somehow corrupted my entire system installation, only to realize I was just fighting a standard Linux permission lock. It’s one of those rites of passage that feels incredibly annoying at the time but makes you feel like a wizard once you finally squash it.

The reason you’re seeing this error is actually a security feature, not a bug. By default, the Docker daemon binds to a Unix socket owned by the root user. Unless you’re running as root—or using sudo—your standard user account doesn't have the necessary permissions to talk to that socket. While sudo docker works because you’re escalating your privileges to superuser, it’s a pain to type every single time, and honestly, it’s not the safest way to handle your daily development workflow.

To fix this for good, you need to add your user to the docker group, which grants you the permissions required to communicate with the daemon without needing root access. First, I always make sure the group exists by running sudo groupadd docker. Once that's confirmed, I add my current user to it with this command:


sudo usermod -aG docker $USER

After you run that, the changes won't take effect immediately. You need to tell your system to refresh the group membership. You can either log out and log back in, or just run newgrp docker in your current terminal to apply the changes right away. Once that's done, verify it worked by running docker run hello-world without any sudo prefix. If it prints the welcome message, you're golden.

Going forward, the best way to prevent this from ruining your flow is to handle your group permissions immediately after installing Docker on any new machine. Don't just settle for sudo prefixes—it’s a bad habit that can lead to file ownership issues with the volumes you mount later on. Just add your user to the group as part of your "new machine setup" script, and you’ll never have to worry about this specific headache again.

Hope this saves you from the same three-hour rabbit hole I fell into. Happy coding!

為什麼每次跑 Docker 都要打 sudo？教你一招徹底擺脫權限地獄

來源：Stack Overflow ↗ · 1420 票

記得我剛開始接觸 Docker 的那天，滿懷興奮地想在 Ubuntu 上跑第一個 Hello World，結果螢幕上冷冰冰地跳出 Permission denied。當時我心想：「我不是剛剛才安裝好嗎？難道是我裝壞了？」最慘的是，為了趕進度，我那幾天竟然養成了「不管什麼指令前面都先補個 sudo」的壞習慣，直到有次我不小心在錯誤的目錄下用 sudo 執行了指令，導致整個專案的檔案權限全亂掉，那天晚上我真的坐在電腦前崩潰到想關機睡覺。

其實這背後的原因一點都不神秘。Docker 的運作機制是透過一個背景常駐程式（daemon）來控制的，而這個 daemon 預設會綁定在 /var/run/docker.sock 這個 Socket 檔案上。因為這檔案的權限屬於 root，所以除非你是超級使用者，不然一般帳號想去碰它，系統就會很有禮貌地把你擋在門外。這雖然是為了安全設計，但對開發者來說，每跑一個指令都要輸入一次密碼，簡直是浪費生命，而且還很容易因為手殘用 sudo 污染到你的開發目錄。

要解決這個問題，其實只要把你的使用者帳號加入到 docker 這個群組就好。當你完成設定後，你的帳號就會被賦予「管理員權限」去操作 Docker daemon，再也不用沒事掛著 sudo 了。你可以先試著執行下面這行指令建立群組（雖然通常裝 Docker 時會自動建立）：


sudo groupadd docker

接著，把你自己的使用者加進這個群組裡：


sudo usermod -aG docker $USER

重點來了，很多人做到這步就以為結束了，結果重開終端機發現還是報錯。記得一定要執行 newgrp docker 來重新整理當前的群組權限，或者最簡單的方式就是直接登出再登入，讓系統重新載入你的權限設定。設定好之後，你試著打 docker run hello-world，如果看到那段成功歡迎訊息，恭喜你，終於可以跟 sudo 說再見了！

至於怎麼預防這種鬼打牆？其實最好的習慣就是「安裝後即刻檢查」。以後你在新的機器上裝完 Docker，第一件事不要急著跑容器，先養成把當前使用者加入群組的習慣。這就像是幫你的開發環境鋪好路，之後在寫 Dockerfile 或者設定 Docker Compose 時，才不會因為權限問題搞到心態爆炸。

解決完這個小問題，終於可以專心寫程式了，祝大家部署順利、Debug 永遠一次過！
