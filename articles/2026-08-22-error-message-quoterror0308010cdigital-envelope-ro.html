How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I updated my Node.js version right before a major client demo, only to have my entire React dev server crash with that cryptic error:0308010C:digital envelope routines::unsupported message. I spent three hours staring at the console, convinced I’d somehow corrupted my entire project, only to realize I was just a victim of a major breaking change in the ecosystem. It’s one of those classic "everything was working fine five minutes ago" moments that makes you want to throw your keyboard out the window.

If you’re seeing this, it’s because you’re running Node.js 17 or higher. When the Node team upgraded to OpenSSL 3.0, they tightened up their security, and suddenly, many older Webpack configurations started failing because they rely on algorithms that are now considered legacy. Essentially, your project is trying to use a hashing method that Node.js has deemed "unsupported" for security reasons, and it’s throwing a tantrum because it doesn't know how to handle the newer, stricter standards.

The quickest way I’ve found to squash this is by telling Node.js to use the legacy OpenSSL provider, which effectively downgrades the security requirements for your build process. If you’re on a Mac or Linux machine, you can fix this instantly by setting an environment variable in your terminal before you run your start script. Just run this in your project root:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re stuck on Windows using Command Prompt, you’ll want to set it like this:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

For those of you who don't want to type that every single time, I usually just update the scripts section in my package.json file. It’s a set-it-and-forget-it approach that saves me from losing my mind every time I open a new terminal session. Just modify your start and build commands to look like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To keep this from biting you again, my best advice is to keep your development environment consistent by using a version manager like nvm (Node Version Manager). By keeping a .nvmrc file in the root of your project, you can lock your team into a specific Node version, which prevents those "it works on my machine but not yours" scenarios that keep us all up at night.

Hope this gets your build back on track so you can get back to shipping code. Happy coding!

崩潰！啟動 React 專案卻噴出 OpenSSL Error：這到底是什麼鬼？

來源：Stack Overflow ↗ · 2572 票

那天我為了趕一個 Side Project 的 Demo，興沖沖地用 IntelliJ 開了個新的 React 專案，結果 npm start 一按下去，終端機直接賞我一串紅通通的 error:0308010C:digital envelope routines::unsupported。我當下真的差點把鍵盤摔了，明明程式碼一行都還沒寫，連 Hello World 都還沒看到就直接原地爆炸，那種「我明明照著文件做，為什麼還是不行」的無力感，真的是工程師心頭永遠的痛。

其實會發生這個災難，是因為 Node.js 在 v17 版本之後升級了 OpenSSL 到 3.0，這傢伙對加密演算法的安全性要求變得很嚴格。但問題就在於，很多我們常用的 React 工具（像是舊版的 webpack）還在使用舊的演算法，兩個世代的軟體兜在一起，OpenSSL 就會跳出來說：「欸，這不安全，我不支援」，然後你的專案就直接罷工給你看。這真的很讓人火大，因為這根本不是我們程式碼寫錯，而是環境配置的代溝。

要解決這個問題，其實不用把整個 Node.js 版本降回去（除非你真的很閒）。最快的方法就是直接告訴 Node.js：「嘿，別管那麼多，先暫時把限制關掉」。如果你是用 Mac 或 Linux，在啟動專案的指令前加上 NODE_OPTIONS=--openssl-legacy-provider 這個環境變數就搞定了。

我的做法是直接改 package.json 裡的 scripts，把啟動指令改成這樣：


"scripts": {
  "start": "NODE_OPTIONS=--openssl-legacy-provider react-scripts start",
  "build": "NODE_OPTIONS=--openssl-legacy-provider react-scripts build"
}

如果你是用 Windows 的 PowerShell，直接這樣寫會報錯，建議直接安裝一個叫 cross-env 的套件，確保不管在哪個作業系統都能跑：


npm install cross-env --save-dev

然後把腳本改成：

"start": "cross-env NODE_OPTIONS=--openssl-legacy-provider react-scripts start"

至於要怎麼預防下次再被這種莫名其妙的環境問題卡死？建議大家養成用 nvm (Node Version Manager) 來管理版本的習慣。當你接手一個舊專案時，先確認該專案原本是用哪個 Node 版本開發的，直接切換過去，通常就能避開這種升級後的相容性地雷。

以後遇到這種莫名其妙的錯誤先別慌，通常都是環境設定在鬧脾氣而已，喝杯咖啡再回來處理通常就能解決了！
