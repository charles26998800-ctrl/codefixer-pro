How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I remember the exact moment I first hit this error. I had just upgraded my Node.js version to v17, sat down with a fresh coffee, and fired up an older side project I hadn’t touched in months. Instead of my local dev server popping up, my terminal exploded with a wall of red text ending in that cryptic error:0308010C:digital envelope routines::unsupported message. I spent three hours—yes, three whole hours—fiddling with my package.json and reinstalling node_modules like a madman before I realized the problem wasn't my code, but the environment itself.

The reason this happens is actually quite straightforward once you look under the hood. Node.js v17 and later updated the OpenSSL version to 3.0, which enforces stricter security standards for cryptographic algorithms. The issue is that many older versions of Webpack and other build tools used in React projects rely on legacy algorithms that are now considered insecure by the new OpenSSL configuration. Essentially, your project is trying to use a "digital envelope" that Node.js has decided is outdated and unsafe, so it shuts the whole process down to keep you secure.

The fastest way I found to fix this without having to upgrade every single dependency in my project is to tell Node.js to enable the legacy OpenSSL provider. You can do this by setting an environment variable called NODE_OPTIONS to --openssl-legacy-provider. If you're on a Mac or Linux machine, you can run this command right in your terminal before starting your development server:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows using PowerShell, the syntax is slightly different, but it achieves the same result:


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

For a permanent fix that saves you from typing that every time you open your terminal, just head into your package.json file. You can modify your scripts section to inject this flag automatically whenever you run your start or build commands, like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

If you want to prevent this headache in the future, the best move is to keep your development environment consistent with your team's or your production environment by using a version manager like nvm (Node Version Manager). I personally keep a .nvmrc file in the root of all my projects that specifies exactly which Node version I’m using. That way, whenever I jump back into an old codebase, I just run nvm use and avoid these configuration mismatches entirely.

Hopefully, this saves you the three hours I wasted staring at my screen. Happy coding, and may your builds stay green!

救命！React 專案噴出 error:0308010C 錯誤，搞到我懷疑人生

來源：Stack Overflow ↗ · 2572 票

那天下午我正準備開工，想說先用 IntelliJ IDEA 跑一個簡單的 React 專案暖暖身，結果 npm start 按下去，終端機直接跳出一長串紅字，那個 error:0308010C:digital envelope routines::unsupported 簡直像是在對我宣示主權。我當時心裡直接罵了一聲髒話，想說這不是最基礎的專案嗎？我連一行程式碼都還沒寫欸，怎麼就直接卡在啟動階段了，那天下午的心情真的瞬間跌到谷底。

後來我去查了一下，才發現這其實是 Node.js 版本惹的禍。簡單來說，Node.js 在 17 版之後升級了加密演算法，採用了更嚴格的 OpenSSL 3.0，但我們平常在用的那些舊版 webpack 或者一些開發工具，它們還在用舊的加密方式，結果兩邊互不相讓，電腦就直接報錯罷工了。那種「我明明什麼都沒改，為什麼世界針對我」的無力感，真的是每個開發者心中永遠的痛。

解決方法其實意外地簡單，只要告訴 Node.js「嘿，請用回舊的演算法模式」就好。最快的方法就是設定一個環境變數 NODE_OPTIONS。如果你是用 Mac 或 Linux，直接在終端機輸入這行指令：


export NODE_OPTIONS=--openssl-legacy-provider

如果你跟我一樣是用 Windows，那就改用下面這段：


set NODE_OPTIONS=--openssl-legacy-provider

設定完之後再執行 npm start，通常就能看到熟悉的編譯成功畫面了。如果你是想永久解決這個問題，也可以直接把這行加到 package.json 的 scripts 區塊裡，把 start 改成 "start": "react-scripts --openssl-legacy-provider start"，這樣就不用每次開專案都要重新打一次指令，省心很多。

至於以後怎麼避免這種崩潰？我的建議是乖乖安裝 nvm (Node Version Manager)。畢竟前端生態圈更新速度快到嚇人，很多舊專案如果不指定 Node 版本，真的會動不動就噴一堆莫名其妙的錯。平常養成好習慣，切換專案前先確認一下 Node 版本，真的能幫你省下不少找 Bug 的頭髮。

希望這篇能救你一命，下次遇到這種紅字別怕，深呼吸，通常都只是版本打架而已啦！
