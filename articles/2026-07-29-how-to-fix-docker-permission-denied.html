Why You Keep Getting "Permission Denied" With Docker on Ubuntu

Source: Stack Overflow ↗ · 1416 votes

I still remember the first time I set up Docker on my shiny new Ubuntu dev machine. I was so excited to spin up my first container, typed docker run hello-world with a smug grin, and was promptly slapped in the face by a wall of red text screaming about permission denied errors. I spent a good hour convinced I’d botched the entire installation, only to realize I was just playing the classic "sudo dance" game that catches every single one of us early on.

The root cause here is actually pretty straightforward: the Docker daemon binds to a Unix socket rather than a TCP port by default, and that socket is owned by the root user. Because your standard user account isn't part of the docker group, the system blocks you from accessing that socket to protect the host machine. It’s a security feature, but it’s incredibly annoying when you’re just trying to get your environment up and running and don't want to prefix every single command with sudo.

To fix this, I simply add my user to the docker group so the system knows I’m authorized to talk to the daemon. First, I create the group if it doesn’t exist, then I add my current user to it using the following commands in my terminal:


sudo groupadd docker
sudo usermod -aG docker $USER

After running those, the changes won't take effect immediately. You’ll need to either log out and log back in, or just refresh your group membership for the current shell by running newgrp docker. Once that's done, you can test it by running the hello-world container one last time without the sudo prefix. If it works, you’re golden, and you won’t have to deal with those pesky permission errors ever again.

Moving forward, the best way to prevent this from ruining your flow is to perform this group assignment immediately after installing Docker on any new environment. It’s become a mandatory line in my "new machine setup" script because nothing kills productivity faster than fighting with permissions when you're trying to ship code.

Hope this saves you the headache it caused me back in the day. Happy coding!

Docker 權限被拒？別再傻傻打 sudo 了，一次徹底解決它

來源：Stack Overflow ↗ · 1416 票

記得剛開始碰 Docker 的時候，我真的快被那個 Permission denied 搞到懷疑人生。那天我明明已經裝好環境，滿心期待地要跑第一個 Container，結果一打指令就噴出一大串紅通通的錯誤訊息，重點是加上 sudo 就能跑，不加就死給我看，那種「明明裝好了卻被拒之門外」的無力感，真的是會讓人想直接把電腦關了去睡覺。

其實這問題背後的原因很單純，Docker Daemon 預設是透過一個 Unix Socket 檔案（就是那個 /var/run/docker.sock）在溝通的，而這個檔案的擁有者是 root 使用者。當我們不加 sudo 執行指令時，系統會認定你只是一般的普通用戶，沒有權限去敲這個 Socket 的門，所以它才會傲嬌地拒絕你的請求。說實話，每次執行指令還要多打五個字母的 sudo，久了真的會讓人覺得很煩躁，尤其是寫腳本的時候，多一個權限錯誤就能讓你除錯半天。

要解決這個問題，其實官方文件裡就有寫，只是當時我太急著想跑程式，直接忽略了。最正統的做法就是把你的使用者帳號加入到 docker 這個使用者群組裡。首先，你得先確認系統有沒有這個群組，沒有的話就手動建一個，然後把當前的使用者塞進去：


# 建立 docker 群組（通常安裝完就有，沒壞就不用動）
sudo groupadd docker

# 把當前使用者加入群組
sudo usermod -aG docker $USER

加完之後，關鍵的一步來了：你必須要登出再重新登入，或者直接重開機，這樣系統才會重新整理你的群組權限。如果你懶得重開，也可以用 newgrp docker 指令讓當前的終端機階段生效，但為了保險起見，我通常還是會建議直接登出再登入，省得後面又出現什麼奇怪的權限殘留問題。

以後要是怕這類權限問題又跑出來搗亂，我建議在剛架好新機器、裝完 Docker 的第一時間，就直接把這行指令加入你的安裝腳本清單裡。養成把使用者加入群組的習慣，能幫你省下後面無數次因為權限不足而中斷開發的尷尬時刻。

搞定這些之後，你就可以享受不用一直打密碼的清爽開發體驗啦，趕快去把你的 Container 跑起來吧！
