Fixing the "RuntimeError: Input type and weight type should be the same" in PyTorch

Source: Stack Overflow ↗ · 202 votes

I still remember the first time I set up a GPU training loop in PyTorch; I was so proud of my model architecture that I didn't even check my data types. I spent three hours staring at my screen, convinced my GPU drivers were fried, only to realize I was trying to feed CPU-bound tensors into a model living comfortably on my NVIDIA card. It’s one of those classic "welcome to deep learning" moments that makes you want to throw your keyboard out the window.

The reason this error bites you is actually pretty straightforward: PyTorch is extremely strict about where your data lives. When you call model.to(device), you are physically moving the model's weights and biases into your GPU’s memory. However, when you iterate through your dataloader, the tensors coming out are still sitting in your system's RAM (the CPU). PyTorch refuses to perform math between two tensors if one is on the CPU and the other is on the GPU because they exist in completely different physical memory spaces. It’s like trying to bake a cake using an oven in a different house; the data just can't get there unless you explicitly move it.

To fix this, you need to be intentional about moving your data to the same device as your model inside your training loop. I usually handle this right after I unpack my data batch. You simply take your inputs and labels and call the .to(device) method on them before passing them to the model. Here is the snippet that saves the day:


device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model.to(device)

for data in dataloader:
    # Move the data to the same device as the model
    inputs, labels = data
    inputs = inputs.to(device)
    labels = labels.to(device)
    
    outputs = model(inputs)
    # ... rest of your training logic

If you want to avoid this headache in the future, my best advice is to stop hardcoding device names and start using a variable at the very top of your script. I always define device = torch.device("cuda" if torch.cuda.is_available() else "cpu") at the global level and then reference that variable consistently throughout my codebase. If you keep your model and your data tensors tethered to that same variable, you’ll never see this error again.

Hope this helps you get your training loop running without any more hair-pulling. Happy coding!

被 PyTorch 的裝置不匹配搞到心累？一行程式碼解決 RuntimeError

來源：Stack Overflow ↗ · 202 票

記得剛開始碰 PyTorch 的時候，為了趕一個死線模型訓練，我熬到半夜兩點，好不容易把模型寫好，滿心期待按下執行鍵，結果螢幕上那行顯眼的紅字 RuntimeError: Input type (torch.FloatTensor) and weight type (torch.cuda.FloatTensor) should be the same 直接讓我崩潰。我當時盯著螢幕看了半天，心想「我不是已經把 model 搬到 GPU 了嗎？為什麼還跟我鬧脾氣？」，那種眼看著 GPU 閒置、自己卻被卡在這種低級錯誤上的無力感，真的是工程師生涯最想原地消失的時刻之一。

其實這問題說穿了就是「溝通不良」。PyTorch 是個很嚴謹的傢伙，它規定模型參數在哪裡，輸入資料就必須跟著去哪裡。我們通常會記得把 model.to(device)，但很常在寫 for 迴圈處理 dataloader 的時候，忘記把那一批批進來的 inputs 和 labels 也搬過去。所以當模型在 GPU 上準備好要運算，卻發現你餵給它的是還留在 CPU 記憶體裡的資料，它就會直接罷工，告訴你這兩邊類型不匹配。

要解決這個問題，真的不需要什麼複雜的邏輯，只要在讀取資料的迴圈裡，順手把資料也推向你的裝置就行了。我通常會這樣寫：


device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model.to(device)

for data in dataloader:
    # 這裡就是關鍵！把輸入和標籤都搬到跟模型同一個裝置
    inputs, labels = data
    inputs = inputs.to(device)
    labels = labels.to(device)
    
    outputs = model(inputs)
    # 之後的 loss 計算也要記得把 label 放在同個裝置喔

為了避免下次又被這種小問題卡住，我現在養成了一個好習慣，就是在定義 device 之後，寫一個簡單的 helper 函數或者直接在資料處理階段統一做搬移。如果你跟我一樣懶，也可以在定義資料集時，確保後續處理流程都有明確指定裝置。其實只要在寫迴圈時，心裡多掛念著「資料也要跟著 model 跑」，這種紅字就不會再出來找你麻煩了。

希望這篇心得能幫你省下寶貴的除錯時間，趕快去把模型跑起來吧！
