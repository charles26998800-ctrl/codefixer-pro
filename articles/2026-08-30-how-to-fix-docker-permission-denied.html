Why Docker Keeps Giving You "Permission Denied" (And How to Fix It)

Source: Stack Overflow ↗ · 1419 votes

I remember the exact moment I set up my first Ubuntu dev box, feeling like a total pro until I ran my first docker run hello-world and got slapped in the face with a wall of permission errors. I spent a solid hour convinced I’d somehow corrupted my entire Linux installation, only to realize I was just fighting a standard Unix socket security feature. It’s one of those classic "welcome to Linux" moments that makes you want to throw your keyboard out the window, but thankfully, it’s an easy fix once you know where to look.

The reason you’re seeing that nasty "permission denied" error is that the Docker daemon binds to a Unix socket at /var/run/docker.sock by default. Because this socket is owned by the root user, your standard user account doesn't have the necessary privileges to talk to it without escalating your permissions. When you add sudo to your command, you’re essentially telling the OS to act as root, which bypasses the restriction, but let’s be honest—typing sudo before every single command gets old real fast.

To fix this for good, you need to add your user to the docker group, which grants you the permissions to interact with that socket directly. First, create the group if it doesn’t exist yet, then add your current user to it using these commands:


sudo groupadd docker
sudo usermod -aG docker $USER

Once you’ve run those, the changes won't take effect immediately. You’ll need to either log out and log back in, or just run newgrp docker in your current terminal session to refresh your group membership. You can verify it worked by running docker run hello-world without the sudo prefix. If you see the "Hello from Docker!" message, you’re golden.

The best way to prevent this from ever being an issue on new machines is to automate your environment setup. I keep a simple shell script in my dotfiles repository that handles the Docker installation and group configuration in one go, so I never have to manually troubleshoot this again when I spin up a new VM or laptop. It saves me the headache of hunting down documentation every time I migrate my workflow.

Hope this saves you some time so you can get back to actually shipping code. Catch you later!

每次都要打 sudo 真的會瘋掉！解決 Docker Permission denied 的終極方案

來源：Stack Overflow ↗ · 1419 票

記得剛開始碰 Docker 的時候，我滿心期待地把環境裝好，想說來跑個 Hello World 試試手感。結果當我興沖沖地按下 Enter，終端機冷冷地回我一句「Permission denied」。我當下真的很火，想說明明都安裝好了，為什麼連個測試都要被阻擋？最痛苦的是，每一次只要忘記加 sudo，或是寫腳本時少打那五個字母，整個流程就直接卡死，那種「明明能跑卻被權限卡住」的無力感，真的會讓人懷疑人生。

其實這問題的根本原因很單純，Docker 的守護行程（Daemon）預設是綁定在 Unix socket /var/run/docker.sock 上，而這個檔案的擁有者是 root。這意味著除非你是 root，或者你有 root 的權限，否則系統是不會讓你隨便去跟那個 socket 講話的。這就是為什麼你加上 sudo 就能跑，因為那時候你暫時擁有了 root 的身分。

要解決這個問題，我們不需要每次都暴力地加上 sudo，只要把當前使用者加入到 Docker 的群組就好了。你可以直接執行下面這幾行指令：


# 建立 docker 群組（通常安裝完就有，但確認一下沒壞處）
sudo groupadd docker

# 把你的使用者帳號加進去
sudo usermod -aG docker $USER

不過要注意，改完權限後並不會馬上生效。你必須要登出再登入，或者直接執行 newgrp docker 來刷新當前的 shell 環境。之後你再試試看 docker run hello-world，應該就能順利跑起來了。

為了預防以後再被這種權限問題搞到心態爆炸，我通常建議大家在配置新環境時，第一件事就是把使用者權限處理好。如果你在公司環境，記得確認一下資安規範，確保你的帳號加入 docker 群組是符合資安政策的。另外，養成檢查 /var/run/docker.sock 權限的習慣，如果哪天又遇到類似問題，至少知道要去查群組設定，而不是在那邊盲目重灌。

總算不用再當個「sudo 奴隸」了，現在打指令順暢多了，大家趕快去把權限設定好，別再讓 sudo 浪費你的生命啦！
