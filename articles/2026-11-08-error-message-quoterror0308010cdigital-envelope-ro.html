Fixing the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I updated my Node.js version, feeling all smug about having the latest environment, only to have my entire project blow up the second I ran npm start. I spent a solid two hours digging through dependency trees and questioning my life choices before realizing it was just a simple compatibility mismatch with OpenSSL. It’s one of those errors that makes you feel like you’ve broken the entire machine when, in reality, you just need to tell your terminal to play nice with the newer security protocols.

The reason this happens is actually quite straightforward once you peel back the curtain: Node.js version 17 and later updated its OpenSSL version to 3.0. This new version is much stricter about the algorithms it allows. Many older build tools, specifically older versions of Webpack or react-scripts, rely on legacy algorithms that OpenSSL 3.0 now flags as insecure. When you try to run your project, the build process tries to generate a hash using these legacy methods, OpenSSL throws a tantrum, and your terminal screams about "digital envelope routines."

To fix this, the industry-standard workaround is to force Node.js to use the legacy provider for OpenSSL. You don't need to roll back your Node version or break your project structure; you just need to set an environment variable. If you’re on a Mac or Linux machine, you can run this command in your terminal before starting your project:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the command looks slightly different because of how the shell handles environment variables. You’ll want to run this in your PowerShell or Command Prompt:


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

If you don't want to type that every single time you start your project, just bake it directly into your package.json file. Find your scripts section and modify your start command so it automatically includes that flag:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

The best way to prevent this headache in the future is to keep your development dependencies updated. This error is almost exclusively a symptom of using an outdated version of react-scripts with a newer Node environment. Whenever I start a new project, I make it a habit to check if there’s a newer version of my build tools available, as keeping those updated ensures you’re using the modern, supported cryptographic standards that OpenSSL 3.0 expects.

Hope this saves you some of the frustration I went through! Happy coding and good luck with the build.

當 React 遇上 Node.js 升級災難：修復「digital envelope routines::unsupported」錯誤

來源：Stack Overflow ↗ · 2572 票

那天下午我正準備開工，想說先用 IntelliJ IDEA 跑個簡單的 React 專案暖暖身，結果 npm start 一按下去，終端機直接噴出一大串紅字，那個 error:0308010C:digital envelope routines::unsupported 簡直像是在對我宣告死刑。我當時心裡真的罵了一聲髒話，想說環境不是昨天才剛裝好嗎？為什麼只是想跑個 Hello World 都能撞牆，害我坐在電腦前盯著那行錯誤訊息發呆了快半小時，那種「明明程式碼沒動過，卻連執行都過不去」的無力感，真的是工程師最想原地離職的痛苦時刻之一。

後來我才搞清楚，這其實是 Node.js 17 版以後搞出來的「好事」。因為 Node.js 開始改用 OpenSSL 3.0，這玩意兒對加密演算法的安全性要求變高了，把一些舊的演算法給封殺掉。但問題是，很多現有的 React 專案（特別是如果你用的是較舊版本的 Webpack）還死守著那些舊的演算法。這就像是你拿著舊鑰匙想去開新鎖，Node.js 當然會毫不留情地拒絕你，直接拋出這個錯誤訊息來抗議。

要解決這個問題，其實不用把整個開發環境砍掉重練。最快的方法就是告訴 Node.js：「嘿，別那麼嚴格，幫我開啟對舊版演算法的支援」。如果你是用 Mac 或 Linux，直接在終端機輸入這行指令：


export NODE_OPTIONS=--openssl-legacy-provider

如果你是在 Windows 的 PowerShell 環境，則是要這樣寫：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

只要設定完這個環境變數，再重新跑一次 npm start，那個惱人的紅色錯誤就會奇蹟般地消失了。如果你不想每次開終端機都要打這行，也可以直接把這段加到 package.json 的 scripts 區塊裡，像是 "start": "react-scripts --openssl-legacy-provider start"，這樣以後就一勞永逸。

為了避免以後又踩到這種雷，我現在養成了每次升級 Node.js 版本前，都會先去確認專案的依賴套件是否跟得上。其實最根本的預防方式，還是儘量保持專案的 react-scripts 或 Webpack 版本在最新狀態，畢竟技術債這東西，真的是放越久利息越重。

搞定這個坑之後，終於可以安心喝杯咖啡繼續寫 code 了，希望你們也能順利避開這個地雷！
