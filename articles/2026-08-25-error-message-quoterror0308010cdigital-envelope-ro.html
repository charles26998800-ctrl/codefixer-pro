How to Fix "error:0308010C:digital envelope routines::unsupported" in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the first time this error hit me; I had just spun up a fresh React project to prototype a quick UI idea, and instead of seeing that familiar "Compiled successfully" message, my terminal exploded with a wall of OpenSSL-related cryptic nonsense. I spent a good two hours convinced that my entire Node environment was corrupted, even going as far as nuking my node_modules folder and reinstalling everything from scratch, which, spoiler alert, did absolutely nothing to help. It’s one of those classic "why is my code yelling at me" moments that makes you want to throw your keyboard out the window.

The reason you're seeing this is actually quite simple, even if the error message makes it sound like your computer is having a meltdown. This error pops up because you’re running a newer version of Node.js (specifically version 17 or higher) with an older version of Webpack or a project dependency that relies on an outdated hashing algorithm. Node 17+ switched to OpenSSL 3.0, which tightened security and decided that the MD4 algorithm used by some older build tools is no longer "supported." Essentially, your modern Node setup is refusing to talk to the older code in your project because of a security mismatch.

The quickest way I’ve found to squash this bug is to force Node to use the legacy OpenSSL provider, which tells the runtime to stop being so picky about those older algorithms. If you're on a Mac or Linux, you can simply set an environment variable in your terminal before running your start command. You'll want to modify your package.json file so you don't have to type this out every single time you spin up your dev server. Just head into the scripts section and update your start command like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

If you're stuck on Windows, the syntax is a bit different, and you might need to use set instead of just prepending the command. If you're using PowerShell, you can run $env:NODE_OPTIONS = "--openssl-legacy-provider" before running your start script. Once you’ve saved those changes, just run npm start again, and you should see your project boot up without any further complaints.

To keep this from biting you in the future, the best move is to keep your dependencies updated. Most modern versions of react-scripts and Webpack have already patched this issue internally, so running npm update or migrating to a newer project template usually clears the path. It’s a great reminder that even if your code is perfect, your environment can still throw a wrench in the works if you aren't paying attention to your Node versions.

Hope this gets your project back on track and saves you that two-hour headache I went through. Happy coding!

救命！React 專案噴出 error:0308010C 崩潰？這其實是 Node.js 版本惹的禍

來源：Stack Overflow ↗ · 2572 票

那天我正準備接手一個舊的 React 專案，想說先 npm install 再 npm start 跑跑看，結果終端機直接吐出一長串紅色錯誤訊息，那個 digital envelope routines::unsupported 簡直像咒語一樣，看得我滿臉問號。當時心裡真的罵了一聲髒話，想說我明明只是想寫個小功能，怎麼環境設定就先卡死，還以為是哪裡的套件壞掉，花了好幾個小時在清 node_modules 和重灌套件，結果完全沒用，那種「明明程式碼沒動卻跑不動」的無力感，真的是工程師最想摔鍵盤的時刻。

其實這背後的原因一點都不神秘，單純就是 Node.js 17 版本之後升級了 OpenSSL 3.0，但我們手邊很多舊版的 React 專案（特別是用 Webpack 4 的那種）還在依賴舊的加密演算法，導致兩邊不相容。簡單說，就是 Node.js 覺得這些舊套件用的加密方式太過時、不安全，所以直接拒絕執行，這才跳出那個看起來很嚇人的錯誤碼。

要解決這個問題，其實不用去改什麼複雜的設定，最快的方法就是告訴 Node.js：「嘿，先放過這些舊套件，暫時允許使用舊版的加密演算法」。你只需要在終端機啟動專案之前，設定一個環境變數就好。如果你是用 Mac 或 Linux，直接在終端機輸入：


export NODE_OPTIONS=--openssl-legacy-provider
npm start

如果你是在 Windows 的 PowerShell 環境，指令長得稍微不一樣：


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

如果不想每次啟動都要打這行，最省事的做法就是直接去 package.json 的 scripts 區塊，把 start 跟 build 指令偷改一下，把環境變數直接塞進去：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

為了避免下次再踩到這種坑，我現在強烈建議大家專案一定要用 nvm (Node Version Manager) 來管理版本。畢竟每個舊專案對 Node.js 的脾氣都不一樣，在專案目錄下放一個 .nvmrc 檔案，規定好這個專案該用哪個版本的 Node.js，以後切換專案時只要打一行指令就能對齊，真的能省下不少翻車的時間。

搞定這個之後，終於可以繼續寫程式了，希望大家不要再被這個錯誤卡住啦！
