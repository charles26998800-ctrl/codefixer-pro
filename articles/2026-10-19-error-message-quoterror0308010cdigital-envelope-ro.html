Why Your React App is Crashing with "digital envelope routines::unsupported"

Source: Stack Overflow ↗ · 2572 votes

I remember sitting down to spin up a quick prototype for a side project, feeling pretty productive, when I ran npm start and was greeted by a wall of red text instead of my dev server. I spent a good three hours convinced I’d somehow corrupted my entire local environment, only to realize that my shiny new Node.js installation was just a little too "modern" for my older project dependencies. It’s one of those errors that makes you feel like you’ve broken something fundamental, even though it’s really just a classic case of tech stack mismatch.

The reason you’re seeing this error:0308010C:digital envelope routines::unsupported message is that Node.js 17 and later versions updated their OpenSSL library to version 3.0. This new version is much stricter about the cryptographic algorithms it allows. Many older projects—or even newer ones using older versions of Webpack—rely on the legacy MD4 algorithm to hash files. Because OpenSSL 3.0 has deprecated these older standards, Node.js throws a fit and refuses to run your build process. It basically sees the legacy code as a security risk and shuts the whole operation down.

The fastest way I’ve found to fix this without rewriting your entire build configuration is to tell Node.js to stop being so picky by enabling the legacy OpenSSL provider. If you’re on a Mac or Linux machine, you can do this right in your terminal before running your start command by setting an environment variable. Just run this in your project root:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is a bit different, so you’ll want to use this command instead:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

To make this permanent so you don’t have to type it every single time you open a new terminal tab, I recommend adding it directly to your package.json file. Find the scripts section and modify the start command like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

Moving forward, the best way to prevent this kind of headache is to keep your project dependencies updated. Most of the time, this error pops up because you’re using an older version of react-scripts that hasn't been maintained to support the latest Node releases. Running npm outdated every once in a while and bumping those packages will save you from these weird environment-specific friction points.

Hope this helps you get back to coding without any more cryptic errors. Let me know if that clears everything up for you!

遇到 error:0308010C？別慌，這只是 Node.js 版本跟 Webpack 在吵架啦！

來源：Stack Overflow ↗ · 2572 票

記得那天我趕著要把一個舊專案搬出來做 Demo，結果才剛打完 npm start，終端機就直接噴出一長串紅字，那個 digital envelope routines::unsupported 的錯誤訊息直接把我嚇出一身冷汗。我當時心想：「慘了，我什麼都沒改啊，難道是我的電腦壞了嗎？」那種看著螢幕發呆、懷疑人生，最後只能無助地把錯誤訊息複製貼上到 Google 的痛苦時刻，相信各位工程師一定都懂。

其實這個問題會出現，是因為你的 Node.js 版本升級到了 17 以上，但你的專案裡頭用的 Webpack 版本還太舊。簡單來說，Node.js 17 之後導入了更嚴格的 OpenSSL 3.0 加密演算法，而舊版的 Webpack 還是習慣用以前那套比較寬鬆的規則。這就像是你拿著舊鑰匙想開新鎖，Node.js 直接冷冷地告訴你：「不支援喔，請換一把。」這不是你的程式碼寫錯了，純粹就是新舊軟體之間的一次「代溝」。

我當初發現這個問題時，第一個反應是想降級 Node.js，但後來覺得太麻煩，直接改環境變數才是最快的方法。如果你是在 Mac 或 Linux 環境，直接在終端機輸入這行指令：


export NODE_OPTIONS=--openssl-legacy-provider

若是 Windows 的使用者，可以在 PowerShell 執行：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

執行完再試著跑一次 npm start，通常那個討厭的錯誤就會直接消失，世界又恢復和平了。如果你不想每次開終端機都要敲一次指令，建議直接把這段加到 package.json 的 scripts 區塊裡，這樣一勞永逸：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

為了避免下次又踩進同一個坑，我現在養成了一個習慣，就是盡量幫每個專案配置 .nvmrc 檔案。這樣無論我換到哪台電腦，只要用 nvm use，就能確保執行的 Node.js 版本跟專案設定是一致的，不用再在那邊猜測是不是因為版本更新導致的莫名錯誤。

好了，解決完這個小麻煩，現在可以繼續回去寫 Code 啦，希望大家都能順利避開這個惱人的紅字！
