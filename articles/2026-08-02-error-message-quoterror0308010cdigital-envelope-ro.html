How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the first time I saw this error pop up in my terminal. I had just spun up a fresh React project to prototype a simple dashboard, and instead of seeing the familiar "Compiled successfully" message, I was staring at a wall of red text screaming about digital envelope routines. I spent a good three hours convinced I’d somehow corrupted my entire Node installation or that my path variables were haunted, only to realize I was just running a newer version of Node than the project’s build tools were ready to handle.

The reason this happens is actually quite straightforward once you peel back the layers. When Node.js bumped up to version 17 and beyond, they switched to OpenSSL 3.0 as the default. The problem is that many older versions of Webpack and other build tools rely on legacy algorithms that OpenSSL 3.0 considers insecure or deprecated. Essentially, your project is trying to use a cryptographic hash method that your current Node environment is now blocking by default. It's a classic case of a breaking change in the underlying platform catching the ecosystem off guard.

When I finally tracked down the fix, I was relieved to find that you don't actually need to downgrade Node or rewrite your build pipeline. You just need to tell Node to allow those legacy algorithms for your build process. The most common way to do this is by setting an environment variable called NODE_OPTIONS to --openssl-legacy-provider. If you're on a Mac or Linux machine, you can patch it instantly by running this command in your terminal:


export NODE_OPTIONS=--openssl-legacy-provider

If you’re working on Windows, the syntax is slightly different. You’ll want to run this in your PowerShell terminal:


$env:NODE_OPTIONS = "--openssl-legacy-provider"

If you want to make this permanent so you don't have to keep typing it every time you open a new terminal window, the easiest path is to update the scripts section in your package.json file. Just prepend the environment variable to your start command like this:


"scripts": {
  "start": "NODE_OPTIONS=--openssl-legacy-provider react-scripts start",
  "build": "NODE_OPTIONS=--openssl-legacy-provider react-scripts build"
}

Moving forward, the best way to prevent this kind of headache is to keep a close eye on your project dependencies. It's usually a sign that your react-scripts or Webpack version is quite outdated. Whenever you start a new project, take a quick peek at the package.json to ensure you aren't using a version from three years ago. Updating your dependencies regularly is a pain, sure, but it’s a whole lot better than wrestling with cryptic OpenSSL errors on a Monday morning.

Hope this saves you the three hours of frustration I went through. Happy coding!

救命！跑個 React 專案怎麼跳出「digital envelope routines」這種天書錯誤？

來源：Stack Overflow ↗ · 2572 票

那天我剛升級完電腦的 Node.js 版本，想說趁著週末把手邊一個放了很久的 React 專案拿出來重構一下，結果 npm start 一按下去，終端機直接噴出一大串紅通通的 error:0308010C:digital envelope routines::unsupported。我當下真的是心涼了一半，明明昨天還好好的，怎麼今天連起個開發伺服器都成了奢望？看著那行完全看不懂的錯誤代碼，我一度懷疑是不是我的電腦中毒了，還在網路上瘋狂搜尋這串亂碼，那種「明明程式碼沒改，世界卻突然崩塌」的無力感，真的是工程師最不想面對的痛苦時刻。

其實這個問題是因為 Node.js 在 v17 版本之後，預設使用了 OpenSSL 3.0，這傢伙對於安全性檢查變得超級嚴格。而我們很多舊的 React 專案（或是那些還在使用舊版 Webpack 的專案）底層依賴的加密演算法，在 OpenSSL 3.0 眼裡被認為是不夠安全的，所以它直接把你的程式擋在門外，不讓你編譯。簡單來說，就是你的舊專案還在用「舊時代的加密方式」，而新的 Node.js 系統因為太講究資安，直接拒絕溝通。

要解決這個問題其實不難，最快的方法就是告訴 Node.js：「嘿，別管那麼多，先讓我把這專案跑起來再說」。我們需要手動把 NODE_OPTIONS 的環境變數設為 --openssl-legacy-provider，這樣就能強迫它沿用舊版的加密邏輯。

如果你是用 macOS 或 Linux，最簡單的做法是在終端機輸入：


export NODE_OPTIONS=--openssl-legacy-provider

如果你是用 Windows 的 PowerShell，則是輸入：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

不過，每次重開終端機都要打一次實在太累了，最推薦的方法是直接改 package.json。找到你的 scripts 區塊，把 start 指令改一下：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

改完之後再去跑 npm start，你就會發現那討厭的錯誤終於消失，熟悉的開發伺服器又回來了。

至於要怎麼預防下次再被這種環境變數搞到崩潰？建議大家養成用 nvm (Node Version Manager) 管理版本的習慣，或者在專案根目錄放一個 .nvmrc 檔案，明確指定這個專案該跑哪個版本的 Node.js。這樣下次換了新電腦或是升級環境時，只要切換回正確的版本，就不用再苦苦掙扎於這些底層的相容性地獄了。
