Solving the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I remember sitting down to start a fresh project late on a Tuesday night, coffee in hand, ready to crush some code. I ran npm start, and instead of my development server firing up, my terminal exploded with a cryptic error:0308010C:digital envelope routines::unsupported message. I spent three hours refactoring my environment variables and reinstalling node modules like a madman before realizing it had absolutely nothing to do with my code and everything to do with a quiet update I’d made to my system.

The reason this happens is actually quite simple, though it’s hidden behind a wall of scary-looking crypto errors. Essentially, this error pops up because you’re running a newer version of Node.js (v17 or higher) with an older version of Webpack or other build tools that rely on the OpenSSL library. Node.js v17+ switched to OpenSSL 3.0, which enforces stricter security standards for hashing algorithms. If your project’s dependencies are still trying to use older algorithms, Node just flat-out refuses to play along, resulting in that annoying "unsupported" wall.

The quickest way I fixed this was by telling Node.js to use the legacy OpenSSL provider, which essentially bridges that compatibility gap. If you’re on macOS or Linux, you can do this by setting an environment variable in your terminal before you run your start script:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is a bit different, so you’ll want to run this in your PowerShell terminal:


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

To make this change permanent so you don't have to type it every time you open a new terminal tab, I recommend updating your package.json file. Just modify your scripts section to inject that variable directly into the command:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

The best way to prevent this headache down the road is to keep your project dependencies updated. Most of the time, this error is a sign that your react-scripts package is outdated and needs a bump to a version that supports OpenSSL 3.0 natively. If you can, run npm update or check for newer versions of your build tools to avoid relying on legacy workarounds.

Hope this saves you from the same late-night rabbit hole I fell down. Happy coding!

啟動 React 專案卻噴出 Error 0308010C？別慌，這只是 Node.js 版本在搞事

來源：Stack Overflow ↗ · 2572 票

那天我剛換了一台新電腦，信心滿滿地打開 IntelliJ IDEA 想要跑一個簡單的 React 練習專案，結果按下 npm start 的瞬間，終端機直接紅字洗版噴出 error:0308010C:digital envelope routines::unsupported。我當下真的是盯著螢幕看了五分鐘，心想「我才剛裝好環境，連程式碼都還沒動，到底是在崩潰什麼啦」，那種剛設定好開發環境就被打臉的無力感，真的讓人想直接把鍵盤收起來去喝杯咖啡冷靜一下。

其實這問題的罪魁禍首就是 Node.js 的版本更新。簡單來說，Node.js 在 17 版以後升級了 OpenSSL 的加密演算法，改成強制的 SHA-256，但偏偏很多舊版的 Webpack 或者 React 的腳本還在用舊的演算法，兩邊兜不起來，編譯器就覺得「我不認識這個格式」，直接罷工給你看。這真的很煩人，因為通常我們只是想跑個專案而已，結果卻得花時間去研究底層加密協定的變更，這種被工具卡住的感覺簡直是開發者的惡夢。

解決這個問題其實不用大費周章去降級 Node.js（雖然那也是個方法，但太麻煩了）。最直接的做法，就是告訴 Node.js：「嘿，請幫我把舊版的 OpenSSL 支援開起來」。如果你是在 Mac 或 Linux 上，直接在終端機輸入這行指令：


export NODE_OPTIONS=--openssl-legacy-provider

如果是 Windows 的使用者，可以在終端機輸入：


set NODE_OPTIONS=--openssl-legacy-provider

設定完之後，再跑一次 npm start，你會發現原本那些惱人的紅字通通消失了，伺服器順利啟動，那一刻真的會覺得世界又恢復了和平。

為了避免以後每次開終端機都要重新打這串指令，我建議直接把這個設定寫進 package.json 的 scripts 區塊裡。你可以把 start 的指令改成這樣：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

這樣一來，不管你換到哪台電腦，只要執行 npm start，它就會自動幫你帶上這個參數，再也不用擔心這個錯誤突然跳出來嚇人。

說真的，開發環境就是這樣，永遠有修不完的相容性問題，習慣就好啦。希望這招能幫你快速脫離紅字地獄，繼續快樂寫 Code！
