Fixing the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I upgraded my local Node.js version and suddenly my entire development workflow ground to a halt. I had a demo due for a client in an hour, and my terminal was screaming at me with that cryptic error:0308010C:digital envelope routines::unsupported message. I spent a good 45 minutes banging my head against the keyboard, convinced I’d somehow nuked my entire project configuration, only to realize it was just a classic mismatch between my shiny new Node version and my legacy build tools.

The reason this happens is actually pretty straightforward once you peel back the layers. When Node.js bumped up to version 17 and beyond, they switched to OpenSSL 3.0 as the default. This update brought some stricter security standards, specifically regarding the hashing algorithms used in older versions of Webpack. Since many React projects—especially those created with older versions of Create React App—rely on Webpack 4 or early Webpack 5, they try to use an algorithm that OpenSSL 3.0 now considers insecure or legacy. It’s essentially a "security vs. compatibility" clash that leaves your build process dead in the water.

Fixing this is luckily a one-liner, though it feels a bit like a hack. Since we’re dealing with an environment variable issue, you just need to tell Node to use the legacy OpenSSL provider before running your start or build scripts. If you’re on a Mac or Linux machine, you can simply prepend the variable to your command in the terminal like this:


NODE_OPTIONS=--openssl-legacy-provider npm start

If you’re working on Windows using Command Prompt, you’d use set NODE_OPTIONS=--openssl-legacy-provider && npm start, or if you’re using PowerShell, it’s $env:NODE_OPTIONS = "--openssl-legacy-provider"; npm start. To make this permanent so you don't have to type it every time, just head over to your package.json file and update your scripts section to include the flag:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

If you want to prevent this headache down the road, my best advice is to embrace a version manager like nvm (Node Version Manager) or fnm. By keeping a .nvmrc file in the root of your project, you ensure that anyone working on the codebase—including your future self—is using the exact Node version the project was designed for. It saves you from those "it works on my machine" moments and keeps your build environment predictable regardless of what version of Node you're currently experimenting with for other projects.

Hope this gets you back to coding without any more cryptic errors. Let me know if you run into any other weird build quirks!

救命！跑個 React 專案怎麼就噴出「digital envelope routines::unsupported」這種鬼東西？

來源：Stack Overflow ↗ · 2572 票

那天我剛換了台新筆電，想說把原本那個寫了一半的 React 練習專案抓下來跑跑看，結果才剛敲下 npm start，終端機就直接噴出一大串紅通通的錯誤，寫著什麼 error:0308010C:digital envelope routines::unsupported。我當下真的差點要把鍵盤砸了，心想「不是吧，連環境都還沒架好就要搞我？」，明明程式碼一行都沒改，這種毫無預警的崩潰感真的會讓人瞬間懷疑人生。

其實後來查了才知道，這根本不是你的程式碼有錯，而是因為 Node.js 在 v17 版本之後升級了底層的加密演算法套件 OpenSSL 3.0。簡單來說，就是 Node.js 變得比較「嚴格」了，以前舊版 React 專案用的 Webpack 4 加密方式，在新的 OpenSSL 眼裡屬於「不安全」的過時標準，所以它直接拒絕執行，就像是你的新房東突然換了把超高級的安全鎖，結果你拿著舊鑰匙想開門，當然就直接被擋在外面了。

當時我為了找這個解法，在 Stack Overflow 上翻了好久，其實最快的方法就是告訴 Node.js：「嘿，別管那麼多，先讓我把舊專案跑起來再說」。你只要在執行指令前，設定一個環境變數 NODE_OPTIONS 就可以了。如果你是用 Mac 或 Linux，直接在終端機輸入這行：


export NODE_OPTIONS=--openssl-legacy-provider
npm start

如果你是用 Windows 的 PowerShell，格式會稍微不一樣：


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

當然，如果你不想每次啟動都要打這一串，最省事的方法就是直接去 package.json 裡面的 scripts 把啟動指令改掉，例如把 "start": "react-scripts start" 改成 "start": "react-scripts --openssl-legacy-provider start"，這樣以後敲 npm start 就再也不會被這個錯誤卡住啦。

為了避免以後再被這種環境問題搞到心累，我現在學乖了，養成習慣在每個專案目錄下放一個 .nvmrc 檔案，指定該專案使用的 Node.js 版本。畢竟與其每次升級 Node 後在那邊瞎忙除錯，不如一開始就鎖定版本來得踏實多了，畢竟我們工程師的時間可是很寶貴的，要拿去寫功能，而不是跟這些底層設定博鬥啊！

這招真的救了我很多次，希望你也順利解開這個惱人的鎖，繼續寫 Code 去吧！
