How to Check if a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7351 votes

Early in my career, I spent a solid three hours debugging a script that was crashing because I kept trying to open configuration files that weren't always there. I was obsessed with using try-except blocks for everything, and my code ended up looking like a giant, nested mess of error handling that made my eyes bleed. I remember staring at the screen, wondering why there wasn't a cleaner, more "Pythonic" way to just peek at the filesystem before diving into an operation.

The reason we run into this is that Python’s philosophy—often summarized as "Easier to Ask for Forgiveness than Permission" (EAFP)—encourages using exceptions. However, there are plenty of scenarios where you simply need to verify a path's existence for logging, conditional logic, or UI updates without the overhead of catching errors. When you use try-except for simple flow control, you're essentially treating a routine check as an exceptional event, which can make your logic harder to follow and slightly less performant if it happens inside a tight loop.

To fix this, I moved away from constant exception handling and started using the pathlib module, which has been the standard way to handle filesystem paths since Python 3.4. It’s readable, object-oriented, and much cleaner than the old os.path methods. If I need to check if a file exists, I simply create a Path object and call the .exists() method.


from pathlib import Path

file_path = Path("config.json")

if file_path.exists():
    print("The file is right where it belongs.")
else:
    print("File not found, skipping...")

If you’re working with a legacy codebase or just need a quick check without instantiating objects, you can still use the older os.path module. It’s a bit more "C-style," but it gets the job done without any fuss.


import os

if os.path.exists("config.json"):
    print("Found it using os.path!")

The best way to prevent this headache in the future is to keep your filesystem interactions isolated. I always try to wrap path-checking logic into small, dedicated utility functions rather than sprinkling exists() calls all over my business logic. This keeps your code modular and makes it way easier to swap out your path-checking strategy if you ever need to migrate to cloud storage or a remote filesystem.

Hope this saves you the three hours of frustration I dealt with back in the day. Happy coding!

不想用 try-except 檢查檔案存不存在？其實 Python 有更優雅的寫法

來源：Stack Overflow ↗ · 7351 票

記得剛開始寫自動化腳本時，我為了讀取設定檔，幾乎把 try-except 當成萬靈丹在用。當時我覺得只要把 FileNotFoundError 抓起來就天下無敵，直到有一次，我的腳本在處理幾萬個小檔案時，因為頻繁觸發異常導致效能慢到我想把電腦砸了，那一刻才意識到，原來「暴力寫法」真的是技術債的溫床。

很多人會問，為什麼不直接用 try-except？其實這跟作業系統底層的資源調度有關。當你用 try 去「試探」檔案是否存在時，程式必須先試著開啟它，觸發例外後再拋出錯誤，這中間的開銷其實比直接詢問作業系統「這個路徑上有東西嗎」大得多。如果你是在迴圈裡跑，那個延遲累積起來真的會讓你懷疑人生，這也是為什麼很多工程師開始追求「優雅的檢查方式」。

我後來學乖了，直接改用 Python 的 pathlib 模組，這東西簡直是現代 Python 開發者的救星。它把路徑當成物件處理，語法乾淨到不行。如果你只想確認檔案在不在，一行程式碼就能搞定：


from pathlib import Path

file_path = Path("config.json")

if file_path.is_file():
    print("檔案還在，可以放心讀取！")
else:
    print("檔案搞丟了，趕快去檢查路徑。")

如果是舊專案或是習慣用 os 模組的人，也可以用 os.path.exists()，這也是很標準的做法。但我個人還是強烈建議盡量切換到 pathlib，因為它處理路徑串接時，完全不用擔心 Windows 和 Linux 斜線方向不同的問題，少掉好多無謂的除錯時間。

說真的，預防這種問題最好的習慣，就是不要把「檢查」和「操作」拆得太開。雖然我們現在可以用 is_file() 先確認，但在高併發的環境下，檔案可能在你檢查完的那一毫秒就被另一個程序刪掉了。所以，如果你的程式邏輯允許，最好的預防策略其實是「先做再說，真的沒找到再處理例外」，或者在讀取前先確認目錄結構完整。只要養成這種「防禦性編程」的直覺，以後寫程式真的會輕鬆很多。

希望這些經驗能幫你省下以後改 Bug 的時間，大家寫程式都能少掉幾根頭髮！
