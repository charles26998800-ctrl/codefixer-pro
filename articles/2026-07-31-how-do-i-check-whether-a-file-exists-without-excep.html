The Right Way to Check if a File Exists in Python

Source: Stack Overflow ↗ · 7349 votes

Back when I was still junior, I remember writing a script to automate some log cleanup, and I was obsessed with using try-except blocks for everything. I ended up wrapping every single file operation in a massive try block, which made my code look like a plate of spaghetti and drove me absolutely insane when I tried to debug a simple missing config file. I spent three hours chasing a silent error that turned out to be a typo in a file path, and that was the day I decided I needed a cleaner, more readable way to handle file existence checks.

The reason people usually get caught up in this is that Python’s philosophy—"it's easier to ask for forgiveness than permission"—often pushes developers toward using try-except blocks. While that’s technically the most "Pythonic" way to handle file operations because it avoids race conditions, it’s not always the most readable. Sometimes you don't want to handle the exception; you just want to know if the file is sitting on the disk before you proceed. The confusion stems from the fact that Python has evolved, moving from the older os.path module to the modern, object-oriented pathlib library, leaving many developers wondering which tool is actually the right one for the job.

If you want to check for a file without the overhead of an exception, my go-to approach is using the pathlib library. It’s built into the standard library, and it makes the code feel much more natural. You just create a Path object and call the is_file() method.


from pathlib import Path

file_path = Path("config.json")

if file_path.is_file():
    print("The file exists and is ready to read.")
else:
    print("File not found, skipping...")

If you’re stuck on an older codebase that relies on the os module, you can still achieve this cleanly using os.path.exists(). Just keep in mind that this returns True for both files and directories, so if you specifically need a file, os.path.isfile() is the safer bet.


import os

if os.path.isfile("data.csv"):
    # Do your work here
    pass

To prevent this from becoming a headache in the future, my best advice is to always use pathlib for any new projects you start. It handles path separators across different operating systems automatically, which saves you from those annoying "it works on my machine" bugs when your code hits a Linux server after being developed on Windows. It’s cleaner, it’s more modern, and it’ll save you from writing those bloated try-except blocks that clutter up your logic.

Hope this helps you clean up your code and makes your next deployment a little smoother! Let me know if you run into any other weird pathing issues.

不想寫 try-except？Python 檢查檔案存在與否的優雅解法

來源：Stack Overflow ↗ · 7349 票

記得幾年前剛開始寫 Python 爬蟲時，為了處理一堆下載下來的圖片，我寫了個簡單的迴圈去檢查檔案是否已經存在。那時候我腦子裡只有「先檢查、後處理」的直覺，結果寫了一大堆冗長的 try-except 包在迴圈裡，整個程式碼看起來簡直像是在演一齣災難片，髒到我連自己都看不下去，當時真的差點因為這些重複的例外處理崩潰，心想難道就沒有更乾淨的寫法嗎？

其實很多人會被這個問題卡住，是因為 Python 習慣強調「請求原諒比請求許可更容易」（EAFP），也就是建議直接嘗試操作，如果失敗了再抓 Exception。但說實話，有時候邏輯簡單到只是想確認一下路徑，還要寫四五行 try-except 真的會讓人火大，特別是在做批次處理時，那種重複感簡直是精神折磨。更痛的是，如果你在檢查檔案的當下，剛好有另一個執行緒把檔案刪了，這種「競態條件」（Race Condition）讓你就算寫了檢查也沒用，程式還是會炸掉。

後來我學乖了，直接擁抱 pathlib 這個神級模組。這玩意兒從 Python 3.4 開始就內建了，完全不需要安裝額外的套件。你只需要把檔案路徑轉成物件，然後呼叫 .exists() 就行了，程式碼瞬間變得超級簡潔。例如這樣寫：


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.exists():
    print("檔案就在這，安心服用！")
else:
    print("檔案找不到，別再找了。")

如果你的路徑比較特殊，像是要確認它是檔案還是目錄，pathlib 還提供了 .is_file() 和 .is_dir()，用起來真的是絲般滑順。以前用 os.path.exists() 雖然也行，但那個風格比較偏向舊式的 C 語言思維，用 pathlib 這種物件導向的風格，讀起來真的舒服多了。

如果要說怎麼預防這種問題再次發生，我建議大家養成一個好習慣：別太依賴「檢查」這個動作，特別是在多執行緒或高併發環境下。如果你的邏輯允許，最好的做法還是直接對檔案進行存取，並且在 try-except 區塊中優雅地處理 FileNotFoundError。因為不管你檢查得再頻繁，系統狀態隨時都在變，直接處理例外狀況才是最符合 Python 設計哲學的做法，也能避免那種「剛檢查完檔案還在，下一秒卻消失」的詭異 Bug。

反正寫程式這條路就是這樣，永遠有更簡潔的寫法等著我們去發現，試試看把 pathlib 加入你的工具箱吧，保證你會回不去。
