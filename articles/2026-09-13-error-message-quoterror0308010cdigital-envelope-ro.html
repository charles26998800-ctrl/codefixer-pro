Troubleshooting the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I pulled a fresh React project from a legacy repo, ran npm start, and was greeted by a wall of red text that looked like complete gibberish. I spent a good three hours convinced that my entire dev environment was corrupted, only to realize that my Node.js version had silently updated overnight. It’s the kind of cryptic error that makes you want to throw your monitor out the window, but once you pull back the curtain, it’s actually a pretty straightforward fix.

The reason you’re seeing this error:0308010C:digital envelope routines::unsupported message is that OpenSSL 3.0, which comes bundled with Node.js version 17 and higher, introduced some stricter security standards for hashing algorithms. A lot of older Webpack versions and legacy React scripts rely on the MD4 algorithm, which OpenSSL 3.0 decided was no longer secure enough to be used by default. Basically, your build tool is trying to use a "deprecated" method, and Node is shutting it down to protect you, even if that protection is just ruining your afternoon.

I fixed this by telling Node to revert to the legacy provider, which essentially lets us use those older algorithms without breaking the entire build process. If you’re on a Mac or Linux machine, you can patch this immediately by setting an environment variable in your terminal before you run your start command:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, you’ll need to set it a bit differently in your command prompt:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

If you don't want to type that every single time, I highly recommend adding it directly to your package.json file. Just update your start script so it looks like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To prevent this from haunting you in future projects, the best habit is to use a version manager like nvm (Node Version Manager). By keeping a .nvmrc file in the root of your projects, you can lock your team to a specific Node version—like Node 16—and avoid these breaking changes entirely until you’re actually ready to upgrade your dependencies.

Hope this saves you a bit of a headache today. Good luck with the build!

遇到 Node.js 的「digital envelope routines::unsupported」錯誤？別慌，這其實是版本代溝惹的禍

來源：Stack Overflow ↗ · 2572 票

那天我心血來潮，想說用 IntelliJ IDEA 開個新的 React 專案來測試個小功能，結果專案才剛建好，連 npm start 都還沒跑下去，終端機就直接噴出一長串紅字，那個 error:0308010C:digital envelope routines::unsupported 看起來簡直像是在跟我宣戰。我當時盯著螢幕大概愣了五分鐘，心裡想說：「我什麼都還沒寫欸，連一行程式碼都還沒動，這是在開我玩笑嗎？」那種「明明照著官方步驟做，結果一開局就翻車」的無力感，真的是每個工程師的噩夢，差點就想直接關掉電腦去喝杯咖啡冷靜一下。

其實這個錯誤會出現，是因為你用的 Node.js 版本太新了。從 Node.js 17 開始，他們升級了 OpenSSL 到 3.0 版本，這玩意兒安全性更高，但代價就是它不再支援一些舊版的加密演算法。偏偏很多我們常用的舊專案，或是像 Webpack 4 這種老工具，它們的底層還在用那些被新版 OpenSSL 棄用的演算法。簡單來說，就是你的新環境太潮了，結果跟舊專案的「古董級」寫法吵架了，它們互看不順眼，最後就是你這個開發者倒楣。

我當時為了快速修好這個坑，最簡單直接的作法就是告訴 Node.js：「嘿，別管那麼多，把舊的加密演算法權限開給我。」你只需要在執行專案的指令前，加上一個環境變數設定。如果你是用 Mac 或 Linux，在終端機輸入：


export NODE_OPTIONS=--openssl-legacy-provider
npm start

如果你是用 Windows 的 PowerShell，指令長得稍微不一樣：


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

這樣設定之後，你會發現原本那串紅字瞬間消失，專案又可以正常跑起來了，那一刻真的會覺得世界又恢復了和平。

為了不要每次開專案都要手動敲這行指令，我建議你直接把這個設定寫進 package.json 的 scripts 區塊裡。比如把 "start": "react-scripts start" 改成 "start": "react-scripts --openssl-legacy-provider start"，這樣以後不管誰來跑這個專案，都不會再被這個問題卡住。當然，長遠來看，升級你的 Webpack 版本或是換成 Vite 這類現代化的開發工具，才是治本之道，畢竟老技術遲早會被環境淘汰。

希望這篇筆記能幫你省下寶貴的除錯時間，別讓這種環境設定的小事壞了你寫程式的興致！
