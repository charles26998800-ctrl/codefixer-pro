Fixing the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2573 votes

I remember sitting down to spin up a quick prototype last year, feeling pretty productive until I ran npm start and was met with a wall of terrifying red text. That cryptic error:0308010C:digital envelope routines::unsupported message stopped me dead in my tracks, and I spent a solid three hours convinced I’d somehow corrupted my entire Node installation. It’s one of those bugs that makes you feel like you’ve forgotten how to code, but it turns out it’s just a mismatch between modern security standards and older project dependencies.

The root of this headache lies in the jump from Node.js v16 to v17. When Node updated to OpenSSL 3.0, they tightened up their security protocols, which effectively broke a ton of older Webpack configurations and libraries that rely on legacy hash algorithms. If you're running a newer version of Node but trying to compile an older React project—or even a default template generated by an older version of create-react-app—the environment simply refuses to run those legacy "digital envelope routines." It’s basically Node saying, "I’m too secure for that old stuff you’re trying to use."

To fix this, I found that the most reliable approach is to tell your terminal to use the legacy OpenSSL provider temporarily. If you’re on a Mac or Linux machine, you can patch this in your terminal by running this command before you start your project:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re stuck on Windows using Command Prompt, you’d use set NODE_OPTIONS=--openssl-legacy-provider instead. However, because I don’t want to type that every single time I open a new terminal tab, I usually add it directly to my package.json file. I just update the start script so it looks like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

This way, the environment variable is injected automatically whenever I run my scripts, and I don't have to worry about the error popping up again mid-sprint.

The best way to prevent this from ruining your morning is to keep your project dependencies updated. Most of the time, this error hits because you're using an outdated version of react-scripts. If you check your package.json and see an old version, try running npm install react-scripts@latest to pull in a version that plays nicely with the newer OpenSSL standards. It’s a bit of a hassle to manage migrations, but it’s definitely better than fighting the legacy provider flag forever.

Hope this saves you some of the time I lost digging through Stack Overflow forums. Happy coding, and may your terminal stay green!

React 專案跑不起來？別慌，這只是 Node.js 的「懷舊風」惹的禍

來源：Stack Overflow ↗ · 2573 票

那天我剛接手一個很久沒動的 React 舊專案，想說只是跑個 npm start 快速確認一下功能，結果終端機直接噴出一大串紅通通的錯誤訊息，最顯眼的關鍵字就是那個 error:0308010C:digital envelope routines::unsupported。我看著螢幕當下真的差點把咖啡噴出來，心想：「我才剛開始工作，專案就直接宣告陣亡？」那種明明什麼都沒改，卻連開發環境都起不來的無力感，真的是工程師最想原地離職的時刻之一。

其實這問題之所以會發生，是因為你電腦上的 Node.js 版本太新了，通常是 v17 以上。簡單來說，Node.js 後來升級了加密演算法的標準，改用了 OpenSSL 3.0，但我們那些舊專案用的 Webpack 等打包工具，還死守著舊版的加密規範不放，兩邊就像在雞同鴨講，Node.js 覺得這些舊工具用的演算法「不安全」，所以直接賞你一個拒絕存取。

當初我為了搞定這個，試過把整個 node_modules 刪掉重裝，甚至想過要把 Node.js 降版，但後來發現最快、最不傷身的方法，就是告訴 Node.js：「嘿，拜託稍微寬容一點，讓我用一下舊演算法吧。」你只需要在啟動指令前面加上一個環境變數設定。

如果你是在 macOS 或 Linux 環境，可以直接把 package.json 裡的 scripts 改成這樣：


"scripts": {
  "start": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

如果是 Windows 的 PowerShell 使用者，語法會稍微不太一樣：


"scripts": {
  "start": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

改完之後，記得重新跑一次指令，你會發現世界瞬間清靜了，專案乖乖跑了起來。

為了避免以後又被這種環境問題搞到心累，我現在養成了使用 nvm (Node Version Manager) 的好習慣。只要是那種超過一兩年的舊專案，我都會先用 nvm use 切換到 Node.js 14 或 16 這種比較穩定的「老版本」，這樣就不用每次都去改設定檔，甚至能減少很多莫名其妙的套件相容性災難。

搞定這些環境地雷後，終於可以繼續安心寫扣了，大家加油！
