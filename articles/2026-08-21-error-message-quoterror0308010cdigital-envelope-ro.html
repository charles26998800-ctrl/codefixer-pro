How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the first time I hit this error. I had just upgraded my Node.js version to v17, sat down with a fresh coffee, and typed npm start expecting my local dev server to boot up. Instead, my terminal exploded with a wall of text ending in that cryptic error:0308010C:digital envelope routines::unsupported message. I spent three hours obsessively deleting my node_modules folder and reinstalling everything, convinced that I’d somehow corrupted my entire machine, only to realize I was just chasing ghosts in the machine.

The reason this happens is actually quite straightforward once you dig into the OpenSSL changes in Node.js 17 and later. Essentially, the maintainers decided to tighten up security by upgrading to OpenSSL 3.0, which enforces stricter standards for cryptographic algorithms. Many older build tools and dependencies—especially Webpack 4, which is baked into older versions of Create React App—rely on legacy algorithms that are no longer allowed by default. Your environment is essentially telling you that your legacy code is using an outdated security standard, and it’s refusing to proceed for your own protection.

To fix this, you need to tell Node.js to use the legacy OpenSSL provider, which effectively downgrades the security check for your build process. If you’re on a Mac or Linux machine, you can run this command in your terminal before starting your project:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, you’ll need to set the environment variable slightly differently. You can do this in your terminal before running your start script:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

If you don't want to type that every single time you spin up your project, the cleanest way is to modify your package.json file directly. Just find the scripts section and inject the variable right into your start command like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

Moving forward, the best way to prevent this kind of headache is to keep your project dependencies updated. This error is a classic sign that your react-scripts version is lagging behind your Node.js version. I always make it a habit to run npm outdated every few weeks and migrate to newer versions of Webpack or Vite when possible. It’s way better to deal with a small breaking change during an update than to deal with a total build failure right when you're trying to push a hotfix.

Hope this saves you the three hours of frustration it cost me back then. Happy coding!

救命！React 專案噴出 error:0308010C 是怎麼回事？

來源：Stack Overflow ↗ · 2572 票

那天我剛換了一台全新的開發機，正準備把手邊的一個 React 老專案跑起來趕個進度，結果 npm start 才剛敲下去，終端機就直接賞我一串紅通通的 error:0308010C:digital envelope routines::unsupported。我當下真的是原地崩潰，明明昨天在舊電腦上跑得好好的，怎麼換個環境就直接變成磚頭，那種「明明程式碼沒動，卻連開發伺服器都起不來」的無力感，真的是工程師最不想面對的惡夢，害我那天下午的咖啡錢都浪費了。

其實這背後的罪魁禍首是 Node.js 的版本升級。簡單來說，Node.js 在 v17 版本之後，預設開啟了 OpenSSL 3.0 的加密演算法，但我們舊專案裡用的 Webpack（特別是 v4 版本）還在用舊版的加密演算法，這兩邊根本是雞同鴨講，Node.js 覺得你的加密方式太老舊又不安全，直接拒絕執行，這才導致了這個錯誤。說穿了就是「新版本的嚴格安全性」撞上了「舊專案的歷史遺產」。

要解決這個問題，其實不用去改那些複雜的 Webpack 設定，最快的方法就是告訴 Node.js：「嘿，請你暫時放寬一點標準」。如果你是用 macOS 或 Linux，只要在啟動指令前加上 NODE_OPTIONS=--openssl-legacy-provider 就可以搞定。我當時是直接把 package.json 裡的 scripts 改掉，讓你以後不用每次都手動輸入，直接這樣寫：


"scripts": {
  "start": "NODE_OPTIONS=--openssl-legacy-provider react-scripts start",
  "build": "NODE_OPTIONS=--openssl-legacy-provider react-scripts build"
}

如果你是在 Windows 的 PowerShell 環境，寫法會稍微不一樣，要改成這樣：


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

至於要怎麼預防下次再被這種環境問題卡住？我覺得最根本的還是要養成使用 nvm (Node Version Manager) 的習慣。我現在都會在專案根目錄放一個 .nvmrc 檔案，裡面直接寫好這個專案該用的 Node.js 版本，這樣以後不管換幾台電腦，只要進目錄執行 nvm use，就能確保環境跟你當初開發時一模一樣，再也不用擔心升級 Node.js 後還要花時間除這種冤枉 bug 了。

希望這篇筆記能幫你省下找解法的時間，趕快回去寫 Code 吧，別讓這種環境問題破壞了你的開發節奏！
