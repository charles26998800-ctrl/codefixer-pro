How to Check If a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7352 votes

Early in my career, I remember writing a file-processing script that was littered with massive try-except blocks. I thought I was being clever, but I ended up spending three hours debugging a silent failure where a typo in a config file made my script skip entire directories without a peep. It was one of those moments where I stared at my monitor, realized my code was a total mess, and finally decided to learn the "proper" way to handle path checks before attempting to touch a file.

The reason most beginners—and even some intermediate developers—reach for try-except blocks is because they’re taught that it’s easier to ask for forgiveness than permission. While that’s generally true for many Python operations, it can be overkill when you just need to verify a file's existence before triggering a heavy process. The real issue is that try-except is meant for handling unexpected runtime errors, not for controlling the standard logic flow of your application. When you use it for simple existence checks, you often accidentally catch errors you didn't intend to, like permission issues or disk read errors, which leads to those frustrating "silent" bugs I mentioned earlier.

To fix this, I stopped relying on exception handling for basic flow control and started using the pathlib module. It’s the modern, object-oriented way to handle filesystem paths in Python, and it makes your code significantly more readable. Instead of writing a bulky try statement, you can simply use the .exists() method.


from pathlib import Path

file_path = Path("my_data.csv")

if file_path.exists():
    print("The file is there, let's process it!")
else:
    print("File not found, skipping.")

If you’re working on a legacy codebase that still relies on os.path, you’ll see people using os.path.isfile(). While it works just fine, I strongly encourage you to migrate to pathlib whenever you get the chance. It’s cleaner, handles cross-platform path separators automatically, and just feels like the right way to write Python in this decade.

The best way to prevent these kinds of headaches is to adopt a "look before you leap" approach only when the check is cheap and reliable. However, keep in mind that even with an exists() check, a file could technically be deleted by another process a millisecond after you check it. That’s why I always keep the actual file opening inside a small, focused try-except block anyway, just to catch those rare "race condition" errors that happen in real-world production environments.

Hope this saves you the three hours of hair-pulling I had to go through! Happy coding and keep those paths clean.

別再為了檢查檔案存不存在寫 try-except 了：Python 檔案檢測指南

來源：Stack Overflow ↗ · 7352 票

還記得剛轉職進這家公司的時候，為了趕一個自動化腳本的死線，我寫了一堆 try-except 來處理檔案讀取，結果整個程式碼看起來像是在寫什麼錯誤處理大賽，邏輯亂到連我自己隔天打開都想哭。最崩潰的是，我當時根本搞不懂為什麼檢查一個檔案存不存在，非得要搞得像是在進行什麼嚴肅的例外處理，寫到最後整個腳本的重點完全失焦，真的差點因為這種小細節對著螢幕崩潰。

其實這背後的原因很單純，很多新手（包括當年的我）會覺得「檔案不存在」是一種異常，所以直覺就用了 try-except 去接 FileNotFoundError。但說真的，檔案不存在在很多時候其實是「預期中」的邏輯路徑，根本稱不上是程式出錯。如果你只是想確認路徑對不對，硬要用 try 區塊把程式包起來，不僅會讓程式碼的可讀性降低，還會因為頻繁的例外捕捉影響到一點點效能，雖然不多，但那種「為了檢查而檢查」的笨重感真的很讓人受不了。

後來學聰明了，我發現 Python 的 pathlib 模組簡直是救星，它把檔案路徑當成物件來處理，寫起來乾淨又直覺。如果你只是想確認檔案在不在，直接用 .exists() 就好。像這樣：


from pathlib import Path

file_path = Path('my_data.txt')

if file_path.exists():
    print("檔案還在，趕快開工！")
else:
    print("檔案沒找到，是不是又被誰刪掉了？")

如果是要判斷它是不是真的是個「檔案」（而不是一個資料夾），用 .is_file() 會更保險。自從改用這一套之後，我的程式碼清爽多了，不再需要那堆冗長的錯誤處理，邏輯也順暢不少。

至於要怎麼預防這種問題再次發生，我建議大家養成一個習慣：別再把「檔案檢查」跟「檔案操作」綁在一起思考了。在寫程式的時候，先切開「檢查狀態」和「執行操作」這兩件事。如果你的程式邏輯是「如果檔案存在，就去讀取」，那就用 pathlib 先確認；如果是「不管三七二十一，直接讀取再處理錯誤」，那才是 try-except 登場的時候。分清楚這兩者的邊界，你就不會再寫出那種混亂的錯誤處理程式碼了。

搞定這個小細節後，剩下的時間拿去喝杯咖啡放空，真的會快樂很多。下次寫腳本遇到類似的狀況，試試看 pathlib，保證你回不去囉！
