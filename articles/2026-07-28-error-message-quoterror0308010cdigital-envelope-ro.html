How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2573 votes

I still remember the day I upgraded my local Node environment, feeling all productive, only to have my entire project scream "error:0308010C:digital envelope routines::unsupported" the second I ran npm start. I spent a solid two hours convinced I’d somehow corrupted my entire node_modules folder or that my OS had developed a vendetta against me. It’s one of those classic "works on my machine" moments that turns out to be a total head-scratcher until you realize it’s just a conflict between modern security standards and older build tools.

The root of this chaos is actually Node.js version 17 and higher. The OpenSSL version bundled with these newer releases enforces stricter security, specifically regarding the legacy hashing algorithms that many older Webpack versions rely on. Essentially, your project is trying to use an algorithm that Node now considers "insecure" or outdated, so it shuts down the process before it can even start. It’s a classic case of your environment moving faster than your dependencies.

The quickest way I’ve found to squash this—and the one I use every time I spin up an older project—is to tell Node to allow those legacy algorithms. You can do this by setting the NODE_OPTIONS environment variable. If you’re on a Mac or Linux machine, just run this in your terminal before you start your project:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is a little different. You’ll want to set it in your command prompt like this:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

If you don't want to type that every single time, you can just bake it into your package.json file. Find the "scripts" section and update your start command so it looks something like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To keep this from biting you in the future, the best habit is to keep your project dependencies updated. Most of the time, this error pops up because you’re using an older version of react-scripts that hasn't been maintained to support newer Node versions. Running npm outdated regularly and bumping those packages to their latest major versions usually resolves the underlying compatibility issue permanently, so you won't have to carry that legacy flag around like a security blanket.

Hope this saves you the headache it caused me! Happy coding, and don't let the build errors get you down.

救命！跑個 React 專案怎麼就炸了？Node.js 的「digital envelope routines」錯誤排除指南

來源：Stack Overflow ↗ · 2573 票

那天我剛換了一台新電腦，想說重灌好環境之後，興沖沖地從 GitHub 把舊的 React 專案拉下來準備開工。結果 npm install 跑完，打下 npm start 的那一刻，終端機直接噴出一大串紅字，那個 error:0308010C:digital envelope routines::unsupported 簡直像是在對我冷笑。我當時真的差點原地崩潰，心想連專案都跑不起來，是要怎麼趕在下班前把功能寫完啊？

其實這個問題是因為 Node.js 升級到 v17 以上的版本後，為了安全性，預設啟用了 OpenSSL 3.0，而很多舊版的 Webpack 裡面的雜湊演算法（Hash Algorithm）跟它不合，就這樣鬧脾氣罷工了。說真的，這種因為「升級導致不相容」的痛苦時刻，相信在座的各位工程師應該都體驗過，明明昨天還好好的代碼，今天就因為環境變了直接報錯，那種無力感真的會讓人想把鍵盤砸了。

要解決這個問題，其實不用把整個 Node.js 版本降回去，最快的方法就是告訴 Node.js：「嘿，別管那麼多安全性，先把舊的演算法放行吧！」你只需要在啟動專案的指令前面加上 NODE_OPTIONS=--openssl-legacy-provider 這個參數。如果你是用 Windows 的 PowerShell，設定方式會稍微長一點，但在 Linux 或 Mac 下，你只要修改 package.json 裡面的 scripts 區塊，把原本的啟動指令改成這樣：


"scripts": {
  "start": "NODE_OPTIONS=--openssl-legacy-provider react-scripts start",
  "build": "NODE_OPTIONS=--openssl-legacy-provider react-scripts build"
}

改完之後再重新執行 npm start，你會發現原本那串惱人的紅字終於消失了，網站也順利跑起來了。

至於要怎麼預防下次再踩到這種雷？老實說，專案環境版本管理真的很重要。我現在強烈建議大家一定要使用 nvm (Node Version Manager) 來管理 Node.js 版本，並且在專案根目錄放一個 .nvmrc 檔案，寫入你這個專案穩定運行的版本號。這樣以後不管換哪台電腦，只要進到資料夾打個 nvm use，環境就能自動對齊，再也不用擔心升級版害你浪費半天時間修這些奇怪的設定了。

好了，現在問題解決了，趕快回去把那些還沒寫完的 code 補上吧，祝大家開發過程順利，Bug 少少！
