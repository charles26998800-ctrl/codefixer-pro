How to Fix "RuntimeError: Input type (torch.FloatTensor) and weight type (torch.cuda.FloatTensor) should be the same"

Source: Stack Overflow ↗ · 202 votes

I still remember the first time I set up a GPU training loop for a computer vision project. I was so proud of my model architecture that I didn't even notice the mismatch until I hit run, only to be slapped in the face by a massive stack trace. I spent nearly three hours debugging my data loaders and model weights, convinced I’d corrupted my environment, only to realize I’d simply forgotten to move my tensors to the same device as my model.

If you’re seeing this error, it’s because PyTorch is strictly enforcing hardware consistency. You’ve successfully moved your model to the GPU, but your input data is still sitting comfortably in your CPU's RAM. PyTorch is a stickler for detail; it refuses to perform matrix multiplication when the model weights are on the GPU and the input tensors are on the CPU. It’s like trying to bake a cake with ingredients located in two different kitchens—the model is ready to work, but it can't reach the data you're providing.

To fix this, you need to manually move your input tensors to the same device your model is currently using. Since you’ve already defined your device variable, you just need to update your training loop to push the inputs and labels to that device before they hit the model. Here’s what that looks like in practice:


device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model.to(device)

for data in dataloader:
    # This is the line you're missing
    inputs, labels = data
    inputs = inputs.to(device)
    labels = labels.to(device)
    
    outputs = model(inputs)
    # ... rest of your training logic

Once you add those .to(device) calls, the error will vanish and your model will start chewing through those batches. If you want to prevent this from ever ruining your afternoon again, I suggest writing a simple helper function or a custom wrapper that handles device assignment automatically whenever you pull data from your loader. Keeping your device logic centralized instead of hardcoding it inside every loop saves you from these headaches when you eventually switch between local development and cloud training.

Hope this clears things up so you can get back to training your models. Happy coding!

救命！PyTorch 報錯：Input 和 Weight 型別不一致的崩潰時刻

來源：Stack Overflow ↗ · 202 票

記得剛開始接觸 PyTorch 時，有次為了趕論文進度，熬夜寫了一個影像分類模型。好不容易把模型架構弄好、資料集也整理完了，按下執行鍵的那一刻，我甚至已經準備好去泡杯咖啡等結果，結果螢幕上瞬間噴出一行紅字：RuntimeError: Input type (torch.FloatTensor) and weight type (torch.cuda.FloatTensor) should be the same。那一瞬間我真的差點崩潰，明明都已經把模型 to(device) 了，為什麼還是在跟我鬧脾氣？

其實這個錯誤的原因很單純，就是我們把 GPU 跟 CPU 的東西硬湊在一起了。簡單說，就是我的模型已經被我乖乖丟進 GPU 跑了（變成 cuda.FloatTensor），但我的資料（inputs）還懶洋洋地躺在 CPU 記憶體裡（FloatTensor）。PyTorch 的規則很嚴格，它不允許讓 GPU 裡面的模型去處理 CPU 給的資料，就像是叫一個頂級廚師去處理根本沒送到廚房的食材，當然會直接罷工給你看。

解決方法其實超簡單，只要在你跑迴圈讀取資料的時候，順手把資料也丟進同樣的裝置就行了。我後來都是這樣改的：


device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model.to(device)

for data in dataloader:
    # 關鍵就在這，把 inputs 跟 labels 都同步搬到同一個 device
    inputs, labels = data
    inputs = inputs.to(device)
    labels = labels.to(device)
    
    outputs = model(inputs)

這樣改完之後，程式就順利跑起來了，當時看著終端機終於開始顯示 training loss 下降，那種感動真的難以言喻。

為了避免以後再犯這種低級錯誤，我現在養成了一個好習慣，就是在寫 for 迴圈的時候，直接寫一個小函式或是用 to(device) 把所有從 DataLoader 拿出來的 Tensor 都過濾一遍。甚至有些時候，我會乾脆把資料搬移的邏輯寫在 Dataset 的 __getitem__ 裡，或者在訓練函式開頭直接寫一個檢查點，確保所有輸入的 tensor 裝置屬性跟模型是一致的。

除錯這條路就是這樣，永遠都有這種小細節在等著偷襲我們，祝大家下次寫 code 時都能一路綠燈順利跑完！
