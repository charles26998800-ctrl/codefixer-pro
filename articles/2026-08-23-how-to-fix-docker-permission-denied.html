How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1417 votes

I still remember the first time I set up my dev environment on a fresh Ubuntu install, feeling like a total pro until I tried to run my first container. I spent a solid hour convinced I’d botched the installation or corrupted the daemon, only to realize I was just fighting a classic Linux permissions issue that everyone hits at least once. It’s one of those moments that makes you feel like you’re losing your mind, but honestly, it’s just Docker protecting the system from unprivileged access.

The reason you’re seeing that "Permission denied" error is that the Docker daemon binds to a Unix socket rather than a TCP port by default. Because that socket is owned by the root user, you’re effectively locked out unless you’re running your commands with sudo. Docker is designed with security in mind, so it doesn't just hand over access to that socket to every user on the machine. It’s a bit annoying when you're just trying to get a quick container running, but it’s a necessary security boundary to ensure that only authorized users can spin up containers that might have root-level access to your host.

To fix this, the cleanest way is to add your user to the docker group. This grants your user account the necessary permissions to interact with the Docker daemon without needing to type sudo every single time. First, you’ll need to create the group if it doesn’t already exist, though the Docker installation usually handles this for you. Then, add your current user to that group using the following commands:


# Create the docker group if it doesn't exist
sudo groupadd docker

# Add your current user to the group
sudo usermod -aG docker $USER

Once you’ve run those, you aren't quite done yet. You’ll need to refresh your group membership for the changes to take effect. You can either log out and log back in, or just run newgrp docker in your current terminal session to apply the changes immediately. After that, you should be able to run docker run hello-world without any issues. If you’re still getting a permission error, a quick reboot usually forces the system to acknowledge the new group permissions across all sessions.

The best way to prevent this headache in the future is to make sure you handle your user groups right after you install Docker. Whenever I spin up a new VM or dev machine, adding my user to the Docker group is part of my standard "get-up-and-running" script. It saves me from the constant cycle of typing sudo and keeps my development workflow feeling smooth.

Hope this saves you the hour of frustration I went through when I first ran into this. Happy coding!

為什麼每次跑 Docker 都要加 sudo？教你優雅解決 Permission denied 的苦惱

來源：Stack Overflow ↗ · 1417 票

還記得剛踏入 Docker 世界的那陣子，我滿懷期待地想把專案容器化，結果指令敲下去出現一堆紅字報錯，當下真的差點崩潰。那時候我反覆檢查了五六遍安裝步驟，甚至以為是作業系統壞了，心想：「明明官方文件就是這樣寫的，為什麼我就是跑不動？」這種明明指令沒錯，卻因為權限問題被系統拒於門外，看著終端機顯示 Got permission denied 的那種無力感，真的是工程師職涯中最想摔鍵盤的時刻之一。

其實這問題的成因很單純，就是因為 Docker 的守護行程（daemon）預設是綁定在 Unix Socket 上的，而這個檔案的權限屬於 root。平常我們不加 sudo 的話，系統就會認為你只是一般的普通使用者，沒有權限去呼叫那個 socket，所以才一直跟你討權限。每次都要加 sudo 不只麻煩，有時候還會因為環境變數的傳遞問題搞出更多 Bug，實在很不優雅。

要解決這個問題，其實只要把你的使用者帳號加入到 docker 這個群組就搞定了。我當時的做法是先建立群組（雖然通常安裝時就有了），然後把自己的帳號加進去。你可以打開終端機，執行下面這行指令：


sudo usermod -aG docker $USER

執行完之後，重點來了！這一步最常被忽略，一定要記得登出再重新登入，或者直接重開機，讓權限設定生效。如果不想登出，也可以用 newgrp docker 這個指令來臨時刷新當前 Shell 的群組權限。設定好之後，你可以試著跑 docker run hello-world，如果沒看到那串討厭的報錯，恭喜你，你已經成功擺脫 sudo 的束縛了。

至於怎麼預防這種狀況，建議大家在以後配置新伺服器或開發環境時，寫一個簡單的 setup.sh 腳本，把建立使用者、安裝 Docker 以及加入群組這些流程自動化。這樣不僅不用每次都手動查指令，也能確保團隊裡每個人的開發環境設定都是統一的，省下以後除錯的時間。

以後敲 Docker 指令終於可以少打五個字母了，祝各位開發順利，少點 Bug 多點咖啡！
