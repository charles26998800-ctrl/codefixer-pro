How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the first time this error hit me; I had just sat down with a fresh coffee, ready to scaffold a new project in IntelliJ, only to be greeted by a wall of red text in the terminal. I spent a good two hours convinced I’d somehow broken my entire Node installation or that my path variables had spontaneously combusted, only to realize I was fighting a battle between my legacy project dependencies and my shiny new version of Node.js. It’s one of those errors that feels like a rite of passage for every React developer, especially when you just want to get your dev server running.

The reason this happens is actually quite straightforward, though it’s hidden behind a cryptic OpenSSL error message. When Node.js bumped up to version 17 and beyond, they switched to OpenSSL 3.0, which has much stricter security standards. A lot of the older libraries that React projects rely on, specifically Webpack, were still using legacy hashing algorithms that this new version of OpenSSL simply refuses to run. Your code isn't necessarily broken; it's just trying to use an old security protocol that your current environment considers "unsupported."

To fix this, you don't need to downgrade your entire Node environment, which is a massive headache. The easiest way to bypass this is by telling Node to use the legacy OpenSSL provider via an environment variable. If you’re on a Mac or Linux machine, you can quickly patch your package.json file. Just look for your scripts section and inject the configuration right into your start command like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

If you’re working on a Windows machine in PowerShell, you might prefer setting the variable globally for your current session by running $env:NODE_OPTIONS = "--openssl-legacy-provider" before you fire up your npm start. I usually stick to the package.json method because it saves me from having to remember to run that command every single time I reopen my terminal.

If you want to avoid this headache in the future, the best approach is to keep your development dependencies updated. Often, this error pops up because your react-scripts package is outdated and still clinging to an older version of Webpack that doesn't play nice with modern Node. Running npm install react-scripts@latest frequently keeps your build tools compatible with the latest security standards, saving you from having to use these legacy workarounds in the first place.

Hope this gets your project up and running so you can get back to the actual coding. Happy hacking!

救命！React 專案噴出 error:0308010C 是怎麼回事？

來源：Stack Overflow ↗ · 2572 票

那天我為了試一個新專案，好不容易在 IntelliJ IDEA 裡建好架構，滿心期待地按下 npm start，結果終端機直接賞我一串紅通通的錯誤代碼：「error:0308010C:digital envelope routines::unsupported」。那一刻我真的差點崩潰，心想：「我什麼都還沒改啊，怎麼連環境都跑不起來？」，看著那個錯誤訊息，我還以為是我的電腦壞了還是 Node.js 撞邪了，那種「明明照著官方文件做卻還是卡死」的無力感，真的是工程師最想原地離職的時刻之一。

後來我才搞清楚，原來這一切都是 Node.js 升級惹的禍。簡單來說，Node.js 17 版本之後引進了 OpenSSL 3.0，這傢伙對加密演算法的要求變得超級嚴格，但我們很多舊有的前端工具（像是 Webpack 4 或舊版的 React-scripts）還在使用過時的演算法，導致兩邊溝通不良。說穿了，就是新版 Node.js 覺得這些套件的加密方式太老派、不安全，所以直接封殺，拒絕幫你編譯程式碼。

既然知道是版本衝突，解決起來其實沒那麼複雜。最快的方法就是告訴 Node.js：「嘿，別管那麼嚴，先幫我跑起來再說」。如果你是在 Mac 或 Linux 環境，直接在終端機輸入這行指令：


export NODE_OPTIONS=--openssl-legacy-provider

如果是 Windows 的使用者，可以在 PowerShell 裡輸入：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

只要執行完這行，再重跑一次 npm start，通常就能順利看到熟悉的編譯成功畫面了。如果不想每次開終端機都打一遍，你可以直接把它寫進 package.json 的 scripts 區塊裡，把 start 改成 "start": "react-scripts start" 變成 "start": "react-scripts --openssl-legacy-provider start"，這樣就一勞永逸。

至於要怎麼預防下次再踩到這種坑？說真的，最好的辦法就是養成使用 NVM (Node Version Manager) 的習慣。畢竟前端生態圈更新速度快得嚇人，很多專案都有特定的 Node 版本需求，與其讓全域環境的版本亂跳，不如針對不同專案鎖定好對應的版本，這樣就不會哪天又因為升級了 Node 而讓整個專案突然原地癱瘓。

希望這招能救回你的一天，別再被這個錯誤訊息氣到摔鍵盤啦！
