How to Check If a File Exists in Python Without Using Try-Except Blocks

Source: Stack Overflow ↗ · 7350 votes

Back when I was a junior dev building my first automated data pipeline, I thought using try-except blocks for every single file operation was just "the way things were done." I ended up wrapping a simple file check in a massive block, and it looked like a total mess of nested logic that made my eyes bleed. I spent three hours debugging a race condition because I was catching exceptions that weren't even related to the file's existence, and I promised myself right then that I’d find a cleaner, more idiomatic way to handle basic path validation.

The reason so many of us fall into the try-except trap is that Python’s philosophy is "it’s easier to ask for forgiveness than permission" (EAFP). While that’s great for high-concurrency environments where a file might vanish between the moment you check it and the moment you open it, sometimes you just need a simple boolean check for a script. Using exceptions for standard flow control often leads to bloated, hard-to-read code that hides actual errors, making your codebase feel like a house of cards.

If you want to handle this cleanly, the standard approach is to use the pathlib module. It’s been the modern, object-oriented way to handle filesystem paths since Python 3.4, and it’s significantly more readable than the older os.path methods. Here is how I usually handle it now:


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.is_file():
    print("The file exists, let's get to work.")
else:
    print("File not found, skipping this step.")

If you’re stuck on a legacy codebase or just prefer the classic style, you can still use the os.path module, which is perfectly reliable for simple checks. It’s a bit more "old school," but it gets the job done without the overhead of an exception block:


import os

if os.path.exists("my_data.txt"):
    # Do something with the file
    pass

To prevent this from becoming a nightmare later, my best piece of advice is to remember the "Time-of-check to time-of-use" (TOCTOU) bug. Even if you check that a file exists, it could be deleted by another process a millisecond later. If your script is mission-critical, checking if the file exists is just a convenience; you should still wrap the actual open() call in a try-except block to handle permissions errors or sudden deletions. Keep your checks simple, but always respect the fact that the filesystem is unpredictable.

Hope this saves you some of the headache I dealt with back in the day. Happy coding!

別再寫 try-except 檢查檔案了：優雅處理檔案存在的幾種方式

來源：Stack Overflow ↗ · 7350 票

剛入行那陣子，我寫過一個自動化處理腳本，當時為了檢查設定檔是否存在，我寫了一大堆 try-except IOError。結果某次程式在跑的時候，因為我把錯誤處理寫得太籠統，導致檔案權限不足的錯誤也被吃掉，程式直接跑出毫無意義的結果，最後我盯著螢幕上的錯誤日誌看了兩小時，差點崩潰，那種「明明程式沒報錯，但就是沒產出結果」的無助感，真的會讓人想把鍵盤砸了。

其實這問題之所以讓人困擾，是因為 Python 的哲學一向是 EAFP（Easier to Ask for Forgiveness than Permission），也就是建議大家「先做再說，出錯了再捕獲」。但在檢查檔案這件事上，這招有時候真的會讓程式碼看起來亂糟糟的，尤其是在邏輯複雜的時候，大量的 try-except 簡直就是閱讀災難。

後來我學乖了，其實 Python 內建的 os 和 pathlib 模組早就準備好了解法。如果你只是想確認檔案在不在，不需要動用到例外處理。我個人現在最推薦的是 pathlib，這是現代 Python 的寫法，用起來直覺很多。你可以直接這樣寫：


from pathlib import Path

file_path = Path("config.json")

if file_path.exists():
    print("檔案就在這，可以放心開工了！")
else:
    print("檔案消失了，去檢查一下路徑吧。")

如果你是在維護比較舊的專案，或者不想引入 pathlib，用 os.path 也是完全沒問題的，寫法差不多：


import os

if os.path.exists("config.json"):
    # 這裡放你要執行的邏輯
    pass

不過，這裡有個「痛苦時刻」一定要提醒大家：雖然檢查檔案是否存在很方便，但這其實有一個潛在的 Race Condition 問題。也就是說，當你檢查完「檔案存在」到你「真正打開檔案」的那幾毫秒之間，那個檔案是有可能被另一個行程刪掉的。所以，如果你的程式涉及多執行緒或高頻率檔案讀寫，還是得乖乖回到 try-except 的懷抱，去捕捉 FileNotFoundError 才是最穩的做法。

要預防這種惱人的 bug，我建議養成「明確定義錯誤」的習慣。千萬不要寫空的 except:，更不要用一個 try 包住整個幾百行的邏輯。如果你檢查完檔案，確認它在，就只對「打開檔案」這個動作做例外處理，把影響範圍縮到最小，這樣下次除錯時，你才不會像當初的我一樣，對著螢幕懷疑人生。

希望這些經驗能幫你省下幾個小時的除錯時間，大家寫 code 愉快，別再被檔案路徑搞瘋了！
