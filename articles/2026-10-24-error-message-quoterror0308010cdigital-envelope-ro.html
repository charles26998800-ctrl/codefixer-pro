How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the first time I hit this wall. I had just upgraded my development machine, pulled down a legacy project I hadn't touched in months, and felt ready to crush some tickets. Instead, I spent three hours staring at a cryptic terminal error that made me question if I’d forgotten how to run npm start. It’s one of those bugs that feels like a personal attack from your own computer, especially when you’re just trying to get a standard boilerplate project off the ground.

The reason you’re seeing this error:0308010C:digital envelope routines::unsupported message is actually quite straightforward, even if the error text is complete gibberish. It comes down to a breaking change in OpenSSL 3.0, which was included in Node.js version 17 and later. Older versions of Webpack (specifically version 4, which many React templates still rely on) use a hashing algorithm that OpenSSL 3.0 considers insecure and has therefore disabled by default. Essentially, your modern Node environment is trying to enforce stricter security standards than your older build tools are prepared to handle.

Fixing this is fortunately a quick win, and you don't need to downgrade your entire Node installation to do it. The most common way to resolve this is to tell Node to use the legacy OpenSSL provider, which allows those older hashing functions to run without throwing a tantrum. If you’re on a Mac or Linux machine, you can set the environment variable right in your terminal before running your start command:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, you’ll want to use a slightly different syntax in your terminal:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

For a more permanent fix, I usually just add this to my package.json file so I don't have to remember to type it every single time I boot up my dev server. You can modify your scripts section like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

If you want to avoid this headache in the future, the best approach is to keep your project dependencies updated. This error is a classic sign that your react-scripts or Webpack version is lagging behind. Whenever you have some downtime, try bumping your dependencies to the latest major versions, as newer releases have moved away from the legacy hashing algorithms that cause this conflict in the first place.

Hope this saves you the three hours of frustration I had to go through! Happy coding, and may your builds stay green today.

React 專案跑不動？別怕，那只是 Node.js 的版本鬧脾氣

來源：Stack Overflow ↗ · 2572 票

說真的，那天我正想用 IntelliJ IDEA 快速建立一個 React 專案來測試個小功能，結果 npm start 一按下去，終端機直接甩給我一長串紅通通的錯誤訊息，重點還是那個看都看不懂的 error:0308010C:digital envelope routines::unsupported。當時我真的差點崩潰，心想：「我什麼都還沒寫啊！連一行程式碼都還沒動，怎麼環境就直接原地爆炸了？」

其實這問題說穿了，就是 Node.js 版本跟舊版 Webpack 的「代溝」。簡單來說，Node.js 在 v17 版本之後升級了加密演算法模組（OpenSSL 3.0），變得更嚴格了，但很多舊版的 React 專案（或是依賴的 Webpack 4）還在用比較舊的雜湊演算法。這兩邊湊在一起，Node.js 就覺得：「你這東西太舊、太不安全，我不跟你玩了。」那種明明是照著官方文件跑，結果卻卡在第一步動彈不得的無力感，真的是工程師最想摔鍵盤的時刻之一。

我自己當下的處理方式其實很暴力，就是告訴 Node.js：「嘿，別管那麼多，先放行再說。」最快的方法就是在你的 package.json 裡面動點手腳。你只需要找到 scripts 區塊，在啟動指令前面加上 NODE_OPTIONS=--openssl-legacy-provider 這一行。如果你是 Windows 用戶，記得要安裝 cross-env 來確保跨平台相容性。具體改法就像這樣：


"scripts": {
  "start": "react-scripts start",
  "build": "react-scripts build"
}

改成：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

改完之後，記得把 node_modules 和 package-lock.json 刪掉重跑一次 npm install，通常這樣就能順利跑起來了。

為了避免以後再遇到這種「環境升級就地獄」的情況，我建議大家平常養成用 nvm (Node Version Manager) 管理版本的習慣。只要專案一多，你就會發現專案 A 需要 Node 14，專案 B 又非得用 Node 18 不可，與其強迫所有專案都跟著系統版本跑，不如在每個專案根目錄放一個 .nvmrc 檔案，規定好該專案該用的 Node 版本，這樣你切換專案時只要打個 nvm use，什麼怪毛病都不會出現。

搞定這個之後，就能繼續開心地寫 Code 了，祝大家除錯順利，少踩點坑！
