How to Check If a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7352 votes

Back when I was still cutting my teeth on Python, I spent a solid three hours debugging a script that was supposed to process a directory of logs. I was obsessed with using try-except blocks for everything, and my code ended up looking like a Russian nesting doll of error handling just to verify if a file was sitting on the disk. I felt like a total amateur when I realized I was essentially reinventing the wheel while making my logic unreadable in the process.

The reason this feels like a hurdle is that Python’s philosophy is often "Easier to Ask for Forgiveness than Permission" (EAFP). Many developers are taught that try-except is the only "Pythonic" way to handle file operations because it avoids race conditions. However, when you’re writing simple scripts or CLI tools, wrapping every single file check in a try block just feels like overkill. You aren't necessarily trying to handle a complex IO error; you just want to know if the file is there so your script can decide whether to skip it or proceed.

To handle this cleanly, I’ve moved away from the old os.path module and started using pathlib exclusively. It’s built into the standard library and makes the code read almost like plain English. If you’re checking for a file, you just grab the path object and call .exists() or .is_file() on it. Here is how I handle it now:


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.is_file():
    print("The file exists and I can start processing.")
else:
    print("File not found, skipping...")

If you’re still working on a legacy codebase that relies on the older os module, you can achieve the same result using os.path.exists(). I used this for years before pathlib arrived, and while it’s a bit more "old-school," it gets the job done without any exceptions popping up. Just keep in mind that exists() will return True for directories, so if you strictly need a file, is_file() is your best bet.


import os

if os.path.exists("my_data.txt"):
    # Proceed with your logic
    pass

The best way to prevent this kind of headache in the future is to stop treating existence checks as the final word. Remember that between the time you check if file.exists() and the time you actually open the file, the file could be deleted or moved by another process. This is known as a Time-of-check to time-of-use (TOCTOU) bug. If you’re building a production-grade application where reliability is paramount, you should eventually embrace the try-except block anyway because it’s the only way to catch those sneaky race conditions. Use the exists() check for flow control, but always wrap your actual file operations in a try block just to be safe.

Hope this saves you a few hours of frustration while cleaning up your codebase. Happy coding!

Python 檢查檔案存不存在，別再寫那種醜死人的 try-except 了！

來源：Stack Overflow ↗ · 7352 票

記得剛進這行沒多久，有次寫一個自動清理 log 的腳本，為了怕程式因為找不到檔案噴錯誤掛掉，我當時瘋狂濫用 try-except。結果整個程式碼長得像迷宮一樣，滿滿的 try 區塊把核心邏輯包得密不透風，最後維護時自己看著都想哭，甚至因為疏忽漏掉了一個例外處理，導致客戶的伺服器半夜直接報錯停擺，那天晚上我真的差點崩潰，在辦公室坐到凌晨三點盯著螢幕懷疑人生。

其實這問題的根本原因很單純，就是 Python 對於「檔案系統」的操作比較保守，它預設是採取「請求原諒比請求許可更容易」（EAFP）的哲學，也就是直接去開檔，如果失敗再丟 Exception。但說實話，對於這種單純確認檔案在不在的小事，硬要用 try 就像是為了買杯咖啡卻要先寫一份買賣合約一樣，完全是殺雞用牛刀，不僅程式碼變得很難讀，效能上其實也沒必要這樣折騰。

後來我學乖了，改用標準庫裡的 pathlib，這才是現代 Python 工程師該用的寫法。自從 Python 3.4 引入這個模組後，處理檔案路徑簡直是優雅到不行。你只需要建立一個 Path 物件，然後呼叫 .exists() 方法，它就會回傳一個乾淨的布林值，完全不需要任何額外的例外處理。程式碼寫起來就像這樣：


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.exists():
    print("檔案就在這，可以安心開工了！")
else:
    print("檔案不存在，別亂讀以免踩雷。")

如果要確保那是一個「檔案」而不是一個「資料夾」，你還可以順便加個 .is_file() 判斷，這樣邏輯會更嚴謹。

為了避免以後又因為這種小細節翻車，我給自己的建議是，除非是牽涉到多執行緒或是高併發的寫入情境（那種狀況下檔案狀態隨時會變，還是建議直接 try-except 比較保險），否則平常寫腳本時，盡量把檢查邏輯寫在讀取之前。養成使用 pathlib 的習慣，不僅能讓你的程式碼看起來乾淨俐落，最重要的是，你再也不用面對那些密密麻麻、看了就頭痛的 try-except 巢狀結構了。

搞定這點小事之後，心情真的會舒暢不少，趕快回去把那些多餘的 try 區塊刪掉吧！
