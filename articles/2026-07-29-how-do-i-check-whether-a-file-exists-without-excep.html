How to Check if a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7349 votes

Early in my career, I was building a data pipeline that processed thousands of small log files, and I got caught up in the "EAFP" (Easier to Ask for Forgiveness than Permission) vs. "LBYL" (Look Before You Leap) debate. I spent three hours debugging a script that was crashing because I was nesting try-except blocks inside a tight loop, which made my code look like a staircase and destroyed my performance. I kept thinking there had to be a more readable, idiomatic way to just peek at the filesystem before diving in.

The root cause of this confusion is that Python’s os module has evolved over time, leading to multiple ways of doing the same thing. In the old days, people relied on os.path.exists(), but then we got the pathlib module in Python 3.4, which changed the game. The "problem" isn't really a bug—it’s just that developers often default to exception handling for flow control when a simple conditional check is much cleaner for small-scale operations. If you're just checking for a config file or a temporary asset, you don't always need to trigger the overhead of an exception.

To fix this, I stopped relying on messy try blocks for simple file presence checks and started using pathlib. It’s the modern standard, and it’s significantly more readable than the legacy os.path syntax. Here is the cleanest way to do it:


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.is_file():
    print("The file exists and I can start processing.")
else:
    print("File not found, skipping this step.")

If you are stuck on a legacy project or just prefer the old-school os approach, you can still use os.path.isfile(). It does exactly what it says on the tin without throwing an error if the file is missing:


import os

if os.path.isfile("my_data.txt"):
    # Do your work here
    pass

One thing to watch out for is the "Time of Check to Time of Use" (TOCTOU) race condition. Even if you check that the file exists, it could be deleted by another process a millisecond later before you actually open it. If your application is running in a highly concurrent environment, don't rely on these checks alone—you'll still want a try-except block around the actual open() call to handle those edge cases safely.

Hope this saves you from the same messy code loops I had to untangle! Happy coding and feel free to reach out if you hit another wall.

別再用 try-except 檢查檔案是否存在了！優雅處理 Python 檔案檢查的正確姿勢

來源：Stack Overflow ↗ · 7349 票

記得剛開始寫 Python 爬蟲那陣子，為了要判斷下載下來的圖片快取是否存在，我寫了一堆 try-except 包住 open()。結果有次程式跑了三個小時，因為某個路徑的小瑕疵，整個邏輯被卡在異常處理裡，看著滿屏的 FileNotFoundError 堆疊追蹤，我當時真的差點沒把鍵盤給摔了，心想：「難道檢查個檔案還要這麼大費周章嗎？」

其實，很多新手（包括當年的我）會習慣用 try-except 去檢查檔案，是因為覺得這樣寫起來很「全面」。但說真的，這就像是為了知道冰箱有沒有牛奶，非要強行打開門看一眼，如果門壞了就崩潰一樣。在 Python 裡，我們其實有更輕鬆、更直覺的方式來處理這種路徑判斷，不需要每次都搞得像在處理什麼重大異常一樣。

後來我學乖了，直接改用 pathlib 模組，這簡直是救贖。pathlib 在 Python 3.4 之後就內建了，它把路徑當作物件來處理，你可以直接對路徑物件呼叫 .exists() 方法。這寫起來乾淨俐落，完全不用擔心什麼例外拋出，程式碼讀起來就像是在讀英文句子一樣順。


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.exists():
    print("檔案就在這裡，安心服用！")
else:
    print("檔案消失了，去檢查一下路徑吧。")

如果你是因為舊專案還在用 os.path 模組，那也沒關係，os.path.exists() 也是一個非常經典的選擇，效果跟 pathlib 一樣好，它回傳的就是一個單純的布林值 True 或 False，完全不會拋出任何讓你心驚膽跳的錯誤。


import os

if os.path.exists("my_data.txt"):
    # 進行你的處理
    pass

不過，這裡有個老司機的忠告：雖然用 exists() 很方便，但要小心「競爭條件」（Race Condition）。也就是說，當你檢查完檔案存在後，在下一行程式碼執行前，檔案有可能被其他執行緒或系統程序給刪掉了。所以，如果你是要進行「讀取」這個動作，最穩健的做法其實還是直接嘗試開啟檔案，並只捕捉 FileNotFoundError。但如果你只是做簡單的邏輯判斷，比如決定要不要建立新檔案，那 pathlib 絕對是你的最佳夥伴。

以後寫程式時，記得盡量讓邏輯保持單純，別讓 try-except 變成你的萬用避難所。好好享受用 pathlib 處理路徑的快感，你會發現程式碼會變漂亮很多。
