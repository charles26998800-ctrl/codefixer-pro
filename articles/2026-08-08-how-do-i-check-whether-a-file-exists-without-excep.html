How to Check If a File Exists in Python Without Relying on Exceptions

Source: Stack Overflow ↗ · 7349 votes

I remember early in my career, I was building a log-parsing script and I was obsessed with using try-except blocks for everything, including simple existence checks. I spent a good three hours debugging a performance bottleneck only to realize I was forcing Python to spin up and tear down exception handlers thousands of times per second just to see if a file was there. It was one of those classic "I'm being too clever for my own good" moments that left me feeling pretty foolish once I realized how much cleaner the code could actually be.

The reason developers often run into this is that Python’s philosophy is "it's easier to ask for forgiveness than permission" (EAFP). While that’s great for dealing with race conditions or unpredictable file permissions, it’s honestly overkill when you just need to branch your logic based on whether a path is present. When you wrap a simple check in a try-except block, you’re adding unnecessary overhead and visual noise to your code, making it harder to read and slightly slower to execute in tight loops.

If you want to check for a file without the ceremony of an exception handler, the most modern and "Pythonic" way to do it is by using the pathlib module. I’ve transitioned all my scripts over to this because it treats paths as objects rather than strings, which makes the code feel much more intuitive. You simply import Path and call the exists() method.


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.exists():
    print("The file exists, let's get to work.")
else:
    print("File not found, skipping this step.")

If you’re working on an older codebase or just prefer the classic functional approach, you can still use the os.path module. It’s been around forever and is perfectly reliable for this specific task. I still see it in legacy projects I maintain, and it gets the job done without any fuss.


import os

if os.path.exists("my_data.txt"):
    print("File found using os.path!")

To prevent this from becoming a recurring headache, my biggest tip is to be mindful of "Time of Check to Time of Use" (TOCTOU) bugs. Checking if a file exists is fine for UI feedback or simple logic, but if you’re about to open that file, don't check for existence and *then* open it. Just try to open the file and handle the FileNotFoundError if it fails. That way, you avoid the race condition where the file disappears between the moment you checked for it and the moment you actually try to read it.

Hope this saves you some of the time I wasted back in the day—happy coding!

別再為了檢查檔案是否存在而寫滿滿的 try-except 了

來源：Stack Overflow ↗ · 7349 票

記得剛開始寫 Python 的時候，我接手了一個處理大量 log 檔的自動化腳本，當時為了確保檔案存在，我腦袋裡只想到用 try...except FileNotFoundError 來包住讀取邏輯。結果有天老闆突然要我加一個「批次檢查」功能，我的程式碼瞬間變成了一座由 try-except 堆疊起來的義大利麵，光是看著那幾十行重複的異常處理，我就覺得自己的代碼品質正在崩塌，那種「明明只是想問個檔案在不在，為什麼要搞得像在處理核災」的無力感，真的讓人很想把鍵盤砸了。

會造成這個困擾，其實是因為 Python 的設計哲學鼓勵「請求寬恕比獲得許可更容易（EAFP）」，也就是習慣用 try-except 來處理執行時可能發生的錯誤。但在處理簡單的檔案檢查時，如果你只是想單純判斷路徑是否存在，頻繁地拋出異常其實是在浪費系統資源，而且程式碼的可讀性會變得很差。想像一下，如果你只是要寫個簡單的 if-else 邏輯，結果卻因為堅持遵循 EAFP 風格，導致原本三行能解決的事情變成十幾行，這對維護者來說簡直是災難。

其實，Python 的 pathlib 模組早就給了我們更優雅的解法。我現在都統一改用 pathlib.Path 物件，它不只語法直覺，還讓程式碼看起來乾淨很多。你只需要一行程式碼就能搞定：


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.exists():
    print("檔案還在，安全感滿滿！")
else:
    print("檔案消失了，快檢查備份！")

如果是舊專案沒辦法導入 pathlib，或者你真的很習慣用 os 模組，那使用 os.path.exists() 也是完全沒問題的，效果一樣好用。

為了避免以後又踩到這種「為了除錯而製造更多髒程式碼」的坑，我給自己的建議是：先釐清你的需求。如果你是要「嘗試開啟並讀取」檔案，那用 try-except 是最正確的，畢竟檔案可能在檢查完 exists() 的那一瞬間剛好被刪除（這就是經典的 Race Condition 問題）。但如果你只是要寫個腳本檢查檔案是否存在，用 pathlib 這種簡潔的方式就綽綽有餘了。學會適時放過自己，別把簡單的邏輯複雜化，寫程式才會更有趣。

希望這招能幫你拯救那些快要爆炸的腳本，趕快去試試看吧！
