How to Fix the "error:0308010C:digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I upgraded my local Node.js environment and tried to spin up a quick React prototype in IntelliJ, only to be greeted by a wall of red text in my terminal. I spent three hours digging through my project configuration, convinced I’d somehow corrupted my dependencies, before realizing it was just a simple version mismatch staring me right in the face. It's one of those classic "why is my build broken" moments that makes you want to throw your coffee across the room, but luckily, it’s a quick fix once you know where to look.

The root cause of this headache is the transition from OpenSSL 1.1.1 to OpenSSL 3.0 in newer versions of Node.js, specifically versions 17 and above. Many older React projects and build tools rely on algorithms—like MD4—that are no longer supported by default in the newer OpenSSL library for security reasons. When your build script tries to hash something using a legacy algorithm, Node.js throws its hands up and gives you that cryptic digital envelope routines::unsupported error. It’s essentially the software equivalent of a security guard refusing to let you into a building because your keycard is using an outdated encryption standard.

To fix this, you need to tell Node.js to use the legacy OpenSSL provider, which brings back support for those older algorithms. The most straightforward way to do this is by setting an environment variable called NODE_OPTIONS to --openssl-legacy-provider. If you're on a Mac or Linux machine, you can update your package.json file to include this in your start script:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

If you’re working on Windows, the syntax changes slightly because of how the command prompt handles environment variables. You’ll want to use set before your command or use a cross-platform tool like cross-env to ensure it works regardless of the OS:


# For Windows (Command Prompt)
set NODE_OPTIONS=--openssl-legacy-provider && npm start

If you're using cross-env (which I highly recommend for any team project), you can keep your package.json clean and portable by doing this:


"scripts": {
  "start": "cross-env NODE_OPTIONS=--openssl-legacy-provider react-scripts start"
}

To prevent this from coming back to haunt you, get into the habit of keeping your build dependencies up to date. This error is almost always a sign that your react-scripts version is lagging behind your Node.js version. If you aren't tied to a specific legacy version, running npm install react-scripts@latest often patches the underlying issue by moving to a hashing method that plays nice with OpenSSL 3.0, saving you from having to use the legacy flag altogether.

Hope this saves you a few hours of frustration and gets your project back on track. Happy coding!

救命！跑個 React 專案怎麼就遇到 OpenSSL 錯誤了？

來源：Stack Overflow ↗ · 2572 票

那天早上我剛換了新筆電，信心滿滿地想把舊專案拉下來跑跑看，結果才剛下完 npm start，終端機就直接噴出一大串紅通通的報錯訊息。看到 error:0308010C:digital envelope routines::unsupported 這一行字的時候，我真的是當場愣住，心裡想說：「不是吧，我連程式碼都還沒改，連環境都還沒動，為什麼它要這樣整我？」那種趕著要 Demo 卻連開發環境都起不來的無力感，真的是工程師最想原地退休的時刻。

其實這個問題的根源，是因為 Node.js 升級到了 v17 或更新的版本。Node.js 在這之後改用了 OpenSSL 3.0，而舊版的 Webpack（特別是 v4 版本，很多舊專案都還在用）裡面的加密演算法跟這個新版本的 OpenSSL 不相容。簡單來說，就是你的專案在問路，但 Node.js 換了新的語言規範，舊版的 Webpack 聽不懂，兩邊就這樣僵住了，導致執行時直接崩潰。

我當時也是試過刪掉 node_modules 再重灌，甚至懷疑人生到想重裝作業系統，後來才發現其實不需要那麼極端。最快、最直接的解法，就是告訴 Node.js 說：「拜託，請你暫時退回到舊版的相容模式」。你只要在執行指令時，加入 NODE_OPTIONS=--openssl-legacy-provider 這個環境變數，問題馬上就能迎刃而解。

如果你是 Linux 或 Mac 的使用者，在終端機輸入這行指令就行：


export NODE_OPTIONS=--openssl-legacy-provider
npm start

如果你是用 Windows 的 PowerShell，寫法稍微不同：


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

當然，如果你不想每次啟動都打這麼長一串，最推薦的方式是直接把這個設定寫進 package.json 的 scripts 區塊裡。把你的啟動指令改成這樣：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

為了預防以後再踩到這種「升級版」的坑，我現在養成習慣，只要是維護舊專案，第一件事就是檢查 package.json 裡的依賴版本，看看有沒有機會把 Webpack 或 react-scripts 升級到比較新的版本。畢竟技術債這東西，早晚都要還的，與其每次跑專案都要在那邊繞過錯誤，不如找個時間把環境升級上去，才是長久之計。

希望這篇心得能幫你省下寶貴的除錯時間，別再為了這些環境設定把自己搞到火大了！
