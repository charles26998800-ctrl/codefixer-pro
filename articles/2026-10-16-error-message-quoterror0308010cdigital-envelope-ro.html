How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I pulled a fresh React project template in IntelliJ, fired up the terminal, and hit npm start expecting a clean dev server, only to be slapped in the face with a wall of red text. I spent nearly three hours digging through Stack Overflow and cursing my package manager, convinced my entire environment was corrupted, before realizing it was just a simple mismatch between my Node version and my project's dependencies. It’s one of those classic "why is my computer fighting me today?" moments that every developer hits at least once.

The root of this headache lies in the shift from OpenSSL 1.1.1 to OpenSSL 3.0, which was introduced in Node.js version 17 and became the default in 18+. Essentially, some of the older hashing algorithms used by Webpack and various build tools in your React project aren't considered secure enough by the newer OpenSSL standards. When Node tries to run these legacy build scripts, it throws the digital envelope routines::unsupported error because it refuses to use those older, deprecated protocols. It’s not that your code is broken—your environment is just being a bit too strict for your older project dependencies.

To fix this, I always go for the simplest approach first: telling Node to use the legacy OpenSSL provider. You can do this globally, but I prefer doing it on a per-project basis so I don't compromise security for every single thing I run. If you’re on macOS or Linux, you just need to export an environment variable in your terminal before running your start command:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is a bit different. You’ll want to set it in your command prompt like this:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

For those of you who don't want to type that out every time you open a new terminal window, just head over to your package.json file and bake it right into your scripts section. It’s a lifesaver for avoiding those "why won't this work?" moments when you come back to a project after a few weeks. You can modify your start script like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

The best way to prevent this from eating your time in the future is to keep your project dependencies updated. Most modern versions of react-scripts and Webpack have moved away from the code that triggers this legacy error, so running npm update or migrating to a newer build tool like Vite usually makes the problem disappear for good.

Hope this saves you a few hours of frustration today. Happy coding!

被 Node.js 版本陰了？解決 error:0308010C 的崩潰時刻

來源：Stack Overflow ↗ · 2572 票

記得那天早上我正準備開啟一個許久沒動的 React 舊專案，想說快速改個 UI 就好，結果 npm start 一按下去，終端機直接噴出一堆紅字，那個 error:0308010C:digital envelope routines::unsupported 簡直像是在對我宣告死刑。我當時心裡真的罵了一聲髒話，想說我明明什麼都沒動，只是更新了一下 Node.js 版本，怎麼整個專案就像被詛咒一樣直接癱瘓了，那一刻真的覺得這世界上最遙遠的距離，就是我明明寫了 code，卻連伺服器都起不來。

其實這背後的原因一點都不神秘，單純是因為我升級到了 Node.js 17 以上的版本。Node.js 在這之後改用了 OpenSSL 3.0，這玩意兒對於一些舊的加密演算法比較嚴格，而我們常用的 Webpack 4 或是早期的 React 腳本，底層依賴的加密方式剛好踩到了這個紅線，導致編譯器直接罷工。說實話，這真的很讓人無力，因為這不是我們程式碼寫錯了，而是環境升級帶來的「副作用」，那種明明沒錯卻無法執行的挫折感，相信每個開發者都懂。

解決的方法其實很暴力但有效。如果你跟我一樣不想花時間去大改底層配置或升級整個專案架構，最快的解法就是告訴 Node.js：「嘿，請你對這些舊演算法寬容一點」。你只需要在執行指令前設定環境變數 NODE_OPTIONS，讓它使用舊版的加密模式。

如果你是用 macOS 或 Linux，直接在終端機輸入：


export NODE_OPTIONS=--openssl-legacy-provider
npm start

如果你是在 Windows 的 PowerShell，則是這樣設定：


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

要是你懶得每次都要打這串，直接寫進 package.json 的 scripts 區塊裡更方便，把 "start": "react-scripts start" 改成 "start": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts start"（Windows）或是在前面加上 export（Mac/Linux），這樣以後執行就不會再看到那個討人厭的錯誤訊息了。

為了避免以後再被這種環境升級雷到，我強烈建議大家在專案裡一定要用 .nvmrc 或者 engines 欄位來鎖定 Node.js 版本。畢竟專案一久，環境變動真的是最大的隱形殺手，把版本規範寫清楚，至少能讓團隊夥伴或是未來的自己少踩一點坑。

好啦，希望這招能救回你的專案，別再為了這行錯誤卡住一整天了！
