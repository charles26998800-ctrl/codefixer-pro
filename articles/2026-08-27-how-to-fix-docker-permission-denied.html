How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1418 votes

I still remember the first time I set up my dev environment on a fresh Ubuntu install, feeling like a total pro until I ran my first container and got slapped with a "Permission denied" error. I spent way too long—at least an hour—blindly typing sudo before every single command, convinced that I had botched the entire Docker installation. It’s one of those classic "welcome to Linux" moments that makes you feel like an imposter for a split second, but luckily, it’s a quick fix that saves you from carpal tunnel syndrome caused by typing sudo ten times a minute.

The reason this happens is actually quite straightforward. By default, the Docker daemon binds to a Unix socket owned by the root user, not your local user account. When you try to run a command without elevated privileges, the Docker client tries to talk to that socket, gets denied access, and throws the error because your user isn't part of the security group that has permission to touch it. It’s a standard security measure, but it’s incredibly annoying for a local development workflow where you’re constantly spinning containers up and down.

To fix this for good, I always add my user to the docker group. First, you need to create the group if it doesn't already exist by running sudo groupadd docker. Once that's set, you add your current user to the group with this command:


sudo usermod -aG docker $USER

After you run that, the changes won't take effect immediately. You’ll need to either log out and log back in, or just run newgrp docker in your current terminal session to force the system to recognize your new group membership. To verify it worked, I usually run docker run hello-world without the sudo prefix. If you see the "Hello from Docker!" message, you’re officially in the clear and can stop prefixing every command with root privileges.

To prevent this from coming back to haunt you, just make sure that whenever you’re setting up a new machine, you add the user to the docker group as part of your standard "dotfiles" or initial setup script. It’s a small step that saves you a massive headache down the road.

Happy coding, and may your containers always start on the first try!

每次都要打 sudo 真的會瘋掉：解決 Docker Permission Denied 的小撇步

來源：Stack Overflow ↗ · 1418 票

記得剛開始碰 Docker 的時候，我正趕著要把一個 Side Project 部署到 Ubuntu 伺服器上。當時我自信滿滿地敲下 docker run hello-world，結果螢幕直接噴出一串紅通通的「Permission denied」。我心想：「蛤？我是不是剛才安裝壞了？」當下真的差點崩潰，為了測試一個小功能還要每次都補上 sudo，那種手感完全不對，而且當時心急如焚，一直懷疑是不是 Docker 的版本衝突，結果搞了半小時才發現自己根本沒把權限搞定，真的是浪費時間又傷身。

其實這問題的根本原因很單純，Docker 的 daemon 預設是用 root 權限跑的，它會監聽 /var/run/docker.sock 這個 Socket 檔案。這個檔案的擁有者是 root，權限群組也是 root。當你用一般使用者身份去執行 docker 指令時，系統就像個嚴格的門禁管理員，因為你的帳號不在那個群組裡，它當然不准你碰這個 Socket，所以才會一直跳出權限不足的錯誤。

要解決這個問題，其實只要把你的帳號加入 docker 這個群組就好。我當時是這麼操作的：先用 sudo groupadd docker 確保群組存在（通常安裝完就會有），接著執行 sudo usermod -aG docker $USER 把自己加進去。搞定這行後，千萬記得要登出再登入，或者直接執行 newgrp docker 讓群組變更生效，不然你會像我當年一樣，改完還在疑惑為什麼還是不能跑，在那邊乾瞪眼。

為了預防以後換台機器又遇到同樣的鳥事，我現在養成一個習慣：每次在新的開發環境安裝完 Docker，我會直接把這串指令存進我的筆記裡。其實最根本的預防方式，就是把這個權限配置當成開發環境設定的一環。只要安裝完 Docker，第一件事就是執行 sudo usermod -aG docker $USER，這樣就能徹底告別那個煩人的 sudo 囉。

把這幾行指令跑完，以後敲 Docker 指令就順暢多了，再也不用為了權限問題在那邊心浮氣躁啦！
