How to Check if a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7350 votes

Early in my career, I spent a good three hours tearing my hair out trying to debug a script that was crashing every time it hit a missing config file. I had wrapped everything in massive try-except blocks because I thought it was the only way to handle file system errors, which made my logs look like a complete disaster. It wasn't until a senior dev walked by my desk, chuckled at my screen, and pointed out that I was essentially using a sledgehammer to crack a nut that I finally learned there were cleaner, more idiomatic ways to handle this.

The root cause of this frustration usually boils down to how Python treats file system operations. When you use the older os module, it’s easy to get caught up in the habit of just trying to open a file and catching the FileNotFoundError. While there's absolutely nothing wrong with that approach—in fact, it's often the most robust way to handle race conditions—it can make your code look cluttered when you're just doing a quick check. People often fall into the trap of using try-except for flow control, which is widely considered an anti-pattern because it obscures the actual business logic of your application.

If you want to check for a file without the overhead of an exception block, the modern, standard way to do it is by using the pathlib module. It was introduced in Python 3.4 and has since become my absolute go-to for anything related to paths. It’s object-oriented, readable, and feels much more like "native" Python than the old-school os.path strings. Here is how I’d recommend you handle it:


from pathlib import Path

file_path = Path("config.json")

if file_path.exists():
    print("The file is right where it should be.")
else:
    print("File not found, proceeding with defaults.")

If you’re stuck on a legacy codebase and can't use pathlib, you can fall back on os.path.isfile. It does the exact same job, though it’s a bit more procedural. Just keep in mind that exists() will return True for directories, so if you specifically need a file, isfile() is the safer bet.


import os

if os.path.isfile("config.json"):
    # Do your work here
    pass

To prevent this from becoming a headache in the future, my biggest tip is to stop thinking about "checking" and start thinking about "acting." Even if you verify that a file exists using pathlib, another process could delete it a millisecond later before your next line of code runs. This is known as a Time-of-check to time-of-use (TOCTOU) bug. Whenever possible, just try to open the file and handle the exception gracefully if it fails; it’s actually more reliable than checking first. Use these checks for UI logic or simple script flow, but trust your try-except blocks for the heavy lifting.

Hope this saves you from the same three-hour headache I had back in the day. Happy coding!

別再用 try-except 檢查檔案了！教你更優雅的寫法

來源：Stack Overflow ↗ · 7350 票

記得剛入行沒多久，那時候寫一個自動處理 logs 的腳本，想說用 try-except 包住 open() 來判斷檔案存不存在。結果程式一跑，因為權限不足加上路徑寫錯，噴出一堆我根本沒預料到的例外，整個 console 滿滿的紅色錯誤訊息，看得我心跳加速，差點以為要把生產環境的資料庫搞掛了。那種「我明明只是想問個檔案在不在，為什麼要搞得像災難現場」的無力感，真的是工程師最想逃避的痛苦時刻。

其實會發生這種困擾，是因為 Python 的哲學是「求原諒比求許可更容易」（EAFP），但這並不代表我們在任何情況下都要把程式碼塞進 try-except 的區塊裡。很多時候，我們只是想在執行下一步前，先確認一下環境狀態而已。如果在這種簡單的邏輯判斷下還要處理一堆複雜的例外狀況，反而會讓程式碼變得又臭又長，邏輯一點也不直觀。

後來我發現，與其在那邊擔心報錯，不如直接用 pathlib 模組，這簡直是現代 Python 工程師的救星。只要把路徑變成一個物件，直接呼叫 .exists() 就好，既乾淨又好讀。這是我的標準做法：


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.exists():
    print("檔案就在這，可以開工了！")
else:
    print("檔案找不到，別再找了。")

如果你還在用舊版的 os.path.exists() 其實也行，但 pathlib 真的潮很多，物件導向的操作方式讓你寫程式更有條理。

為了預防這種問題再次發生，我建議大家養成一個習慣：在處理檔案 IO 之前，先建立一個「環境檢查」的函數，或者是直接把路徑處理邏輯封裝起來。不要把檔案檢查的邏輯直接散落在業務邏輯裡，因為檔案系統是隨時會變動的，誰也說不準你檢查完的下一毫秒，檔案會不會被什麼奇怪的背景程序刪掉。所以即便你檢查過檔案存在，後續操作依然要保持防禦性思維，不要過度依賴檢查結果。

寫程式嘛，偶爾踩點坑也是成長的一部分，希望這個小技巧能幫你省下不少除錯的時間！
