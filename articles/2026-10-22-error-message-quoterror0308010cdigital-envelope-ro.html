How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I remember exactly where I was when this error first popped up—staring at my terminal on a Sunday afternoon, just trying to spin up a quick demo project. I had just upgraded to Node.js v17, and suddenly my perfectly good build pipeline decided to throw a massive tantrum with that cryptic "digital envelope routines::unsupported" message. I spent three hours digging through Stack Overflow and cursing my decision to update my environment right before a deadline, only to realize it was a classic case of new-tech-meets-legacy-dependencies.

The reason this happens is actually pretty straightforward once you peel back the layers. When Node.js bumped up to version 17 and higher, they switched to a newer version of OpenSSL—specifically OpenSSL 3.0. This update introduced stricter security standards that don't play nice with older algorithms like MD4, which a lot of older Webpack versions and React scripts still rely on for hashing. Essentially, the build tool is trying to use a legacy hashing method that Node now considers insecure or "unsupported," causing the entire process to crash before it even gets off the ground.

If you’re running into this, the absolute fastest way to get back to work is by telling Node to loosen its security requirements for your specific session. You can do this by setting an environment variable called NODE_OPTIONS to --openssl-legacy-provider. If you're on a Mac or Linux machine, just run this in your terminal before you start your project:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

For those of you working on Windows, you'll want to use the command prompt syntax instead:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

If you want to make this fix permanent so you don't have to type it every time, you can edit your package.json file. Just update your scripts section to inject the variable automatically whenever you run your build or start commands, like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To keep this from biting you again, my biggest piece of advice is to start using a version manager like nvm (Node Version Manager) or fnm. It lets you switch between different Node versions in seconds, so if you're working on a legacy project that needs Node 14 or 16, you can just flip a switch instead of fighting your global installation.

Hope this saves you the headache it caused me! Happy coding and good luck getting that project running.

救命，Node.js 升級後 React 專案直接噴出「digital envelope routines」錯誤！

來源：Stack Overflow ↗ · 2572 票

那天下午我正準備趕工一個新專案，剛從 IntelliJ IDEA 建好預設的 React 環境，手癢順手把 Node.js 更新到了 v17 以上的版本。結果按下 npm start 的那一刻，終端機直接跳出一長串紅字，那個 error:0308010C:digital envelope routines::unsupported 簡直像在嘲笑我的無知。我當時真的差點崩潰，心想：「我什麼都沒改啊，為什麼連開個專案都會炸掉？」

其實這個錯誤之所以會發生，是因為 Node.js v17 之後引進了 OpenSSL 3.0，這個新版本對於加密演算法的安全性要求變高了，把一些舊的、不夠安全的演算法給擋掉了。而我們常用的 Webpack 4 或者一些舊版的套件，偏偏就很依賴這些被棄用的演算法，所以兩邊一碰頭，編譯器就直接罷工。最痛苦的時刻莫過於我當時還以為是專案路徑有問題，在那邊瘋狂刪除 node_modules 又重新 npm install 了三次，看著螢幕跑了半小時的進度條卻依然跳出一樣的錯誤，那種無力感真的讓人想直接關機下班。

後來我查了一下才知道這根本不是程式碼的問題，而是執行環境的相容性。最快也最無腦的解決方法，就是告訴 Node.js 說：「拜託，先幫我啟用舊版的演算法支援吧！」你只需要在啟動專案的指令前面加上環境變數設定。如果你是 Windows 使用者，可以在 package.json 的 scripts 區塊把 start 改成這樣：


"scripts": {
  "start": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

如果是 Mac 或 Linux 的使用者，記得指令要改成 export 的語法：


"scripts": {
  "start": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

改完之後再執行一次，看到熟悉的編譯成功畫面，真的會有一種想流淚的感動。

為了避免以後再踩到這種坑，我現在養成了一個好習慣，就是專案開發環境盡量跟生產環境（Production）保持一致。如果你跟我一樣是個愛嘗鮮、喜歡用最新版 Node.js 的人，強烈建議裝一個 nvm (Node Version Manager)。這樣當你接到舊專案時，可以直接切換回比較穩定的 v14 或 v16 版本，完全不需要去改環境變數，省事又省心，也不會讓你的專案結構變得奇奇怪怪。

搞定這些之後，終於可以安心去喝杯咖啡，繼續面對接下來的 debug 地獄了。希望這篇筆記能救到正在螢幕前崩潰的你！
