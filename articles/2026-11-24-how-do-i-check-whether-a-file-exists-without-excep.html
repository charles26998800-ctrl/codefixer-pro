How to Check If a File Exists in Python Without Using Try-Except Blocks

Source: Stack Overflow ↗ · 7352 votes

Early in my career, I remember staring at a script I’d written to process batch logs, convinced it was bulletproof. I’d wrapped every I/O operation in a massive try-except block because I thought it was the "correct" way to handle missing files, but the code became an unreadable mess of nested logic. I spent three hours refactoring that disaster only to realize I was over-engineering a simple file existence check, making my logs harder to parse and my code harder to maintain.

The reason so many of us fall into the trap of over-using exception handling for flow control is that Python embraces the "Easier to Ask for Forgiveness than Permission" (EAFP) philosophy. While EAFP is idiomatic, it isn't always the cleanest approach if you're just doing a quick check before a conditional branch. Sometimes, you just want to know if the file is sitting there on the disk without triggering a full-blown stack trace if it isn't. When you rely on try-except for simple existence checks, you end up cluttering your logic with overhead that makes the actual purpose of your function invisible.

To handle this cleanly, I’ve moved away from os.path.exists in favor of the modern pathlib library. It’s built into Python 3 and feels much more like an object-oriented part of the language. If I’m writing a utility script and I need to verify a path, I’ll use the .exists() method on a Path object. It’s clean, readable, and avoids the mess of catching FileNotFoundError just to perform a basic gatekeeping check.


from pathlib import Path

file_path = Path("config.yaml")

if file_path.exists():
    print("File found! Proceeding with data processing.")
else:
    print("File missing, skipping this step.")

If you’re stuck on a legacy codebase that hasn’t adopted pathlib yet, the os.path module is the classic way to go. I still use this when I'm hacking together quick shell-like scripts where I don't want to import extra classes. It gets the job done without any exceptions flying around, keeping your logic linear and easy to follow.


import os

if os.path.exists("data.csv"):
    # Do your work here
    pass

The best way to prevent these kinds of headaches is to keep your file checks separate from your actual file operations. You should always treat existence checks as a "hint" rather than a guarantee. Remember, just because a file exists when you check it doesn't mean another process won't delete it a millisecond later. Even if you use these non-exception checks, always keep your actual read/write operations wrapped in a minimal try-except block to handle permission errors or sudden network drops, because the disk is a fickle beast that will always find a way to surprise you.

Hope this saves you some of the time I wasted back in the day. Happy coding!

Python 檢查檔案是否存在：別再亂用 try-except 了！

來源：Stack Overflow ↗ · 7352 票

還記得剛入行那年，我正在趕一個自動化部署腳本，當時為了處理設定檔是否存在，直接寫了一整串的 try-except 包在迴圈外面，結果程式跑一半因為路徑權限問題噴出各種非預期的錯誤，我盯著那堆 traceback 看了一個下午，差點沒在辦公室崩潰。那時候我就在想，難道檢查一個檔案還得先試著打開它嗎？這種「先試試看，不行再補救」的邏輯，簡直就是災難的開始。

其實會發生這種困擾，是因為 Python 傳統的 os.path 模組設計比較古早，很多人習慣用 os.path.exists()，但這傢伙在面對權限問題或是符號連結時，行為有時候會讓人一頭霧水。而且很多新手（包括當年的我）會習慣性地用 try...except IOError 來測試檔案，這其實很不乾淨，因為你把「檢查檔案」和「處理檔案存取錯誤」這兩件事混在一起了，程式碼看起來又臭又長，根本看不出核心邏輯在哪裡。

後來我學乖了，現代 Python 開發最推薦的做法是直接擁抱 pathlib 模組。這東西簡直是救星，它把路徑當作物件來處理，語法優雅到不行。如果你只是想確認檔案在不在，根本不需要搞什麼例外捕捉，直接用 exists() 方法就搞定。


from pathlib import Path

file_path = Path('config.json')

if file_path.exists():
    print("檔案在這，趕快開工！")
else:
    print("檔案搞丟了，先去泡杯咖啡再說。")

如果你是在開發比較嚴謹的系統，還可以進一步用 is_file() 來確保它真的是個檔案，而不是一個剛好同名的資料夾。對我這種有強迫症的工程師來說，這行程式碼不僅乾淨，讀起來也像是英文句子一樣流暢。

至於怎麼預防這種問題再次發生？我的建議是，別再把檢查檔案這件事當成「例外狀況」來處理。很多時候我們寫 try-except 是為了防禦性程式設計，但如果你的邏輯是「這檔案如果不存在，我就要跑另一套流程」，那這就屬於正常的流程控制，不該用例外處理。養成習慣，在處理檔案路徑時優先考慮使用 pathlib，它會幫你省下很多除錯的時間，也能讓你的同事在看你 code 時覺得你其實還挺專業的。
