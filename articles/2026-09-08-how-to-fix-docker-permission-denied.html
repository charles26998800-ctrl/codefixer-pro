How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1419 votes

I still remember the first time I set up a fresh Ubuntu box for a side project. I was feeling pretty productive, had my coffee ready, and fired off a docker run command only to be hit with that soul-crushing "permission denied" error. I spent a good hour convinced I had somehow corrupted my entire Docker installation, frantically reinstalling packages and restarting the service before I realized it was just a simple permissions issue that I’d faced a dozen times before.

The reason you’re running into this is actually quite straightforward: the Docker daemon binds to a Unix socket rather than a TCP port by default. Because that socket is owned by the root user, you need elevated privileges to talk to it. Unless you specifically add your user account to the docker group, you’re forced to prefix every single command with sudo. It’s a security feature meant to keep unauthorized users from having root-level access to your containers, but man, it gets old fast when you're trying to iterate quickly.

To fix this for good, I always just add my current user to the docker group. First, you need to make sure the group exists by running sudo groupadd docker. Once that's set, you add your user to it with sudo usermod -aG docker $USER. The most important step that people usually skip—and the one that cost me half an hour of debugging once—is that these changes don't take effect immediately. You either need to log out and log back in, or run newgrp docker in your current terminal session to refresh your group membership. After that, you can run docker run hello-world without sudo and everything should just work.

If you want to avoid this headache in the future, just make it part of your standard setup script for new machines. Whenever I provision a new environment, I include the group addition command in my bootstrap bash script. It keeps my workflow clean and prevents those annoying "permission denied" interruptions from breaking my flow later on.

Hope this saves you some time so you can get back to building cool stuff. Catch you later!

為什麼執行 Docker 指令總是要加 sudo？教你優雅解決 Permission denied

來源：Stack Overflow ↗ · 1419 票

剛開始學 Docker 的時候，我真的被這個 permission denied 搞到快崩潰。記得那天我正準備測試一個新專案，信心滿滿地敲下 docker run hello-world，結果螢幕直接噴出一大串紅字，說什麼無法連接到 /var/run/docker.sock。當下我心想：「我不是剛剛才安裝好嗎？難道是安裝壞了？」最慘的是，為了趕進度，我那幾天執行任何指令都乖乖加上 sudo，結果後來因為權限控管太亂，搞得我還要花時間去修復那些被 sudo 建立出來的 root 權限檔案，真的是搬石頭砸自己的腳，那種「明明裝好了卻不能用」的無力感，相信很多人都懂。

其實這個問題的原因很單純，Docker 的守護行程（daemon）預設是以 root 權限在跑的，而 /var/run/docker.sock 這個檔案的權限剛好也只有 root 或 docker 群組可以存取。如果你不是 root，又不在 docker 群組裡，系統當然會把你擋在門外。這就像是這棟大樓的門禁系統，你沒有那張專屬的感應卡（權限），警衛當然不讓你進去，這也是為什麼加了 sudo 就能過，因為 sudo 直接讓你變成了管理員。

要解決這個問題，其實只要把你目前的帳號加入到 docker 這個系統群組就好。首先，你可以先執行 sudo groupadd docker 確保群組存在，接著用 sudo usermod -aG docker $USER 把自己加進去。搞定之後，最關鍵的一步來了：你必須登出再重新登入，或者直接執行 newgrp docker，讓系統刷新你目前的群組權限。你可以試著打 docker run hello-world 看看，如果沒出現報錯，恭喜你，終於擺脫每次都要打 sudo 的惡夢了。

至於要怎麼預防下次再踩雷？其實養成習慣很重要。每當你在新環境安裝 Docker 後，第一件事就是把自己的帳號加入 docker 群組，這應該要變成你設定開發環境的標準 SOP。另外，平常沒事也盡量避免用 sudo 去跑 Docker 容器，這樣可以減少很多後續檔案權限錯亂的麻煩。

希望這篇筆記能幫你省下不少除錯時間，之後碰到這種紅字就不用再在那邊懷疑人生啦！
