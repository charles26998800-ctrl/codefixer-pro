How to Check if a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7352 votes

Back when I was just starting out as a junior dev, I remember cluttering up my codebase with massive try-except blocks just to see if a configuration file existed before reading it. I actually spent about three hours one afternoon debugging a script that was failing because I hadn't realized that FileNotFoundError was being swallowed by a generic exception handler I’d written in my sleep-deprived state. It was one of those classic "why is my code doing nothing?" moments that makes you want to throw your laptop out the window, but it taught me that there's a much cleaner way to handle file checks.

The reason most beginners run into this is that Python’s philosophy is often "Easier to Ask for Forgiveness than Permission" (EAFP), which encourages using try-except blocks. However, when you're writing scripts where file existence is a standard logical check rather than an edge case, wrapping everything in exception handling can make your code look like a plate of spaghetti. You end up with deeply nested logic that’s hard to follow, and honestly, sometimes you just want a simple boolean check to decide whether to skip a process or prompt the user for input.

When I need to check for a file without the overhead of exceptions, I rely on the pathlib module. It’s been part of the standard library since Python 3.4, and it’s significantly more readable than the older os.path methods. Here is how I handle it in my projects:


from pathlib import Path

config_file = Path("settings.json")

if config_file.is_file():
    print("File exists, proceeding with load.")
else:
    print("File missing, skipping.")

If you’re working on a legacy system or just prefer the classic approach, the os.path module still works perfectly fine. Most engineers I work with still keep this in their back pocket for quick one-liners:


import os

if os.path.exists("settings.json"):
    # Do your thing
    pass

One thing to keep in mind is the "Time of Check to Time of Use" (TOCTOU) race condition. Even if is_file() returns True, another process could delete that file a millisecond later before your script actually opens it. To prevent this, I always make sure that even if I check for existence first, I still wrap the final open() call in a minimal try-except block. It’s the safest way to ensure your code doesn't crash if the file disappears right under your nose.

Hope this saves you some of the headache I dealt with back in the day. Happy coding, and don't let those file paths get the best of you!

別再用 try-except 檢查檔案了：Python 檢查路徑的優雅寫法

來源：Stack Overflow ↗ · 7352 票

當年我剛接手一個處理大量日誌文件的舊專案時，為了檢查檔案是否存在，寫了一大堆 try...except IOError 的區塊，結果程式碼簡直像被亂碼轟炸過一樣，醜到我自己都不敢看。最慘的一次是，因為我把錯誤處理寫得太籠統，導致檔案權限不足的錯誤也被吃掉，程式直接跑出毫無意義的結果，我花了一整個週末加班除錯，差點沒在辦公室崩潰。那時候我就在想，難道 Python 就不能給我們一個優雅一點、不用在那邊窮舉例外狀況的檢查方式嗎？

其實這背後的問題在於，很多人（包含當年的我）習慣了「請求原諒比請求許可更容易」（EAFP）的 Python 哲學，但在檢查檔案是否存在這種情境下，一直觸發 Exception 其實既消耗效能又讓程式邏輯變得支離破碎。當你只是想知道路徑對不對時，強迫程式跑進例外處理流程，就像是為了確認門有沒有鎖，卻每次都直接把門撞開一樣，既暴力又不必要，還容易掩蓋掉真正嚴重的系統錯誤。

後來我學乖了，直接改用 pathlib 模組，這簡直是救贖。這個模組在 Python 3.4 就引進了，它把路徑當作物件來操作，寫起來非常直覺。如果你只是想確認檔案在不在，用 .exists() 就好。這不僅讓程式碼乾淨很多，也不會因為丟出 Exception 而導致效能損耗。如果是要確認那個路徑是否真的是個「檔案」（而不是資料夾），那就加個 .is_file()。


from pathlib import Path

file_path = Path('my_data.txt')

if file_path.is_file():
    print("檔案存在，可以開工了！")
else:
    print("找不到檔案，先去喝杯咖啡冷靜一下吧。")

如果要預防這種「檔案檢查地獄」再次發生，我強烈建議大家在寫這類涉及檔案系統的操作時，儘早養成使用 pathlib 的習慣。不要再把那些 os.path.exists 的舊寫法當作聖經了，那樣寫真的很容易讓你的程式碼長得像上個世紀的產物。另外，記得在開發時多思考一下「競爭條件」（Race Condition）的問題，就算你檢查檔案存在，下一毫秒它還是可能被別的執行緒刪掉，所以寫程式時心態要放寬，核心業務邏輯還是要保留適度的防禦性設計。

反正寫程式就是不斷踩坑再填坑，換個寫法就能少掉一堆頭痛的例外處理，何樂而不為呢？
