How to Check If a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7352 votes

Back when I was still cutting my teeth on Python scripts for automated deployments, I remember writing a cleanup utility that kept crashing because of a missing log file. I spent three hours debugging a FileNotFoundError loop, only to realize I was trying to read files that didn't exist yet, and my try-except blocks were making the code look like a giant bowl of spaghetti. I eventually realized there had to be a cleaner, more idiomatic way to handle file checks without wrapping every single operation in bulky exception handling.

The reason this feels like such a hurdle is that Python usually follows the "Easier to Ask for Forgiveness than Permission" (EAFP) philosophy. By design, Python developers prefer using try-except blocks because they’re safer in concurrent environments where a file might vanish in the nanosecond between you checking for it and you actually opening it. However, when you’re just writing simple scripts or CLI tools, you don't always need that level of architectural overhead. Sometimes, you just want a quick, clean boolean check to decide whether or not to proceed with a specific task.

When I need to check for a file without the ceremony of an exception block, I reach for the pathlib module. It’s the modern, object-oriented way to handle filesystem paths in Python, and it’s been part of the standard library since version 3.4. Instead of importing os.path and dealing with clunky string manipulations, you just create a Path object and call the exists() method.


from pathlib import Path

file_path = Path("my_config.json")

if file_path.exists():
    print("The file exists, let's load it.")
else:
    print("File not found, skipping.")

If you’re working on a legacy codebase that’s stuck in the past, or you just prefer the classic functional approach, you can still use the os.path module. It does the exact same job, though it feels a bit more dated. You’ll use os.path.isfile() for this, which is specifically designed to return True only if the path points to a file (and not a directory).


import os

if os.path.isfile("my_config.json"):
    print("Found it!")

To prevent these kinds of headaches in the future, my biggest piece of advice is to stop using string-based paths entirely. If you stick to pathlib.Path objects throughout your entire project, you avoid all those annoying slash-direction bugs and you get a much more readable API that makes these existence checks feel like a natural part of your logic rather than a hacky workaround.

Hope this saves you some of the frustration I went through when I was first starting out. Happy coding!

別再濫用 try-except 了！優雅檢查 Python 檔案是否存在的小技巧

來源：Stack Overflow ↗ · 7352 票

記得剛入行那會兒，我在寫一個處理大量日誌檔的腳本，心想「這簡單啊，不就是讀檔嗎？」，結果程式跑不到一半直接噴出 FileNotFoundError，整個服務當場掛掉。那時候我真的是氣到差點要把鍵盤摔了，因為我為了省事，把所有邏輯都包在一個巨大的 try-except 裡，結果根本不知道到底是哪個檔案漏了還是路徑寫錯，除錯過程簡直像是在玩躲貓貓，痛苦到讓我懷疑人生。

其實，很多人會覺得檢查檔案存不存在非得用 try-except 不可，是因為我們被過去的程式設計思維給制約了。在 Python 裡，這種寫法雖然可行，但如果你的程式邏輯裡充斥著大量的例外處理，反而會讓程式變得又臭又長，甚至掩蓋掉真正嚴重的錯誤。最尷尬的時刻，莫過於你以為檢查了檔案，結果因為權限不足或是剛好有 Race Condition（競爭條件），檔案在檢查完到讀取的那一毫秒間消失了，這時候就算用了 try 還是會崩潰，那種挫折感真的會讓人想下班回家打電動。

後來我學乖了，其實 Python 內建的 pathlib 模組根本就是救星。我現在都習慣用 pathlib.Path 物件來處理路徑，它提供了一個超級直觀的 .exists() 方法，寫起來乾淨又優雅。比起以前那種混亂的寫法，現在我的程式碼看起來清爽多了：


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.exists():
    print("檔案還在，可以安心工作！")
else:
    print("檔案不見了，先跳過這個任務吧。")

如果你是在處理比較舊的專案，或者習慣用 os 模組，其實用 os.path.isfile() 也是一樣的效果。但我還是強烈建議大家全面轉向 pathlib，因為它處理路徑的方式更貼近現代程式開發的思維。

為了避免以後再踩到這種坑，我現在養成一個習慣：絕對不要把「預期會發生」的邏輯塞進 try-except 裡。檢查檔案是否存在應該視為一種流程控制，而不是異常處理。如果我發現自己對同一個檔案要做多次檢查，我就會把路徑先定義成一個變數，甚至寫個小函式來管理，這樣萬一哪天路徑格式變了，我只需要改一個地方，不用在那邊對著幾百行程式碼發呆。

好了，今天就分享到這，希望這些小撇步能拯救你的專案，少掉幾根頭髮！趕快去試試看，你會發現程式碼真的會變漂亮喔。
