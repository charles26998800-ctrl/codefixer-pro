How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2573 votes

I remember exactly where I was when this error first hit my terminal—it was a late Tuesday night, and I had just initialized a fresh React project to prototype a simple dashboard. I stared at the screen for two hours, convinced that my local environment was haunted or that I’d somehow broken my entire Node installation, only to realize I’d just upgraded Node to version 17 without checking the compatibility notes. I felt like a complete amateur, but it turns out I was just one of thousands of developers blindsided by this exact same update.

The reason you’re seeing this cryptic error is actually quite simple, even if it feels like your machine is throwing a tantrum. When Node.js bumped up to version 17 and beyond, they switched to OpenSSL 3.0, which enforces stricter security standards for hashing algorithms. Many older packages and build tools—like the version of Webpack used in standard React templates—still rely on older, less secure algorithms like MD4. Since your new version of Node refuses to use these outdated methods, it throws the "digital envelope routines::unsupported" error as a way of saying it doesn't trust the tools trying to run your build.

Fixing this is luckily straightforward, and you don’t need to downgrade your entire Node environment to get back to coding. The quickest way to resolve this is to tell Node to allow those legacy algorithms by setting an environment variable called NODE_OPTIONS. If you’re on a Mac or Linux machine, you can patch this in your terminal by running the following command before starting your development server:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax changes slightly. You’ll want to use set instead of export in your command prompt:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

For those of you who don’t want to type that out every time you spin up your project, you can permanently add this to your package.json file. Just modify your scripts section so that the start command looks something like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

Moving forward, the best way to prevent these headaches is to get comfortable with using a version manager like nvm (Node Version Manager). Instead of letting a global Node update break every project on your machine, you can use nvm to switch between specific versions on a per-project basis. If you keep your older projects on a stable LTS version like 14 or 16, you’ll avoid these breaking changes entirely until you’re actually ready to upgrade your dependencies.

Hope this saves you the hours of frustration I went through! Happy coding and try to get some sleep.

救命！遇到「digital envelope routines::unsupported」錯誤，別再重灌 Node.js 了！

來源：Stack Overflow ↗ · 2573 票

那天我為了趕一個專案的 Demo，想說用 IntelliJ IDEA 快速起一個 React 專案，結果 npm start 一按下去，終端機直接噴出一大串紅字，那個 error:0308010C:digital envelope routines::unsupported 簡直像是在嘲笑我。我當下心裡真的罵了好幾句髒話，心想：「我明明只是想開個專案，為什麼連第一步都過不去？」那種滿懷熱血準備寫 Code，卻在起跑點就因為環境問題卡住的無力感，真的是工程師最痛的瞬間之一。

其實這個問題會發生，是因為我當時電腦裡的 Node.js 版本太新了。Node.js 在 v17 版本之後，預設使用 OpenSSL 3.0，而一些舊版的 Webpack 或者 React 腳本依賴的是比較舊的加密演算法，這兩者根本「雞同鴨講」。簡單來說，就是 Node.js 升級了加密機制，但我們用的舊版開發工具還沒跟上，導致系統覺得這些加密行為「不安全」而不給過。

當下我查了半天，終於找到最快解決這場惡夢的方法，那就是強制讓 Node.js 降級回去使用舊的 OpenSSL 模式。如果你是 macOS 或 Linux 使用者，只要在執行指令前加上環境變數設定就好，像這樣：


export NODE_OPTIONS=--openssl-legacy-provider
npm start

如果你是用 Windows 的 PowerShell，指令則是：


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

這樣改完再執行，原本那串嚇人的紅字就會消失，專案也能順利跑起來了。如果你不想每次都手動輸入，直接把這段加到 package.json 的 scripts 區塊裡，把 "start": "react-scripts start" 改成 "start": "react-scripts --openssl-legacy-provider start" 也是一樣的效果。

至於怎麼預防這種鬼打牆？其實最好的方法就是「統一戰線」。我強烈建議大家在開發專案時，一定要在根目錄放一個 .nvmrc 檔案，並且強迫團隊成員都使用 nvm (Node Version Manager) 來管理版本。這樣當你要維護一個比較舊的專案時，只要進到目錄打個 nvm use，就能確保你的 Node 版本跟專案設定是一樣的，就不會再遇到這種因為升級版本而導致的無妄之災啦。

搞定這個之後，終於可以安心喝杯咖啡繼續寫 Code 了，祝大家的終端機都能一路綠燈！
