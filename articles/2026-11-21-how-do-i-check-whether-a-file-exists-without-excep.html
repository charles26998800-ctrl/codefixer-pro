How to Check If a File Exists in Python Without Using Try-Except Blocks

Source: Stack Overflow ↗ · 7352 votes

Back when I was a junior dev building my first automated log-rotation script, I was obsessed with keeping my code "clean" and avoiding try-except blocks at all costs. I spent three hours one night fighting with a script that kept crashing because I was trying to read a config file that hadn't been generated yet, and I stubbornly refused to wrap it in an exception handler because I thought it was "lazy." I eventually realized that there are cleaner, more idiomatic ways to handle file existence checks without turning my codebase into a nested mess of error handling.

The root cause of this common headache is simply that Python is designed to be an "ask for forgiveness, not permission" language. Usually, the developers behind Python want you to just try to open the file and handle the failure if it doesn't exist. However, when you’re writing scripts where you need to branch logic based on file presence—like checking if a backup file exists before initiating a transfer—using a try-except block for basic flow control feels overkill. It makes your code harder to read and honestly, it’s just noisy when all you want is a simple boolean true or false.

The way I handle this now is by using the pathlib module, which has been the standard way to interact with the filesystem since Python 3.4. It’s elegant, object-oriented, and makes the code read almost like English. Instead of importing the old os.path library, I just instantiate a Path object and call the .exists() method. It’s incredibly straightforward and saves me from writing unnecessary boilerplate.


from pathlib import Path

file_path = Path("config.json")

if file_path.exists():
    print("The file is there, let's process it.")
else:
    print("File not found, skipping.")

If you’re working on a legacy project or just happen to be stuck with os.path, you can still get the job done easily with os.path.exists(). It works similarly, though it doesn't feel as modern as the pathlib approach.


import os

if os.path.exists("config.json"):
    print("File exists!")

The best way to prevent this from becoming a race condition in your production apps is to remember that these checks are just snapshots in time. Even if path.exists() returns True, another process could delete that file a millisecond later before you actually open it. If you’re building something mission-critical, don't rely solely on a check-then-act pattern. Always keep your actual file operations inside a try-except block anyway to catch those "file disappeared" edge cases, even if you used an existence check for your initial logic flow.

Hope this saves you some of the headache I dealt with back in the day. Happy coding!

Python 檢查檔案是否存在，真的非得用 try-except 嗎？

來源：Stack Overflow ↗ · 7352 票

記得剛轉職沒多久，那時候寫的一個自動化腳本因為讀取不到設定檔，整天在那邊噴 FileNotFoundError，當時為了圖快，我直接在程式碼裡塞了一大堆 try-except。結果後來專案越來越大，到處都是這種錯誤處理區塊，程式邏輯亂到我連自己寫了什麼都看不懂，簡直是要崩潰，那時候真的覺得寫程式怎麼可以這麼痛苦，像是在挖一個永遠填不平的坑。

其實新手或剛從其他語言轉過來的人，都很容易陷入這個思維陷阱。在 Python 的哲學裡，大家常說「求原諒比求允許容易」（EAFP），但這不代表我們隨時隨地都要用 try-except。當我們只是想單純確認一個路徑是不是真的有東西時，硬寫錯誤處理反而會讓邏輯變得很累贅，特別是當你只是想根據檔案狀態做個簡單的 if-else 分支時，那些錯誤捕捉語句簡直就是雜訊。

後來我學乖了，其實 Python 的 pathlib 模組根本是現代工程師的救星。以前我們還在用舊版的 os.path，雖然能用，但寫起來總覺得有點過時。現在我強烈建議直接擁抱 pathlib，它的語法非常直觀，寫出來的程式碼就像在讀英文句子一樣。你只需要引入這個模組，接著建立一個 Path 物件，然後呼叫 .exists() 就行了，完全不需要處理任何異常。


from pathlib import Path

file_path = Path("config.yaml")

if file_path.exists():
    print("檔案還在，繼續工作！")
else:
    print("檔案不見了，趕快去檢查伺服器！")

如果你是因為習慣舊版 Python 而一直堅持用 os.path，那其實 os.path.exists() 也能達成一樣的效果，只是寫起來沒那麼優雅而已。我個人是覺得既然都 2024 年了，還是用 pathlib 比較能跟上現代開發的節奏。

為了避免以後再因為這種「檔案憑空消失」的問題搞到心力交瘁，我現在的習慣是，在處理檔案路徑時，一律會先用 pathlib 做檢查，並且把路徑定義成常數或設定檔，不要讓路徑字串散落在程式碼的各個角落。如果你發現你的腳本常常在找檔案，不如把這些檢查邏輯封裝成一個小函式，這樣下次改需求的時候，你只需要改一個地方，不用在那邊大海撈針。

寫程式嘛，能讓自己少掉幾根頭髮的方法就是好方法，祝你們的腳本都能跑得順順利利！
