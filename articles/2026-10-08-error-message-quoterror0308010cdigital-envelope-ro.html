How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I remember the exact moment I first saw this error. I had just spun up a fresh project in IntelliJ, ready to start hacking away on a new feature, only to have the terminal blow up in my face with a wall of red text. I spent a good three hours convinced I’d somehow corrupted my entire Node environment, frantically reinstalling packages and questioning my life choices before realizing it was just a simple version mismatch.

This headache happens because of a change in OpenSSL 3.0, which is included in Node.js version 17 and higher. Basically, the older Webpack versions used in many React scaffolding tools rely on an older hashing algorithm that OpenSSL now considers insecure. When your code tries to run that legacy hash function, Node essentially puts its foot down and throws the digital envelope routines::unsupported error. It’s not that your code is broken; it’s that your Node version is just a bit too new for the aging dependencies in your project.

The quickest way I’ve found to squash this bug without having to rewrite your entire dependency tree is by telling Node to use the legacy OpenSSL provider. You can fix this globally for your current terminal session by setting an environment variable before you run your start script. If you’re on macOS or Linux, just run this in your terminal:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is slightly different, but the goal is the same. You’ll want to run this in your command prompt:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

If you want to make this change stick so you don't have to type it every time, you can modify the "scripts" section inside your package.json file. Just update your start script to inject that variable automatically:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To keep this from biting you again, my best advice is to keep your project dependencies updated. Tools like npm-check-updates are lifesavers here. If you keep your react-scripts package current, you’ll eventually move to a version that drops the legacy hashing requirements altogether, meaning you won’t have to rely on these workarounds anymore.

Hope this saves you from the same headache I had! Happy coding, and may your terminal stay green.

救命！React 專案突然報錯：Error: error:0308010C:digital envelope routines::unsupported

來源：Stack Overflow ↗ · 2572 票

記得那天晚上，我正準備趕在 Dead-line 前把一個舊的 React 專案跑起來，結果終端機剛按下 npm start，螢幕上就噴出一長串紅通通的錯誤訊息，寫著什麼 digital envelope routines::unsupported。我當時整個人直接傻掉，心想：「我什麼都沒改啊，昨天不是還好好的嗎？」那種「專案明明沒壞，卻因為環境更新而瞬間原地爆炸」的無力感，真的是每個工程師的噩夢，差點就讓我直接合上筆電去睡覺了。

其實會發生這種鳥事，罪魁禍首就是 Node.js 的版本更新。簡單來說，Node.js 在 v17 之後升級了底層的 OpenSSL 版本，換成了 OpenSSL 3.0，這傢伙對於安全性檢查變得嚴格很多。偏偏很多舊的 React 專案（特別是還在用 Webpack 4 的那種）裡面依賴的雜湊演算法比較老舊，被新版的 OpenSSL 認定為不安全，所以它就直接罷工，給你一個「不支援」的錯誤。說穿了，就是新管家嫌舊家具不合規格，直接把它丟出門外。

要解決這個問題其實不難，最快的方法就是告訴 Node.js：「嘿，別管那麼多安全檢查了，先讓我把程式跑起來吧！」我們只需要透過設定一個環境變數 NODE_OPTIONS 來繞過這個限制。如果你是用 Mac 或 Linux，直接在終端機輸入這行：


export NODE_OPTIONS=--openssl-legacy-provider

如果你是用 Windows 的 PowerShell，指令則是：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

只要設定完再重新執行 npm start，通常就能順利看到熟悉的編譯畫面了。如果你不想每次開終端機都打一遍，也可以直接把這行加到 package.json 的 scripts 區塊裡：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

為了避免下次換台電腦又被這個地雷炸到，我強烈建議大家平時開發專案時，一定要統一 Node.js 的版本。最簡單的方式就是在專案根目錄放一個 .nvmrc 檔案，寫上你目前穩定使用的 Node 版本號。這樣以後不管是你自己或是隊友，只要執行 nvm use，就能確保環境一致，再也不會因為亂升級 Node 而搞到半夜還在除錯。

搞定這個之後，終於可以安心去喝杯咖啡了，希望這招能幫你省下寶貴的頭髮！
