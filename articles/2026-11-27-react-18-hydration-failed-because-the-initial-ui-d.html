Fixing the "Hydration Failed" Error in Next.js and React 18

Source: Stack Overflow ↗ · 341 votes

I still remember the first time I saw the "Hydration failed" warning in a React 18 project. I had just finished migrating a dashboard, feeling pretty proud of my performance optimizations, when I refreshed the page and saw my console turn into a blood-red sea of errors. I spent three hours refactoring my entire state management setup before realizing the issue was actually a simple mismatch between my server-rendered HTML and the client-side browser output.

Basically, this error happens because React is a perfectionist. When you use Server-Side Rendering (SSR), Next.js generates the initial HTML on the server and sends it to the user. When that HTML hits the browser, React "hydrates" it—meaning it attaches event listeners and makes it interactive. If the HTML React generates on the client doesn't match the HTML it received from the server down to the very last tag, React throws its hands up in frustration. This usually happens when you use browser-only APIs like window or localStorage during the initial render, or when you use random values like Math.random() or dates that differ between the server and the client.

The fix I've found to be most reliable involves delaying the rendering of the problematic component until the client has mounted. By using a simple useEffect hook, you can ensure that the code causing the mismatch only runs in the browser. I usually create a small wrapper component to handle this logic so I don't have to clutter my main files. Here is the pattern I use:


import { useState, useEffect } from 'react';

const ClientOnly = ({ children }) => {
  const [hasMounted, setHasMounted] = useState(false);

  useEffect(() => {
    setHasMounted(true);
  }, []);

  if (!hasMounted) {
    return null;
  }

  return <>{children}</>;
};

export default ClientOnly;

Once you’ve got that component, you just wrap the part of your UI that depends on browser state inside it. For example, if you’re displaying a user’s local settings from localStorage, you’d wrap that component like this: . This forces React to render a blank slate on the server and then inject the actual content once the client is ready, which keeps the hydration process perfectly in sync.

The best way to prevent this in the future is to keep your render logic "pure." I always try to ensure that my components return the same output regardless of the environment. If you absolutely need browser-specific data, make it a habit to fetch that data inside a useEffect after the component mounts rather than trying to calculate it during the initial render phase. It’ll save you a lot of late-night debugging sessions.

Hope this clears up the headache for you. Happy coding, and may your console stay clean!

React 18 Hydration Error：那個讓我熬夜到凌晨兩點的「伺服器與客戶端不對盤」惡夢

來源：Stack Overflow ↗ · 341 票

記得剛升級到 React 18 那陣子，我滿心期待地想體驗 SSR 的威力，結果一打開瀏覽器控制台，整片紅通通的 "Hydration failed" 錯誤訊息直接往我臉上砸。當時我盯著螢幕，心裡想說：「我明明程式碼寫得好好的，HTML 結構也沒錯啊，到底哪裡惹到你？」最痛苦的是，這 Bug 有時候會出現、有時候又莫名消失，害我在那邊瘋狂重新整理頁面，搞得像在玩什麼抽獎遊戲一樣，心態真的差點原地崩潰。

其實這問題的根源說穿了，就是 React 的「雙重人格」衝突。在 SSR 環境下，伺服器先生成了一份靜態 HTML 傳給瀏覽器，但當瀏覽器端開始執行 JavaScript 並進行 Hydration（水合）時，React 發現瀏覽器渲染出來的 UI，跟伺服器給的那份竟然長得不一樣。這通常發生在你用了 Date.now()、隨機數 Math.random()，或是根據當前時區、瀏覽器 localStorage 這些只有客戶端才知道的資訊來渲染畫面。因為伺服器渲染時拿不到這些值，兩邊對不起來，React 就會氣到直接報錯。

我後來發現，最常見的兇手就是我在元件裡直接用了 new Date().toLocaleString() 之類的方法。要解決這個問題，最乾淨的做法就是確保「第一次渲染」時，兩邊的內容是一致的。我通常會用一個 useEffect 來處理這些「客戶端限定」的邏輯，因為 useEffect 只會在瀏覽器端執行，伺服器根本碰不到，這樣就能完美避開衝突。

如果你遇到類似的情況，試著把會變動的邏輯移到 useEffect 裡，像這樣處理：


import { useState, useEffect } from "react";

function MyComponent() {
  const [isClient, setIsClient] = useState(false);

  useEffect(() => {
    setIsClient(true);
  }, []);

  return (
    <div>
      {isClient ? new Date().toLocaleString() : "載入中..."}
    </div>
  );
}

這樣一來，伺服器渲染時會先看到「載入中...」，等瀏覽器接手後再切換成正確的時間戳記，完全避開了 Hydration mismatch 的地雷。

至於怎麼預防這種鬼東西再次出現？我的建議是平時寫元件時，養成一個「伺服器潔癖」。也就是在開發階段，刻意把瀏覽器端的某些 API（像是 window 或 localStorage）視為「禁止直接取用」的區域。只要涉及到這些東西，一律丟進 useEffect 或者 next/dynamic 的 ssr: false 模式裡處理，這能幫你省下大把除錯的時間。
