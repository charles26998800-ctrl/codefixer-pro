How to Check If a File Exists in Python Without Using Try-Except Blocks

Source: Stack Overflow ↗ · 7351 votes

Early in my career, I remember staring at a massive script I’d written to process batch logs, convinced that wrapping every single file operation in a try-except block was the height of professional coding. I ended up with so many nested blocks that my code looked like a staircase, and I spent three hours one Tuesday afternoon trying to figure out why a specific file wasn't being detected because I’d accidentally caught the wrong exception. It was a humbling reminder that sometimes, the "cleanest" looking code is actually just an unnecessary hurdle.

The reason we often reach for try-except when dealing with files is that Python encourages the "Easier to Ask for Forgiveness than Permission" (EAFP) philosophy. Usually, it’s safer to try opening a file and handle the error if it fails, because between the moment you check if a file exists and the moment you open it, a race condition could occur—the file might be deleted or moved by another process. However, if you’re just writing a simple utility script or checking for a configuration file at startup, using a try block feels like overkill. You aren't always looking for a robust, bulletproof production system; sometimes you just want to know if the file is there so you can move on with your logic.

The most modern and "Pythonic" way I’ve found to handle this is by using the pathlib module, which was introduced back in Python 3.4. It turns file paths into objects rather than just strings, which makes your code much more readable. Instead of importing os.path and dealing with clunky syntax, you can simply create a Path object and call the exists() method.


from pathlib import Path

file_path = Path("config.json")

if file_path.exists():
    print("The file is right where it should be.")
else:
    print("File not found, skipping...")

If you’re stuck on a legacy codebase and can’t use pathlib, the classic os.path.exists() method is still the gold standard. It’s what I used for years before pathlib came along, and it’s perfectly reliable for simple checks.


import os

if os.path.exists("config.json"):
    print("Found it!")

To prevent these kinds of headaches in the future, my biggest tip is to always distinguish between "checking" and "acting." If you need to perform an operation on a file, don't just check if it exists—check if it's actually a file and not a directory using is_file() from pathlib. It’s saved me from countless bugs where my script would crash because it tried to "read" a directory as if it were a plain text file.

Happy coding, and may your file paths always resolve correctly!

別再用 try-except 檢查檔案是否存在了，優雅一點吧！

來源：Stack Overflow ↗ · 7351 票

記得剛踏入 Python 世界那年，我寫了一個自動化處理報表的腳本，當時為了檢查設定檔在不在，我瘋狂地在程式碼裡塞 try-except。結果因為邏輯寫得太爛，導致整個程式跑起來像在玩踩地雷，只要稍微漏掉一個例外處理，整個腳本就直接崩潰，甚至還發生過因為檔案權限不足導致 except 沒抓到預期錯誤，最後報錯訊息亂噴一通，我盯著螢幕差點沒把鍵盤給砸了，那種「我明明寫了防護機制卻還是炸掉」的無力感，真的讓人超級崩潰。

其實這背後的原因很單純，Python 的哲學本來是「請求原諒比請求許可容易」（EAFP），但如果你只是想單純確認檔案在不在，一直用 try-except 反而會把程式邏輯搞得支離破碎，甚至掩蓋掉真正重要的錯誤。更慘的是，如果你在檢查檔案的當下，作業系統剛好發生了檔案鎖定或是權限變更，那種「檢查時存在，打開時消失」的 Race Condition 簡直是工程師的惡夢，會讓你懷疑人生。

現在我學乖了，如果只是單純要確認檔案狀態，我會推薦用 pathlib 這個現代化的模組。它處理起來乾淨俐落，寫出來的程式碼看起來也舒服多了。你可以像下面這樣寫，比起用 os.path.exists 這種老派寫法，pathlib 的物件導向風格真的優雅太多：


from pathlib import Path

file_path = Path("config.json")

if file_path.is_file():
    print("檔案乖乖躺在這裡，可以開始處理囉！")
else:
    print("找不到檔案，先別急著讀取，趕快去檢查路徑吧。")

如果要預防這種問題再次發生，我強烈建議大家別再把「檢查」跟「操作」拆成兩個步驟。很多時候，我們以為檢查完就沒事了，結果下一行程式碼執行前檔案剛好被刪除，這叫「檢查後失效」。最好的做法其實是「先操作，再處理錯誤」，或者在確保路徑正確的情況下使用 pathlib 提供的工具方法，盡量讓你的程式碼保持原子性。

反正寫程式就是這樣，少一點硬寫的邏輯，多用點現成的標準庫，日子會好過很多。希望能幫你們避開當年的那些坑，寫出更乾淨的程式碼！
