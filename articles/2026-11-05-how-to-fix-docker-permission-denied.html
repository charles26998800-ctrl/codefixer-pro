How to fix Docker: Permission denied (without sudo)

Source: Stack Overflow ↗ · 1420 votes

I remember the first time I set up Docker on a fresh Ubuntu install, feeling like a total pro until I ran my first container command. I spent a good hour convinced I’d botched the entire installation because every single command I typed resulted in that annoying "Permission denied" error unless I prefixed it with sudo. It was one of those classic "why is my computer fighting me?" moments that made me want to throw my coffee across the room.

The reason you're bumping into this is actually pretty straightforward once you look under the hood. By default, the Docker daemon binds to a Unix socket owned by the root user, not your standard user account. When you try to run a command without sudo, the Docker client tries to talk to that socket, but the system shuts the door in your face because your user isn't part of the exclusive club—the docker group—that has permission to touch that socket.

To fix this, we need to add your current user to the docker group so you can interact with the daemon without needing root privileges every time. First, you'll need to create the group if it doesn't already exist:


sudo groupadd docker

Next, add your user to that group by running this command:


sudo usermod -aG docker $USER

Once you've done that, the changes won't take effect immediately. You’ll need to either log out and log back in, or run this command to apply the new group membership to your current shell session:


newgrp docker

To verify it's working, just run docker run hello-world without the sudo prefix. If you see the "Hello from Docker!" message, you’re officially in business.

The best way to prevent this from driving you crazy in the future is to always check your group permissions immediately after installing Docker on a new machine. It’s a tiny bit of boilerplate setup that saves you from typing sudo a thousand times a day.

Hope this clears things up so you can get back to building cool stuff. Happy coding!

為什麼 Docker 老是嫌我權限不足？解決 Permission denied 的心路歷程

來源：Stack Overflow ↗ · 1420 票

剛開始學 Docker 的時候，我真的差點被這個權限問題搞到崩潰。當時我正趕著要在本地跑一個專案，好不容易把 Docker 安裝好，滿心期待地輸入 docker run hello-world，結果螢幕直接甩我一個「Permission denied」。更氣人的是，明明前面加上 sudo 就跑得動，但每次都要打密碼真的會打到懷疑人生，感覺自己就像個被系統拒之門外的邊緣人。

其實這背後的原因很單純，Docker 的守護行程（daemon）預設是用 root 權限在跑的，它會監聽 /var/run/docker.sock 這個 Socket 檔。因為這個檔案的權限設定得很嚴格，只有 root 或者屬於 docker 這個群組的使用者才有權限去跟它溝通。當我們不用 sudo 直接下指令時，系統發現你只是一般的普通使用者，當然就會直接把你擋在門外，這就是為什麼加了 sudo 就能跑的原因。

解決的方法其實很簡單，就是把你自己的帳號加進 docker 這個群組裡。首先，我會先用 sudo groupadd docker 確保這個群組存在（雖然通常安裝完就有了），接著輸入 sudo usermod -aG docker $USER 把自己塞進去。這時候千萬別急著狂按 Enter，你還需要讓系統重新讀取群組權限，最快的方法就是直接登出再登入，或者簡單粗暴地執行 newgrp docker，這樣你當前的終端機視窗就能直接生效了。你可以試試看輸入以下指令：


sudo usermod -aG docker $USER
newgrp docker

搞定之後，試著跑跑看 docker run hello-world，如果看到那串歡迎訊息，恭喜你，終於不用再忍受每次都要 sudo 的惱人操作了。

至於怎麼預防這種鬼打牆的情況？其實只要養成習慣，在安裝完 Docker 的第一時間，就把這行指令列入你的「新機設定清單」裡。以後不管換到哪台 Ubuntu，只要先確認使用者已經加入 docker 群組，基本上就不會再被權限問題卡住。

以後遇到這種權限報錯，別再傻傻地一直加 sudo 了，直接把權限設定好，開發效率絕對提升一個檔次！
