How to Check If a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7350 votes

Early in my career, I remember writing a log-parsing script that crashed unceremoniously because it tried to open a file that hadn't been generated yet. I spent three hours debugging a "File not found" error, stubbornly refusing to use a try-except block because I thought it made my code look "messy." I eventually learned that while exceptions are a powerful tool in Python, there are cleaner, more readable ways to handle existence checks when you just need a simple boolean answer.

The reason this feels like a hurdle is that Python’s philosophy is often "Easier to Ask for Forgiveness than Permission" (EAFP). This means the core language design pushes you toward just trying to open the file and catching the error if it fails. However, when you’re building simple scripts or CLI tools, you don't always want the overhead of an exception handler. Sometimes, you just need a quick check to decide whether to skip a process or prompt the user for input, and using a try-except block for basic control flow can make a simple task feel like a major architectural decision.

When I need to check for a file without the ceremony of an exception block, I reach for the pathlib module. It’s the modern, object-oriented way to handle filesystem paths in Python. Ever since it was introduced in Python 3.4, I’ve stopped using the older os.path functions because pathlib is much more intuitive. You simply create a Path object and call the .exists() method.


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.exists():
    print("The file is exactly where it should be.")
else:
    print("File not found, skipping...")

If you’re working on a legacy codebase or just prefer the classic approach, the os.path module is still perfectly valid. I used this for years before switching to pathlib. It works exactly the same way, providing a clean boolean return:


import os

if os.path.exists("my_data.txt"):
    print("Found it!")
else:
    print("Still nothing.")

If you want to ensure you're dealing with a file and not a directory—which is a common mistake that leads to bugs—make sure to use .is_file() instead of just .exists(). That little extra check has saved me from accidentally trying to "open" a folder more times than I care to admit.

To prevent these kinds of race conditions in the future, remember that checking for a file's existence is just a snapshot in time. A file could be deleted by another process the exact millisecond after your check returns True. If your application is mission-critical, checking first is good for user feedback, but you should always wrap the actual file operation in a try-except block anyway to handle those rare, unpredictable moments.

Happy coding, and I hope this saves you those three hours I lost back in the day!

別再濫用 try-except 了！檢查檔案是否存在其實有更優雅的寫法

來源：Stack Overflow ↗ · 7350 票

記得剛入行那會兒，我寫了一個自動化備份腳本，為了檢查設定檔在不在，我直接把 try-except 塞進迴圈裡。結果那個腳本跑起來慢得要命，甚至有時候因為檔案權限問題拋出例外，搞得我大半夜還在公司修 Bug，當時真的差點沒把鍵盤砸了。最痛苦的是，當程式邏輯被一大堆 try-except 包圍時，根本分不清到底是檔案真的不存在，還是程式碼哪裡寫壞了，那種「明明程式跑得動，但邏輯完全失控」的挫折感，到現在還記憶猶新。

其實我們之所以會想避開 try-except，是因為在 Python 裡，例外處理的成本並不低。如果你的程式需要頻繁檢查檔案狀態，過度使用例外處理不僅讓程式碼看起來像裹了層厚厚的棉被，還會拖慢執行效能。更重要的是，這種寫法違反了「例外應該只處理例外狀況」的原則，如果檔案不存在是我們預期內會發生的狀態，那它根本就不該算是一種「異常」。

後來我學乖了，直接改用 pathlib 這個現代化的模組。它處理路徑的方式非常直覺，只要建立一個 Path 物件，呼叫 .exists() 方法就能搞定，完全不需要寫那種又臭又長的 try 區塊。你可以像這樣寫：


from pathlib import Path

file_path = Path('config.yaml')

if file_path.exists():
    print("檔案就在這，安心服用！")
else:
    print("檔案消失了，或是你路徑打錯囉。")

如果是為了避開競態條件（Race Condition），也就是擔心檢查完檔案存在後，下一秒檔案就被別人刪掉了，這時候用 try-except 去嘗試開啟檔案反而是比較穩健的做法。但我通常建議，除非是極度高併發的環境，否則平時開發用 pathlib 就已經綽綽有餘，程式碼看起來也乾淨清爽多了。

想要預防這種寫法帶來的坑，最好的習慣就是「不要為了避開錯誤而寫程式」。在寫檢查邏輯前，先確認你的需求到底是什麼：如果只是單純確認狀態，用 pathlib 檢查就好；如果是要確保後續操作成功，那就乾脆直接嘗試操作，並處理好可能出現的 FileNotFoundError。把這兩種邏輯分開處理，你的程式碼維護起來會輕鬆非常多。

希望這些經驗能幫你省下不少除錯的時間，下次寫程式時，記得多給 pathlib 一個機會，別再讓 try-except 綁架你的邏輯囉！
