How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1420 votes

I still remember the first time I set up Docker on a fresh Ubuntu install, feeling like a total pro until I tried to run my first container without typing sudo. I spent a solid hour convinced I had somehow corrupted the installation or messed up my kernel settings, only to realize I was just fighting a standard Linux permission boundary. It’s one of those classic "welcome to Linux" moments that makes you want to throw your keyboard out the window when you're just trying to get a simple environment running.

The reason you're hitting this wall is that the Docker daemon binds to a Unix socket rather than a TCP port by default. Because that socket is owned by the root user, only users with superuser privileges—or members of the docker group—can interact with it. When you run a command without sudo, your current user account simply doesn't have the kernel-level permissions required to talk to that socket, so the daemon shuts you down with a blunt "permission denied."

To fix this, you need to add your user to the docker group, which grants you the necessary permissions to communicate with the daemon without needing root access every single time. First, you'll need to create the group if it doesn't already exist:


sudo groupadd docker

Next, add your current user to that group so the system recognizes your elevated rights:


sudo usermod -aG docker $USER

The most important part that trips everyone up is that these group changes don't take effect immediately. You have to log out and log back in, or run this command to refresh your current shell's group membership:


newgrp docker

Once you’ve done that, try running docker run hello-world again. If it prints the welcome message without needing sudo, you’re golden.

To keep your sanity, my biggest tip is to always verify your group membership after adding yourself to a new group by running the groups command in your terminal. It’s a quick sanity check that saves you from scratching your head wondering why your permissions haven't updated yet.

Hope this helps you skip the frustration and get back to shipping code! Happy containerizing!

每次都要敲 sudo 才跑得動 Docker？教你一招徹底擺脫這個惡夢

來源：Stack Overflow ↗ · 1420 票

記得我剛開始摸索 Docker 的時候，那天為了趕一個 demo，整個人心急如焚。好不容易寫好 Dockerfile，興沖沖地打下 docker run 指令，結果螢幕直接甩我一個冷冰冰的 Permission denied。當時的我心裡真的只想罵髒話，明明我就是這台電腦的最高管理員，為什麼還要一直被 sudo 限制住？最痛苦的是，每次手殘忘記加 sudo，看到那一長串錯誤訊息，真的會讓人懷疑人生，感覺自己像個被系統拒之門外的局外人。

其實這問題一點都不神祕，歸根結底就是權限控管的問題。Docker 的 Daemon 服務預設是綁定在 Unix socket (/var/run/docker.sock) 上的，而這個檔案預設只有 root 使用者才有權限存取。當你直接執行 docker 指令時，你是用一般使用者的身份去敲門，Docker 這位「守門員」當然會因為你不夠格而把你擋在門外。雖然加個 sudo 確實能讓它乖乖聽話，但長期這樣搞，不僅麻煩，還容易因為權限設定導致後續掛載目錄時出現一堆麻煩的檔案歸屬問題。

要解決這個問題，其實只要把你的使用者帳號加入到 docker 這個特殊的群組裡就好。首先，你得先建立這個群組（雖然安裝 Docker 時通常會自動建立）：

sudo groupadd docker

接著，把當前的使用者加進去：

sudo usermod -aG docker $USER

做完這步後，千萬別傻傻地直接試，因為系統還沒更新你的群組權限。你必須要先登出再登入，或者更暴力一點直接重開機，讓權限設定生效。如果不想重開，也可以用 newgrp docker 這個指令來臨時重新整理當前 Shell 的群組權限。搞定之後，試著跑跑看 docker run hello-world，如果看到那個歡迎訊息，恭喜你，終於不用再忍受那個惱人的 sudo 了。

至於要怎麼預防下次再被這種權限問題搞到心累？我的建議是，以後拿到新的開發環境或安裝完 Docker 後，第一件事就是把這行指令設成你的「安裝後檢查清單」。習慣成自然，養成把自己的使用者帳號歸位到 Docker 群組的習慣，能幫你在未來的開發路上省下不少冤枉時間。
