Solving the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the first time I hit this error. I had just spun up a fresh React project to prototype a new feature, feeling productive and ready to go, when suddenly my terminal exploded with a wall of red text ending in error:0308010C:digital envelope routines::unsupported. I spent a solid two hours convinced I’d somehow corrupted my entire Node environment, only to realize I was just caught in the middle of a major breaking change in the Node.js ecosystem.

The root of the problem is actually pretty straightforward once you peel back the layers. When Node.js bumped up to version 17 and beyond, they switched to OpenSSL 3.0 as the default. This newer version of OpenSSL is much stricter about the algorithms it allows, and it essentially deprecated the older, less secure hashing algorithms that many older Webpack configurations and React build tools rely on. Since your project is trying to use these legacy routines, Node basically throws its hands up and refuses to build, leaving you stuck with a broken dev server.

To fix this, I usually go with the most direct route: telling Node to fall back to the legacy OpenSSL provider. You can do this by setting an environment variable called NODE_OPTIONS to include --openssl-legacy-provider. If you're on a Mac or Linux machine, you can patch this in your package.json file by modifying your start script like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

If you’re working in a Windows environment, the syntax changes slightly. You’ll need to use set before the command, or better yet, just install cross-env to keep things consistent across different operating systems. You’d run npm install cross-env --save-dev and then update your scripts to look like this:


"scripts": {
  "start": "cross-env NODE_OPTIONS=--openssl-legacy-provider react-scripts start",
  "build": "cross-env NODE_OPTIONS=--openssl-legacy-provider react-scripts build"
}

Moving forward, the best way to prevent this from ruining your morning is to keep your dependencies updated. Most of the time, this error pops up because you're using an older version of react-scripts that hasn't been maintained for the newer Node environment. If you're starting a brand new project, always check that you’re pulling in the latest versions of your build tools, as they’ve long since been patched to handle OpenSSL 3.0 without needing these custom workarounds.

Hope this saves you from the same headache I had! Happy coding, and may your builds stay green today.

React 專案啟動直接噴 Error？別慌，這只是 Node.js 的版本代溝

來源：Stack Overflow ↗ · 2572 票

記得那是某個週一的早上，我剛從 GitHub 拉下一個舊的 React 專案準備修個小 bug，結果指令才剛敲下 npm start，終端機就直接賞我一長串紅通通的錯誤訊息，甚至還出現了什麼 digital envelope routines::unsupported。那一刻我真的差點崩潰，心想：「我什麼都還沒改啊，為什麼連專案都跑不起來？」當時趕著要 demo，看著那串看起來很像加密演算法出包的鬼東西，真的會懷疑人生，感覺就像是程式碼在跟我玩「誰才是老大」的遊戲。

後來我花了一點時間研究，才發現這其實不是你的程式寫壞了，而是 Node.js 在升級到 v17 以上版本時，為了安全性調整了 OpenSSL 的演算法。簡單來說，React 的一些舊版套件（特別是 Webpack 4）還在使用比較舊的加密演算法，結果新版的 Node.js 覺得這些算法不夠安全，直接把它們拒之門外。這就像是你拿著一張舊版的通行證想進新蓋的辦公大樓，結果警衛直接把你擋在門外，說這證件已經過期了。

解決方法其實意外地單純，我們只需要告訴 Node.js：「嘿，這次就先放行吧，讓那些舊的演算法先跑一下。」我們可以在啟動專案的指令前，強制加入一個環境變數。如果你是用 macOS 或 Linux，只要在 package.json 的 scripts 區塊動點手腳，把原本的 start 指令改成這樣：


"scripts": {
  "start": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

如果是 Windows 的使用者，語法會稍微不太一樣，記得用 set 來設定：


"scripts": {
  "start": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

改完存檔之後，再執行一次 npm start，你會發現原本那些討人厭的錯誤訊息全部消失，專案又乖乖跑起來了。

為了避免以後再被這種環境變數搞到心累，我現在都會養成習慣，在接手舊專案時先檢查 package.json 裡的依賴版本，如果可以的話，儘量把 Webpack 或相關的 build 工具升級到最新版，畢竟「技術債」這東西越早還越輕鬆。當然，如果你跟我一樣是個懶人，也可以考慮直接安裝 nvm（Node Version Manager），在不同專案之間切換 Node 版本，這樣也能從根本上避開這些惱人的兼容性問題。

搞定之後，終於可以去補我那杯早就冷掉的咖啡了，祝大家的終端機從此不再噴紅字！
