How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I updated Node.js to version 17 and tried to fire up a legacy project I hadn't touched in months. I was already running on my third cup of coffee, ready to knock out a quick UI change, when my terminal exploded with that cryptic error:0308010C:digital envelope routines::unsupported message. I spent three hours digging through Stack Overflow and cursing at my screen, only to realize I’d walked straight into a classic compatibility trap between my new Node environment and older build tools.

The reason this happens is actually quite straightforward once you look past the intimidating error message. When Node.js bumped up to version 17 and beyond, they upgraded the underlying OpenSSL library to version 3.0. This new version has stricter security policies regarding algorithms. Many older build tools, specifically Webpack versions used in common React templates, rely on older hashing algorithms like MD4 that OpenSSL 3.0 now deems insecure. Your terminal is basically saying, "I refuse to run this code because it uses an outdated security method," even if the code itself is perfectly fine for your local development environment.

To get around this, you have to tell Node.js to use the legacy OpenSSL provider, effectively giving it permission to use those older algorithms. If you're on a Mac or Linux machine, the quickest way to fix this is to set an environment variable right in your terminal before you run your start command. You can do this by running:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you're on Windows using Command Prompt, you'll need to use set instead of export. If you're using PowerShell, the syntax changes slightly to $env:NODE_OPTIONS = "--openssl-legacy-provider". Since I hate typing that out every single time I open a new terminal window, I usually just add it to the scripts section in my package.json file. It keeps things clean and ensures the project builds correctly every time:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

The best way to prevent this headache in the future is to keep your development environment as consistent as possible across your team. I’ve started using a .nvmrc file in the root of all my projects, which specifies exactly which version of Node.js the project expects. If you aren't using a version manager like nvm (Node Version Manager) yet, do yourself a favor and install it today. It lets you switch between Node versions in seconds, so you don't have to break your global setup just to keep an old project running.

Hope this saves you the three hours of frustration I went through. Happy coding, and may your builds always stay green!

崩潰！啟動 React 專案卻噴出 OpenSSL 錯誤：error:0308010C

來源：Stack Overflow ↗ · 2572 票

那天我正準備接手一個舊專案，想說在 IntelliJ IDEA 裡跑個 npm start 快速預覽一下，結果終端機直接跳出一長串紅字，那個 digital envelope routines::unsupported 簡直像是在對我冷笑。我當時真的差點沒把鍵盤砸了，心想：「我明明什麼都沒動，只是更新了 Node.js 版本而已，為什麼連個開發環境都跑不起來？」在那一瞬間，看著那個堆疊錯誤，我深刻體會到什麼叫做「明明環境裝好了，卻哪裡都去不了」的無力感。

其實這問題的兇手是 Node.js 17 之後的版本。簡單來說，Node.js 升級了 OpenSSL 到 3.0，這玩意兒對加密演算法的安全性要求變高了，但我們很多常用的舊版 React 腳本（特別是 Webpack 4 以前的）還在用舊的加密方式，兩邊一搭不起來，系統就直接賞你一個「我不支援」的錯誤。說穿了，就是新版本的管家嫌舊專案的鑰匙不夠安全，乾脆直接把門鎖死，讓你連開發伺服器都進不去。

我當下試了好幾種方法，最後發現最快、最不傷腦筋的解法，就是直接告訴 Node.js：「嘿，別管那麼多，先降級相容一下吧。」我們只需要在啟動指令前面加上一個環境變數設定。如果你是 Windows 使用者，直接在 package.json 的 scripts 區塊改一下：


"scripts": {
  "start": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

如果是 Mac 或 Linux 的朋友，記得把 set 換成 export，或者簡單一點，直接在指令前面加個 NODE_OPTIONS 也可以：


"scripts": {
  "start": "NODE_OPTIONS=--openssl-legacy-provider react-scripts start"
}

改完之後再跑一次 npm start，那個熟悉的瀏覽器啟動畫面就會跳出來了。

至於要怎麼預防下次再被這種環境變數搞到崩潰？我覺得最根本的方法還是定期維護專案的依賴套件。雖然我們總說「能跑就不要動」，但適度更新 react-scripts 或相關的 Webpack 設定，才能避免這種「技術債」越積越深。建議大家平常開發時，可以用 nvm (Node Version Manager) 來管理 Node 版本，這樣萬一哪天又遇到這種相容性地獄，你至少能快速切換回舊版環境救急，而不至於手忙腳亂。

希望這篇筆記能幫你省下寶貴的除錯時間，趕快去喝杯咖啡休息一下吧！
