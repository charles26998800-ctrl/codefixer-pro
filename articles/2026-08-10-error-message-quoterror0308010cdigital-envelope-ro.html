Fixing the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I pulled a fresh React project from a legacy repository, feeling confident I’d have it running in five minutes. Instead, I spent three hours staring at the console, convinced my entire Node.js installation was corrupted because of a cryptic error:0308010C:digital envelope routines::unsupported message that seemed to pop up out of thin air. I even reinstalled my OS version of Node before realizing I was just fighting a version mismatch I hadn't accounted for.

The reason you’re seeing this is actually quite simple, even if the error message makes it sound like a catastrophic failure. When Node.js bumped up to version 17, they upgraded the underlying OpenSSL library to version 3.0. This new version is significantly stricter about the algorithms it allows for hashing. If you’re working on an older React project—or using older build tools like Webpack 4—those tools often rely on older, less secure cryptographic functions that OpenSSL 3.0 now rejects by default. It's basically a "security vs. legacy compatibility" standoff, and your local environment is stuck in the middle.

To fix this, you don't need to downgrade your Node installation, which is a massive headache. You just need to tell Node to allow the legacy OpenSSL provider to run alongside the new one. The quickest way to do this is by setting an environment variable called NODE_OPTIONS. If you're on a Mac or Linux machine, you can run this command in your terminal before starting your dev server:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is a bit different. You'll want to use set in your command prompt:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

If you want a more permanent fix so you don't have to type that every time, just head over to your package.json file. You can modify your scripts section to inject that flag automatically whenever you run your start script:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

Moving forward, the best way to prevent these kinds of headaches is to keep your build dependencies updated. I’ve made it a habit to run npm outdated once a month to see which packages are falling behind. When you keep your react-scripts and Webpack versions current, you’re far less likely to run into these legacy crypto issues because the newer versions of those tools have already been updated to play nice with the latest Node.js security standards.

Hope this saves you the three hours of frustration I went through! Happy coding and good luck with the rest of your build.

又是這該死的 Node.js 版本地獄：解決 error:0308010C 錯誤

來源：Stack Overflow ↗ · 2572 票

那天早上我剛接手一個遺留已久的 React 專案，原本想說只是簡單跑個 npm start 確認環境，結果終端機直接噴出一大串紅通通的 error:0308010C:digital envelope routines::unsupported。我看著螢幕當下真的差點崩潰，想說這專案明明昨天還好好的，怎麼過了一晚就突然像中邪一樣完全跑不動，搞得我連咖啡都喝不下去了。

其實這問題的兇手就是 Node.js 的版本升級。簡單來說，Node.js 在 17 版之後升級了底層的 OpenSSL 3.0，而舊版的 Webpack（特別是 webpack 4）使用的加密演算法被新版 OpenSSL 判定為不安全或是過時了，所以直接在底層把它給擋掉。這就像你拿著一把十年前的鑰匙想去開一扇剛換過的高級電子鎖，鎖芯直接跟你說「我不認識你」，導致編譯器在處理雜湊運算時直接罷工。

我當時試過各種重裝 node_modules 的偏方，甚至想過要把整個專案拆掉重練，結果發現最直接的解法其實就是告訴 Node.js：「嘿，請你暫時放寬心，把那些舊的加密機制先放行吧。」如果你是用 macOS 或 Linux，最快的方法就是在你的終端機輸入這行指令來設定環境變數：


export NODE_OPTIONS=--openssl-legacy-provider

如果你跟我一樣是用 Windows 的 PowerShell，指令則要稍微調整一下：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

只要設定好這個環境變數，再跑一次 npm start，那個惱人的紅色錯誤就會神奇地消失了。為了不想每次開終端機都要重新打一次，建議你可以直接把它寫進 package.json 的 scripts 裡面，像這樣修改：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

至於要怎麼預防下次再被這種環境問題搞到瘋掉？我強烈建議大家一定要用 nvm (Node Version Manager) 來管理環境。每個專案在開發初期，最好都在根目錄放一個 .nvmrc 檔案，明確指定該專案該用哪個版本的 Node.js。這樣下次換電腦或是同事接手時，只要敲個 nvm use 就能確保環境一致，不用再浪費時間跟這些版本相容性的 bug 搏鬥。

希望這招能救回你的開發進度，別再被這錯誤訊息搞到懷疑人生啦！
