How to Fix "error:0308010C:digital envelope routines::unsupported" in React

Source: Stack Overflow ↗ · 2572 votes

I remember exactly where I was when I first hit this wall: I had just pulled down a legacy internal dashboard to make a quick UI tweak, and suddenly my terminal erupted in a sea of red text. I spent a solid two hours convinced I’d somehow nuked my global Node installation or that my path variables had spontaneously combusted, only to realize I was just running a newer version of Node than the project expected. It’s one of those cryptic errors that makes you feel like you’ve forgotten how to code entirely, but I promise, it’s not your fault.

The root cause is actually quite simple: it comes down to OpenSSL. When Node.js upgraded to version 17 and beyond, it started using a newer version of OpenSSL that enforces stricter security standards. Many older build tools and libraries—like the ones commonly generated by IntelliJ’s React templates or older Create React App versions—rely on legacy algorithms that OpenSSL now considers insecure. Essentially, your build tool is trying to use an old-school hash function, and Node is slamming the door in its face.

To fix this, we need to tell Node to chill out and use the legacy provider for OpenSSL. The quickest way to do this without messing with your system-wide environment variables is to set the NODE_OPTIONS environment variable right before you run your start script. If you’re on a Mac or Linux machine, you can just update your package.json file like this:


"scripts": {
  "start": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

If you’re stuck on Windows, the syntax changes slightly because of how the command prompt handles environment variables. You’ll want to use set instead of export:


"scripts": {
  "start": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

For those who want to be platform-agnostic without manually editing scripts every time, I highly recommend installing the cross-env package. You just run npm install cross-env --save-dev and update your scripts to use cross-env NODE_OPTIONS=--openssl-legacy-provider. It saves you from those "it works on my machine" moments when your teammates are on different operating systems.

To prevent this from coming back to haunt you, get into the habit of using a version manager like nvm (Node Version Manager) for all your projects. By adding an .nvmrc file to the root of your repository, you can lock the project to a specific Node version that you know is compatible with your dependencies. It keeps your environment clean and saves you from the headache of dependency mismatches when you jump between different projects.

Hope this saves you a few hours of head-scratching today. Happy coding, and may your builds stay green!

救命！React 專案噴出 error:0308010C，害我以為電腦要壞了

來源：Stack Overflow ↗ · 2572 票

那天我正準備接手一個舊的 React 專案，心想不過就是跑個 npm start，結果終端機直接賞我一串紅通通的 error:0308010C:digital envelope routines::unsupported。當下我真的差點崩潰，螢幕上一堆看不懂的加密演算法錯誤，害我懷疑是不是剛升級的 Node.js 版本跟專案犯沖，甚至一度想說乾脆把電腦重灌算了，畢竟那個當下真的覺得這專案根本啟動不了，搞得我進度嚴重落後，坐在電腦前盯著錯誤訊息發呆的那半小時，簡直是我工程師生涯最想撞牆的時刻之一。

後來冷靜下來去爬文才知道，這其實是因為 Node.js 17 版本之後，底層換成了 OpenSSL 3.0，而舊版的 Webpack（特別是那些依賴舊加密演算法的套件）根本還沒跟上這個變動。簡單來說，就是 Node.js 覺得這些舊寫法「太不安全了」所以直接拒絕執行，導致我們在跑開發伺服器時，系統直接報錯抗議。說穿了，這就是一個「新環境與舊程式碼代溝」的經典案例。

解決方法其實意外地單純，我們只要告訴 Node.js：「嘿，別管那麼多，先暫時允許使用這些舊的加密演算法吧」。最快的方式就是在終端機執行指令，把 NODE_OPTIONS 設定加上 --openssl-legacy-provider。如果你是用 Mac 或 Linux，直接在指令前面補上這一段：


export NODE_OPTIONS=--openssl-legacy-provider
npm start

如果你是用 Windows 的 PowerShell，設定方式稍微不一樣，可以這樣跑：


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

如果不想每次開專案都要打這串指令，我建議直接把它寫進 package.json 的 scripts 區塊裡。把 start 的指令改成 "start": "react-scripts --openssl-legacy-provider start"，這樣以後不管誰來跑這個專案，都不會再被這個錯誤卡住。

至於要怎麼預防這種狀況？老實說，最好的辦法就是養成「統一 Node.js 版本」的習慣。我現在都會在專案根目錄放一個 .nvmrc 檔案，並且強烈建議團隊成員使用 NVM (Node Version Manager) 來管理環境。只要每個人開發時用的 Node 版本都一致，就能避開這種因為環境升級而產生的莫名其妙的相容性地獄。

總算把這個惱人的錯誤解決掉了，希望這篇心得能幫你省下不少崩潰的時間，大家開發順利啦！
