How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I pulled a fresh React project template, ran npm start, and was greeted by a wall of red terminal text instead of my local development server. I spent a solid two hours digging through dependency trees and clearing my node_modules like a madman before I realized the issue had nothing to do with my code and everything to do with my Node.js version. It’s one of those classic "why is my environment conspiring against me?" moments that makes you want to throw your keyboard out the window.

The root cause of this headache is a mismatch between your Node.js version and the OpenSSL library used by your build tools. When Node.js upgraded to version 17, they switched to OpenSSL 3.0, which enforces stricter security standards. A lot of older webpack configurations and legacy plugins rely on algorithms that OpenSSL 3.0 considers outdated, so it throws the digital envelope routines::unsupported error as a way of saying, "I'm not touching that insecure code." It's essentially a breaking change that blindsided a massive portion of the React ecosystem overnight.

The quickest way I’ve found to resolve this—without downgrading your entire Node installation—is to tell your terminal session to use the legacy OpenSSL provider. If you're on a Mac or Linux machine, you can fix this by setting an environment variable before you run your start command. Just open your terminal in your project root and run this:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is a bit different, so you’ll want to run this in your command prompt instead:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

If you don't want to type that out every single time, you can just bake it directly into your package.json file. Find the scripts section and modify the start command to look like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

Moving forward, the best way to prevent these environment-specific gremlins is to always use a version manager like nvm (Node Version Manager). I make it a habit to check the engines field in my package.json files or keep a .nvmrc file in my project root to ensure I'm using the exact Node version the project was designed for. It saves me from these environment headaches and keeps my development workflow feeling a lot smoother.

Hope this saves you from losing as much hair as I did over it. Happy coding!

React 啟動噴出「digital envelope routines::unsupported」？別怕，這只是 Node.js 的版本代溝

來源：Stack Overflow ↗ · 2572 票

記得那是某個週一的早晨，我剛升級完電腦環境，想說把手邊的一個舊 React 專案拿出來微調一下。結果 npm start 一敲下去，終端機直接吐出一長串紅色警告，最後停在那個令人絕望的 error:0308010C:digital envelope routines::unsupported。我當下真的差點把咖啡噴出來，心想：「我不過就是升級個系統，程式碼一字未動，怎麼連啟動都沒辦法啟動了？」那種明明趕著要 demo，系統卻在這種莫名其妙的地方卡死，甚至連 Google 到的解法都看起來很像咒語的感覺，真的會讓人想直接把筆電闔上回家睡覺。

其實會發生這個問題，是因為我們用了太新的 Node.js 版本（通常是 v17 以上）。Node.js 在 v17 之後導入了 OpenSSL 3.0，這玩意兒安全性更高，但代價就是它不再支援舊版 Webpack 裡那些比較寬鬆的加密演算法。簡單來說，就是你的舊專案還在用舊時代的加密標準，而你的新版 Node.js 卻堅持要用更嚴格的規範，兩邊講話搭不上線，Webpack 就直接罷工不幹了。

解決這個問題其實比想像中簡單，最快的方法就是告訴 Node.js：「嘿，別管那麼多，先幫我把舊版的加密支援打開。」你只需要在啟動指令前面加上 NODE_OPTIONS=--openssl-legacy-provider 這個環境變數就可以了。如果你是用 npm 的話，直接修改 package.json 裡的 scripts 區塊，把原本的 start 改成這樣：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

改完之後再跑一次 npm start，通常就能順利看到熟悉的編譯進度條在跑了。如果你是在 macOS 或 Linux 環境，也可以在終端機直接輸入 export NODE_OPTIONS=--openssl-legacy-provider 來暫時解決，但為了長久之計，寫進 package.json 還是最保險的。

至於要怎麼預防下次再踩到這種坑？我強烈建議大家開始使用 nvm（Node Version Manager）這類工具。只要養成習慣，在進入每個舊專案時先用 nvm use 切換到專案當初開發時的 Node.js 版本（比如 v14 或 v16），就能完美避開這些因為版本更新帶來的相容性地獄。畢竟，與其每次遇到問題才在修補，不如一開始就給每個專案正確的「生長環境」。

希望這篇筆記能救你一命，不用再為了這行紅字浪費整個下午的寶貴時間！
