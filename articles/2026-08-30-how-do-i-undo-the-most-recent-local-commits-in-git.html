How to Undo Your Most Recent Local Git Commits Without Losing Your Mind

Source: Stack Overflow ↗ · 27237 votes

I still remember the first time I accidentally committed a massive folder of local environment logs and API keys to my main branch. I spent a good three hours sweating, convinced I’d just permanently nuked my project history or ruined the remote repo, only to realize I was making it way more complicated than it needed to be. It’s a classic rite of passage for every developer, and honestly, if you haven’t had that mini heart attack after hitting enter on a git commit, have you even really coded?

The reason this happens is usually just a simple lapse in concentration—we get into a flow state, stage everything with git add ., and commit before double-checking the status. Since Git tracks everything you do, it doesn't just "delete" the commit; it keeps the data in the background, which is why it feels so intimidating to try and roll back. You haven't actually broken anything; you’ve just created a pointer to a specific state in your history, and you just need to move that pointer back to where it belongs.

When I need to undo that last commit but keep my work in the staging area so I can fix the files, I use a soft reset. This is my go-to move because it doesn't destroy the changes I just made; it just peels the commit layer off like a sticker. You just run this command:


git reset --soft HEAD~1

If you’re like me and you realize you completely botched the files and just want to wipe the commit and the changes entirely—essentially throwing the whole thing in the trash—you use the hard reset. Be careful with this one, because it’s permanent:


git reset --hard HEAD~1

If you committed, realized your mistake, and just want to add one more file or change the commit message without creating a whole new history entry, you can use the amend flag. It’s the cleanest way to fix a sloppy commit:


git commit --amend

To keep this from happening again, I started a habit of running git status every single time before I commit. It takes three seconds, but it saves me from the headache of cleaning up my mess later. I also use a .gitignore file religiously to make sure my logs and environment variables never even get the chance to be staged in the first place.

Hopefully, this helps you get back to shipping code without the panic. Catch you on the next commit!

手殘把垃圾塞進 Git Commit 了？別怕，這招救命技巧學起來

來源：Stack Overflow ↗ · 27237 票

記得剛入行那陣子，我為了趕一個緊急的 hotfix，腦袋整個當機。在那種「只要趕快 commit 就能下班」的幻覺下，我竟然把一堆還在測試階段、甚至包含機密設定檔的垃圾檔案通通 commit 進去了！當我意識到這件事，看著終端機上顯示的 [main 1a2b3c4]，那一瞬間我的心臟真的漏跳了一拍，冷汗直接從背脊冒出來，心想：「完了，如果我不小心 push 上去，明天大概就要去人事部報到了。」

說真的，這種情況發生過一次就會記一輩子。其實會發生這種事，通常就是因為 Git 的暫存區（Staging Area）太好用了，好用到我們常常忘了執行 git status 就直接暴力 git add .。Git 的設計邏輯是把你的修改打包成一個個「紀錄點」，但如果你在打包前沒檢查好裡面的內容，這個紀錄點就會變成你揮之不去的惡夢。

既然還沒推送到遠端伺服器，這一切都還有救，重點就是 git reset 這個指令。如果你只是想把剛剛那次 commit 撤銷，並且讓那些檔案回到「還沒 commit 但還在暫存區」的狀態，你可以用：


git reset --soft HEAD~1

這行指令最溫柔，它只會把 commit 紀錄抹掉，但你剛剛修改的程式碼完全不會消失，全都在。如果你是連剛剛的 git add 都後悔了，想把檔案丟回工作目錄（變成 untracked 狀態），那就用：


git reset HEAD~1

最慘的情況是，如果你發現那些檔案根本寫得像屎一樣，連留著看都嫌礙眼，想直接讓一切回到 commit 之前的乾淨狀態，那就用這個大絕招，不過請記住，這會讓你所有的變更直接消失，請務必確認過再執行：


git reset --hard HEAD~1

經歷過好幾次「差點因為手殘被開除」的經驗後，我現在養成一個強迫症習慣：在執行 git commit 之前，一定會先跑一次 git status 檢查到底有哪些檔案在清單裡。甚至我會習慣使用 git add -p，這樣我可以一個檔案、甚至一個區塊一個區塊地檢查，確保真的要進去 commit 的東西是我心裡想的那堆程式碼，而不是一時手滑多加進去的雜物。

Git 雖然強大，但它的反悔機制確實也是工程師的好朋友，下次手滑時記得深呼吸，別急著亂砍分支就好囉！
