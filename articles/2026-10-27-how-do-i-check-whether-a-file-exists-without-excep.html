How to Check if a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7352 votes

Early in my career, I was building a log-parsing script that had to scan thousands of directories for specific configuration files. I initially wrapped every single file access in a massive try-except block because I thought it was the "Pythonic" way to handle things, but the code quickly became an unreadable, indented mess. I spent three hours debugging a race condition because I was catching the wrong exception, and by the time I fixed it, I realized my terminal output was just a sea of noise.

The reason we often want to avoid try-except for simple existence checks usually comes down to readability and performance. While Python’s philosophy often favors "Ask for forgiveness, not permission" (EAFP), there are plenty of scenarios where wrapping a simple check in a try block feels like using a sledgehammer to crack a nut. When you're just trying to verify a path exists before triggering a background process or updating a UI element, catching FileNotFoundError every single time the user hasn't uploaded a file yet just feels like overkill.

To handle this cleanly, I shifted toward using the pathlib module, which has become my go-to for filesystem operations. It’s built into the standard library and feels much more intuitive than the older os.path methods. If I want to check if a file exists, I simply create a Path object and call .exists() or .is_file(). Here is how I usually write it:


from pathlib import Path

file_path = Path("config.yaml")

if file_path.is_file():
    print("The file exists and I can proceed.")
else:
    print("File not found, skipping this step.")

If you are working on a legacy codebase or just prefer the classic approach, os.path.exists() still works perfectly fine. Just keep in mind that is_file() is often safer if you need to distinguish between a regular file and a directory. I’ve definitely had bugs where my script tried to open a folder as if it were a text file, so checking the file type specifically is a great habit to get into.

To prevent these kinds of headaches in the future, my best advice is to stop relying on existence checks as a substitute for robust error handling. Even if you check if file.exists(), the file could be deleted by another process a millisecond later. Use these checks for flow control or user feedback, but always keep a real try-except block around the actual open() call to handle those rare, inevitable permission errors or disk failures that happen when you least expect them.

Hope this helps you clean up your scripts and save some time. Happy coding!

別再用 try-except 檢查檔案了！Python 檢查檔案存在的正確姿勢

來源：Stack Overflow ↗ · 7352 票

當年我剛接手一個處理大量日誌檔的自動化專案，為了確認檔案是否存在，我寫了一堆 try-except IOError。結果某次程式跑一半，因為系統權限問題，我在檢查檔案時跳出了一堆奇怪的例外，導致整個流程崩潰，半夜被客戶電話吵醒要求修復，那種看著滿屏錯誤訊息、心裡只想著「為什麼只是想確認個檔案也要這麼累」的崩潰感，至今我都還記得。

其實會發生這種問題，是因為我們太習慣「先請求再說」的思維。在 Python 裡，如果你一直依賴 try-except 來處理這種基礎狀態檢查，程式碼會變得非常臃腫，讀起來就像是在玩躲避球，每個步驟都要防著系統會不會炸掉。更糟的是，這會讓你忽略了「檔案存在與否」其實只是檔案系統的一個狀態查詢，而不是一個嚴重的錯誤。

後來我學乖了，直接改用 pathlib 模組，這簡直是救贖。pathlib 把檔案路徑當作物件來處理，檢查檔案是否存在根本不需要什麼例外處理，只需要一個優雅的 .exists() 方法。你可以像這樣寫：


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.exists():
    print("檔案就在這裡，安心用吧！")
else:
    print("檔案找不到，別急著操作它。")

如果是要檢查它是不是真的檔案（而不是一個資料夾），用 .is_file() 會更保險。自從換成這套寫法，我的程式碼乾淨了不只一個檔次，而且再也不會因為一個小小的檔案檢查就觸發一堆莫名其妙的例外堆疊，那種寫程式的順暢感真的會讓你懷疑人生，為什麼以前要跟 try-except 糾纏那麼久。

要預防這種惱人的 bug 重演，我建議大家養成一個習慣：別把「檔案檢查」和「檔案操作」混在一起。在寫程式前，先明確區分哪些是「狀態查詢」，哪些是「業務邏輯」。像是檢查檔案是否存在、有沒有讀寫權限，這些屬於前置狀態，用 pathlib 處理就好；而真的讀取檔案內容時，再用 try-except 去捕捉那些真正不可預期的底層錯誤。這樣分開處理，你的程式邏輯會清晰很多，半夜被客戶叫醒的機率也會大幅降低。

說真的，把程式碼寫得簡潔一點，多出來的時間拿去喝杯咖啡不香嗎？下次遇到這種需求，記得試試看 pathlib，保證你用了就回不去。
