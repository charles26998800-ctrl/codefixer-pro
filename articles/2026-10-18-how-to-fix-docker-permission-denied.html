How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1420 votes

I remember the exact moment I first ran into this. It was about 2:00 AM on a Tuesday, and I was trying to spin up a quick container to test a microservice. I typed docker run hello-world, got hit with a wall of "Permission denied" errors, and stared at my screen for a good five minutes wondering why my perfectly valid command was being treated like a security threat. I spent way too long trying to chmod the socket file before I realized I was just making things worse—classic rookie mistake.

The reason you’re seeing this is actually pretty straightforward once you look at how Docker operates. When you install Docker on Ubuntu, it creates a Unix socket at /var/run/docker.sock, which is owned by the root user and the docker group. By default, your standard user account isn't part of that docker group, so when you try to talk to the Docker daemon, the kernel shuts you down immediately. You’re essentially trying to enter a restricted room without the proper security badge.

To fix this, you need to add your current user to the docker group. You don't need to reinstall anything or mess with your root permissions. First, create the docker group if it doesn't already exist, then add your user to it using the following commands:


# Create the docker group
sudo groupadd docker

# Add your user to the group
sudo usermod -aG docker $USER

Once you’ve run those, the changes won't take effect immediately because your shell session still thinks you don't have those permissions. You can either log out and log back in, or run newgrp docker in your current terminal to refresh your group membership. After that, you should be able to run docker run hello-world without needing sudo. If you’re still seeing an error, a quick reboot of your machine usually clears out any lingering session caches.

The best way to prevent this from ever ruining your workflow again is to handle it as part of your initial setup script. Whenever I provision a new dev machine, I always include that usermod command in my setup.sh file so I never have to deal with these permission headaches on a fresh install. It’s a small step that saves you a massive headache later on.

Hope this gets you back to shipping code without the sudo friction. Happy containerizing!

被 Docker 權限問題搞到崩潰？其實只要一行指令就能解決

來源：Stack Overflow ↗ · 1420 票

記得剛開始學 Docker 的時候，我滿心期待地想把專案跑起來，結果每次打完 docker run 得到的永遠是那句冷冰冰的 permission denied。當時我真的差點崩潰，心想「明明我都裝好了，為什麼連個 hello-world 都跑不動？」，甚至一度懷疑是不是安裝過程出了什麼奇怪的 bug，搞得我連續兩個小時都在瘋狂重灌 Docker，結果還是一樣卡在那個權限報錯，那種「明明答案就在眼前卻怎麼都抓不到」的挫折感，真的會讓人很想把鍵盤砸了。

後來我才搞懂，這其實是因為 Docker 的守護程序（daemon）預設是綁定在 Unix socket 上的，而那個 socket 檔案的擁有者是 root。簡單來說，就是你的系統安全機制在保護那個 socket，不讓一般使用者隨便碰。雖然你用 sudo 可以暫時繞過，但說實話，每次執行指令都要打 sudo 實在太麻煩了，而且要是寫腳本時忘了加，整個自動化流程就會瞬間卡死，那種好不容易寫完腳本卻因為權限問題跑不起來的痛，我真的不想再經歷第二次。

要解決這個問題，其實最標準的做法就是把你的使用者帳號加入到 docker 這個使用者群組裡。這樣一來，你就不用每次都求著 root 幫你執行指令了。我當初解決時，就是先用 sudo groupadd docker 確保群組存在，接著執行 sudo usermod -aG docker $USER 把自己加進去。最後最重要的一步，一定要記得執行 newgrp docker 或者乾脆登出再登入一次，不然系統根本不會更新你的權限，我當初就是忘了這一步，還以為指令沒生效，在那邊傻傻地重試了半天。


# 把使用者加入 docker 群組
sudo usermod -aG docker $USER

# 讓權限變更立即生效（或者你也可以直接登出再登入）
newgrp docker

以後如果又換了新的開發環境，記得安裝完 Docker 第一件事就是把這行指令補上，不然哪天你在趕專案進度時被這個權限問題卡住，真的會想哭。只要養成這個習慣，基本上就不會再被這種新手村等級的 bug 絆倒了。

趕快去試試看吧，把權限問題搞定後，就可以專心寫程式囉！
