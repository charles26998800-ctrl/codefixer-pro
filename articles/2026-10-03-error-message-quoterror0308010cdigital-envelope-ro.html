How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I upgraded my local Node.js version and suddenly my entire development environment imploded. I sat there staring at my terminal for a solid hour, convinced I’d somehow corrupted my global dependencies or botched a fresh React install, only to find out it was just a tiny OpenSSL change that decided to ruin my afternoon. I wasted way too much time hunting for deep configuration issues when the fix was actually sitting right in front of me the whole time.

The reason you’re running into this error:0308010C:digital envelope routines::unsupported message is pretty straightforward once you peel back the layers. When Node.js bumped up to version 17 and beyond, they switched to OpenSSL 3.0. This new version is a lot stricter about the hashing algorithms it allows, and as it turns out, a massive chunk of older Webpack versions and legacy build tools still rely on the older, "insecure" MD4 algorithm. Essentially, your modern Node environment is looking at your older React build scripts and saying, "I don't trust that," which causes the whole process to crash before it even starts.

To get back to coding, you need to tell Node.js to stop being so picky by enabling the legacy OpenSSL provider. If you're on a Mac or Linux machine, the quickest way to fix this is to set an environment variable in your terminal before you run your start command. You can do this by running:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax changes slightly. You’ll want to run this in your PowerShell or Command Prompt:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

If you don't want to type that out every single time, you can just bake it directly into your package.json file. Find the "scripts" section and update your start command to look like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

The best way to prevent this from popping up in the future is to keep your dependencies updated. Most of the time, this error is a signal that your react-scripts version is lagging behind your Node version. Whenever you jump to a new major Node release, take a moment to audit your package.json and ensure your build tools are current; it’ll save you from these weird configuration headaches down the road.

Hopefully, this gets your project back on track so you can get back to building something cool. Happy coding!

崩潰！啟動 React 專案時噴出 error:0308010C 錯誤的解決心法

來源：Stack Overflow ↗ · 2572 票

那天我正準備接手一個舊專案，想說先開個開發環境檢查一下程式碼，結果 npm start 按下去，終端機竟然直接吐出一大串紅通通的 error:0308010C:digital envelope routines::unsupported。當下我真的傻眼，心想「我昨天才剛重灌電腦，難道是環境設定壞掉了？」，甚至一度懷疑是不是 node_modules 沒裝好，氣到差點想把整包專案砍掉重練。

其實這個錯誤的背後原因說穿了挺單純的，就是 Node.js 版本升級惹的禍。簡單來說，Node.js 在 17 版以後更新了 OpenSSL 的加密演算法，變得更嚴格了，但很多舊版的 React 專案或是相關的打包工具（像是 Webpack），還在用舊的那套加密方式。兩邊「頻率對不上」，打包工具就直接罷工給你看。那種感覺真的很無力，明明程式碼沒改，卻因為底層環境升級導致連專案都跑不起來，這種「環境地獄」真的是每個開發者心中永遠的痛。

要解決這個問題，其實不用去改動專案裡那一堆看不懂的加密設定，最快的方法就是告訴 Node.js：「嘿，請暫時用回舊版的加密規範吧」。你只要在執行指令前加上一個環境變數設定就行了。

如果你是用 Mac 或 Linux，直接在終端機輸入：


export NODE_OPTIONS=--openssl-legacy-provider

如果你是在 Windows 的 PowerShell 下，寫法會長這樣：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

設定完之後再跑一次 npm start，通常就能看到久違的編譯成功畫面了。如果你不想每次開終端機都要敲這行，建議直接把這個設定寫進 package.json 的 scripts 裡，像這樣：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

為了避免以後再被這種環境問題搞到心態崩潰，現在我養成了一個習慣，就是開發任何專案前，一定會先確認 nvm (Node Version Manager) 是否裝好，並且針對該專案寫個 .nvmrc 檔案。這樣只要切換目錄，node 版本就會自動對應，省得為了這種版本相容性問題浪費大把時間。

搞定之後喝杯咖啡壓壓驚，希望這招能救到正對著螢幕抓狂的你！
