How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I remember exactly where I was when I first hit this. It was late on a Tuesday, and I was just trying to spin up a quick prototype for a new project in IntelliJ. I ran npm start, grabbed a coffee, and came back to a wall of red text that looked like it was screaming at me. I spent three hours digging through my environment variables and reinstalling Node modules like a maniac, only to realize I had blindly updated Node to a version that was just a bit too "modern" for the project's dependencies.

The reason this happens is actually pretty straightforward once you stop the panic. When Node.js bumped up to version 17 and higher, they switched to OpenSSL 3.0. This new version has much stricter security requirements regarding cryptographic algorithms. A ton of older Webpack versions and build tools used in React projects rely on an older algorithm that OpenSSL 3.0 decided was no longer cool. Essentially, your build tool is trying to use a legacy hashing method that Node now considers a security risk, so it just shuts the whole thing down.

The quickest way I’ve found to handle this—without having to downgrade my entire Node environment—is to force Node to use the legacy OpenSSL provider. You can do this by setting an environment variable before your build command runs. If you're on a Mac or Linux machine, you just need to prepend the variable to your start script in your package.json file like this:


"scripts": {
  "start": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

If you happen to be stuck on Windows, the syntax is slightly different, so you’ll want to use set instead of export:


"scripts": {
  "start": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

Alternatively, if you don't want to mess with your package.json files, you can just run the command directly in your terminal before you start your dev server. For macOS or Linux, run export NODE_OPTIONS=--openssl-legacy-provider in your terminal session, or use set NODE_OPTIONS=--openssl-legacy-provider if you're using Command Prompt on Windows.

To prevent this headache in the future, I highly recommend using a version manager like nvm (Node Version Manager) or fnm. It lets you lock your project to a specific Node version that you know works with your current build tools. That way, you aren't forced to deal with breaking changes every time you decide to update your global Node installation.

Hope this saves you the three hours of frustration I went through! Happy coding.

救命！React 專案噴出 error:0308010C 錯誤，原來是 Node.js 版本惹的禍

來源：Stack Overflow ↗ · 2572 票

那天我剛換了一台新電腦，興沖沖地想把舊專案拉下來跑一下，結果才剛輸入 npm start，終端機就毫不留情地炸出一堆紅字，其中最顯眼的就是那串 error:0308010C:digital envelope routines::unsupported。我當下心裡真的是髒話連發，明明程式碼一行都沒改，怎麼前幾天還好好的專案，現在就像個廢鐵一樣動都不動，那種「我明明什麼都沒做，為什麼世界要這樣對我」的無力感，真的是工程師最痛的瞬間。

後來我花了一點時間查了一下，才發現這一切都是 Node.js 升級惹的禍。簡單來說，Node.js 在 v17 版本之後改用了新的 OpenSSL 3.0 加密演算法，但我們舊的 React 專案（通常是基於 Webpack 4 的架構）還在使用比較舊的演算法，兩邊就像是雞同鴨講，Webpack 說「我要用這個舊標準」，Node.js 卻回「這太老舊了我不支援」，最後兩邊就直接當場翻臉，直接報錯給你看。

其實解決方案比想像中簡單很多，既然是因為加密演算法不對盤，那我們就告訴 Node.js 暫時退回到舊模式就好。如果你是用 Mac 或 Linux，只要在啟動專案前，設定一下環境變數就可以了。我當時是在 package.json 的 scripts 區塊動了點手腳，直接把啟動指令改成這樣：


"scripts": {
  "start": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

如果你是 Windows 的使用者，記得指令要換成 set NODE_OPTIONS=--openssl-legacy-provider && ... 這種寫法。改完之後再跑一次 npm start，看到熟悉的編譯成功畫面，真的會有一種想對著螢幕尖叫的衝動，終於不用再卡在這個鳥問題上了。

至於要怎麼預防下次再踩到這種雷，最根本的方法其實是「版本控制」。我現在強烈建議大家在專案裡放一個 .nvmrc 檔案，並且在 package.json 裡面加上 engines 欄位，明確規範這個專案該跑在哪個 Node.js 版本下。這樣下次當你換電腦或交接給同事時，直接用 nvm use 就能切換到正確環境，再也不用為了這些底層的加密庫衝突搞到懷疑人生。

希望這篇能救到正在螢幕前崩潰的你，趕快去改設定然後去喝杯咖啡休息一下吧！
