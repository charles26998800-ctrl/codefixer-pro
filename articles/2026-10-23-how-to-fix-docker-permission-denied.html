How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1420 votes

I remember the exact moment I first ran into this. It was about four years ago, right after I’d set up a fresh Ubuntu machine for a new project. I spent three hours debugging my environment variables, convinced I’d botched the installation, only to realize I was just typing docker run instead of sudo docker run. I felt like an absolute amateur, but it’s a rite of passage for every developer starting out with Docker on Linux.

The reason you’re seeing that "Permission denied" error is actually pretty simple once you peek under the hood. Docker’s daemon runs as the root user, and it communicates via a Unix socket located at /var/run/docker.sock. By default, that socket is owned by root, which means your standard user account doesn’t have the necessary permissions to talk to it. You’re essentially trying to knock on a door that’s locked to everyone except the administrator, which is why prefixing your command with sudo acts like a master key.

To fix this for good, I always add my user to the docker group. This grants your account the correct permissions to interact with the daemon without needing to type sudo every single time. First, you’ll need to create the group if it doesn’t exist, though the Docker installation usually handles this for you:


sudo groupadd docker

Once the group is ready, add your current user to it using this command:


sudo usermod -aG docker $USER

Here’s the part that usually trips people up: these changes won't take effect immediately. You need to tell your system to re-evaluate your group membership. You can either log out and log back in, or just run this command to activate the changes in your current shell:


newgrp docker

After that, you should be able to run docker run hello-world without any errors. If you still run into trouble, a quick reboot usually forces the shell to refresh the group permissions and clears up any lingering issues.

To prevent this from becoming a headache in the future, just make it a habit to run the group configuration immediately after installing Docker on a new machine. It’s one of those "set it and forget it" tasks that saves you from typing those extra five letters every time you spin up a container.

Hope this clears up your terminal woes and gets your containers running smoothly. Happy coding!

Docker 權限被拒？別再傻傻加 sudo 了！

來源：Stack Overflow ↗ · 1420 票

記得我剛開始接觸 Docker 時，為了架設一個簡單的開發環境，光是安裝就折騰了半天。好不容易裝好後，興沖沖地輸入 docker run hello-world，結果螢幕直接噴出一大串紅通通的 Permission denied，那當下我真的差點崩潰，心想：「明明安裝過程都沒報錯，怎麼連個 Hello World 都跑不起來？」最痛苦的是，每次為了測試一個小功能，都得在指令前面補上 sudo，打久了真的會懷疑人生，甚至好幾次因為忘了加 sudo 而卡住，那種「我明明就在這，你卻說我不認識我」的荒謬感，真的讓人很想把鍵盤砸了。

會發生這種狀況，其實是因為 Docker 服務（Daemon）預設是透過 Unix Socket 來溝通的，而這個 socket 檔案的擁有者是 root 使用者。簡單來說，Linux 的權限機制為了安全，不讓普通使用者隨便去碰這個系統級的 Socket，所以當你不用 sudo 時，你的帳號在 Linux 眼中就是個沒權限的「外人」，當然會被擋在門外。

解決這個問題其實一點都不難，我們只需要把自己的使用者帳號加入到 docker 這個群組裡就好。首先，先建立一個 docker 群組（通常安裝時會自動建立，但檢查一下最保險）：


sudo groupadd docker

接著，把目前的使用者加進去：


sudo usermod -aG docker $USER

這時候重點來了，很多新手（包括當年的我）做到這步就以為結束了，結果重開終端機發現還是一樣報錯。這是因為群組權限的變更需要重新登入才會生效，所以最快的方法就是直接登出再登入，或者簡單粗暴一點，直接輸入 newgrp docker 強制讓當前的 Shell 重新載入群組設定。搞定之後，你就可以自信滿滿地執行 docker run hello-world，不需要再加那討人厭的 sudo 了。

為了避免這種權限地獄再次找上門，建議大家養成習慣，在安裝完 Docker 之後的第一件事，就是把自己的帳號放進群組裡，並設定好開機自動啟動服務。這樣不僅能省下每次打 sudo 的麻煩，也能讓你在寫腳本或是跑複雜容器時，少掉很多因為權限導致的莫名其妙錯誤。

現在你的 Docker 應該已經乖乖聽話了，趕快去寫點有趣的 Code 吧！
