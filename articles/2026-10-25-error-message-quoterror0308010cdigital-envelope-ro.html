Solving the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I remember the exact moment I first ran into this error; I had just spun up a fresh project in IntelliJ, expecting a clean boilerplate, and instead, my console exploded with a wall of red text ending in digital envelope routines::unsupported. I spent about three hours convinced my entire Node environment was corrupted, fruitlessly reinstalling everything in sight before realizing it was just a simple version mismatch. It’s one of those classic "welcome to the world of JavaScript fatigue" moments that makes you want to throw your keyboard out the window.

The reason this happens is actually quite straightforward once you peel back the layers. When Node.js version 17 was released, they upgraded to OpenSSL 3.0, which introduced stricter security standards for hashing algorithms. A lot of the build tools we use in the React ecosystem, specifically older versions of Webpack, rely on legacy algorithms that OpenSSL 3.0 decided were no longer acceptable. So, when your build tool tries to fire up the dev server, Node essentially says, "I don't trust this old hashing method anymore," and shuts the whole process down.

To fix this, you don't actually need to downgrade your entire Node installation. You just need to tell Node to allow the legacy OpenSSL provider for your specific project. If you're on a Mac or Linux machine, you can handle this right in your terminal before you run your start script. Just run this command:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you're working on Windows, the syntax is a little different—you'll want to use set instead of export:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

For those of you who don't want to type that every single time you open a terminal, just head over to your package.json file. You can permanently bake this configuration into your scripts section so you never have to think about it again:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

The best way to prevent this headache in the future is to keep your dependencies updated. Most of the time, this error pops up because you're using an older version of react-scripts that hasn't been patched to support the newer Node security requirements. Running npm update or checking for newer versions of your build tools regularly will save you from these legacy configuration traps.

Hope this helps you get back to coding without the constant console errors. Happy debugging!

React 2026-10-25

救命！React 專案突然報錯：error:0308010C:digital envelope routines::unsupported

來源：Stack Overflow ↗ · 2572 票

那天我正準備接手一個舊專案，想說先跑個 npm start 暖暖身，結果終端機直接噴出一大串紅字，那個 digital envelope routines::unsupported 看得我一頭霧水。當下真的差點崩潰，想說明明昨晚還好好的，怎麼今天連專案都起不來，那種心跳漏一拍、懷疑人生覺得自己環境是不是壞掉的感覺，相信各位工程師一定都懂。

其實這個問題的兇手是 Node.js 的版本更新。簡單來說，Node.js 17 之後引進了 OpenSSL 3.0，這傢伙對於加密演算法的檢查變得超級嚴格。偏偏很多我們常用的 React 舊版打包工具（像是 Webpack 4 等）還在用舊的演算法，兩邊一搭上線，OpenSSL 就會覺得這些舊東西「不安全」而直接拒絕執行，於是你就拿到這張「拒絕門票」了。

要解決這個問題，其實不用把 Node.js 降版降到地老天荒，只要讓系統暫時「睜一隻眼閉一隻眼」就好。最快的方法就是設定一個環境變數，告訴 Node.js 允許使用那些舊版的演算法。如果你是用 Mac 或 Linux，直接在終端機輸入這行：


export NODE_OPTIONS=--openssl-legacy-provider

若是 Windows 的 PowerShell，則是輸入：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

如果你懶得每次重開終端機都要敲一次，最推薦的做法是直接改 package.json。在 scripts 的 start 或 build 前面加上這段設定，這樣不管誰來跑這個專案，都不會再遇到這個鬼打牆的錯誤了：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

至於要怎麼預防下次再被這種環境問題搞到瘋掉？我強烈建議大家一定要用 nvm (Node Version Manager) 來管理 Node 版本。針對舊專案，你可以直接在專案根目錄放一個 .nvmrc 檔案，寫入對應的 Node 版本號。這樣只要進到資料夾下個 nvm use，環境就會自動切換到當初開發時的版本，不用再擔心升級 Node 後整個世界毀滅。

把這個環境變數設好後，我的專案終於成功跑起來了，那一刻真的覺得世界又變得美好了。希望這篇筆記能幫你省下寶貴的除錯時間，趕快回去寫 Code 吧！
