How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the first time I ran into this error. I had just upgraded my Node.js version, sat down with a fresh coffee, and fired up an older side project I hadn't touched in months. I expected it to spin up in seconds, but instead, my terminal exploded with a wall of red text ending in that cryptic error:0308010C:digital envelope routines::unsupported. I spent a good two hours convinced my entire development environment had imploded before I realized it was just a simple compatibility mismatch.

The root cause of this headache is actually quite simple: OpenSSL 3.0. When Node.js bumped up to version 17 and beyond, they switched to OpenSSL 3.0, which tightened up security requirements for certain hashing algorithms. A lot of the older build tools—like Webpack 4 or older versions of react-scripts—rely on legacy algorithms that OpenSSL 3.0 now rejects by default. It's not that your code is broken; it’s that your build pipeline is trying to use a "deprecated" way of hashing files, and the newer Node runtime is refusing to play along.

The quickest way I’ve found to resolve this is to force Node.js to use the legacy OpenSSL provider. You don't need to downgrade your Node version or rewrite your entire build chain. You just need to set the NODE_OPTIONS environment variable. If you’re on macOS or Linux, you can run this command right in your terminal before starting your project:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is a bit different. You’ll want to use this in your command prompt:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

If you don't want to type that every single time you start your project, just edit your package.json file. You can prepend the variable directly to your start script so it’s handled automatically:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To prevent this from coming back to haunt you, get into the habit of keeping your dependencies up to date. This error is effectively a "technical debt" alarm—it’s telling you that your react-scripts or Webpack version is lagging behind modern security standards. Whenever you see this, it’s a great nudge to check if you can bump your react-scripts version to a newer release that natively supports OpenSSL 3.0, which is a much cleaner long-term fix than relying on the legacy provider flag.

Hopefully, this saves you the two hours of staring at your screen that I had to endure. Happy coding!

當 React 專案突然壞掉：解決 error:0308010C 的崩潰時刻

來源：Stack Overflow ↗ · 2572 票

記得那天早上我剛開工，滿心期待地把一個許久沒碰的 React 舊專案 clone 下來打算修個小 bug，結果一打 npm start，終端機直接噴出一大串紅通通的錯誤訊息，結尾還掛著那個讓人火大的 error:0308010C:digital envelope routines::unsupported。當下我真的差點把咖啡噴在螢幕上，心想：「我明明什麼程式碼都還沒改，為什麼專案就這樣原地爆炸了？」

其實這問題的兇手是 Node.js 的版本更新。簡單來說，Node.js 在 v17 版本之後升級了加密演算法的標準，改用了 OpenSSL 3.0，但我們手邊那些稍微有點年紀的專案（或是依賴舊版 Webpack 的專案）還在使用舊的演算法。這兩者就像是雞同鴨講，Node.js 覺得這些舊演算法不安全，所以直接拒絕執行，這才導致這場災難。最讓我痛苦的地方在於，你明明知道程式碼沒問題，卻因為開發環境的升級而卡住，那種「明明能跑卻跑不動」的無力感，真的是工程師最想摔鍵盤的時刻之一。

要解決這個問題其實不難，最快的方法就是告訴 Node.js：「嘿，請暫時回到舊的模式去跑吧」。如果你是 macOS 或 Linux 使用者，只要在執行指令前加上 NODE_OPTIONS 參數就行了。你可以直接修改 package.json 裡的 scripts，把啟動指令改成這樣：


"scripts": {
  "start": "NODE_OPTIONS=--openssl-legacy-provider react-scripts start",
  "build": "NODE_OPTIONS=--openssl-legacy-provider react-scripts build"
}

如果是 Windows 的 PowerShell 使用者，語法會稍微不太一樣，或者你也可以直接在終端機輸入 set NODE_OPTIONS=--openssl-legacy-provider 再跑 npm start。這樣設定之後，你會發現原本那些惱人的錯誤訊息瞬間消失，專案又奇蹟般地活過來了。

為了避免以後再被這個問題搞到心態炸裂，我現在養成了一個習慣，就是專案目錄下一定會放一個 .nvmrc 檔案，明確鎖定這個專案該用的 Node.js 版本。畢竟與其每次升級環境都提心吊膽，不如從源頭管理好版本，讓專案在不同的機器上都能有穩定的環境。

搞定這個之後，終於可以安心喝完那杯冷掉的咖啡了，祝大家的終端機從此不再出現紅色的錯誤訊息！
