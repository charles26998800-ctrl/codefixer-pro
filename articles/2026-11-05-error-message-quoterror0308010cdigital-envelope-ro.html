How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I pulled a fresh React project from a legacy repo, ran npm start, and watched my terminal explode with a wall of red text. I spent nearly two hours convinced I’d somehow corrupted my entire Node environment, only to realize that my shiny new version of Node.js was playing a game of chicken with some older Webpack dependencies. It’s one of those errors that makes you feel like you’ve broken the fundamental laws of your machine, but it’s actually just a classic case of version mismatch.

The reason you’re seeing this error:0308010C:digital envelope routines::unsupported message is that Node.js v17 and later switched to OpenSSL 3.0. This new version is much stricter about the algorithms it allows. Many older projects—or even default templates generated by older versions of Create React App—rely on an older hashing algorithm that OpenSSL 3.0 decided is no longer secure. Essentially, your project is trying to use a legacy cryptographic method, and Node is slamming the door in its face. It’s not that your code is "broken," it’s just that your environment is too modern for the dependencies you’re trying to run.

I found that the cleanest way to handle this without nuking my entire Node installation is to tell Node to use the legacy OpenSSL provider just for that specific process. If you’re on macOS or Linux, you can simply prepend the NODE_OPTIONS environment variable to your start command in your package.json file. You’ll want to look for the "scripts" section and update your "start" and "build" commands to look like this:


"scripts": {
  "start": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

If you’re stuck on Windows using PowerShell, the syntax is slightly different, so you’d use this instead:


"scripts": {
  "start": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

Once you save that file and run npm start again, the error should vanish like magic.

To keep this from haunting you in the future, my best advice is to embrace .nvmrc files in every project you manage. By creating a simple file in your project root that specifies the exact Node version (like v16.14.0), you can use the Node Version Manager to switch environments automatically whenever you cd into that directory. It stops these version-related headaches before they even start, saving you from having to debug your local environment every time you switch between an old side project and a new production app.

Hope this gets you back to coding without any more cryptic errors. Good luck with the build!

救命！React 專案噴出 error:0308010C 是怎麼回事？

來源：Stack Overflow ↗ · 2572 票

那天我剛接手一個舊專案，想說先在本地跑起來檢查一下環境，結果 npm start 才剛敲下去，終端機就給我炸出一大串 error:0308010C:digital envelope routines::unsupported。當時心裡真的有一萬隻草泥馬奔騰而過，心想「我只是想跑個專案，為什麼要這樣對我？」，那種明明環境都裝好了，卻連第一步都踏不出去的無力感，真的是工程師最想原地離職的痛苦時刻。

其實這問題說穿了就是 Node.js 版本惹的禍。簡單來說，是因為 Node.js 17 版本之後升級了 OpenSSL 3.0，這玩意兒對加密演算法的要求變嚴格了，而舊版的 Webpack（特別是 v4）還在用一些被視為「不安全」的舊加密演算法，兩邊一搭上線就直接吵架，結果就是報錯給你看。我知道很多人跟我一樣，當下看到那個長長的錯誤訊息，直覺反應就是去刪 node_modules 再重新 npm install，但相信我，那樣做只會讓你重複經歷三次崩潰而已。

當時我折騰了半天，發現最快的方法就是告訴 Node.js：「嘿，幫我把舊版的演算法相容性打開」。如果你是用 Mac 或 Linux，只要在啟動專案的指令前加上環境變數設定就好，像這樣：


export NODE_OPTIONS=--openssl-legacy-provider
npm start

如果你是在 Windows 的 PowerShell 環境，指令則稍微有點不同：


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

當然，如果你不想每次啟動都要打這一長串，直接去 package.json 的 scripts 區塊修改啟動指令是最方便的。把原本的 start 指令改成 NODE_OPTIONS=--openssl-legacy-provider react-scripts start 就一勞永逸了，下次再按 npm start 就能順利跑起來。

為了避免以後又踩到這種雷，我現在養成一個習慣，就是專案一定會加上 .nvmrc 檔案，並且明確規定團隊使用特定的 Node.js LTS 版本。畢竟前端生態圈更新速度太快，有時候「追求最新版本」反而會變成維護上的惡夢，固定版本才是保護自己心臟健康的最好方法。

希望這篇能救回你的開發進度，別再為了這個錯誤卡在那邊自我懷疑啦！
