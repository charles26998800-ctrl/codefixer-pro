How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2573 votes

I remember the exact moment I first saw this error. I had just spun up a fresh React project in IntelliJ to prototype a quick feature, and instead of seeing the familiar "Compiled successfully" message, my terminal exploded with a wall of red text ending in error:0308010C:digital envelope routines::unsupported. I spent a solid hour tweaking my project config and reinstalling node_modules like a madman, only to realize I was fighting a losing battle against a mismatch between my Node.js version and my build tools.

The root cause here is actually pretty straightforward once you peel back the layers. When Node.js bumped up to version 17, they upgraded their underlying cryptographic library to OpenSSL 3.0. This new version is much stricter about the algorithms it allows, and it effectively deprecated some older, legacy hash functions that older versions of Webpack (specifically version 4, which many Create React App projects use) rely on. Essentially, your build tool is trying to use an "unsupported" legacy hashing method that the new Node.js environment refuses to execute for security reasons.

The quickest way I’ve found to resolve this—without having to rip out and upgrade your entire Webpack configuration—is to tell Node.js to use the legacy OpenSSL provider. You can do this by setting an environment variable called NODE_OPTIONS to --openssl-legacy-provider. If you're on a Mac or Linux machine, you can patch this in your terminal right before you run your start command:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is a bit different. You’ll want to run this in your PowerShell or Command Prompt:


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

If you don't want to type that every single time you spin up your dev server, the best approach is to modify your package.json file directly. Just head over to the scripts section and prepend the variable to your existing start or build commands like this:


"scripts": {
  "start": "NODE_OPTIONS=--openssl-legacy-provider react-scripts start",
  "build": "NODE_OPTIONS=--openssl-legacy-provider react-scripts build"
}

To keep this from biting you in the future, my best advice is to embrace version management tools like nvm (Node Version Manager). Keeping a .nvmrc file in the root of your projects ensures that everyone on your team is using the same Node version that the project was actually built for. It’s a massive time-saver and spares you from dealing with these environmental "gotchas" when you're just trying to get some code written.

Hope this saves you the headache it caused me! Happy coding, and let me know if you run into any other weird build errors.

遇到 error:0308010C？別慌，這只是 Node.js 版本跟 Webpack 在吵架啦！

來源：Stack Overflow ↗ · 2573 票

那天早上我剛開完會，想說趁著靈感正好的時候，趕快把手邊一個放了一陣子的 React 舊專案跑起來，結果終端機直接噴出一大串紅通通的錯誤訊息，那個 error:0308010C:digital envelope routines::unsupported 簡直像是在跟我宣戰。我當時真的差點沒把鍵盤砸了，心想：「我明明什麼都沒改啊，昨天還好好的，怎麼今天連專案都起不來了？」盯著那個 Hash 錯誤發呆了十分鐘，感覺就像是在看天書一樣，整個開發心情都被毀了。

其實會出現這個狀況，主要是因為你電腦裡的 Node.js 版本升級到了 17 或 18 以上，但你跑的那個專案還在用比較舊的 Webpack 版本。簡單來說，新版的 Node.js 為了安全性，導入了更嚴格的 OpenSSL 3.0 加密演算法，結果舊版的 Webpack 覺得這套新規格太嚴格，彼此溝通不良，它就會直接罷工給你看。這真的很讓人火大，明明程式碼都沒變，只是換個環境跑就壞掉，這種「環境地獄」真的是每個工程師的惡夢。

解決這件事其實比想像中簡單，最快的方法就是告訴 Node.js 說：「嘿，請暫時用舊版的加密演算法模式來執行吧！」如果你是用 Mac 或 Linux，只要在啟動專案的指令前面加上環境變數設定就行。你可以試著修改 package.json 裡的 scripts，把啟動指令改成這樣：


"scripts": {
  "start": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

如果是 Windows 的使用者，記得要把 export 換成 set，或者是用 cross-env 這個套件來處理跨平台的問題。只要加上這行 NODE_OPTIONS=--openssl-legacy-provider，就像是給 Node.js 一個懷舊濾鏡，它就能順利吃下舊版的 Webpack 配置了。

為了避免以後又遇到這種莫名其妙的環境衝突，我現在養成一個習慣，就是不管做什麼專案，一定會加上 .nvmrc 檔案，明確指定這個專案該用哪個版本的 Node.js。而且如果你有安裝 NVM（Node Version Manager），切換專案時只要打個 nvm use，就能確保開發環境跟當初寫程式時一模一樣。

希望這招能救你脫離崩潰邊緣，趕快回去寫程式吧，別讓這種破事佔用你寶貴的 Coding 時間！
