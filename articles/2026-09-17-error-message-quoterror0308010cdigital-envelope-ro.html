How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I upgraded my local Node.js version and suddenly my entire development environment went up in flames. I spent three hours staring at the terminal, convinced I’d somehow corrupted my global dependencies or messed up my IntelliJ IDEA project configuration, only to realize it was a classic mismatch between my shiny new Node version and an older Webpack setup. It’s one of those errors that makes you want to throw your keyboard out the window, but once you understand what’s actually happening, it’s a quick fix.

The root cause is actually quite simple: Node.js version 17 and above switched to OpenSSL 3.0, which has stricter security defaults. Many older libraries—specifically those relying on older versions of Webpack—try to use the MD4 hashing algorithm, which OpenSSL 3.0 effectively blocks because it’s no longer considered secure. It’s not that your code is broken, it’s just that your environment is playing by a new set of rules that your project’s legacy dependencies aren't ready for yet.

The most effective way I’ve found to squash this is by telling Node.js to use the legacy OpenSSL provider. You can do this by setting an environment variable before your start script runs. If you’re on a Mac or Linux machine, just update your package.json file like this:


"scripts": {
  "start": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

If you’re working on Windows, the syntax changes slightly because of how the command prompt handles environment variables. You’ll want to use set instead:


"scripts": {
  "start": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

If you don't want to mess with your package.json every time, you can also set this globally in your terminal session by running export NODE_OPTIONS=--openssl-legacy-provider before you trigger your build command.

To keep this from biting you again, my best advice is to keep your project dependencies updated. Most of the time, this error pops up because you're using an outdated version of react-scripts. Running npm install react-scripts@latest or checking for a Webpack migration guide will eventually solve this for good, rather than just patching over the symptoms with a legacy flag.

Hopefully, this saves you the headache it caused me back in the day. Happy coding, and may your builds stay green!

React 專案啟動直接噴 Error？別怕，這只是 Node.js 版本在搞你

來源：Stack Overflow ↗ · 2572 票

那天我正準備接手一個舊的 React 專案，想說先跑個 npm start 確認開發環境，結果螢幕上直接跳出一大串 error:0308010C:digital envelope routines::unsupported 的紅字。我當時真的差點沒把鍵盤砸了，心想：「我才剛把環境架好，什麼都沒動，為什麼連個 Hello World 都跑不出來？」那種明明準備好要大展身手，結果第一步就被腳下的石頭絆倒的挫折感，真的讓人超級無力。

其實這個錯誤會發生，是因為 Node.js 在 v17 版本之後升級了 OpenSSL 到 3.0，這是一個安全性上的大升級，但悲劇的是，很多舊版的 Webpack（特別是 v4 以下）或是一些常用的套件，用的加密演算法在新的 OpenSSL 標準下被判定為不安全，所以 Node.js 就直接「拒絕服務」了。簡單來說，就是你的新版 Node.js 覺得舊專案的打包方式「太過時、不夠安全」，所以直接罷工。

解決方法其實意外地單純，我們只需要告訴 Node.js：「嘿，別管那麼多，先讓我把這個專案跑起來再說。」最快的方法就是在啟動指令前面加上一個環境變數。如果你是 Mac 或 Linux 的使用者，直接在終端機輸入這行：

export NODE_OPTIONS=--openssl-legacy-provider && npm start

如果你是用 Windows 的 PowerShell，寫法會稍微不一樣：

$env:NODE_OPTIONS = "--openssl-legacy-provider"; npm start

不過，我強烈建議你直接去 package.json 裡面的 scripts 把這段加進去，這樣以後就不用每次啟動都要打這一長串指令，省事很多。像這樣修改你的啟動腳本：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

為了避免以後再被這個問題卡住，我現在養成一個習慣：只要是接手舊專案，第一件事就是檢查 package.json 裡的 Node 版本需求，或者乾脆用 nvm (Node Version Manager) 來管理環境。如果你發現專案年代久遠，最好直接鎖定在 Node.js v14 或 v16 這種比較穩定的版本，這樣就能完美避開這類因為 OpenSSL 更新帶來的地雷。

搞定這個之後，終於可以開開心心開始寫程式了，別讓這幾行錯誤訊息壞了你的開發心情！
