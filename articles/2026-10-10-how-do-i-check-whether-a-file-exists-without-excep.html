How to Check If a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7351 votes

Back when I was still cutting my teeth on automation scripts, I remember writing a massive file-processing pipeline that relied on try-except blocks for everything. I spent a good three hours debugging a performance bottleneck only to realize that my code was throwing and catching thousands of "File Not Found" exceptions per minute just to poll for incoming data. It felt like I was trying to open a door by smashing my shoulder into it and waiting for the pain to tell me if it was locked.

The reason this feels so clunky is that Python’s try-except pattern is technically the "Pythonic" way to handle errors—the EAFP (Easier to Ask for Forgiveness than Permission) philosophy. However, when you’re checking for file existence in a loop or a high-frequency system, it creates unnecessary overhead. You're effectively asking the operating system to attempt an operation that you already expect to fail, which forces the kernel to generate a traceback and handle an error state. It’s a clean approach for one-off operations, but it’s absolute overkill for simple state checks.

To fix this without the exception noise, I’ve moved over to using the pathlib module, which has been the standard since Python 3.4. It feels much more like object-oriented programming and, honestly, it’s just cleaner to read. You simply instantiate a Path object and call the exists() method. If you need to ensure it's specifically a file and not a directory—because we’ve all been bitten by that edge case—you can use is_file() instead.


from pathlib import Path

file_path = Path("config.json")

if file_path.is_file():
    print("The file exists and I can start processing.")
else:
    print("File not found, skipping this step.")

If you’re stuck on a legacy codebase and can't use pathlib, the old-school os.path.exists function is still hanging around. It’s a bit more "C-style" and functional, but it gets the job done without triggering exceptions.


import os

if os.path.exists("data.csv"):
    print("Found it!")

The best way to prevent these headaches is to stop thinking of file existence as an error condition and start thinking of it as a state you need to verify before acting. Always try to validate the environment before you jump into your logic, and you'll save yourself from those messy try-except chains that clutter up your business logic.

Hope this helps you clean up your scripts and stop those unnecessary exceptions from firing. Happy coding!

別再用 try-except 檢查檔案了：Python 檢查路徑的優雅寫法

來源：Stack Overflow ↗ · 7351 票

記得剛開始寫 Python 那年，我正在接一個自動化爬蟲的案子，當時為了檢查下載的圖片有沒有成功落地，我直接寫了一個很暴力的 try-except FileNotFoundError。結果那天下午我差點崩潰，因為我的程式碼在處理大批次檔案時，邏輯判斷變得極度混亂，那些異常捕捉簡直像在疊磚塊，看得我頭暈眼花，甚至因為捕捉錯誤的範圍太大，導致根本不該被忽略的 Bug 也被我順手「吃掉」了，除錯除到懷疑人生。

為什麼我們總想避開 try-except？其實是因為在這種單純的「檢查是否存在」場景下，用異常處理（Exception Handling）有點殺雞用牛刀，甚至會讓程式碼的可讀性變得很差。異常處理的初衷是為了應對「意料之外」的狀況，但檢查檔案存不存在，很多時候是我們邏輯判斷的一部分，這時候硬塞一個異常處理機制，反而在效能和結構上都顯得有點笨重。

後來我學乖了，直接改用 Python 的 pathlib 模組，這簡直是救贖。這套標準函式庫自從 Python 3.4 出現後，我幾乎就拋棄了舊有的 os.path 寫法。你只要這樣寫，世界瞬間清靜：


from pathlib import Path

file_path = Path('my_data.txt')

if file_path.exists():
    print("檔案就在這，安心開工！")
else:
    print("檔案消失了，去檢查一下路徑吧。")

如果你是因為要在路徑操作上更嚴謹，還可以順便判斷它是不是一個檔案：file_path.is_file()。這種寫法不但語意清晰，而且不會因為一個檢查動作就觸發昂貴的異常堆疊追蹤（Stack Trace），寫起來真的舒服多了。

要預防這種「為了檢查檔案而寫出一堆髒程式碼」的情況，我給的建議是：永遠不要把「流程控制」跟「異常處理」混在一起談。如果你心裡想的是「這檔案可能不存在」，那就把它當作正常的邏輯分支去處理，而不是把它當成一個「錯誤」來捕捉。當你開始習慣用 pathlib 這種物件導向的方式去思考路徑，你會發現你的程式碼會變得像散文一樣好讀，再也不用擔心在哪裡少寫了一個 except 而導致程式崩潰了。

現在我就算半夜寫 code，看到這種檢查邏輯也不會再焦慮了，畢竟程式碼寫得乾淨，睡覺都能睡得安穩點。
