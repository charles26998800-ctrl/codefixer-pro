How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I remember exactly where I was when this error first hit my terminal: 2:00 AM, fueled by cold coffee and pure stubbornness, trying to spin up a quick prototype. I had just updated Node.js to version 17, thinking I was being proactive, only to have my build process crash immediately with that cryptic digital envelope routines::unsupported message. I spent three hours digging through Stack Overflow and cursing my own decision to upgrade "just because," convinced I’d somehow corrupted my entire project environment.

The reason behind this headache is actually pretty straightforward: OpenSSL 3.0. When Node.js bumped up to version 17 and beyond, they switched to OpenSSL 3.0, which has stricter security defaults. Older versions of Webpack (specifically ones used in older React project templates) rely on algorithms like MD4, which are now considered legacy and aren't supported by the new OpenSSL configuration by default. Essentially, your project is trying to use an old-school cryptographic handshake that the new Node.js runtime refuses to acknowledge for security reasons. It’s not that your code is broken; it’s that your build tool is speaking a language that the new environment doesn't want to translate.

Fixing this is a breeze once you know the secret, and thankfully, you don’t have to downgrade your entire Node installation to get back to work. Since the issue is caused by the OpenSSL version, you just need to tell your Node process to use the "legacy" provider. You can do this by setting an environment variable called NODE_OPTIONS before your start script runs. If you’re on a Mac or Linux machine, just pop this into your terminal:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is slightly different, so you’ll want to run this in your PowerShell terminal instead:


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

If you don't want to type that out every time you boot up your dev server, you can permanently bake it into your package.json file. Just update your scripts section so that the start command looks like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

Moving forward, the best way to prevent this kind of friction is to keep your development dependencies, especially react-scripts, up to date. This specific error is a classic sign that your build tools are lagging behind your runtime environment, and keeping your package.json dependencies aligned with modern Node versions usually clears these hurdles before they even appear.

Hope that saves you the midnight headache I dealt with! Happy coding, and let me know if you run into any other weird build errors.

救命！React 專案噴出 error:0308010C，害我以為電腦壞了

來源：Stack Overflow ↗ · 2572 票

那天我正準備從頭開始寫一個新的 React 小專案，滿心期待地用 IntelliJ IDEA 開了個預設模板，結果 npm start 才剛敲下去，終端機直接甩我一臉紅通通的錯誤訊息，寫著什麼 digital envelope routines::unsupported。當下我真的傻眼，心想：「我什麼都還沒寫欸？連一行程式碼都還沒動，這是在跟我開什麼玩笑？」那種滿腔熱血準備寫 Code 卻被環境變數擋在門外的無力感，真的是會讓人瞬間想把鍵盤丟了。

其實這個錯誤會出現，是因為 Node.js 在 v17 版本之後換了一套加密演算法叫 OpenSSL 3.0，但我們平常在用的舊版 Webpack（特別是 webpack 4）還在用比較舊的加密演算法，兩邊兜不起來，Node.js 就覺得你在用不安全的舊東西，直接給你一個大大的拒絕。簡單講，就是你的 Node.js 太新，但你的專案環境太「復古」，兩邊鬧彆扭了。

我當下查了一下，發現網路上討論度超高，解決方案其實很直覺，就是把 OpenSSL 的限制強制關掉。如果你是用 Mac 或 Linux，只要在啟動指令前面加上 NODE_OPTIONS=--openssl-legacy-provider 就行了。我當時的操作是直接去 package.json 裡面的 scripts 改掉啟動指令：


"scripts": {
  "start": "NODE_OPTIONS=--openssl-legacy-provider react-scripts start",
  "build": "NODE_OPTIONS=--openssl-legacy-provider react-scripts build"
}

如果你是用 Windows 的 PowerShell，直接這樣寫會報錯，記得要安裝一個叫 cross-env 的套件來處理跨平台環境變數的問題，不然就得乖乖去系統變數設定，那真的太麻煩了。

說到預防，其實最根本的辦法就是盡量保持專案依賴的更新。很多時候這種過時的錯誤，都是因為我們太久沒更新 react-scripts 或者 Webpack 版本。我現在學乖了，每隔一陣子就會檢查一下專案的 package.json，看看有沒有什麼套件已經被棄用了。另外，如果不想每次都改設定，也可以考慮直接降版 Node.js 到 v16，不過現在看起來這招已經越來越少用了，畢竟跟著新技術走還是比較實在。

處理完這個問題之後，看到終端機終於跳出 Compiled successfully! 的那一刻，真的是比寫出什麼複雜邏輯還要感動。希望這篇能幫到同樣被這個錯誤卡住的你，別氣餒，環境問題就是軟體工程師的宿命啊！
