How to Fix "RuntimeError: Input type and weight type should be the same" in PyTorch

Source: Stack Overflow ↗ · 202 votes

I still remember the first time I built a custom training loop in PyTorch, feeling like a genius for finally getting my model onto the GPU. I hit run, watched the progress bar for two seconds, and then—boom—the console exploded with a RuntimeError telling me my input and weight types didn't match. I spent three hours refactoring my entire custom dataset class and checking my tensor shapes before realizing I had simply forgotten to move the input batch to the device, a classic "I should probably go take a nap" moment.

The root cause of this headache is actually pretty straightforward, even if it feels like PyTorch is being intentionally cryptic. Deep learning frameworks require your model’s parameters (the weights) and the data you’re feeding into them (the inputs) to reside in the exact same memory space. If you’ve pushed your model to the GPU using .to(device), but your data is still sitting in the CPU's RAM, PyTorch refuses to perform the operation because it can't cross the bridge between the two memory types during the forward pass. It's essentially like trying to plug a European power cord into an American outlet—they're both electricity, but they aren't speaking the same language.

To fix this, you need to explicitly move your input tensors to the same device as your model inside your training loop. I usually handle this right after I pull the data from my dataloader. Here is how I structure it to make sure the device is always synced:


device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model.to(device)

for data in dataloader:
    inputs, labels = data
    # This is the line that saves the day:
    inputs = inputs.to(device)
    labels = labels.to(device)
    
    outputs = model(inputs)
    # ... rest of your training logic

If you are dealing with multiple tensors, I find it’s cleanest to move them individually, but you could also write a helper function if your dataloader returns complex dictionaries or tuples. Just don't forget the labels if you're calculating your loss on the GPU, because that will trigger the exact same error when you try to compare the output to the ground truth.

To prevent this from ever ruining your afternoon again, I’ve started writing my training loops to be device-agnostic from the very first line. Instead of hardcoding cuda or cpu everywhere, I define my device variable at the top of my script and then consistently call .to(device) on every tensor that enters the model. If you make it a habit to move your data the moment it leaves the dataloader, you’ll never see this error pop up in your terminal again.

Hope this clears things up so you can get back to training those models. Happy coding!

救命！PyTorch 報錯：Input 和 Weight 型別不一致的崩潰時刻

來源：Stack Overflow ↗ · 202 票

記得剛開始碰 PyTorch 的時候，我熬夜寫了一個看起來很完美的訓練迴圈，好不容易等到資料跑進去，結果螢幕上那個刺眼的 RuntimeError: Input type (torch.FloatTensor) and weight type (torch.cuda.FloatTensor) should be the same 直接跳出來。我當時真的差點把鍵盤砸了，心想我明明都把 model 丟進 .to(device) 了，為什麼這傢伙還在跟我鬧脾氣？那種感覺就像是你把所有行李都塞進車子準備出發，結果發現鑰匙還鎖在屋裡一樣讓人抓狂。

說穿了，這問題其實非常「單純」但又很「機車」。PyTorch 對於資料的龜毛程度超乎想像，它規定運算時，模型權重（Weights）跟輸入資料（Inputs）必須待在同一個地方。我的 model 確實已經被我搬到 GPU 上了，但我的 inputs 卻還懶洋洋地待在 CPU 的記憶體裡。當這兩位「異地戀」的傢伙試圖在運算時碰頭，PyTorch 就會因為兩邊的身分證（裝置位址）不一樣，直接拒絕讓它們互動。這就是為什麼你會看到一個是 FloatTensor（CPU 的），另一個卻是 cuda.FloatTensor（GPU 的）。

解決方法其實比想像中簡單，只要把從 dataloader 取出來的那些資料也一起「打包送上 GPU」就行了。我後來學乖了，每次取資料時，都會習慣性地加上一行 .to(device)。就像這樣：


device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model.to(device)

for data in dataloader:
    # 這裡就是關鍵！記得把 inputs 和 labels 都推過去
    inputs, labels = data
    inputs = inputs.to(device)
    labels = labels.to(device)
    
    outputs = model(inputs)
    # 接下來的 loss 計算也記得確保 labels 在同個地方

要預防這種鳥事再次發生，我建議大家養成一個好習慣：不要只定義一個 device 變數就放著不管，而是要把它當成一種「標記」。每當你寫到任何需要參與運算的 Tensor，甚至是測試階段的資料，都隨手檢查一下有沒有 .to(device)。如果你的程式碼規模比較大，甚至可以寫一個簡單的 helper function 來處理資料載入，這樣就不用每次都擔心漏掉某個維度或是某個變數沒轉移。

以後看到這個錯誤，別急著懷疑人生，記得檢查一下你的資料是不是還在 CPU 曬太陽就好。希望大家都能少踩點坑，早點把模型訓練出來去睡覺！
