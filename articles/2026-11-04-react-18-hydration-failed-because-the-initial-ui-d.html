How to Fix "Hydration failed" Errors in Next.js and React 18

Source: Stack Overflow ↗ · 341 votes

I still remember the first time I saw the "Hydration failed" error in React 18; I was convinced my machine was haunted. I spent three hours debugging a simple date component, only to realize that the server was rendering the current time while the client was rendering a placeholder, causing a complete meltdown in the browser console. It’s one of those bugs that makes you want to throw your keyboard out the window because the app looks perfectly fine, yet React is screaming at you that everything is broken.

The reason this happens is actually quite logical once you peel back the layers of how Next.js works. When you use Server-Side Rendering (SSR), React generates the HTML on the server and sends it to the browser. Once that HTML arrives, React "hydrates" it, meaning it attaches event listeners and makes it interactive. If the HTML that the browser receives doesn't perfectly match what React expects during its first client-side render, it throws a hydration mismatch error. Usually, this is caused by dynamic content like Date.now(), Math.random(), or browser-only APIs like localStorage that aren't available during the server build process.

To fix this, I’ve found that the best approach is to force the component to wait until it’s officially mounted on the client before rendering the problematic content. You can do this by using a simple useEffect hook to track the mount state. Here is how I usually structure it:


import { useState, useEffect } from 'react';

export default function MyComponent() {
  const [isMounted, setIsMounted] = useState(false);

  useEffect(() => {
    setIsMounted(true);
  }, []);

  if (!isMounted) {
    return null; // Or return a simple loading skeleton
  }

  return (
    <div>
      {/* Now this will only render on the client */}
      <p>The time is: {new Date().toLocaleTimeString()}</p>
    </div>
  );
}

By returning null or a static placeholder during the initial server render, you ensure that the server and client are perfectly synced. Once the component hits the browser and runs the useEffect, the state flips to true, and React re-renders with your dynamic content. Since the server-side output (the loading state) now matches the initial client-side output, the hydration error vanishes instantly.

The best way to prevent this in the future is to keep a close eye on your dependencies. If you are using any library or logic that relies on window or document, always wrap it in a custom hook that checks for the component's mount status. It’s a tiny bit of extra boilerplate, but it saves you from losing your mind during your next deployment.

Hope this helps you get your app back on track without the headache. Happy coding!

React 18 Hydration 大魔王：為什麼伺服器跟瀏覽器總是不對盤？

來源：Stack Overflow ↗ · 341 票

那天我正準備把一個舊專案升級到 Next.js 搭配 React 18，想說順手把 SSR（伺服器端渲染）優化一下。結果程式一跑起來，瀏覽器控制台直接噴出一大串紅通通的「Hydration failed」錯誤訊息，畫面還閃爍了一下才載入，當時的我盯著螢幕，內心真的只有無數個問號，差點直接把鍵盤砸了。最痛苦的是，明明程式碼看著都沒錯，但在開發環境裡就是死活不肯乖乖配合，那種「我明明寫了，但瀏覽器說沒看到」的無力感，真的是工程師職涯中的惡夢。

其實這個問題的核心很簡單，就是「資訊不對稱」。簡單來說，React 的 SSR 流程是這樣的：伺服器先跑一次程式碼，產生出靜態的 HTML 傳給瀏覽器，然後瀏覽器再接手，把這些靜態 HTML 變成活蹦亂跳的互動頁面。但因為 React 18 強調效能，它會嚴格比對伺服器產出的 HTML 跟瀏覽器第一次渲染出來的結果。如果兩者有丁點不同，像是你用了 new Date()、隨機數 Math.random()，或是判斷裝置類型的邏輯，導致伺服器算出來的結果跟瀏覽器算出來的不一樣，React 就會因為「覺得被騙了」而直接報錯，甚至乾脆放棄渲染，直接讓畫面爛掉。

我後來發現，最常見的兇手通常是因為我在組件裡直接用了 window 物件或是瀏覽器特有的 API。解決這個問題，最直接的手段就是讓組件「先閉嘴」，等到瀏覽器確定載入完畢之後，再執行那些會造成不一致的邏輯。我通常會寫一個簡單的 useEffect 來處理，確保這段程式碼只會在客戶端執行，像這樣：


import { useState, useEffect } from 'react';

function MyComponent() {
  const [isClient, setIsClient] = useState(false);

  useEffect(() => {
    setIsClient(true);
  }, []);

  if (!isClient) return null; // 或者給個 Loading 狀態

  return <div>這裡放那些會導致 Hydration 錯誤的內容：{window.innerWidth}</div>;
}

透過這種方式，伺服器渲染時會先回傳一個乾淨的狀態，等到瀏覽器真的接手後，再把真正的內容補上去，這樣兩邊的結果就能完美契合了。

至於要怎麼預防下次再被這種問題搞到崩潰？我覺得最重要的一點就是養成「防禦性寫作」的習慣。在寫任何會依賴環境變數或是瀏覽器 API 的功能時，心裡都要先閃過一個念頭：「這東西在 Server 端還存在嗎？」只要保持這個警覺，多利用 useEffect 或者 dynamic import 把這些邏輯隔離在客戶端，基本上就能避開 90% 的 Hydration 陷阱。

搞定這個之後，看著控制台終於恢復乾淨的樣子，那種成就感真的無價。希望這篇筆記能幫你少掉幾根頭髮，我們下次再見！
