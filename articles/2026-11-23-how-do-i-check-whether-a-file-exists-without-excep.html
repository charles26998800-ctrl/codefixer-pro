How to Check If a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7352 votes

Early in my career, I remember staring at a script that was supposed to process a batch of CSV files, only to watch it crash every time a single file was missing. I spent three hours debugging a mess of nested try-except blocks because I thought it was the only "Pythonic" way to handle file paths, only to realize I was making my code look like a plate of spaghetti. It was incredibly frustrating to realize that I was essentially using a sledgehammer to crack a nut when I just needed to verify a file's presence.

The root cause of this confusion usually stems from the "Easier to Ask for Forgiveness than Permission" (EAFP) philosophy that Python champions. While EAFP is generally a great pattern, it doesn't mean you have to wrap every single file operation in a try-except block. Sometimes, you just need a simple boolean check to decide whether to skip a file or log an error, and forcing an exception handling flow for simple existence checks can make your code noisy and harder to read.

If you want to check for a file without the overhead of exception handling, the standard library’s pathlib module is my go-to recommendation. It’s been the modern standard since Python 3.4, and it makes your code look much cleaner. You simply instantiate a Path object and call the is_file() method.


from pathlib import Path

file_path = Path("my_data.csv")

if file_path.is_file():
    print("The file exists and is ready for action.")
else:
    print("File not found, skipping this one.")

If you’re stuck working on a legacy codebase that uses the older os module, you can still avoid exceptions by using os.path.exists(). It returns a boolean and is perfectly reliable for basic checks, though I’ll always lean toward pathlib because it handles path manipulations much more gracefully across different operating systems.


import os

if os.path.exists("my_data.csv"):
    print("The file is there.")

To prevent this kind of headache in the future, my best advice is to stop using file existence checks as a prerequisite for opening files. Even if you check that a file exists, a race condition could occur where the file is deleted or moved a millisecond later. The best pattern is to write your code to handle the actual FileNotFoundError when you attempt to open the file. Reserve the is_file() checks for when you truly need to change the program's logic based on the file's existence, not as a gatekeeper for basic I/O operations.

I hope this helps you clean up your scripts and save some of those precious hours I lost. Happy coding!

別再用 try-except 檢查檔案了：Python 檢查檔案存在的正確姿勢

來源：Stack Overflow ↗ · 7352 票

記得剛開始寫 Python 那會兒，為了處理一個自動化腳本，我滿腦子只想著「暴力破解」。當時我天真地用 try-except 包住所有讀取檔案的操作，結果程式跑起來簡直是一場災難，效能慢到我想哭，而且因為邏輯寫得太髒，後來要維護時，看著滿螢幕的 except 區塊，我真的差點崩潰，完全搞不懂哪一個異常才是真的系統出錯。

這其實是因為很多新手（包含當年的我）都有個迷思，覺得 Python 的哲學是「請求寬恕勝過許可」（EAFP），所以遇到檢查檔案這種事，直覺就想用 try-except 來接錯誤。但說實話，如果只是想確認檔案在不在，還要走一遍異常處理的流程，那開銷真的太大了。這就像是為了知道門鎖了沒，你直接把門踹開再修好它一樣，既沒效率又折騰，更別提如果在高頻率讀取的迴圈裡這麼幹，你的程式會卡得像在跑幻燈片。

後來我學乖了，其實 Python 的 pathlib 模組根本就是神器。現在我只要檢查檔案，都會直接用 pathlib.Path。它不僅語法簡潔，而且讀起來跟讀英文句子沒兩樣，完全不需要什麼複雜的錯誤捕捉。像這樣寫：


from pathlib import Path

file_path = Path('my_data.txt')

if file_path.exists():
    print("檔案就在這，可以開工了！")
else:
    print("檔案消失了，是不是被誰移走了？")

如果你是在維護一些比較舊的程式碼，或是剛好只需要快速檢查，os.path.exists() 也是個老字號的選擇，但我個人強烈建議擁抱 pathlib，因為它處理路徑的方式真的優雅太多了。

至於怎麼預防這種「檢查後檔案又消失」的 Race Condition 悲劇，我後來養成了個習慣：檢查歸檢查，但永遠不要假設檔案在檢查完後一定還會乖乖在那裡。最穩的做法，其實是在實際讀取時還是得保留最底層的錯誤處理，但這不是為了讓你「隨便寫」，而是為了處理那些「萬一檔案剛好在這一毫秒被刪除」的極端情況。把檢查當成是一種「流程優化」，而不是「絕對保證」，你的程式碼穩定度絕對會提升好幾個檔次。

希望這些建議能救你一命，別再讓那堆沒必要的 try-except 塞滿你的程式碼啦！趕快去把那些髒髒的邏輯修掉，今晚就能準時下班了。
