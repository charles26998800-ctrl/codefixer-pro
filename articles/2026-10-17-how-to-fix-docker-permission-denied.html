How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1420 votes

I still remember the first time I set up Docker on a fresh Ubuntu install. I was feeling pretty productive, ready to spin up a containerized development environment, but when I typed docker run hello-world, I was greeted with that dreaded "permission denied" wall. I spent a good two hours convinced I’d somehow corrupted my entire system installation before realizing it was just a simple group membership issue—a classic rite of passage for every developer starting their journey with containers.

The reason you’re seeing this error is that the Docker daemon binds to a Unix socket rather than a TCP port by default, and that socket is owned by the root user. Unless you’re running as root, you don't have the necessary privileges to interact with it. When you prepend sudo to your command, you’re essentially telling the system to run the request with root authority, which bypasses the restriction. It's safe, but it's also a major pain to type every single time you want to check your logs or restart a container.

To fix this for good, you need to add your user to the docker group, which grants you the permissions required to communicate with the daemon socket without needing root elevation. First, I always make sure the group exists by running sudo groupadd docker. Once that’s handled, I add my current user to the group with this command:


sudo usermod -aG docker $USER

After you run that, the changes won't take effect immediately. You’ll need to either log out and log back in or, if you’re feeling impatient like I usually am, just run newgrp docker to refresh your group membership for the current shell session. You can verify it worked by running docker run hello-world without any sudo prefix. If the output shows the "Hello from Docker!" message, you’re officially good to go.

Moving forward, the best way to prevent this from sneaking up on you is to always verify your group memberships during your initial server setup phase. Whenever I provision a new machine, I include the usermod command in my post-install script immediately after installing the Docker engine. It saves me from that momentary panic when I eventually forget to type sudo on a command I've run a thousand times before.

Hope this clears up your terminal woes and gets you back to coding. Let me know if you run into any other weird permission hiccups!

Docker 老是跳 Permission denied？別再無腦加 sudo 了！

來源：Stack Overflow ↗ · 1420 票

記得剛踏入 Docker 世界的那幾天，我簡直快被 sudo 搞到崩潰。當時我正準備部署一個小專案，滿心期待輸入 docker run hello-world，結果螢幕直接噴出一大串紅字，說什麼無法連接到 /var/run/docker.sock。當下我心裡的第一個反應是：「蛤？我不是剛安裝完嗎？難道是我人品不好？」最痛苦的是，每次為了跑個容器都要打一遍 sudo，搞得我開發節奏完全被打亂，甚至有幾次因為權限衝突，搞到 Docker 容器裡的檔案權限全亂掉，光是修這些權限就花了半個下午，真的是挫折感滿滿。

其實這問題的根本原因很單純，就是 Docker daemon 在 Ubuntu 底下是以 root 權限運行的，而我們一般的帳號預設並沒有權限去碰那個 socket 檔案。想像一下，那個 socket 就像是 Docker 的大門鑰匙，系統為了安全，預設只把鑰匙交給 root，所以當你不用 sudo 時，Docker 就會覺得你是一個「沒鑰匙的陌生人」，直接把你擋在門外。

解決方法其實不用這麼麻煩，只要把你自己的帳號加入 docker 這個群組就搞定了。我當時是在終端機輸入這幾行指令，問題就迎刃而解了：


# 建立 docker 群組（通常安裝時就有了，但保險起見跑一下也無妨）
sudo groupadd docker

# 把當前使用者加入 docker 群組
sudo usermod -aG docker $USER

不過要注意，執行完這些指令後，並不會馬上生效。你必須要讓系統重新讀取你的群組權限，最快的方法就是直接登出再登入，或者更暴力一點直接重開機。如果不想重開機，也可以用 newgrp docker 這個指令強制讓當前的 shell 重新啟用群組權限，這樣你就可以直接在當前的視窗暢行無阻了。

為了預防這種「權限地獄」再次發生，我建議大家以後安裝完 Docker 後，第一件事就是把這組設定寫進你的個人環境配置清單裡。只要記得「把自己加入群組」這個動作，之後就再也不用擔心 sudo 權限卡手，開發效率真的會提升不少。

搞定這個設定後，以後敲指令就能俐落多了，再也不用在那邊糾結要不要加 sudo 啦！
