Why You’re Seeing "error:0308010C:digital envelope routines::unsupported" and How to Fix It

Source: Stack Overflow ↗ · 2572 votes

I remember exactly where I was when this error first hit my terminal—I’d just upgraded my local machine to Node.js v17, feeling pretty proud about keeping my stack updated, only to have my entire React dev server crash instantly. I spent three hours digging through cryptic GitHub issues and convinced myself I’d somehow corrupted my entire node_modules folder, but it turned out to be a classic case of "new tech, old dependencies" biting me in the back.

The reason this error pops up is actually quite simple, even if the message looks like total gibberish. When Node.js bumped up to version 17, they switched to a newer version of the OpenSSL library, which tightened up security by default. A lot of older tools, like the Webpack versions used in many React templates, rely on an older hashing algorithm that this new OpenSSL version considers "insecure" and refuses to run. Basically, your build tool is trying to use an old crypto method, and Node is slamming the door in its face.

Fixing this is luckily straightforward, and you don't need to downgrade your entire Node environment to get back to work. Since this is an environment-level configuration, the easiest way to handle it is by telling Node to allow those legacy algorithms before you run your start script. If you’re on a Mac or Linux machine, you just need to prepend the NODE_OPTIONS environment variable to your command in your package.json file like this:


"scripts": {
  "start": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

If you’re working on Windows, the syntax changes slightly because of how the command prompt handles environment variables, so you’ll want to use set instead:


"scripts": {
  "start": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

If you want to avoid this headache in the future, the best move is to keep your project dependencies as current as possible. This error is a massive signal that your build tools are drifting away from the modern ecosystem, so running npm outdated or using a tool like npm-check-updates every once in a while will save you from these legacy configuration nightmares.

Hope this gets your project back up and running so you can get back to building cool stuff. Happy coding!

救命！跑個 React 專案怎麼就噴出個 digital envelope routines 錯誤？

來源：Stack Overflow ↗ · 2572 票

那天我剛升級完電腦的 Node.js 版本，想說趁著週末把手邊一個放了很久的 React 專案打開來跑跑看。結果指令 npm start 才剛敲下去，終端機馬上跳出一大串紅通通的錯誤訊息，重點還是那個看都看不懂的 error:0308010C:digital envelope routines::unsupported。當時我真的差點崩潰，明明上週才跑得好好的，怎麼只是更新個環境，整個世界就好像跟我過不去一樣，連開發伺服器都啟動不了。

後來我才搞懂，原來這一切都是 Node.js 17 版本之後搞的鬼。Node.js 從那時候開始升級了 OpenSSL 到 3.0，這玩意兒對加密演算法的要求變嚴格了，而我們舊專案裡面用的 Webpack 4 或者一些老舊的套件，還在使用舊版的加密演算法，這兩邊就像是雞同鴨講，OpenSSL 看到這些舊東西直接翻臉說「我不支援」，於是你的專案就這樣卡在半路動彈不得。那種明明程式碼一行都沒改，卻因為底層環境變動而報錯的無力感，真的是每個工程師心頭永遠的痛。

要解決這個問題，其實最快的方式就是告訴 Node.js：「嘿，請暫時放寬心，幫我啟用舊版的加密演算法支援吧！」我當時就是在終端機直接設定一個環境變數來繞過這個檢查。如果你是用 macOS 或 Linux，只要在執行指令前加上 NODE_OPTIONS 就行了：


export NODE_OPTIONS=--openssl-legacy-provider
npm start

如果你是用 Windows 的 PowerShell，語法會稍微長一點點：


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

如果不想每次開專案都要打這串，最懶人也最推薦的做法，是直接去你的 package.json 裡面，把 scripts 的啟動指令改掉。把 "start": "react-scripts start" 改成這樣：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

這樣以後你只要無腦輸入 npm start，系統就會自動幫你處理好那些麻煩的加密設定，再也不用擔心報錯了。

至於怎麼預防這種鳥事再發生，我的建議是盡量幫專案導入 nvm (Node Version Manager) 來管理環境。畢竟這年頭 React 生態系變動得太快，不同的專案有時真的需要不同版本的 Node.js 才能和平共處，用 nvm 隨時切換版本，比起跟 OpenSSL 的版本衝突硬碰硬要聰明多了。

好了，現在趕快去試試看，希望你的終端機也能順利跑出綠色的成功訊息！
