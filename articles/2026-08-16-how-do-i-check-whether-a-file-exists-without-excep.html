How to Check If a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7349 votes

Early in my career, I remember writing a file-processing script that was littered with try...except IOError blocks. I thought I was being "Pythonic" by embracing EAFP (Easier to Ask for Forgiveness than Permission), but I ended up with a mess of nested logic that made my head spin. I spent three hours debugging a race condition where a file would vanish right between the time I checked for it and the time I tried to open it, and I realized that sometimes, you just need a simple, clean way to look before you leap.

The reason this is such a common point of confusion is that Python offers two different eras of file system management. You’ve got the older os.path module, which is functional but feels a bit dated, and the modern pathlib module, which treats file paths as actual objects rather than just strings. When you're trying to avoid exception handling, it's usually because you want to keep your control flow linear and readable. The root cause of why this feels tricky is that the file system is inherently volatile; even if you check that a file exists, it might be deleted by another process a millisecond later. That’s why purists argue for try-except, but for simple scripts or logging, checking existence first is often exactly what you need.

When I need to keep my code clean and avoid the boilerplate of error handling, I reach for pathlib. It’s built into the standard library and is much more expressive than the old-school os module. Here is the modern way to do it:


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.exists():
    print("The file is there!")
else:
    print("No file found.")

If you’re working on a legacy codebase or just prefer the classic approach, os.path.exists still gets the job done perfectly well. It’s just a simple function call that returns a boolean, which is exactly what you’re looking for if you want to avoid try blocks:


import os

if os.path.exists("my_data.txt"):
    print("File exists, proceed with caution.")

To prevent the classic "check-then-act" trap, my biggest piece of advice is to keep your logic as tight as possible. If you check for a file's existence and then perform an operation on it five lines of code later, you’re inviting a race condition where the file could be moved or deleted in the interim. Always try to perform the check immediately before the action, or better yet, use a context manager to handle the file operation safely even if the file isn't where you expect it to be.

Hope this clears up the confusion and helps you write some cleaner, more readable code. Happy coding!

檢查檔案存不存在，真的非得用 try-except 嗎？

來源：Stack Overflow ↗ · 7349 票

剛入行那陣子，我寫了一個自動化搬運 Log 的腳本，當時為了處理「檔案如果不存在就跳過」的需求，我幾乎在每個讀取檔案的地方都塞了 try...except FileNotFoundError。結果那個腳本跑起來簡直像是在演災難片，整個程式碼被大量的例外處理包得密不透風，邏輯亂到連我自己都看不下去，差點就在趕專案的半夜對著螢幕崩潰。最痛苦的是，當我試著去 debug 邏輯錯誤時，因為到處都是例外處理，根本分不清到底是檔案真的不在，還是程式邏輯跑偏了。

其實會發生這種困擾，是因為 Python 的哲學一向是「請求原諒比請求許可更容易」（EAFP），所以官方文件才一直鼓勵大家用 try...except。但說實話，在某些簡單的情境下，為了判斷一個檔案存不存在而寫那一大串程式碼，真的會讓整體的閱讀體驗變得非常差，感覺就像為了喝一杯牛奶，卻得先養一頭牛一樣誇張。

後來我學乖了，改用 pathlib 這個現代化的模組。它處理這類問題真的優雅太多了，你不需要再寫那些囉唆的例外處理，只需要透過 path.exists() 就能直接得到一個布林值。如果你只是想確認檔案在不在，用這個方法真的清爽很多：


from pathlib import Path

file_path = Path('my_data.txt')

if file_path.exists():
    print("檔案還在，可以安心工作了！")
else:
    print("檔案不見了，先休息一下吧。")

當然，使用這個方法要注意一個經典的「競態條件」（Race Condition）問題。雖然 exists() 檢查完檔案存在，但在你執行下一步操作的那幾毫秒內，檔案還是有可能被其他程序刪除。如果你的程式涉及多執行緒或高併發，我還是強烈建議回歸 try...except 的懷抱，因為那才是最嚴謹的「原子操作」。

為了避免以後再因為這些瑣事踩坑，我現在的原則很簡單：如果只是寫寫簡單的腳本，就用 pathlib 讓程式碼乾淨點；但如果是要上線的正式服務，那就乖乖用 try...except，別為了省那幾行程式碼，最後反而讓系統變得脆弱。

寫程式嘛，最重要的是讓未來的自己好讀、好維護，別為了追求「無例外」而讓程式變得更複雜。
