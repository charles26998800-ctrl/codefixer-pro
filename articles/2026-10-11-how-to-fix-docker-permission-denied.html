How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1420 votes

I remember the first time I set up my dev environment on a fresh Ubuntu install; I felt like a total pro until I tried to run my first container and got slapped with a "Permission denied" error. I spent a good hour convinced I’d botched the entire Docker installation, frantically reinstalling packages and scouring forums, only to realize I was just missing a simple user group configuration. It’s one of those classic "gotcha" moments that makes you feel like you’re back at square one, even when you know exactly what you’re doing.

The reason you’re seeing this error is actually pretty straightforward. By default, the Docker daemon binds to a Unix socket owned by the root user, not your local user account. When you run a command without sudo, the Docker client tries to communicate with that socket, but the Linux kernel shuts it down because your user doesn't have the required permissions. Using sudo works because you’re essentially "becoming" root, but let’s be honest—typing sudo before every single command is a massive productivity killer that gets old fast.

To fix this for good, you need to add your user to the docker group, which grants you the necessary permissions to interact with the daemon without elevated privileges. First, you’ll want to create the group if it doesn't already exist:


sudo groupadd docker

Once that’s set, add your current user to that group using the following command:


sudo usermod -aG docker $USER

After you’ve run that, the most important part is to refresh your group membership. You don’t need to reboot your entire machine, but you do need to log out and log back in, or run this command to apply the changes to your current shell session:


newgrp docker

Once you’ve done that, you can test it by running docker run hello-world without the sudo prefix. If the container pulls and executes successfully, you’re all set.

Moving forward, the best way to prevent this from sneaking up on you again is to automate your environment setup. If you’re setting up a new machine, I highly recommend keeping a small bash script in your dotfiles that handles these group assignments automatically. It saves you the headache of remembering these commands every time you switch laptops or spin up a new cloud instance.

Hope this saves you some frustration today—happy coding!

Docker 權限被拒？別再每次都敲 sudo 了！

來源：Stack Overflow ↗ · 1420 票

記得剛開始接觸 Docker 時，為了趕著部署一個測試環境，我整個人心急如焚。當我興奮地輸入 docker run hello-world 想驗證安裝成功沒，終端機卻冷冷地丟回一句 permission denied，當時我心裡真的只想罵髒話，心想：「明明安裝過程都順利跑完，為什麼連個 hello-world 都跑不起來？」最慘的是，每打一次指令都要補上 sudo，搞得我開發節奏完全被打亂，甚至有幾次因為權限問題，把掛載的檔案權限搞得亂七八糟，那個當下真的會讓人崩潰到想把電腦關掉休息。

其實這問題一點都不複雜，原因在於 Docker daemon 預設是透過 Unix socket 來溝通的，而這個 socket 檔案的擁有者是 root。當你用一般使用者身份去執行 Docker 指令時，系統發現你的權限不足以存取這個 socket，所以直接把你擋在門外。這就像是你拿著遊樂園的票卻想硬闖員工專用通道，門口的守衛當然會攔下你。

要解決這個問題，其實只要把你當前的使用者帳號加入到 docker 這個群組就好。這樣你就能在不需要 root 權限的情況下，直接跟 Docker daemon 溝通。首先，你要建立一個 docker 群組（通常安裝時會自動建立，但檢查一下比較保險）：


sudo groupadd docker

接著，把你的使用者帳號塞進去：


sudo usermod -aG docker $USER

這裡有個關鍵動作千萬別漏掉，你必須登出再重新登入，或者直接重開機，讓權限設定生效。如果懶得重開機，也可以在終端機輸入 newgrp docker 強制更新當前的群組權限。設定完成後，試著再次執行 docker run hello-world，如果一切正常，系統就會直接跑出那段熟悉的歡迎訊息，從此告別惱人的 sudo。

以後如果遇到新開的機器，我建議在安裝完 Docker 的當下，就先把這個群組設定加進去。養成這個好習慣，之後不管是在寫 Dockerfile 還是處理 volume 掛載時，都不會再因為權限問題卡住，開發體驗真的會順暢非常多。

總算不用再當個「sudo 奴隸」了，現在可以開開心心地繼續寫程式囉！
