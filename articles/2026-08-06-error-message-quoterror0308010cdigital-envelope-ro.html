How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I upgraded my Node.js version to 17, feeling all smug about having the latest tech, only to have my entire build pipeline explode the moment I ran npm start. I spent a solid two hours staring at the console, convinced I’d somehow corrupted my entire project, before realizing the issue had absolutely nothing to do with my code and everything to do with a sudden security shift in the Node ecosystem. It’s one of those classic "everything was working fine yesterday" moments that makes you want to throw your monitor out the window.

The reason this error pops up is actually quite simple, even if the error message itself sounds like it’s written in an ancient, cryptic language. When Node.js moved to version 17 and beyond, they updated OpenSSL to version 3.0. This new version introduced stricter security standards that essentially reject older, less secure algorithms, like MD4, which a lot of older Webpack versions used for hashing. Since your React build process relies on these older dependencies, the new Node environment hits a wall and throws that "digital envelope routines" error because it refuses to play ball with the legacy crypto routines.

Fixing this is luckily straightforward, and you don’t need to downgrade your entire development environment just to get a project running. The easiest way to bypass this is by telling Node to allow these legacy algorithms through an environment variable. If you’re on a macOS or Linux machine, you just need to prepend the export command to your start script in your package.json file. Change your start script to look like this:


"scripts": {
  "start": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "export NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

If you happen to be on Windows, the syntax changes slightly because of how the command prompt handles environment variables. You’ll want to use set instead:


"scripts": {
  "start": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts start",
  "build": "set NODE_OPTIONS=--openssl-legacy-provider && react-scripts build"
}

If you want to avoid these headaches in the future, my best advice is to embrace a version manager like nvm (Node Version Manager). It allows you to switch between different Node versions per project easily, so you can keep your legacy projects running on Node 16 while using the latest stable version for your new work. It’s saved me from countless dependency conflicts and lets me keep my sanity intact.

Hope this gets your build back on track and saves you that two-hour headache I dealt with. Happy coding!

又是 Node.js 版本惹的禍：解決 error:0308010C:digital envelope routines::unsupported

來源：Stack Overflow ↗ · 2572 票

上週我為了開發一個簡單的 React 練習專案，興致勃勃地打開 IntelliJ IDEA 點了建立專案，結果編譯瞬間噴出一大串紅通通的錯誤訊息，當下我真的是差點崩潰，心想「我才剛開始寫程式欸，連一行 Code 都還沒動，為什麼世界要這樣對我？」。那種明明環境都裝好了，卻卡在第一步的無力感，真的是每個工程師這輩子最想刪除的記憶之一。

其實會出現這個 digital envelope routines::unsupported 的錯誤，歸根究底就是 Node.js 版本更迭造成的「代溝」。簡單來說，從 Node.js v17 開始，官方引入了 OpenSSL 3.0，這玩意兒對加密演算法的要求變嚴格了，而我們舊有的專案或是某些 Webpack 版本還在使用舊的演算法，兩邊兜不起來，OpenSSL 就直接拒絕執行，導致你的打包工具（Webpack）直接罷工。

解決方法其實比想像中簡單很多，你不需要去改動那些看不懂的底層設定，最快的方式就是告訴 Node.js：「嘿，請你用舊版的加密邏輯去跑就好」。如果你是在 Mac 或 Linux 環境，只要在啟動指令前面加上 NODE_OPTIONS=--openssl-legacy-provider 就可以搞定。如果是 Windows 的 PowerShell 使用者，指令會稍微長一點點。

我在我的 package.json 裡是這樣處理的，直接把啟動指令改成：


"scripts": {
  "start": "NODE_OPTIONS=--openssl-legacy-provider react-scripts start",
  "build": "NODE_OPTIONS=--openssl-legacy-provider react-scripts build"
}

如果你是用 Windows 的 CMD，記得要用 set 指令，或者乾脆安裝一個叫 cross-env 的套件，這樣寫就不管在哪個作業系統都能跑，完全不用擔心跨平台的問題。

說到預防這類問題，我現在學乖了，養成習慣在每個新專案目錄下放一個 .nvmrc 檔案，裡面寫上你目前開發環境使用的 Node 版本。這樣下次當你換了一台電腦，或是過幾個月再回來維護舊專案時，只要執行 nvm use 就能自動切換到正確的版本，不用再為了這些環境相容性問題抓狂。

希望這篇筆記能幫你把寶貴的時間省下來，去寫更有趣的邏輯，而不是在那邊跟環境變數打架。祝你的開發過程順利，別再被這些莫名其妙的 Error 給卡住啦！
