How to Check if a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7352 votes

Early in my career, I was building a log-parsing script that had to scan thousands of directories, and I remember obsessively wrapping every single file operation in massive try-except blocks. I spent three hours debugging why my code was running at a snail's pace, only to realize the overhead of catching exceptions in a tight loop was absolutely killing my performance. I felt like a total amateur when I realized there were much cleaner, more "Pythonic" ways to handle existence checks without constantly relying on error handling.

The reason we often reach for try-except is that it’s the standard way to follow the "Easier to Ask for Forgiveness than Permission" (EAFP) principle in Python. While that’s usually great advice, checking for a file's existence is one of the few places where "Look Before You Leap" (LBYL) actually makes sense. When you use try-except, you’re essentially asking the operating system to try to open the file and then panicking if it fails; if you're doing this inside a massive loop, that context switching and error handling overhead adds up fast.

If you want to keep your code clean and skip the exception handling, the modern way to do this is by using the pathlib module. It’s been the standard since Python 3.4, and honestly, it’s a breath of fresh air compared to the old os.path syntax. You just create a Path object and call the exists() method. It’s readable, expressive, and doesn't trigger the heavy machinery of an exception if the file isn't there.


from pathlib import Path

file_path = Path("my_data_file.txt")

if file_path.exists():
    print("The file is right where it belongs.")
else:
    print("No file found, moving on gracefully.")

If you’re stuck on a legacy system or just prefer the classic approach, the os.path module still works perfectly fine. You’ll use os.path.isfile() to verify the file specifically, which is often safer than exists() because it ensures you’re dealing with an actual file and not a directory that happens to share the same name.


import os

if os.path.isfile("my_data_file.txt"):
    print("Confirmed: this is a file and it exists.")

To prevent these kinds of headaches in the future, my best tip is to always watch out for "race conditions." Even if you check that a file exists, another process could delete it a millisecond later before you actually open it. So, while these methods are great for simple scripts and flow control, if you’re building something mission-critical, you should still keep a light try-except block around the actual open() call just to be safe.

Hope this helps you clean up your codebase and save you some of the frustration I dealt with back in the day. Happy coding!

別再為了檢查檔案存不存在寫滿滿的 try-except 了！

來源：Stack Overflow ↗ · 7352 票

記得剛入行那年，我寫了一個自動化處理報表的 Python 腳本，當時為了要確認設定檔在不在，我心想「反正 Python 強調 EAFP（請求原諒比請求許可容易），直接 try-except 就對了」。結果那天為了趕專案進度，我寫了整整五層嵌套的 try-except 結構，程式碼醜到連我自己都看不下去。最崩潰的是，後來因為一個權限錯誤觸發了 except，我竟然傻傻地以為檔案真的不存在，結果花了一個下午在除錯，最後才發現檔案就在那裡，只是我沒權限讀取，那個當下真的恨不得把鍵盤給摔了。

其實會遇到這種「為了檢查檔案」而頭痛的問題，主要是因為我們太執著於 Python 的傳統風格，或者說是對 os 模組的用法還不夠靈活。很多新手（包含當年的我）以為要判斷檔案在不在，一定要用 try-except FileNotFoundError 來包住開啟檔案的動作，但當你的邏輯變得複雜，或者你只是想在讀取前先做個簡單的檢查時，這種寫法不僅冗長，還會讓程式碼的可讀性瞬間掉到谷底，甚至像我當年一樣，因為錯誤捕獲太籠統而造成邏輯判斷上的災難。

後來我學乖了，直接改用 Python 3.4 後內建的 pathlib 模組，這東西簡直是救星。你不需要再去處理那些煩人的例外，只要一行程式碼就能搞定。現在我的習慣是直接這樣寫：


from pathlib import Path

file_path = Path('config.json')

if file_path.exists():
    print("檔案找到啦！可以開始工作了。")
else:
    print("檔案不存在，跳過處理程序。")

這不僅看起來乾淨俐落，而且 pathlib 把路徑處理變成物件導向的形式，比起以前那種 os.path.exists() 的寫法，操作起來直覺太多了。如果你還在用舊版的 os 模組，我也建議你趕快換過來，畢竟誰想在維護程式碼時，還要花腦袋去解讀那堆亂七八糟的錯誤處理機制呢？

至於怎麼預防這種無謂的折騰，我的建議很簡單：不要過度依賴例外處理來做「流程控制」。如果你只是單純想知道檔案在不在，那就用 pathlib 的 exists()；如果你是要確保程式穩定，那就在讀取檔案時再用 try-except 去處理權限不足或檔案損壞等「真正的異常」。把邏輯檢查跟異常處理分開，你的程式碼看起來會清爽很多，改天回頭看時也不會想揍當年的自己。

希望大家都能少踩點坑，寫程式這條路已經夠累了，讓它保持簡潔一點吧！
