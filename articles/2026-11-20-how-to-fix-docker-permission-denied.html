How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1420 votes

I still remember the first time I set up Docker on a fresh Ubuntu install. I was feeling pretty productive, finally ready to spin up a containerized environment, but every time I typed docker run, I was greeted with that dreaded "permission denied" wall. I spent nearly two hours convinced I’d botched the entire installation, repeatedly purging and reinstalling the daemon like a madman before I finally realized I was just fighting a simple group membership issue.

The reason you’re running into this is actually quite logical once you peek under the hood. By default, the Unix socket at /var/run/docker.sock is owned by the root user and the docker group. When you run a command without sudo, your standard user account doesn't have the necessary privileges to talk to that socket. It’s a security feature—Docker essentially gives you root-level access to your host machine, so the system tries to keep that gate locked unless you explicitly give yourself the keys.

To fix this, you don't need to keep typing sudo every single time you want to fire up a container. Instead, you need to add your user to the docker group. First, you'll want to create the group if it doesn't already exist:


sudo groupadd docker

Once that's sorted, go ahead and add your current user to that group:


sudo usermod -aG docker $USER

Here’s the part that catches most people off guard: this change isn't instant. You have to log out and log back in, or restart your terminal session, for the group changes to actually take effect. If you're in a hurry and can't log out, you can run newgrp docker in your current terminal to refresh your group membership manually. You can verify it worked by running docker run hello-world without the sudo prefix. If you see the "Hello from Docker!" message, you're officially in the club.

The best way to prevent this from ruining your flow in the future is to make it part of your "new machine" checklist. Whenever I provision a new dev environment or spin up a fresh VM, I add this group configuration immediately after installing the Docker engine. It’s a small step that saves you from having to type sudo a thousand times a day and keeps your command history looking clean.

Happy containerizing, and hopefully, this saves you from the same headache I had!

為什麼每次跑 Docker 都要加 sudo？真的會打到心很累！

來源：Stack Overflow ↗ · 1420 票

還記得剛開始學 Docker 的時候，我滿心期待地想把第一個 container 跑起來，結果終端機直接賞我一臉「Permission denied」。當時我以為是我哪裡指令打錯，反覆檢查了半天，最後發現加個 sudo 就能過，於是接下來的一個月，我每天都在跟這個多出來的單字搏鬥。最痛苦的時刻，莫過於在寫自動化部署腳本時，因為權限問題一直卡住，明明程式邏輯都對，卻被一個權限設定搞到深夜兩點還在抓狂，那種無力感真的讓人很想把鍵盤砸了。

其實這背後的原因一點都不複雜，簡單來說，Docker daemon 預設是綁定在 Unix socket 上的，而這個 socket 檔案的擁有者是 root。當你不用 sudo 去執行 docker 指令時，你的使用者帳號並沒有權限去存取這個 socket，所以 Docker 就直接拒絕你的連線請求。雖然加 sudo 是最快的解法，但這就像是你每次進自家大門都要先去申請通行證一樣，真的太麻煩也太不安全了。

要解決這個問題，其實只要把你目前的使用者加進 docker 這個群組就好。我當時是這樣做的，先建立一個 docker 群組（通常安裝時就有了，但保險起見還是確認一下）：


sudo groupadd docker

接著，把你的使用者帳號丟進去：


sudo usermod -aG docker $USER

重點來了，很多工程師改完這行指令就以為好了，結果發現還是報錯。其實你必須要登出系統再重新登入，或者直接執行 newgrp docker 來讓變更生效。當你看到 docker run hello-world 不用加 sudo 就能噴出那些歡迎訊息時，那種順暢的感覺真的會讓人感動得想哭。

為了避免以後又遇到這種權限地獄，最簡單的預防建議就是養成習慣：以後在安裝完 Docker 的第一時間，就直接把當前使用者加入群組。這樣以後不管是跑什麼 container，都不用再心不甘情不願地補上那個 sudo 了。

總算不用再跟 sudo 糾纏不清了，希望這招能幫你省下不少崩潰的時間。
