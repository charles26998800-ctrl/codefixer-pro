How to Check if a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7351 votes

Early in my career, I was building a log-processing utility that felt like it should take me thirty minutes to finish. I ended up spending three hours debugging because I was obsessed with using try-except blocks for every single file operation, which turned my clean logic into a nested nightmare of unreadable spaghetti code. I remember staring at my screen, frustrated that something as simple as verifying a file's existence required so much boilerplate, and that’s when I finally decided to learn the proper, idiomatic ways to handle path checks in Python.

The reason developers often trip over this is because Python’s philosophy is famously "Easier to Ask for Forgiveness than Permission" (EAFP). The standard approach is to just try opening the file and catch the FileNotFoundError if it fails. However, there are times—like when you’re building a UI that needs to toggle a button state or simply checking if a configuration file is present before kicking off a process—where you don't actually want to open the file yet. You just want a boolean answer. Using try-except for control flow in these cases feels like using a sledgehammer to crack a nut, which is why the pathlib module was introduced to save us from that headache.

To fix this, I stopped relying on the older os.path module and fully embraced pathlib. It’s built into Python and makes the code much more readable. If I need to check if a file exists, I simply import Path and call the .exists() method. It’s clean, it’s object-oriented, and it gets the job done without any exception handling bloat.


from pathlib import Path

file_path = Path("config.json")

if file_path.exists():
    print("The file is right where it should be.")
else:
    print("File not found, skipping...")

If you need to be extra careful and confirm that the path isn't just a folder masquerading as a file, you can use .is_file() instead. It’s a small detail, but it’s saved me from plenty of runtime errors when a stray directory happens to share the same name as my expected input file.

The best way to prevent this kind of confusion is to stop thinking about file existence as an "exception" and start thinking about it as a state. If you’re planning on reading the file immediately after checking it, just use a try-except block anyway to handle race conditions—where a file might be deleted by another process the millisecond after you check it. Save these boolean checks for when you truly just need to verify presence without performing an I/O operation immediately.

Hope this clears up the confusion and saves you from the same three-hour rabbit hole I fell down. Happy coding!

別再用 try-except 檢查檔案了！聊聊 Python 檢查檔案存在的正確姿勢

來源：Stack Overflow ↗ · 7351 票

還記得剛轉職當後端工程師那年，我寫了一個自動化處理報表的腳本，當時為了檢查輸入檔案在不在，我大喇叭地寫了十幾個 try-except 包住每一行邏輯，結果那天系統上線不到兩小時，Log 檔直接被噴出的錯誤訊息塞到炸開，硬碟空間直接滿載，我盯著那滿螢幕的 Traceback，手心全是汗，心想這下真的要被主管釘在牆上了。

其實這背後的原因很單純，很多新手（包括當年的我）會覺得「有錯就抓」是 Pythonic 的寫法，但在檢查檔案是否存在這件事上，頻繁地拋出例外其實是在跟作業系統「搶資源」。當你用 try-except 去判斷檔案，其實是先試圖開啟它，如果失敗了再丟出錯誤，這一來一回的開銷在處理大量檔案時，簡直就是效能殺手，更別提那種程式碼混亂到像是一團毛線球的挫折感了。

後來我學乖了，我開始擁抱 pathlib，這簡直是救贖。現在我處理這種檢查，永遠只會用 pathlib.Path.exists()。你只需要這樣寫，程式碼看起來清爽又優雅：


from pathlib import Path

file_path = Path("data_report.csv")

if file_path.exists():
    print("檔案在這，趕快開工！")
else:
    print("找不到檔案，先去喝杯咖啡吧。")

這行程式碼背後做的事情其實就是問作業系統：「嘿，這個路徑現在有東西嗎？」，它直接給你 True 或 False 的回傳值，完全不會搞那些有的沒的例外拋出。如果你還想更嚴謹一點，確保那個路徑不僅存在，而且真的是個檔案而不是資料夾，用 file_path.is_file() 就搞定，完全不需要去處理什麼 FileNotFoundError。

要預防這種「過度依賴例外處理」的壞習慣，我給你的建議很簡單：養成定義「邊界條件」的習慣。在寫邏輯前先問自己：「這是一個預期會失敗的操作嗎？」如果只是簡單的檢查，那就用 pathlib 這種工具型方法；只有當你真的沒辦法預先判斷（例如權限不足這種不可控因素）時，才把 try-except 拿出來用。

學會這招之後，我的 Log 總算安靜了，我也終於能準時下班去買杯珍珠奶茶犒賞自己。希望這篇能幫你避開那個讓我崩潰過的深坑，寫程式就是要越寫越輕鬆嘛！
