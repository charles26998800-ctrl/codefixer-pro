How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I remember the exact moment I first saw this error. It was late on a Tuesday, and I was trying to spin up a quick prototype to test a new component library. I had just finished my coffee, opened a fresh terminal, and ran npm start, only to be greeted by a cryptic wall of text ending in error:0308010C:digital envelope routines::unsupported. I spent a solid hour convinced I’d somehow corrupted my entire Node environment, only to realize I was fighting a classic case of version mismatch.

The reason this happens is actually quite straightforward once you peel back the layers. When Node.js upgraded to version 17, they switched to OpenSSL 3.0, which enforces stricter security standards. A lot of the older build tools—specifically Webpack 4, which is baked into older versions of Create React App—rely on legacy algorithms that OpenSSL 3.0 now flags as insecure. Essentially, your project is trying to use an outdated hashing method that your current Node installation refuses to run, leading to that frustrating crash before your dev server even has a chance to breathe.

The fix I always reach for is setting an environment variable that tells Node to use the legacy provider, effectively telling it to calm down and allow those older algorithms. If you're on a Mac or Linux machine, you can patch this in your terminal immediately by running the following command before your start script:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows via Command Prompt, you’ll need to set it a bit differently:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

For those of you who don't want to type that out every single time you spin up your project, I highly recommend adding it directly to your package.json file. Just find the scripts section and modify the start command so it looks like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To prevent this from haunting you in the future, my best advice is to keep your development environment as consistent as possible using a version manager like nvm (Node Version Manager). By pinning your project to a specific LTS version of Node—or better yet, updating your dependencies to versions that support OpenSSL 3.0—you stop relying on these "legacy" band-aids and keep your build pipeline clean.

Hope this helps you get back to coding without the headache. Catch you in the next one!

救命！React 專案噴出 error:0308010C，害我以為電腦壞了

來源：Stack Overflow ↗ · 2572 票

那天我正準備要接手一個老專案，才剛把程式碼 clone 下來，自信滿滿地敲下 npm start，結果螢幕瞬間跳出一大串紅通通的 error，最醒目的就是那行 error:0308010C:digital envelope routines::unsupported。我當下心裡真的冒出髒話，想說「我什麼都還沒改欸，怎麼連跑起來都不行？」，甚至一度懷疑是不是我的電腦中毒了，或是哪個套件版本衝突到直接原地爆炸，那種「明明照著步驟做卻被重重打臉」的無力感，真的是工程師最想找個洞鑽進去的時刻。

其實這個問題的兇手是 Node.js 的版本更新。簡單來說，Node.js 在 17 版之後採用了更嚴格的 OpenSSL 3.0 加密演算法，但很多舊版的 Webpack 或者一些常用的開發套件，還停留在舊的加密標準，兩邊就像雞同鴨講，導致系統在嘗試進行雜湊運算時直接崩潰。這就像是你拿著一張舊版的通行證想進入新蓋好的高科技大樓，門禁系統直接判定你不合法，直接把你拒之門外。

我當時試過重新安裝 node_modules、清空快取，結果通通無效，後來才發現其實只要一行指令就能繞過這個檢查。如果你是在 Mac 或 Linux 上，直接在終端機輸入這行：


export NODE_OPTIONS=--openssl-legacy-provider

如果你是用 Windows 的 PowerShell，就要改成這樣：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

輸入完後再跑一次 npm start，專案就奇蹟般地活過來了。如果你不想每次開終端機都要敲一次，最方便的做法是把它加到你的 package.json 裡面的 scripts：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

為了避免以後再被這種環境問題搞到心態崩掉，我現在學乖了，建議大家直接用 nvm (Node Version Manager) 來管理版本。如果遇到這種很舊的專案，直接切換回 Node 16 或更舊的版本通常是最乾淨的解法，不用在那邊跟加密協定硬拚。

以後看到這串錯誤代碼，就不用再慌張啦，記得這只是版本之間的小代溝而已。祝大家開發順利，少點 bug 多點咖啡！
