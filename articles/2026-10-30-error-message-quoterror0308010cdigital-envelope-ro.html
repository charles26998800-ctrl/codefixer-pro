How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I remember the exact moment this hit me; I was onboarding a new junior dev, and we were trying to spin up a fresh React project to get them started on our codebase. We ran npm start, and instead of seeing that familiar "Compiled successfully" message, the terminal just exploded with a wall of red text ending in error:0308010C:digital envelope routines::unsupported. I honestly felt like tossing my MacBook out the window because I’d spent three hours the night before debugging a complex API issue, and I really didn't have the patience for a cryptic OpenSSL error on a brand-new project.

The reason you're seeing this is actually pretty straightforward, even if the error message sounds like it’s written in an alien language. It boils down to a major shift in how Node.js handles cryptography. When Node.js bumped up to version 17 and beyond, they upgraded to OpenSSL 3.0, which enforces stricter security standards. A lot of older tools—specifically the Webpack version used in older create-react-app templates—rely on algorithms that are now considered legacy and are no longer supported by default. Essentially, your project is trying to use an outdated hashing method that your newer version of Node.js refuses to run for security reasons.

To get things back on track, you don't necessarily have to downgrade your entire Node environment, which is a massive headache. The quickest fix is to tell Node to use the "legacy" provider for OpenSSL. If you’re on a Mac or Linux machine, you can do this by exporting an environment variable in your terminal before running your start script:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is a bit different. You’ll want to set it in your command prompt like this:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

If you want to avoid typing this every single time you open a new terminal window, just head over to your package.json file and modify your scripts section. You can hardcode the environment variable directly into the start command so it’s always applied:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

The best way to prevent this from ruining your day in the future is to keep your project dependencies updated. This error is a classic sign that your react-scripts version is lagging behind. Whenever you start a project, check if you’re using the latest versions of your build tools, or consider migrating to a modern build tool like Vite. Vite doesn't rely on the same legacy Webpack configurations, so you’ll likely never see this specific error again.

Hope this saves you the headache it caused me! Let me know if you run into any other weird build issues.

救命！React 專案突然報錯 error:0308010C？這不是你的錯，是 Node.js 的鍋

來源：Stack Overflow ↗ · 2572 票

記得那天下午，我正信心滿滿地想要幫一個老舊的 React 專案做點小改動，結果執行 npm start 的瞬間，終端機直接噴出一大串紅通通的錯誤訊息，重點是那個 error:0308010C:digital envelope routines::unsupported。我當下真的差點要把鍵盤砸了，心想：「我明明什麼都沒動啊，昨天還好好的，到底是哪個環節出了鬼？」那種在趕進度卻被莫名其妙的環境問題卡住的無力感，真的是工程師最想原地離職的痛苦時刻。

其實這問題的兇手是 Node.js 的版本升級。從 Node 17 開始，系統引入了 OpenSSL 3.0，這傢伙對於加密演算法的安全性要求變高了，但我們很多舊版的 React 專案（特別是還在使用 Webpack 4 的那種）還在依賴舊的演算法，兩邊一搭不上線，就會直接拋出這個「不支援」的錯誤。簡單來說，就是你的專案太古早，跟不上 Node.js 變得嚴格的審美觀了。

我當下冷靜下來後，發現其實不必大費周章去降級 Node.js（雖然那也是一種方法，但太麻煩了）。最快的方式，就是直接告訴 Node.js：「嘿，請你暫時放寬對 OpenSSL 的限制。」我們只需要在啟動指令前面加上 NODE_OPTIONS=--openssl-legacy-provider 這個參數。如果你是用 Windows 的 PowerShell，設定方式會稍微有點不同，但我習慣直接改 package.json，這樣不管誰來跑這個專案都不會報錯。你可以直接把 scripts 區塊改成這樣：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

改完之後再跑一次 npm start，看著那熟悉的編譯成功畫面，真的會有一種想對著螢幕尖叫的衝動。

為了避免以後又被這種環境問題陰到，我後來養成了一個好習慣，就是嚴格控管開發環境的版本。我強烈建議大家一定要用 nvm (Node Version Manager) 來管理 Node.js 版本，並且在專案根目錄放一個 .nvmrc 檔案，裡面寫好當前專案適用的 Node 版本號。這樣下次換電腦或是同事接手時，只要敲一行 nvm use，就能確保大家都在同一個頻率上，不用再為了這些奇怪的環境錯誤浪費生命。

希望這篇筆記能幫你省下幾個小時的除錯時間，趕快回去寫 Code 吧，別再被這些沒意義的報錯折磨啦！
