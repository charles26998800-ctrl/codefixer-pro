How to Check if a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7351 votes

Early in my career, I was building a log-parsing script and found myself wrapping every single file access in massive try-except blocks. I remember staring at my screen for three hours, frustrated because my code looked like a jagged mountain range of indentation just to handle basic file existence checks. I finally realized I was treating simple IO operations like they were catastrophic system failures, which made my codebase nearly impossible to read.

The reason this feels so clunky is that Python’s philosophy is often "Easier to Ask for Forgiveness than Permission" (EAFP). Many developers default to try-except because it’s technically more robust in multi-threaded or high-concurrency environments where a file might vanish in the nanosecond between your check and your action—a race condition known as TOCTOU (Time-of-Check to Time-of-Use). However, for simple scripts or batch processing, constantly catching FileNotFoundError is overkill and just creates unnecessary noise in your logic.

When I need to keep my code clean and readable, I reach for the pathlib module. It’s the modern, object-oriented way to handle filesystem paths in Python, and it makes checking for a file as simple as calling a method. Here is how I handle it in my own projects:


from pathlib import Path

file_path = Path("config.json")

if file_path.is_file():
    print("File exists, proceeding with the logic.")
else:
    print("File missing, skipping this step.")

If you’re working on a legacy codebase or just need a quick one-liner without importing pathlib, the os.path module is the old-school standard I still see everywhere. You’ll use os.path.exists() for general paths or os.path.isfile() if you want to ensure it isn't a directory accidentally masquerading as a file.


import os

if os.path.isfile("data.csv"):
    # Do your work here
    pass

To prevent this from becoming a headache later, my biggest tip is to define your file paths as constants or configuration objects at the top of your modules. Don't litter your logic with hardcoded string paths that change every time you move a folder, or you'll be debugging "file not found" errors for the rest of your afternoon.

Hope this clears up the clutter in your scripts! Let me know if you run into any other weird Python quirks.

別再為了檢查檔案存不存在寫滿滿的 try-except 了！

來源：Stack Overflow ↗ · 7351 票

記得剛入行寫 Python 的時候，我接手過一個處理大量日誌的腳本，當時為了判斷某個 log 檔在不在，我瘋狂地在程式碼裡塞 try...except FileNotFoundError。結果那個腳本跑起來簡直像在玩「踩地雷」，一旦檔案消失的瞬間，整個程式就因為沒處理好異常而崩潰，搞得我當時熬夜修到懷疑人生，真的差點就要把螢幕砸了。

會遇到這種情況，其實是因為 Python 的設計哲學鼓勵「請求寬恕勝過許可」（EAFP），所以很多教學都會教你直接去操作檔案，然後用 try 把錯誤抓起來。但老實說，在某些情境下，我們只是想先確認一下環境，如果硬要寫成異常處理，程式碼看起來會非常髒，邏輯也會變得很破碎，就像是你明明只是想問路，卻得先準備好被路人拒絕的心理建設一樣累。

後來我發現，其實 Python 的標準庫早就給了我們更優雅的工具。如果你跟我一樣，不想在程式碼裡寫一堆沒必要的例外處理，強烈建議直接使用 pathlib 模組。這是我現在處理檔案路徑的標配，它把路徑當成物件處理，看起來直覺很多。只要簡單呼叫 .exists() 方法，就能輕鬆搞定，完全不用擔心什麼例外跳出來嚇人。


from pathlib import Path

file_path = Path("my_data.log")

if file_path.exists():
    print("檔案就在這，安心服用！")
else:
    print("檔案找不到，去旁邊喝咖啡吧。")

如果你是在維護舊專案，不方便引入 pathlib，那 os.path.exists() 也是個老牌的好選擇。雖然它長得比較傳統一點，但效果是一樣的，同樣能幫你避開那些討人厭的錯誤觸發。

不過說實話，就算你用了這些檢查方法，還是要小心「競爭條件」（Race Condition）的問題。這是我曾經吃過的大虧：我檢查完檔案存在，正準備打開它的那幾毫秒內，檔案剛好被別的程序刪除了，結果程式還是噴了錯。所以，最好的預防策略其實是「保持檢查與執行的簡潔」，或者在非同步、多執行緒的環境下，還是乖乖地把操作放在 try-except 裡，因為那才是最萬無一失的做法。

平時寫程式還是簡單點好，別為了這點小事讓自己壓力那麼大。下次遇到這種檢查需求，試試看 pathlib 吧，你會愛上這種清爽感的！
