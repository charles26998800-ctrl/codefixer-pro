How to Check If a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7351 votes

Back when I was a junior dev, I remember writing a massive script to process logs, and I was obsessed with using try-except blocks for absolutely everything. I spent three hours debugging a "file not found" error because I had accidentally nested my exception handlers so deeply that I couldn't tell which file was actually missing. I felt like a total amateur when I realized there were cleaner, more idiomatic ways to handle existence checks without wrapping every single line in a block that looked like a staircase.

The reason we often reach for try-except in Python is that the language philosophy leans heavily toward "Easier to Ask for Forgiveness than Permission" (EAFP). However, sometimes you just want to verify if a file exists before you commit to opening it, especially when you're writing configuration loaders or cleanup scripts. If you’re checking existence just to decide whether to run a specific log or skip a task, an exception-heavy approach can clutter your business logic, making the code harder to read and significantly more annoying to maintain.

To fix this, I moved over to using the pathlib module, which has been the standard way to handle filesystem paths since Python 3.4. It’s object-oriented, readable, and saves you from the headache of string manipulation. You can simply use the .exists() method on a Path object to get a clean boolean result. Here is how I prefer to do it now:


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.exists():
    print("The file is right where it needs to be.")
else:
    print("File not found, skipping...")

If you’re stuck on a legacy codebase and can’t use pathlib, the os.path module is the classic alternative that still gets the job done without any fuss. You’ll use os.path.exists() or os.path.isfile() to confirm the path is there and that it’s actually a file rather than a directory.


import os

if os.path.isfile("my_data.txt"):
    # Do your work here
    pass

The best way to prevent these issues from spiraling into a mess is to always keep your "check" and "action" logic as close together as possible. If you check for a file at the very start of a long function and then try to use it twenty lines later, you’re creating a "Time-of-check to time-of-use" (TOCTOU) race condition where the file could be deleted or moved in between. If your application depends on that file being there, sometimes it is actually better to just try opening it and handle the error—but for simple existence checks, sticking to pathlib will keep your code clean and readable.

Hope this saves you from some of the frustration I dealt with early in my career. Happy coding!

不想寫 try-except？Python 檢查檔案存不存在的優雅寫法

來源：Stack Overflow ↗ · 7351 票

剛入行那陣子，我寫了一個自動化清理暫存檔的腳本，心想這多簡單啊，直接用 open() 去開檔案，如果開失敗就代表檔案不存在。結果有次上線跑沒多久，程式直接噴出滿屏的錯誤堆疊，因為那時候正好有一個同步程序在刪除檔案，導致我的腳本在「檢查到有檔案」到「嘗試開啟它」之間的時間差裡，檔案被消失了。那種看著 logs 瘋狂報錯、心跳加速的感覺，真的會讓人懷疑人生，搞到最後我只要看到 try-except 嵌套在邏輯裡就頭痛。

其實這問題的核心就在於 Python 的哲學，它很喜歡用「請求原諒比請求許可更容易」（EAFP）的邏輯，也就是鼓勵你直接做，失敗了再處理。但有時候我們只是想單純做個路徑檢查，不想搞得滿地都是例外處理。加上如果你是在寫一些底層邏輯，或者只是想做簡單的條件判斷，硬塞一個 try-except 確實會讓程式碼變得又臭又長，看起來一點都不乾淨。

後來我學乖了，直接改用 pathlib 這個標準庫。它真的是 Python 界的一大德政，比起以前那種還要 import os 然後寫一大串 os.path.exists 的古老寫法，pathlib 的物件導向風格簡直是救贖。現在我處理這類需求，通常都是這樣寫：


from pathlib import Path

file_path = Path('my_data.txt')

if file_path.is_file():
    print("檔案還活著，可以開工！")
else:
    print("檔案不見了，先跳過吧。")

這種寫法不僅語意清楚，而且閱讀起來就像在讀英文句子一樣順暢。如果你不確定那路徑到底是檔案還是資料夾，直接用 .exists() 就行了。雖然說這依然存在「競態條件」（Race Condition）的問題——也就是說，你檢查完到你真的去操作檔案的那一毫秒內，檔案還是有可能被刪掉——但對於絕大多數的應用場景來說，這種寫法已經足夠優雅且好維護了。

如果要預防這種「檢查跟操作不同步」帶來的隱患，最好的建議就是，如果你的腳本需要頻繁讀寫檔案，就乾脆放棄「先檢查再操作」的念頭，直接把操作邏輯包在一個穩定的處理函式裡，並預留好該處理的例外狀況。別為了省那幾個 try-except 的字元，反而讓程式碼變得難以除錯。

寫程式嘛，工具選對了，心情自然就輕鬆了，祝大家都能避開這些惱人的 Race Condition 地雷。
