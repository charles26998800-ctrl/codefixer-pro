How to Check If a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7349 votes

Back when I was a junior dev, I spent an embarrassing three hours trying to debug a script that was crashing every time it hit a missing config file. I had wrapped everything in massive try-except blocks because I thought that was the "Pythonic" way to handle everything, but my logs became an absolute nightmare to read. I eventually realized I was just being lazy with my flow control and needed a cleaner, more readable way to verify file paths before trying to touch them.

The root cause of this frustration is usually how we perceive "error handling" versus "state checking." In Python, there’s a famous philosophy about "Easier to Ask for Forgiveness than Permission" (EAFP), which encourages using try-except blocks. However, when you’re writing scripts that perform bulk file operations, constant exception handling can slow down your runtime and make your logic look like a cluttered mess. If you just need a simple boolean check to decide whether to skip a file or proceed with a read, relying on exceptions feels like taking a sledgehammer to crack a nut.

The modern way to handle this is by using the pathlib module, which has been standard since Python 3.4. It’s object-oriented and honestly just feels much more intuitive than the old os.path methods. Here is how I usually handle it now:


from pathlib import Path

file_path = Path("config.json")

if file_path.exists():
    print("File is there, let's get to work.")
else:
    print("File doesn't exist, skipping this task.")

If you’re still working on a legacy codebase or just prefer the classic approach, you can stick with os.path. It’s not as elegant, but it gets the job done without any extra overhead:


import os

if os.path.exists("config.json"):
    print("The file exists!")

Just keep in mind that exists() returns True for directories too. If you need to be strictly sure it’s a file and not a folder, use file_path.is_file() instead.

To prevent this from becoming a headache in the future, my best advice is to embrace pathlib for all your filesystem interactions. It turns string-based path manipulation into actual objects, which prevents those nasty "file not found" surprises from bubbling up in the middle of a long-running process. Once you switch over, you'll never want to go back to concatenating strings with os.path.join ever again.

Hope this saves you from the same three-hour headache I had. Happy coding!

別再用 try-except 檢查檔案是否存在了，Python 其實有更優雅的寫法

來源：Stack Overflow ↗ · 7349 票

記得剛入行那陣子，我寫了一個自動化搬移 Log 的腳本，為了怕程式因為找不到檔案噴錯誤，我瘋狂地在程式碼裡塞滿 try-except。結果那個腳本讀起來簡直像是一團糾結的義大利麵，當我想要維護它時，光是看那些重複的區塊就讓我頭痛到想撞牆，最痛苦的莫過於有一次因為寫錯了例外處理的邏輯，導致程式默默吞掉了一個真正的致命錯誤，讓我整整 debug 了兩個小時才發現檔案根本沒被建立，心態差點原地崩潰。

其實很多人會用 try-except 來檢查檔案，是因為直覺上覺得「試著打開看看，不行再報錯」是最直接的，但在 Python 的世界裡，這其實不是最乾淨的做法。這種方式會讓你的邏輯變得非常凌亂，尤其是當你只是想確認個路徑是否存在，卻要處理一堆複雜的異常處理流程時，程式碼的可讀性會直接降到谷底。

後來前輩教我一個比較「Pythonic」的寫法，直接使用內建的 os.path 模組，或者更現代一點的 pathlib，就能輕鬆解決這個問題。如果你還在用舊版的寫法，我強烈建議改用 pathlib，因為它把路徑當作物件處理，用起來實在太舒服了。

如果你的專案比較老舊，用 os.path 就可以搞定：


import os

if os.path.exists('my_file.txt'):
    print("檔案還在，可以放心處理！")
else:
    print("檔案不見了，先別亂操作。")

但如果你想寫出更潮、更好維護的程式碼，請務必擁抱 pathlib：


from pathlib import Path

file_path = Path('my_file.txt')

if file_path.exists():
    print("檔案存在，任務繼續。")
else:
    print("找不到檔案，跳過這個步驟。")

這樣寫不僅乾淨俐落，也不會因為過度使用 try-except 而誤抓到不該抓的錯誤。

要預防這種問題再次發生，我的建議是養成「先檢查再操作」的習慣，但更重要的是要區分「檢查是否存在」與「處理操作失敗」。如果你的邏輯是「如果檔案存在就讀取，不存在就建立」，那就直接用 pathlib 的 is_file() 或 exists() 來做條件判斷，千萬別把檢查邏輯跟你的業務邏輯混在一起，不然哪天程式崩了，你真的會哭不出來。

寫程式就是為了讓生活變簡單，別讓這些檢查的小細節把自己搞得太累啦！
