How to Undo Your Last Local Git Commit Without Losing Your Mind

Source: Stack Overflow ↗ · 27236 votes

I still remember the first time I accidentally committed my entire node_modules folder and a local config file containing a test API key to a repo I was about to push. I sat there staring at my terminal for a solid five minutes, sweating, terrified that I’d have to delete the entire project folder and start over. I ended up spending two hours deep-diving into Git documentation, feeling like a total amateur, only to realize there was a single command that could have saved me all that panic.

The reason this happens is usually just a simple lapse in focus; you’re in the flow, you run git add . without checking the status, and suddenly your commit history is cluttered with garbage you never intended to track. Git is designed to be a permanent record of your work, so it doesn't make it immediately obvious how to "delete" history. Because Git operates on a directed acyclic graph of commits, when you realize you've made a mistake, you aren't really deleting history as much as you are telling Git to point your branch reference back to a previous state.

If you’re in the same boat I was, the fix is actually quite straightforward. You’ll want to use git reset. If you just want to undo the commit but keep your changes in your staging area—maybe you just need to add one more file or tweak a commit message—you should use git reset --soft HEAD~1. This keeps your work intact, allowing you to fix the commit and try again. 


# Undo the last commit, but keep your changes staged
git reset --soft HEAD~1

If you committed absolute nonsense and you want to completely wipe the changes from that commit, you’ll use the --hard flag. Be careful with this one, because it will discard all the work you did in that commit. I’ve definitely used this in a fit of rage after realizing my code was fundamentally broken, and it’s a great way to get back to a clean slate.


# WARNING: This destroys the changes in the last commit
git reset --hard HEAD~1

Once you’ve reset, if you had already pushed a previous version of that branch, you’ll need to force push your changes to the remote server with git push origin --force. Just make sure you aren't doing this on a shared team branch, or your coworkers might actually hunt you down.

To keep this from happening again, I’ve made it a habit to run git status every single time before I type git commit. It takes two seconds, but it’s saved me from countless "oops" moments where I accidentally included files I didn't mean to touch. Keeping an eye on your staging area before finalizing the commit is the best insurance policy you can have.

Good luck with your cleanup, and don't beat yourself up—we've all been there. Catch you later!

手殘黨救星：還沒 Push 的 Git Commit 怎麼優雅地撤回？

來源：Stack Overflow ↗ · 27236 票

記得剛入行那年，有次趕著下班，沒檢查清楚就把一堆還在測試中的 Debug 用的 Log 和亂七八糟的廢棄程式碼直接 git commit 了下去。當我按下 Enter 的那一刻，看著終端機顯示 commit 成功，心跳直接漏了半拍，那種「完了，整包髒東西都被我存進歷史紀錄」的崩潰感，真的會讓人想當場把電腦關掉裝死。那時候我盯著螢幕，腦袋一片空白，心想這下是不是要整個專案重拉了，那種心臟快要跳出來的痛苦時刻，我到現在還記憶猶新。

其實這問題的根本原因很簡單，Git 的設計就像是一個會幫你「蓋印章」的紀錄器，當你 commit 下去，你就等於在歷史上蓋了一個戳記。但好消息是，只要你還沒把這些戳記傳到遠端伺服器（Push），這些紀錄其實都還只是「你的個人私事」，只要運用 Git 的 reset 指令，就能把這些戳記像橡皮擦一樣塗掉，讓一切回到還沒 commit 的那個當下。

當我發現這個救命指令時，真的覺得 Git 救了我一命。如果你的目標只是想撤銷最近一次的 commit，但想保留剛剛辛苦寫好的程式碼修改，只要打開終端機輸入這行指令：

git reset --soft HEAD~1

這行指令會把那個 commit 拆掉，但你剛剛修改的所有檔案都會保留在暫存區（Staging Area），你可以直接修改那些不該進去的檔案，然後重新 commit。如果你是連改動的內容都不想要了，想徹底毀屍滅跡，直接還原到 commit 之前的狀態，那就把 --soft 改成 --hard：

git reset --hard HEAD~1

注意喔，用了 --hard 之後，你剛剛改的那些程式碼就會直接消失，想救都救不回來，按下去之前一定要確認好！

為了避免這種心驚膽跳的時刻再次發生，我現在養成了一個習慣，就是每次 commit 前一定會先打 git status 看一下清單。如果覺得自己很容易手滑，也可以在 IDE 裡裝個 Git 插件，在 commit 前會有一個視覺化的視窗讓你檢查到底加了哪些檔案，而不是無腦地 git add .。多花這幾秒鐘確認，真的能省下後面一小時的除錯與修復時間。

反正 Git 就是這樣，用久了就會發現它其實滿人性化的，只要別亂推到遠端，基本上都有救。希望這招能幫你度過那個想把鍵盤砸爛的瞬間，我們下次見！
