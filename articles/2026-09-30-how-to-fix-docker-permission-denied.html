How to fix the Docker "Permission Denied" error on Ubuntu

Source: Stack Overflow ↗ · 1419 votes

I still remember the first time I set up my development environment on a fresh Ubuntu install, feeling like a total pro until I typed docker ps and got slapped with a "Permission denied" error. I spent way too long assuming I had somehow broken the entire Docker installation, frantically reinstalling packages and rebooting my machine like a madman before I realized it was just a simple group membership issue. It’s one of those rites of passage every developer goes through, and honestly, feeling like a genius one minute and being humbled by a socket file the next is just part of the job.

The reason you're seeing this error is actually quite logical once you peek under the hood. The Docker daemon binds to a Unix socket located at /var/run/docker.sock, which is owned by the root user and the docker group by default. When you run a command without sudo, your current user doesn't have the necessary permissions to communicate with that socket. It’s a security feature designed to prevent just any user on the system from having root-level control over your containers, but it’s definitely an annoying hurdle when you’re just trying to get your local environment running.

To fix this, I simply add my current user to the docker group, which grants me the necessary access without needing to prefix every single command with sudo. First, you need to create the group if it doesn't already exist—though the Docker installation usually handles this for you—and then add your user to it. Just run these commands in your terminal:


sudo groupadd docker
sudo usermod -aG docker $USER

After running those, the changes won't take effect immediately. You’ll need to either log out and log back in, or run newgrp docker to refresh your shell's group membership. Once you've done that, you can verify it worked by running docker run hello-world without any sudo privileges. If the container pulls and executes successfully, you're all set.

Moving forward, the best way to prevent this headache is to always double-check your group permissions whenever you spin up a new Linux machine or environment. I’ve made it a part of my standard post-install checklist to run the usermod command immediately after installing the Docker engine, so I never have to deal with that frustrating "Permission denied" message again.

Hope this saves you a few hours of head-scratching. Happy coding and enjoy building your containers!

Docker 權限被拒？別再為了打個 sudo 指令懷疑人生了

來源：Stack Overflow ↗ · 1419 票

剛開始學 Docker 那陣子，我真的是被這個 Permission denied 搞到快崩潰。記得那天為了趕一個 demo，我在終端機裡瘋狂輸入 docker run，結果螢幕上冷冰冰地跳出一行「Got permission denied」，當下我心裡直接罵了一句髒話，心想：「明明我都安裝好了，為什麼連跑個 hello-world 都要跟我過不去？」最痛苦的是，每次都要多打那五個字母 sudo，對於我們這種追求效率的工程師來說，這簡直是精神折磨，甚至有幾次因為忘了加 sudo，指令打完按下 Enter 才發現白忙一場，那種挫折感真的只有經歷過的人才懂。

其實這背後的道理很簡單，Docker 的背景程式（Daemon）預設是綁定在 unix socket 上的，而這個檔案的擁有者是 root。這意味著除非你是超級使用者，或者你被明確授權，否則作業系統是不會讓你隨便碰它的。這其實是一種資安機制，怕有人隨便亂改 Docker 的設定，但對我們開發者來說，這道牆確實有點煩人。

要解決這個問題，其實只要把你的使用者帳號加進 docker 這個群組就好。我當時是這麼處理的，先在終端機執行建立群組的指令：


sudo groupadd docker

接著把當前的使用者加入這個群組：


sudo usermod -aG docker $USER

這時候千萬別急著關掉視窗，你必須讓系統重新載入群組權限。最簡單的方法就是直接登出再登入，或者如果你懶得重開機，也可以用 newgrp docker 指令立即生效。搞定之後，試著執行 docker run hello-world，如果沒看到那串討厭的錯誤訊息，恭喜你，以後再也不用在那邊 sudo 來 sudo 去的了。

不過要提醒一下，把使用者加進 docker 群組等於是給了你 root 等級的權限，畢竟 Docker 容器本來就能輕易掛載系統目錄。平時開發用用沒問題，但如果是那種多人共用的伺服器環境，還是要稍微留意一下資安風險。

好了，現在可以把那該死的 sudo 從你的肌肉記憶裡刪除了，趕快回去寫程式吧！
