How to Check If a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7352 votes

Early in my career, I remember writing a script to automate log cleanup on a production server. I was convinced that wrapping every single file operation in a massive try-except block was the height of defensive programming, until I spent three hours debugging a race condition that only popped up when the system was under heavy load. I felt like a total amateur when I realized I was fighting the language instead of using the tools it provided for simple existence checks.

The reason developers often trip over this is that Python leans heavily into the "EAFP" philosophy—Easier to Ask for Forgiveness than Permission. It encourages you to just try an action and catch the error if it fails. While that’s usually great, sometimes you just need a simple boolean check to decide whether to trigger a workflow or skip a step. When you force a try-except block into a logic flow where it doesn't belong, you end up with "exception soup," where your code becomes unreadable and you lose track of which errors you’re actually catching.

To fix this properly, I stopped trying to force everything into an exception handler and started using the pathlib module. It’s the modern, object-oriented way to handle filesystem paths in Python, and it’s become my absolute go-to. If you’re on a modern version of Python, you can simply create a Path object and call the .exists() method. It’s clean, it’s readable, and it doesn't require any messy boilerplate.


from pathlib import Path

file_path = Path("my_data_file.txt")

if file_path.exists():
    print("The file is right there, ready to go.")
else:
    print("Nothing to see here.")

If you’re working on a legacy codebase or just prefer the old-school os module, you can still achieve this without exceptions by using os.path.isfile(). It returns a simple boolean, which is exactly what I want when I’m writing conditional logic.


import os

if os.path.isfile("my_data_file.txt"):
    print("File confirmed.")

The best way to prevent this headache in the future is to stop using existence checks as a substitute for robust error handling. Even if you check that a file exists, it could be deleted by another process a millisecond later before you manage to open it. Use these checks for simple logic branching, but always keep your actual file operations wrapped in a try-except block anyway. It’s the only way to handle those pesky permission errors or hardware glitches that no amount of pre-checking can predict.

Hope this saves you a few hours of head-scratching! Happy coding, and may your files always be exactly where you expect them to be.

別再用 try-except 檢查檔案了！Python 優雅檢查檔案存在的正確姿勢

來源：Stack Overflow ↗ · 7352 票

記得剛開始寫 Python 爬蟲的那陣子，為了處理大量的圖片下載，我寫了一段邏輯是「先檢查檔案在不在，不在就下載」。當時為了偷懶，直接包了一個巨大的 try-except IOError 在迴圈裡，結果某次程式跑到一半，因為權限問題導致錯誤捕捉變得一團亂，整個 Log 噴滿了錯誤訊息，我當時坐在螢幕前看著那幾千個報錯，心裡真的是差點崩潰，完全搞不清楚到底是因為檔案真的不存在，還是我的讀寫權限出了包。

說實話，很多人會想避開 try-except 是因為覺得這種寫法很不「直覺」，好像在寫防禦性程式設計時，把錯誤當成流程控制的一部分很不乾淨。但其實在 Python 裡，最根本的原因在於檔案系統是一個極度不穩定的環境。當你執行 os.path.exists() 檢查完檔案，到你下一行真正去打開檔案的那一毫秒之間，那個檔案可能早就被另一個執行緒、或是系統自動清理機制給刪掉了。這就是所謂的「競爭條件（Race Condition）」，也是為什麼很多新手明明寫了檢查，卻還是會遇到 FileNotFoundError 的痛苦時刻。

後來我學乖了，與其在那邊糾結要不要用 try，不如直接擁抱 Python 的現代化工具。現在我幾乎全面改用 pathlib 模組，這東西簡直是救星。如果你只是單純想知道檔案在不在，用 pathlib.Path 的 .exists() 方法就夠了，寫起來乾淨俐落，完全不需要寫那種醜醜的 try 區塊，程式碼看起來也舒服多了：


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.exists():
    print("檔案就在這，可以開工了！")
else:
    print("檔案消失了，去喝杯咖啡再說。")

如果你是擔心檔案雖然存在，但其實是個資料夾，或者權限不足，pathlib 同樣能幫你處理，像是 .is_file() 這個方法就比單純的 exists() 更嚴謹，直接幫你過濾掉那些「看起來像檔案但其實是目錄」的坑。

為了不讓這種「檔案消失」的惡夢再次發生，我的建議是：如果你接下來的動作是要「打開並讀寫檔案」，那就乾脆把檢查這步省了，直接在 open() 的時候使用 try-except 捕捉錯誤。這是 Python 社群推崇的 EAFP 風格（Easier to Ask for Forgiveness than Permission，先做了再說，出錯再處理）。把錯誤處理放在真正操作檔案的那一行，比起先檢查再操作，反而能更精準地抓到是因為「權限問題」還是「檔案被刪除」，這樣除錯的時候你才不會像無頭蒼蠅一樣亂撞。

把這招學起來，下次寫程式時就能少掉幾根頭髮，祝你的程式碼永遠跑得順順利利！
