How to Check if a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7352 votes

Back when I was a junior developer, I remember writing a script to automate some log cleanup, and I was obsessed with using try-except blocks for everything. I spent three hours chasing a bug because I had wrapped a simple file check in a massive try block, and the code was silently swallowing a completely different PermissionError that I hadn't anticipated. It was one of those classic "I’m clearly overcomplicating this" moments that made me realize I needed a cleaner, more explicit way to handle basic filesystem checks.

The reason we often get stuck on this is that Python’s philosophy usually leans toward "Easier to Ask for Forgiveness than Permission" (EAFP). While using a try-except block is often the most robust way to handle file operations—because it accounts for race conditions where a file might vanish in the millisecond between your check and your action—sometimes you just need a simple boolean check for logic flow. When you're just trying to verify a path exists without triggering the overhead of exception handling, you need a different approach that doesn't feel like you're wrapping your entire script in safety nets.

I’ve moved away from the old os.path module in favor of the modern pathlib library, which is built into Python 3 and makes everything much more readable. If you want to check if a file exists, you should be using the exists() method on a Path object. It’s clean, it’s object-oriented, and it won't throw an error if the file is missing. Here is how I usually implement it in my projects:


from pathlib import Path

file_path = Path("my_config.txt")

if file_path.exists():
    print("The file exists, proceeding with the load.")
else:
    print("File not found, creating a new one instead.")

If you specifically need to ensure that the path isn't just *any* object, but specifically a file (rather than a directory), you can swap .exists() for .is_file(). This has saved me from accidentally trying to "open" a directory as if it were a text file, which usually leads to some very confusing error messages.

To keep your code clean, my biggest tip is to stop checking for existence entirely unless you absolutely have to. If you're going to open the file anyway, just write your code to handle the FileNotFoundError directly. It’s faster, it’s more "Pythonic," and it’s the only way to guarantee that your program won't crash if another process deletes that file a microsecond after you checked for it.

Hope this saves you a few hours of head-scratching. Happy coding!

為什麼 Python 檢查檔案存在一定要用 try-except？其實不用啦！

來源：Stack Overflow ↗ · 7352 票

記得剛開始寫 Python 那會兒，我為了處理一個簡單的設定檔讀取，滿腦子想著怎麼優雅地避開那些煩人的例外處理。當時我為了寫一個檢查機制，搞了一堆 try-except 區塊，結果程式碼看起來簡直像個迷宮，更慘的是，有次我在處理併發任務時，因為 race condition，檔案明明上一秒還在，下一秒卻消失了，那個 Exception 噴出來的瞬間我差點在辦公室崩潰，心想：「難道就沒有更直覺、不那麼暴力的方法嗎？」

其實很多人覺得一定要用 try-except，是因為 Python 的哲學是「求原諒比求許可更容易」（EAFP），也就是與其先檢查再動作，不如直接衝過去做，失敗了再抓例外。這邏輯沒錯，但在寫小型工具或是單純想確認狀態時，這種寫法真的會讓程式變得又臭又長。如果你的需求只是單純想問「這檔案到底在不在？」，其實根本不需要在那邊大費周章地捕捉錯誤。

我後來發現，最乾脆的解法就是直接利用 pathlib 這個 Python 內建的神器。自從 Python 3.4 之後，這玩意兒簡直是救星，它把檔案路徑當作物件處理，檢查是否存在只要一行程式碼就搞定了。你只要這樣寫：


from pathlib import Path

file_path = Path('config.json')

if file_path.exists():
    print("檔案還活著，可以開工了！")
else:
    print("檔案不見了，先休息一下吧。")

如果你還在用舊專案，必須堅持使用 os 模組，那 os.path.exists() 也是一樣好用，效果完全沒差。但我強烈建議你盡量往 pathlib 轉，因為它的語法讀起來就像在寫英文句子，對於我們這種維護程式碼的人來說，可讀性高太多了。

說到預防再次踩坑，我覺得最關鍵的觀念是「別太相信你檢查到的結果」。即使你用 exists() 檢查過了，在多執行緒或是系統資源緊張的環境下，檔案狀態還是可能在檢查後的那一毫秒內發生改變。所以，如果你是要進行「讀取」這個動作，還是得保留一點點防禦性思維，或者乾脆把檢查和讀取包在一個原子操作裡。別像當年的我一樣，為了追求程式碼的「乾淨」而犧牲了健壯性，這才是寫 code 最心累的地方。

好了，希望這招能幫你的程式碼瘦身成功，別再被那些 try-except 搞得心煩意亂啦！
