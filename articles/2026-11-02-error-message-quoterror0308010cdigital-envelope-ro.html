How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I updated my Node.js version just to stay current, only to have my entire project pipeline blow up in my face the moment I ran npm start. I spent a solid three hours digging through dependency trees and questioning my life choices before I realized it was just a simple mismatch between my new Node environment and some older build tools. It’s one of those classic "why is my code suddenly haunted?" moments that every dev hits at least once.

If you’re seeing the dreaded error:0308010C:digital envelope routines::unsupported message, it’s because you’re likely running Node.js version 17 or higher. The issue stems from the fact that Node updated its OpenSSL library to version 3.0, which enforces stricter security protocols. Many older React projects and build tools—specifically Webpack 4—still rely on legacy algorithms like MD4 for hashing, which OpenSSL 3.0 now deems "unsupported" by default. Essentially, your project is trying to use an old security handshake that your newer version of Node refuses to acknowledge.

The quickest way I’ve found to resolve this is to tell Node to use the legacy OpenSSL provider. You don't need to downgrade your entire environment, which is a massive relief. If you're on a Mac or Linux machine, you can fix this by setting an environment variable directly in your terminal before running your start command:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the command syntax changes slightly, but the logic remains identical. You’ll want to run this in your terminal:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

For a more permanent fix, I usually just add this to my package.json file so I don't have to remember it every single time I restart my dev server. You can modify your scripts section like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

Moving forward, the best way to prevent this kind of headache is to keep your project dependencies updated. Most of the time, this error pops up because you're using an outdated version of react-scripts. By running npm update or migrating to a newer version of Webpack, you’ll eventually move away from the legacy hashing algorithms that trigger this error in the first place, allowing you to stop using that legacy provider flag entirely.

Hope that clears things up and gets you back to shipping code. Happy debugging!

救命！React 啟動噴出 error:0308010C，Node.js 版本升級後的惡夢

來源：Stack Overflow ↗ · 2572 票

那天早上我剛接手一個舊專案，想說開個新分支準備修個小 Bug，結果才剛輸入 npm start，終端機就直接送我一長串紅通通的錯誤訊息。看到那個 digital envelope routines::unsupported 的瞬間，我真的差點要把鍵盤砸了，心想「我只是想跑個專案而已，怎麼連伺服器都起不來？」為了這該死的錯誤，我甚至還檢查了好幾次是不是自己把環境變數弄壞了，結果發現根本不是我的錯，而是 Node.js 更新後跟舊套件打架了。

其實這問題的根源就在於 Node.js 17 版之後，預設開啟了 OpenSSL 3.0，這玩意兒安全性更高，但對於舊的 Webpack 或是某些加密演算法比較敏感的套件來說，根本就是災難。簡單來說，就是你的專案用了比較舊的加密演算法，但新版的 Node.js 說「我不支援這種舊玩意兒了」，所以兩邊互看不順眼，直接罷工給你看。

解決方法其實沒想像中那麼複雜，我們只要告訴 Node.js「嘿，請你暫時允許這些舊版的加密演算法」就行了。最快的解法就是設定一個環境變數 NODE_OPTIONS。如果你是用 macOS 或 Linux，直接在終端機輸入這行：


export NODE_OPTIONS=--openssl-legacy-provider

如果你是在 Windows 的 PowerShell，指令則是：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

設定完之後，再試一次 npm start，通常就能順利看到熟悉的開發介面出現了。不過，如果你不想每次開終端機都要敲一次指令，建議直接改一下 package.json 裡的 scripts 設定，把指令寫死在裡面，這樣就一勞永逸：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

至於要怎麼預防下次再被這種莫名其妙的錯誤嚇到？其實最根本的還是專案維護。建議大家養成習慣，定期檢查一下 package.json 裡的依賴套件，尤其是 Webpack 這類核心工具，只要有空就把它們更新到支援新版 Node.js 的版本。如果專案已經太舊沒辦法升級，那就乾脆在開發環境裝個 nvm（Node Version Manager），針對不同的舊專案切換到適合的 Node.js 版本，這樣才是最保險的做法。

希望這篇筆記能幫你省下半小時去喝杯咖啡，別再被這些沒意義的環境錯誤搞壞心情了！
