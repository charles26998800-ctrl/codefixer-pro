How to Fix the "error:0308010C:digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I remember the first time this error popped up in my terminal. I had just upgraded to Node.js version 17, feeling pretty proud of myself for keeping my environment up-to-date, when suddenly my entire React build pipeline decided to go on strike. I spent a good two hours staring at my screen, convinced I’d somehow corrupted my node_modules or messed up a critical dependency, only to realize that the latest Node release had quietly broken compatibility with the older Webpack versions I was using.

The reason this happens is actually quite straightforward, even if it feels like a total mystery at first. When Node.js bumped up to version 17 and beyond, they switched to OpenSSL 3.0. This new version of OpenSSL is significantly more secure, but it deprecated several legacy algorithms that older versions of Webpack (specifically anything using the webpack 4 or earlier ecosystem) rely on for hashing. Because your project is trying to use these older, "insecure" algorithms, the new Node runtime throws up a wall and gives you that cryptic digital envelope routines::unsupported message. It’s essentially the software equivalent of trying to play a vintage cassette tape in a cutting-edge digital streaming deck—it just doesn't speak the same language anymore.

The fix I usually reach for is setting the NODE_OPTIONS environment variable to allow the use of legacy OpenSSL providers. If you’re on macOS or Linux, you can do this directly in your terminal before running your start command. Just run this snippet:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is a bit different. You’ll want to run this in your PowerShell or Command Prompt:


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

If you don't want to type that every single time you spin up your dev server, you can just bake it into your package.json file. Find your scripts section and modify the start and build commands like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To keep this from haunting you in the future, the best approach is to keep your dependencies updated. This error is almost always a sign that your project is running on an aging version of react-scripts or Webpack. Whenever you have some downtime, check if you can bump those packages to their latest versions, as newer releases have moved away from the legacy hashing algorithms that trigger this conflict.

Hope this saves you the headache I went through. Happy coding and good luck with the build!

救命！React 專案噴出 error:0308010C，害我以為電腦壞了

來源：Stack Overflow ↗ · 2572 票

那天我正準備要接手一個舊專案，想說先跑個 npm start 確認環境沒問題，結果終端機直接吐出一長串紅色錯誤訊息，那個 digital envelope routines::unsupported 簡直讓我當場傻眼。我心想這什麼鬼東西，明明昨天這台電腦還好好的，還以為是我的 Node.js 版本跟專案犯沖，差點就想直接重灌電腦，在那個當下，看著螢幕上的報錯心真的涼了一半，完全不知道該從哪裡下手。

其實會發生這個問題，是因為 Node.js 在 v17 版本之後升級了 OpenSSL 到 3.0，而舊版的 Webpack（特別是 v4 以前的版本）用的加密演算法被新版 OpenSSL 認為不夠安全，所以直接被擋下來了。說白了就是「新版 Node.js 嫌棄舊版 Webpack 的加密太老派」，結果就是你的開發環境直接罷工，留你在那邊乾瞪眼。

解決這個問題其實比想像中簡單，最快的方法就是告訴 Node.js：「嘿，請暫時用回以前的加密模式」。如果你是用 Mac 或 Linux，只要在啟動指令前面加上環境變數設定就好，像這樣：


export NODE_OPTIONS=--openssl-legacy-provider
npm start

如果你是 Windows 用戶，習慣用 PowerShell 的話，可以試試看 $env:NODE_OPTIONS = "--openssl-legacy-provider"，然後再執行 npm start。如果不想每次都打這些指令，最一勞永逸的辦法是直接去 package.json 的 scripts 區塊，把指令改成這樣：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

這樣每次執行指令時，它就會自動帶入這個設定，再也不用擔心報錯跳出來嚇人。

至於要怎麼預防下次再踩到這個坑，最好的建議就是「養成檢查 Node.js 版本的習慣」。每次換到舊專案時，我現在都會先用 node -v 看一下版本，如果專案真的太舊，我就會乖乖用 nvm (Node Version Manager) 切換到 v16 甚至更早的版本來跑，這樣通常能省下很多不必要的麻煩。畢竟與其在那邊修補加密演算法，不如直接用適合當下專案的版本來開發，才是工程師最輕鬆的生存之道。

希望這些經驗能幫你省下寶貴的除錯時間，別讓這幾行錯誤訊息壞了你寫程式的好心情！
