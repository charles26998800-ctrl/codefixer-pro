How to fix the Docker "Permission denied" error on Ubuntu

Source: Stack Overflow ↗ · 1420 votes

I still remember the first time I set up Docker on a fresh Ubuntu install, feeling like a total pro until I ran my first container command and got slapped with a nasty "permission denied" error. I spent a good hour convinced I’d borked the entire installation, repeatedly typing sudo out of habit before realizing I was stuck in a loop of administrative overkill. It’s one of those classic "welcome to Linux" moments that makes you want to throw your keyboard out the window when you’re just trying to get a simple project off the ground.

The reason you’re seeing that wall of text about the Docker daemon socket is actually pretty straightforward. By default, the Docker daemon binds to a Unix socket owned by the root user, not your standard user account. When you try to run a command without sudo, the Docker client attempts to communicate with that socket, but your user doesn't have the necessary group permissions to access it. It’s a security feature to ensure that only users with elevated privileges can interact with the daemon, but for a developer, it's a massive productivity killer.

To fix this, I always add my user to the docker group, which grants the necessary permissions to talk to the socket without needing root access every single time. First, you’ll want to create the docker group if it doesn’t exist, then add your current user to it using these commands:


sudo groupadd docker
sudo usermod -aG docker $USER

Once you’ve run those, the most important step is to tell your system to recognize the group change. You can either log out and log back in, or just run newgrp docker in your current terminal session to apply the changes immediately. You can verify it worked by running docker run hello-world without the sudo prefix. If the output shows the "Hello from Docker!" message, you’re officially in the clear and can stop typing sudo like a robot.

If you want to avoid running into this in the future, just make sure you set up your user groups as part of your standard machine provisioning script. Whenever I spin up a new dev environment, I include that usermod line in my setup dotfiles so I never have to deal with those permission headaches on a fresh install again.

Hope this saves you the headache it caused me back in the day. Happy coding!

Docker 權限被拒？別再每次都敲 sudo 了！

來源：Stack Overflow ↗ · 1420 票

記得剛開始碰 Docker 的時候，我滿心期待地把環境裝好，想說來跑個 Hello World 測試一下。結果指令敲下去，終端機直接賞我一句「Permission denied」，當下我真的滿頭問號，明明才剛安裝完，怎麼連個容器都跑不起來？最痛苦的是，我那時候每次執行 Docker 指令都要補上 sudo，搞得我開發節奏超級破碎，甚至好幾次因為忘記加 sudo，打了一長串參數結果全部重來，心態真的差點原地爆炸。

其實這背後的原因一點都不神秘，就是 Linux 的權限控管機制在作祟。Docker 的守護行程（daemon）預設是綁定在 /var/run/docker.sock 這個 Unix socket 檔案上，而這個檔案的擁有者是 root 使用者。這代表除非你是 root，或者你有 root 的權限，否則系統根本不讓你碰它。當我們不加 sudo 執行指令時，我們只是以一般使用者的身份在呼叫 Docker，系統當然會冷冷地回你一句「權限不足」，因為你沒資格去跟那個 socket 溝通。

要解決這個問題，其實根本不需要每次都打 sudo，只要把你的使用者帳號加進 docker 這個群組就搞定了。首先，你要用下面這行指令建立一個 docker 群組（雖然通常安裝時就有了，但檢查一下不吃虧）：


sudo groupadd docker

接著，把你目前的使用者加進去，這樣你就會擁有存取那個 socket 的權限了：


sudo usermod -aG docker $USER

這時候先別急著關掉視窗，記得要執行 newgrp docker 或者乾脆登出再重新登入一次，讓群組權限生效。這樣之後你就可以直接輸入 docker run hello-world，不需要再加那該死的 sudo，整個開發體驗瞬間清爽許多！

為了預防這種權限問題再次困擾你，我建議養成一個習慣：以後每當你在新的 Linux 環境設定開發工具時，第一件事就是檢查是否有類似的群組權限需求，並在建立使用者環境時就統一配置好。或者，乾脆寫一個簡單的 setup.sh 腳本，把這些設定自動化，以後換電腦直接跑一下，省得每次都要去查這段指令。

反正以後不用再多打那五個字母，敲鍵盤的速度都變快了，趕快去試試看吧！
