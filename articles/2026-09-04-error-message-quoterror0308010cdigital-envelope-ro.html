How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I updated Node.js to version 17 on my dev machine, feeling all smug about having the latest tools, only to have my entire workflow grind to a halt five minutes later. I spent a good two hours staring at my terminal, convinced I’d somehow corrupted my global dependencies or messed up my path variables, when in reality, my project was just having a mid-life crisis because of an OpenSSL update. It’s one of those cryptic errors that makes you question your entire career for a second, but it’s actually a pretty simple fix once you peel back the layers.

The reason you’re seeing this error:0308010C:digital envelope routines::unsupported message is that Node.js v17 and later switched to OpenSSL 3.0. This new version of OpenSSL is significantly more secure, but it also tightened up the requirements for legacy algorithms like MD4. A lot of older Webpack configurations and React scripts rely on these older algorithms for hashing files during the build process, so when Node.js tries to run them, it throws a tantrum because it’s no longer allowed to use the "insecure" legacy methods by default.

The quickest way I’ve found to resolve this—without downgrading your entire Node installation—is to tell your terminal to allow the legacy OpenSSL provider before running your start script. If you’re on macOS or Linux, you can do this by exporting an environment variable in your terminal session:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the command structure is slightly different. You can set it directly in your command prompt or PowerShell window like this:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

For those who want a more permanent fix so you don't have to type that out every time you open a new terminal window, you can just tweak your package.json file. Find the scripts section and modify your start and build commands to include the flag automatically:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To prevent this headache from coming back, I’ve made it a habit to use a version manager like nvm (Node Version Manager) for all my projects. By creating a .nvmrc file in the root of your project folder, you can lock your project to a specific Node version, like v16, which doesn't have this OpenSSL headache. It’s a lifesaver when you’re juggling legacy codebases and modern side projects simultaneously.

Hopefully, this saves you the afternoon of debugging I had to endure. Happy coding, and may your builds stay green!

剛升級 Node.js 就原地崩潰？搞定 "digital envelope routines::unsupported" 錯誤

來源：Stack Overflow ↗ · 2572 票

那天我為了趕一個專案進度，心想「反正 Node.js 升級到 v17 很久了，乾脆順手升級一下好了」，結果指令跑完執行 npm start 的那一刻，螢幕上直接噴出一長串紅字，那個 error:0308010C:digital envelope routines::unsupported 簡直像是在嘲笑我的魯莽。我當時真的差點把鍵盤給砸了，明明五分鐘前還跑得好好的，怎麼升級個版本就像是把整個世界拆了一樣，連最基本的啟動都做不到。

其實這個問題的原因說穿了就是「世代交替的摩擦」。簡單來說，從 Node.js v17 開始，系統引入了新版的 OpenSSL 3.0，這玩意兒對加密演算法的安全性要求變高了，偏偏很多我們常用的舊版 Webpack 或者是其他打包工具，還在用舊式的 MD4 演算法，新版的 Node.js 一看：「這太老舊了，我不准你跑！」於是直接把你的專案擋在門外。這真的超痛苦，因為你根本沒動程式碼，只是想升級環境，結果卻被環境反咬一口，那種「明明沒錯卻被系統制裁」的無力感，相信經歷過的人都懂。

當時我為了趕時間，沒空去深究怎麼改 Webpack 設定，直接用了最暴力也最有效的解法，就是告訴 Node.js：「嘿，別管那麼嚴，先讓我跑起來再說。」做法其實就是在執行指令之前，把 NODE_OPTIONS 這個環境變數設為 --openssl-legacy-provider。如果你是用 macOS 或 Linux，直接在終端機輸入：


export NODE_OPTIONS=--openssl-legacy-provider
npm start

如果是 Windows 的 PowerShell 使用者，語法稍微不一樣，要改成：


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

如果你不想每次都要手動打這一長串，最省事的做法就是直接去 package.json 裡面的 scripts 把啟動指令改掉，例如把 "start": "react-scripts start" 改成 "start": "react-scripts --openssl-legacy-provider start"，這樣以後只要下 npm start 就會自動幫你帶上這個設定。

為了避免以後再踩到這種坑，我現在養成了一個習慣：除非專案真的需要新版 Node.js 的特性，否則我都會乖乖使用 NVM (Node Version Manager) 來管理環境。畢竟每個專案的依賴環境都不同，與其讓全域的 Node 版本在那邊瞎攪和，不如針對專案鎖定好版本，才不會哪天又突然跳出這種奇怪的加密錯誤，搞得自己滿頭大汗。
