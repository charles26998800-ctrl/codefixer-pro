How to Check if a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7352 votes

Early in my career, I was building a log-processing utility that needed to verify a configuration file before attempting to parse it. I spent nearly three hours banging my head against a wall because I was wrapping every single file check in massive try-except blocks, which made my code look like a plate of spaghetti and felt incredibly bloated. I remember staring at the screen at 2 AM, wondering why something as simple as asking "is this file here?" had to result in such an ugly, verbose mess of exception handling.

The reason this feels so clunky is that Python’s philosophy is often "Easier to Ask for Forgiveness than Permission" (EAFP). Many Pythonistas will tell you that using try-except is the "Pythonic" way to handle file operations because it avoids race conditions. If you check if a file exists and then try to open it a millisecond later, another process might have deleted it in that tiny window. However, when you’re writing simple scripts or CLI tools where that level of concurrency isn't an issue, the constant error handling just gets in the way of readable code.

When I finally moved away from try blocks for simple existence checks, I started using the pathlib module, which is the modern standard for handling filesystem paths. It’s clean, object-oriented, and honestly, just a joy to use compared to the older os.path methods. Here is how I usually handle it now:


from pathlib import Path

file_path = Path("config.json")

if file_path.is_file():
    print("The file exists, let's proceed!")
else:
    print("File not found, skipping.")

If you’re working on a legacy codebase or just prefer the older os module style, you can also use os.path.exists(). It’s essentially the same logic, though it returns True for both files and directories, so keep that in mind if you need to be strictly specific about it being a file.


import os

if os.path.exists("config.json"):
    # Do your work here
    pass

To prevent this from becoming a recurring headache, my best advice is to stop checking for existence entirely unless you absolutely have to. Instead of checking if a file exists and then opening it, just write your logic to handle the FileNotFoundError gracefully in one clean block. If you absolutely need to check, stick to pathlib because it keeps your path logic organized and readable as your project grows.

Hope this saves you from the same late-night frustration I dealt with! Happy coding.

別再用 try-except 檢查檔案了！Python 檢查檔案存在的正確姿勢

來源：Stack Overflow ↗ · 7352 票

以前剛寫 Python 時，我真的超愛用 try-except 來處理各種狀況，覺得這樣寫看起來很專業，直到有一次我在寫一個自動化腳本，要處理幾萬個 log 檔案，因為用了 try-except 把每個檢查都包起來，結果程式跑起來慢到我想哭，CPU 佔用率還高得嚇人。那天凌晨三點，我看著螢幕上卡住的進度條，心想：「這簡直是把簡單的問題複雜化，我到底在幹嘛？」那種明明程式沒錯，但效率卻爛到炸開的無力感，真的是工程師最想原地辭職的時刻。

其實會發生這種問題，是因為很多人（包括當年的我）把「例外處理」當成了「邏輯判斷」在用。在 Python 的設計哲學裡，try-except 是用來處理那些「不可預期」的錯誤，而不是用來檢查檔案存不存在這種「預期內」的狀態。當你瘋狂地拋出並捕捉例外，底層需要耗費大量的資源去建立 traceback，這對於效能來說簡直是災難。

後來我就學乖了，改用標準函式庫提供的 pathlib，這東西簡直是救星。你可以直接呼叫 exists() 方法，它回傳的就是一個單純的布林值 True 或 False，乾淨又俐落。


from pathlib import Path

file_path = Path('my_data.txt')

if file_path.exists():
    print("檔案還在，可以繼續工作！")
else:
    print("檔案不見了，先別急著讀取。")

如果你是因為工作環境還卡在舊版 Python，或者單純習慣用 os 模組，那使用 os.path.exists() 也是完全沒問題的，效果一樣好。


import os

if os.path.exists('my_data.txt'):
    # 進行你的後續操作
    pass

為了避免以後又踩到這種效能地雷，我現在養成一個習慣：在寫程式前先問自己，「這是一個會發生的常態嗎？」如果是常態，那就用 if 判斷式處理；如果是真的出乎意料的崩潰，再交給 try-except 去接住。另外，記得要小心「競爭條件（Race Condition）」的問題，就算你檢查了檔案存在，下一毫秒它還是可能被別人刪掉，所以該有的錯誤處理還是不能少，只是別把它當成主要的邏輯判斷就好。

希望這招能幫你省下不少除錯的頭髮，別再讓程式碼跑得像烏龜一樣啦！
