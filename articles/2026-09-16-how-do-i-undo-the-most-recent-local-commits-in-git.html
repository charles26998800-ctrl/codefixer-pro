How to Undo Your Most Recent Local Git Commits Without Losing Your Work

Source: Stack Overflow ↗ · 27239 votes

I still remember the first time I accidentally committed a .env file containing my actual AWS secret keys to a local repository. My heart sank as I realized I’d just saved my credentials into the version history, and I spent a solid two hours frantically Googling how to "delete" a commit before I panicked and deleted the entire project folder. It was a classic rookie mistake that felt like the end of the world, but once I learned how git reset actually works, it became just another routine command in my daily workflow.

The reason this happens is usually just human error combined with the way Git manages its history. When you run git commit, Git takes a snapshot of your staged changes and moves the branch pointer forward. If you haven't pushed that commit to a remote server yet, that history exists only on your machine, which is great news. Because Git is essentially a directed acyclic graph of snapshots, "undoing" a commit is really just moving that branch pointer back to a previous state. It isn't magic; it's just telling Git to pretend the last step never happened.

When I need to fix a local commit that hasn't been pushed, my go-to tool is git reset. If I want to undo the commit but keep the changes I made to the files in my working directory—which is what I usually want so I can fix the mistake—I run a soft reset.


git reset --soft HEAD~1

Using HEAD~1 tells Git to move the pointer back by one commit. The --soft flag is the secret sauce here; it keeps all your files staged and ready for a new commit. If you realized you committed the wrong files entirely and want to wipe those changes out of your working directory completely, you can use the --hard flag instead.


git reset --hard HEAD~1

Just be careful with that --hard flag, because it will permanently discard any changes you made in that commit, so make sure you’ve backed up anything you actually intended to keep.

To prevent this in the future, I started using a pre-commit hook to scan for credentials or sensitive patterns before the commit is even created. You can also get into the habit of running git status one last time right before you hit enter on your commit command, just to double-check that you aren't accidentally staging a file you didn't mean to include.

We’ve all been there, so don't sweat it too much next time you mess up your history. Happy coding, and may your Git tree always stay clean!

手滑 commit 了機密檔案？教你如何優雅地把 Git 時光倒流

來源：Stack Overflow ↗ · 27239 票

記得有一次凌晨兩點，我正趕著要下班，腦袋已經呈現關機狀態，直接執行了 git commit -am "fix bugs"。結果按完 Enter 的瞬間我才驚覺，我不小心把剛剛測試用的 API Key 和一大堆除錯用的垃圾 log 全部包進去了！那一刻我整個人從椅子上彈起來，心臟漏跳好幾拍，在那裡盯著終端機畫面發呆，心想：「完了，這要是推上去被掃到，明天我是不是直接不用去公司了？」

其實這問題的本質很簡單，就是 Git 在你的本地端建立了一個新的「快照」，而我們只是想把這個快照撤銷，回到 commit 發生之前的狀態。很多人會慌，是因為怕檔案不見，但其實 Git 的 reset 指令就像是時光機，只要還沒推送到遠端伺服器（Remote），這一切都還算在你的掌控範圍內。

當下我冷靜下來後，用的就是 git reset。如果你只是想撤銷最後一次 commit，但想保留修改過的檔案內容，好讓你重新整理一下再 commit，我建議直接用這個指令：


git reset --soft HEAD~1

這行指令會把你的 commit 撤銷掉，但你剛剛寫好的程式碼會完好無缺地留在 Staging Area（暫存區）。如果你連剛剛做的變更都想一併丟掉，徹底回到 commit 之前的乾淨狀態，那就改用：


git reset --hard HEAD~1

不過要特別提醒，用 --hard 前一定要確認你真的不想要那些改動了，因為它執行下去是不會回頭的，我就曾經因為手殘把改了兩小時的功能全刪了，當場在辦公室發出淒厲的叫聲。

為了不要再經歷這種心臟病發作的時刻，我現在養成了一個習慣：在 commit 之前，一定會先打 git status 看一眼。如果真的怕漏掉什麼，可以善用 .gitignore 檔案，把那些測試用的設定檔、環境變數或是會自動產生的 log 直接過濾掉。只要把這些東西寫進去，Git 就會自動無視它們，以後就算你再怎麼手滑，也不會誤把敏感資訊 commit 出去啦。

以後遇到這種手滑狀況別慌，Git 的時光機功能強大得很，多練習幾次你就跟我一樣淡定了。
