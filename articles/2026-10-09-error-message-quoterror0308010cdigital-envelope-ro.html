Fixing the "error:0308010C:digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I remember the exact moment I first hit this error. I’d just spun up a fresh React project to prototype a quick feature, and I was ready to dive into the code, only to be greeted by a wall of red text in my terminal. I spent a good two hours convinced I’d somehow broken my entire Node installation or missed a crucial dependency, all while chugging cold coffee and questioning why something as simple as npm start felt like it was trying to launch a rocket.

The reason you’re seeing this cryptic digital envelope routines::unsupported message is actually quite straightforward once you peel back the layers. When Node.js upgraded to version 17, they switched to OpenSSL 3.0. This new version has stricter security standards, and many older libraries—including the Webpack versions used by older React project templates—rely on legacy algorithms that OpenSSL 3.0 now rejects by default. It's basically a compatibility mismatch where your build tools are trying to use an "outdated" encryption method that your newer Node version refuses to touch.

The most effective way I’ve found to squash this bug is to force Node to use the legacy provider. You don't need to downgrade your entire Node environment to do this; you just need to set an environment variable. If you’re on a Mac or Linux machine, you can run this command in your terminal before starting your project:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is a bit different. You’ll want to run this in your PowerShell or Command Prompt:


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

For those who want a permanent fix so you don't have to remember to run that command every single time you open your IDE, you can modify your package.json file. Just head over to the scripts section and inject the variable directly into your start command like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To keep this from haunting you in the future, my best advice is to stay on top of your project dependencies. This error is almost always a sign that your react-scripts or Webpack version is lagging behind. Whenever you have a spare afternoon, run npm outdated and start bumping those versions up. Keeping your build tools current is a lot less painful than debugging crypto errors in the middle of a sprint.

Hope this gets your dev environment back on track. Happy coding!

被 Node.js 版本背刺？解決 error:0308010C 的崩潰現場

來源：Stack Overflow ↗ · 2572 票

那天我正準備接手一個舊專案，想說先開個開發環境跑跑看，結果 npm start 一按下去，終端機直接跳出一長串紅字，那個 digital envelope routines::unsupported 看得我頭暈目眩。我當下真的差點要把鍵盤砸了，心想：「我才剛把環境架好耶，連程式碼都還沒改，為什麼直接給我來個這種莫名其妙的報錯？」

其實這問題的兇手就是 Node.js 的升級。簡單來說，Node.js v17 之後導入了 OpenSSL 3.0，這玩意兒對於加密演算法的安全性要求變高了，偏偏很多我們常用的舊版 React 專案（或是 Webpack 舊版本）還在用比較舊的加密演算法。兩邊這下就鬧矛盾了，Node.js 覺得這些舊演算法不安全不給跑，結果就是你的編譯直接炸裂。那種明明什麼都沒動，卻因為升級了 Node 版本就導致專案跑不動的感覺，真的是開發者心中的痛，感覺就像是房子蓋好了，結果地基規格突然改了。

要解決這個問題，其實不用把整個 Node 版本降回去，最快的做法就是在啟動專案時，直接告訴系統：「嘿，拜託稍微寬容一點，讓我跑一下這些舊演算法吧。」你只需要設定一個環境變數 NODE_OPTIONS，把 --openssl-legacy-provider 這個參數加進去就搞定了。

如果你是用 macOS 或 Linux，最簡單的方法就是在終端機輸入：


export NODE_OPTIONS=--openssl-legacy-provider

然後再執行你的 npm start，通常這樣就能順利跑起來了。如果你是用 Windows 的 PowerShell，指令則是：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

或是直接寫在 package.json 的 scripts 裡面，把啟動指令改成這樣：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start"
}

這樣以後每次執行 npm start 就會自動帶上這個參數，不用擔心哪天忘記又要重查一次。

至於要怎麼預防這種鳥事再發生？我覺得最根本的還是要學會用 nvm (Node Version Manager) 來管理版本。畢竟每個專案依賴的環境真的差很多，與其為了新專案升級 Node 導致舊專案全滅，不如乖乖在專案目錄下放一個 .nvmrc 檔案，記錄下該專案建議的 Node 版本。下次換環境或是切換專案時，直接 nvm use 一下，保證你會感謝當初多做這一步的自己。

希望這篇能拯救正在螢幕前抓狂的你，搞定之後趕快去喝杯咖啡壓壓驚吧！
