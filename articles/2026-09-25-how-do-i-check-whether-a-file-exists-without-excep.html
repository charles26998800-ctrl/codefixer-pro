How to Check If a File Exists in Python Without Using Try-Except Blocks

Source: Stack Overflow ↗ · 7351 votes

Early in my career, I remember writing a script to process a massive batch of log files, and I wrapped every single file operation in a bulky try-except block. I spent three hours debugging a performance bottleneck because the sheer volume of exception handling was absolutely tanking my execution time, only to realize I was overcomplicating a simple existence check. It was one of those classic "junior developer" moments where I learned that while exceptions are powerful, they aren't always the cleanest tool for the job.

The reason developers often struggle with this is that Python’s philosophy—often summarized as "Easier to Ask for Forgiveness than Permission" (EAFP)—encourages using exceptions. However, when you’re just doing a quick sanity check before reading a config file or initializing a download, catching a FileNotFoundError every time a file happens to be missing feels like overkill. It clutters your logic and, in tight loops, can actually impact the performance of your application.

To handle this cleanly, I prefer using the pathlib module, which has been the standard way to handle filesystem paths since Python 3.4. It’s object-oriented, readable, and much more intuitive than the old-school os.path functions. If I need to verify a file's existence, I simply instantiate a Path object and call the .exists() method.


from pathlib import Path

file_path = Path("config.json")

if file_path.exists():
    print("File found, proceeding with the load...")
else:
    print("File is missing, skipping this step.")

If you specifically need to ensure that the path is a file and not a directory—which is a common trap because exists() returns True for directories too—you should use is_file() instead. It’s saved me from several "permission denied" errors when my script accidentally tried to read a folder instead of a document.


if file_path.is_file():
    # Do your work here
    pass

The best way to prevent these kinds of headaches is to adopt a "look before you leap" approach only when the check is cheap and you expect the file to be missing occasionally. If you're building a mission-critical system where files *should* always be there, stick with the try-except block because it forces you to handle the error explicitly. Just don't get into the habit of using exceptions for control flow when a simple boolean check does the trick.

Hope this clears up the confusion and helps you write some cleaner, more readable code. Catch you later!

別再用 try-except 檢查檔案是否存在了，Python 其實有更優雅的解法

來源：Stack Overflow ↗ · 7351 票

記得幾年前剛開始寫 Python 爬蟲時，為了處理下載好的圖片，我寫了個簡單的腳本來檢查檔案是不是已經存在。當時我為了省事，直接用了 try-except IOError 把檢查邏輯包起來。結果那個破腳本在跑幾萬張圖片時，瘋狂觸發例外處理，效能慢到我想把電腦砸了，更慘的是，因為 try-except 包得太寬，我竟然沒發現其實是權限不足導致的報錯，還在那邊傻傻地等它跑完，最後發現檔案根本沒寫入成功，那種心血全白費的絕望感，真的會讓人懷疑人生。

其實，很多人會想避開 try-except 去檢查檔案，是因為我們直覺上覺得「檢查」應該是個輕量級的操作。但在 Python 的世界觀裡，有一種觀念叫 EAFP（It's easier to ask for forgiveness than permission），也就是與其先檢查再動作，不如直接做，出錯了再處理。但問題是，當你只是想確認檔案在不在，而不是要「打開」它時，頻繁觸發例外處理其實是非常昂貴的開銷，這會讓你的程式碼看起來既臃腫又沒效率。

後來我學乖了，其實 Python 的標準函式庫已經提供了很直覺的解法。如果你還在用舊版的 os.path.exists，建議可以趕快轉向 pathlib，這東西真的好用到會讓你後悔沒早點用。只要一行程式碼，就能乾淨俐落地判斷檔案存不存在，完全不需要跟例外處理糾纏。


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.is_file():
    print("檔案還在，可以放心讀取！")
else:
    print("檔案搞丟了，準備重建吧。")

如果要預防這種「檔案檢查」帶來的坑，我強烈建議大家養成一個習慣：不要只檢查檔案存不存在，還要檢查權限。很多時候 is_file() 回傳 True，但你程式卻因為沒權限讀取而崩潰，這才是最讓人崩潰的邊緣案例。所以我現在都會習慣在檢查完檔案後，順便確認一下讀寫權限，或者乾脆把邏輯封裝成一個小工具函式，集中管理這些硬碟 IO 的碎事，這樣日後維護起來才不會像是在拆地雷。

寫程式就是這樣，避開這些坑，你的程式跑起來才會順心，不會半夜還被報錯通知吵醒。
