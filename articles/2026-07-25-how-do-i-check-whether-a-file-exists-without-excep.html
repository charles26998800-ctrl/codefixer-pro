How to Check if a File Exists in Python Without Using Try-Except Blocks

Source: Stack Overflow ↗ · 7349 votes

I still remember the first time I built a file-processing script for a production pipeline; I was obsessed with writing "clean" code and convinced that wrapping every single file operation in a try...except FileNotFoundError block was just sloppy. I spent three hours refactoring my logic to avoid those blocks, only to realize I was fighting against Python’s "it's easier to ask for forgiveness than permission" (EAFP) philosophy. It was a classic case of over-engineering a simple task, and honestly, the resulting code was way more confusing than it needed to be.

The reason so many of us run into this friction is that Python’s design encourages handling exceptions rather than checking conditions beforehand. When you check for a file’s existence before opening it, you open the door to a race condition. Between the split second your code confirms the file is there and the moment it actually attempts to open it, another process could have deleted or moved that file. This is why the language developers usually prefer the try-except approach, but I get it—sometimes you just want a clean boolean check to control your application flow without cluttering your logic with error handlers.

If you really want to avoid the try statement, the modern and most "Pythonic" way to do this is by using the pathlib module. It’s been standard since Python 3.4, and it makes handling paths feel like you're actually working with objects rather than just strings. You can simply call the .exists() method on a Path object, which returns a clear True or False.


from pathlib import Path

file_path = Path("my_data_file.txt")

if file_path.exists():
    print("The file is right where it should be.")
else:
    print("No file found, moving on.")

If you’re working with older codebases or just prefer the classic os module, you can use os.path.isfile(). It’s the traditional way to check for files, and it works perfectly fine for most basic scripts.


import os

if os.path.isfile("my_data_file.txt"):
    print("File exists and it's a file, not a directory.")

To prevent this headache in the future, my best advice is to embrace the EAFP principle for critical file operations. Even if you use .exists() to check a file, always wrap your actual file opening logic in a try...except block anyway. You can’t control what happens to the file system during runtime, and it's much better to have a robust error handler than to have your script crash because someone deleted a file while your code was mid-execution.

Hope this clears up the confusion and helps you write some cleaner file-handling logic today. Happy coding!

別再用 try-except 檢查檔案是否存在了！Python 的優雅解法

來源：Stack Overflow ↗ · 7349 票

記得幾年前我在趕一個自動化部署腳本，當時為了處理設定檔，我腦子一熱，直接寫了一大串 try-except FileNotFoundError 來判斷檔案在不在。結果那個腳本在伺服器上跑起來後，因為權限問題頻繁觸發例外，搞得 Log 檔直接炸開，光是清理那些無用的錯誤紀錄就讓我差點崩潰，當時心裡真的只想罵髒話。

其實很多人剛學 Python 時，都會覺得用 try-except 包起來最安全，畢竟這是 Python 的核心哲學：「請求原諒比請求許可容易」。但問題在於，如果你的邏輯只是單純想知道「這東西在不在」，根本不需要動用到例外處理機制。每次觸發 try-except 其實都會消耗額外的效能資源，如果是在迴圈裡大量檢查，你的程式跑起來就像是背著沙包在跑步，效率爛到想哭。

後來我學乖了，改用了 pathlib 這個模組，這簡直是救贖。現在我檢查檔案是否存在，都直接用它內建的方法，代碼看起來乾淨又直覺。你可以直接這樣寫：


from pathlib import Path

file_path = Path("config.json")

if file_path.exists():
    print("檔案找到了，趕快開工！")
else:
    print("檔案不見了，先去哭一下。")

如果你還在用舊版的 os.path 其實也行，寫法是 os.path.exists(path)，但我個人真心推薦全面擁抱 pathlib。它不僅能檢查檔案，連目錄是否存在、檔案權限怎麼設，都可以用物件導向的方式處理，比起以前那種字串拼接的寫法，真的優雅太多了。

說到預防再次踩坑，我建議大家以後在寫這類功能時，養成一個習慣：不要只檢查「檔案在不在」，還要順手檢查它是不是「真的是個檔案」。因為我有次被坑過，程式碼檢查 exists() 回傳 True，結果那其實是一個同名的資料夾，導致後面的讀取操作直接報錯。所以現在我都會寫成 file_path.is_file()，這樣就能確保萬無一失，再也不用擔心這種低級錯誤毀了我的週末了。

以後遇到這種小問題，記得別再動不動就拋出例外啦，用正確的工具讓程式碼看起來乾淨點，自己看了也舒心。
