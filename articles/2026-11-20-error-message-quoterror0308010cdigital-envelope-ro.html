How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2573 votes

I remember exactly where I was when this error first hit my terminal—I’d just pulled down a legacy project for a quick hotfix, feeling pretty confident that I’d be done in twenty minutes. Instead, I spent the next two hours staring at my screen, confused why a project that worked for my teammate was suddenly spitting out a cryptic OpenSSL error the second I ran npm start. It’s one of those bugs that makes you want to throw your keyboard out the window because it doesn’t actually have anything to do with your code; it’s just the environment throwing a tantrum.

This whole mess boils down to a mismatch between your version of Node.js and the Webpack version used in your project. When Node.js bumped up to version 17, they switched to OpenSSL 3.0, which has stricter security defaults. A lot of older Webpack configurations (specifically versions 4 and below) try to use algorithms like MD4, which are now considered legacy and are blocked by the new OpenSSL engine. Essentially, your Node environment is telling your build tool, "I don't trust that old math you're trying to use," and it shuts down the entire process.

The quickest way I found to fix this without spending all day refactoring build scripts is to tell Node.js to use the legacy OpenSSL provider. You can do this temporarily by setting an environment variable before running your start command. If you’re on macOS or Linux, you’ll want to run this in your terminal:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is a bit different, so you’ll need to use set instead:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

If you don't want to type that out every single time, you can just bake it directly into your package.json file. Just find the scripts section and update your start command like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To stop this from haunting your future projects, the best habit to get into is using a version manager like nvm (Node Version Manager). I keep my environments pinned to the specific version required by the project I’m working on—usually an LTS version—which prevents these major breaking changes from sneaking up on me when I upgrade my global Node installation. It’s saved me from countless headaches and lets me focus on the actual features rather than debugging my build pipeline.

Hopefully, this gets your project back up and running so you can get back to building cool stuff. Happy coding!

當 React 遇上 Node.js 升級災難：搞定 error:0308010C

來源：Stack Overflow ↗ · 2573 票

那天我剛換了一台新電腦，想說要把擱置已久的 React 專案拿出來跑一下，結果 npm start 才剛敲下去，終端機就噴出一大串紅通通的錯誤訊息，最顯眼的就是那行 error:0308010C:digital envelope routines::unsupported。我當時真的差點原地崩潰，心想：「我明明什麼都沒動，只是重灌個環境而已，是在演哪齣？」

其實這問題說穿了，就是 Node.js 升級惹的禍。簡單來說，從 Node.js 17 版本開始，為了資安考量，官方引入了 OpenSSL 3.0，但我們手邊很多舊版的 React 專案（特別是還在用 Webpack 4 的那些老骨頭）還在使用舊的雜湊演算法。新版的 Node 覺得這些演算法不夠安全，直接拒絕執行，導致你的打包工具在編譯時當場罷工。那種感覺真的很無力，就像是你明明沒改程式碼，卻被環境莫名其妙卡住，想趕進度卻連第一個畫面都跑不出來，真的會氣到想把鍵盤拆了。

我當下冷靜了一下，發現最快的解法其實就是告訴 Node.js：「嘿，別管那麼多，幫我把舊的演算法打開。」如果你跟我一樣急著要讓專案動起來，只要在啟動指令前加上一個環境變數設定就能搞定。

如果你是 macOS 或 Linux 使用者，直接在終端機輸入：


export NODE_OPTIONS=--openssl-legacy-provider
npm start

如果你是在 Windows 的 PowerShell 環境，指令長得稍微不一樣：


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

當然，如果你不想每次都要打這串指令，最乾脆的方法是直接改掉 package.json 裡的 scripts 設定，把 start 的部分改成這樣：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

為了避免以後再被這種環境問題搞到心累，我現在養成了一個習慣，就是每個專案一定會加上 .nvmrc 檔案，明確指定該專案對應的 Node.js 版本。這樣下次交接或是換電腦時，我只要用 nvm use 就能無腦切換到正確的版本，不用再賭運氣看新版 Node 是不是又把什麼東西拔掉了。

處理完這個地雷後，專案終於順利跑起來了，希望這招能拯救正在螢幕前焦慮的你。
