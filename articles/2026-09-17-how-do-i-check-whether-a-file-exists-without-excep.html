How to Check If a File Exists in Python Without Using Try-Except Blocks

Source: Stack Overflow ↗ · 7351 votes

Back when I was a junior developer, I remember writing a script to automate log cleanup, and I was obsessed with keeping my code as "clean" as possible. I thought using try-except blocks for basic file checks felt like I was treating every file existence check as a catastrophic failure, so I wasted an entire afternoon trying to find a "cleaner" way to do it. It was one of those classic "I’m overthinking this" moments that eventually led me to realize that Python actually provides built-in tools for exactly this scenario, saving me from writing verbose error-handling code for routine tasks.

The reason people run into this is that Python’s philosophy is often "Easier to Ask for Forgiveness than Permission" (EAFP), meaning try-except is usually the preferred, idiomatic way to handle file operations. However, when you’re building a script where you just need to verify a path before branching your logic, wrapping everything in a try block can feel like overkill. You’re essentially dealing with the discrepancy between the file system's state and your script's knowledge of it, and sometimes you just want a simple boolean check to keep your control flow readable and concise.

To fix this, I stopped fighting the language and started using the pathlib module, which is the modern, object-oriented way to handle file system paths in Python. Instead of relying on the older os.path module, pathlib makes the code significantly more readable. You simply create a Path object and call the .exists() method. It’s elegant, it doesn't raise exceptions, and it returns a straightforward True or False. Here is exactly how I handle it now:


from pathlib import Path

file_path = Path("my_data_file.txt")

if file_path.exists():
    print("The file exists, proceeding with processing...")
else:
    print("File not found, skipping...")

If you’re still working on a legacy codebase that hasn't made the jump to pathlib, you can use the os.path.exists() function, which does the same thing under the hood. It’s not quite as modern, but it gets the job done without throwing an error:


import os

if os.path.exists("my_data_file.txt"):
    print("Found it!")

The best way to prevent future headaches with this is to always verify what you're actually checking for. A file might exist, but it could be a directory or a symbolic link, which often leads to "Permission Denied" errors later on. I’ve started using file_path.is_file() instead of just .exists() whenever I’m specifically looking for a file rather than a folder. It’s a small change that saves me from those frustrating "Is a directory" errors that inevitably pop up when you assume every path you find is the file you expected.

Hope this helps you clean up your scripts and save you that afternoon I lost. Happy coding!

別再用 try-except 檢查檔案是否存在了！優雅處理路徑的正確姿勢

來源：Stack Overflow ↗ · 7351 票

記得剛開始寫自動化腳本的時候，我為了檢查設定檔在不在，滿篇程式碼都塞滿了 try-except。當時寫得洋洋得意，覺得這樣肯定萬無一失，直到有次我寫了一個處理上萬個小檔案的腳本，因為過度使用例外處理，效能慢到我懷疑人生，甚至在除錯時被亂竄的例外訊息搞到快崩潰。最痛苦的時刻，莫過於你以為自己寫了防禦性程式碼，結果因為邏輯寫錯導致程式在關鍵時刻直接跳出，搞得我還要半夜爬起來看 Log，那種心累真的只有經歷過的人才懂。

其實會發生這種問題，主要還是因為我們太依賴這種「先試試看，不行再處理」的直覺邏輯。在 Python 裡，try-except 本來是用來處理那些「不可預測的意外」，而不是用來控制正常的流程。如果你只是想確認檔案在不在，一直拋出例外再捕捉它，其實是在浪費電腦的資源，而且程式碼看起來也會像是一團糾結的毛線球，維護起來簡直是地獄。

後來前輩指點我，其實只要用 pathlib 模組就能解決這個問題，這才是現代 Python 該有的寫法。我們不需要去捕捉什麼例外，直接問那個檔案「你在嗎？」就好。你可以這樣寫：


from pathlib import Path

file_path = Path('config.json')

if file_path.exists():
    print("檔案找到了，趕快開工！")
else:
    print("檔案不存在，先別亂動以免崩潰。")

透過 pathlib，程式碼會變得乾淨很多，邏輯也一眼就能看懂。如果你還在用舊版的 os.path.exists()，其實也可以，但 pathlib 把路徑處理得像物件一樣，未來如果要進行路徑拼接或權限檢查，會方便非常多。

至於要怎麼預防這種爛攤子再次出現？我強烈建議大家養成「檢查前先思考」的習慣。在動手寫程式前，先問自己這個檢查是屬於「業務邏輯的一部分」還是「真的無法預期的錯誤」。如果是業務邏輯（例如檔案讀取），請用 pathlib 檢查；如果是真的可能發生權限不足或硬碟故障，那才是 try-except 該出場的時候。別把這兩者混在一起，你的程式碼壽命才會長一點。

把這些邏輯理清楚之後，寫起來真的輕鬆不少，祝大家的腳本都能跑得又快又穩！
