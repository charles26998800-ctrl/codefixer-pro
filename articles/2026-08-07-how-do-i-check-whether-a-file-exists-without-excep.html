How to Check If a File Exists in Python Without Using Try-Except Blocks

Source: Stack Overflow ↗ · 7349 votes

Early in my career, I remember writing a file-processing script that was littered with try...except IOError blocks for every single I/O operation. I spent three hours debugging a simple utility because my exception handling was so bloated that I accidentally swallowed a permissions error, thinking the file just didn't exist. It was a classic "junior dev" trap where I was over-engineering a simple path validation, and I promised myself I’d find a cleaner, more readable way to handle file existence checks.

The reason we often get stuck here is that Python’s philosophy is usually "easier to ask for forgiveness than permission" (EAFP), which encourages using try blocks. However, there are plenty of scenarios—like checking if a configuration file is present before triggering a heavy setup process—where a simple boolean check is much more readable than a full exception-handling block. When you use try...except, you’re telling Python to prepare for a failure, but sometimes you just want a quick "yes or no" to keep your control flow clean and avoid the overhead of exception stack traces when you know a missing file is a perfectly normal state.

To fix this, I moved away from the old-school os.path module and started using pathlib, which has been the standard since Python 3.4. It treats paths as objects rather than strings, which makes the code feel much more modern. If you want to check if a file exists, you simply instantiate a Path object and call the .exists() method.


from pathlib import Path

file_path = Path("config.yaml")

if file_path.exists():
    print("File found, proceeding with load.")
else:
    print("File missing, skipping.")

If you need to be even more specific—for instance, distinguishing between a file and a directory—you can use .is_file() or .is_dir(). I prefer this approach because it’s incredibly explicit and reads almost like plain English, which saves me from having to explain my code to teammates during a PR review. While os.path.exists() still works fine, pathlib is just more expressive and less prone to the weird edge cases you get with string-based path manipulation.

The best way to prevent these kinds of headaches is to adopt pathlib for all your filesystem interactions from day one. It forces you to think about your paths as structured objects rather than loose strings, which prevents a lot of the common bugs related to path concatenation and OS-specific separators.

Hope this saves you a few hours of debugging and keeps your codebase looking clean. Let me know if you run into any other weird path issues!

不想寫 try-except？Python 檢查檔案存不存在的優雅做法

來源：Stack Overflow ↗ · 7349 票

還記得剛進這行沒多久時，為了處理一個自動化腳本，我寫了大量的 try-except FileNotFoundError 來確認設定檔在不在。結果那個程式碼醜到連我自己都看不下去，滿滿的巢狀結構讓我那天加班加到懷疑人生，甚至在發現是因為路徑少打一個字母而噴錯時，差點直接對著螢幕崩潰。當時我就在想，難道就沒有那種「先問一下再動手」的乾淨寫法嗎？

其實很多人會被這個問題困擾，是因為 Python 的哲學通常是「請求寬恕比申請許可更容易」（EAFP），也就是鼓勵你直接做，有錯再抓。但有時候在寫工具指令或腳本時，我們真的只是想先確認檔案在不在，好決定要不要執行下一步，這時候硬要寫 try-except 反而顯得囉唆，甚至會讓你的邏輯判斷變得非常破碎。

如果你跟我一樣不想在程式碼裡塞滿一堆例外處理，最推薦的做法就是直接用 pathlib 模組。這是我這幾年寫 Python 養成的新習慣，比起以前那種老派的 os.path，它的語法簡直是現代工程師的救贖。你只需要這樣寫：


from pathlib import Path

file_path = Path("config.json")

if file_path.exists():
    print("檔案找到了，準備開工！")
else:
    print("檔案不存在，先閃人去別的地方。")

你看，這樣寫是不是清爽多了？pathlib 把路徑當成物件處理，語意非常明確，而且 exists() 這個方法直接回傳布林值，完全不用擔心會噴出什麼惱人的例外。如果你還在用舊版的 os.path.exists()，雖然它也能用，但 pathlib 在處理路徑拼接和跨平台問題上真的好用太多了，強烈建議大家把舊習慣換掉。

要預防這種「檔案明明在，程式卻找不到」的痛苦時刻，我個人的建議是永遠不要把路徑寫死。試著養成使用 pathlib 處理相對路徑的習慣，或者在程式啟動時就先檢查環境變數跟路徑設定。只要把這些檢查邏輯抽離成一個簡單的工具函式，你的主程式邏輯就會乾淨到讓你心情變好，再也不用為了檢查檔案存不存在這種小事搞得心力交瘁了。

希望這些經驗能幫你省下不少除錯的時間，這招學起來，以後寫腳本真的會順手很多。
