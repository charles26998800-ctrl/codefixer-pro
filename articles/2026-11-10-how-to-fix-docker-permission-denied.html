How to fix the Docker "Permission Denied" error on Ubuntu

Source: Stack Overflow ↗ · 1420 votes

I remember the first time I set up a fresh Ubuntu server for a side project, feeling like a total pro until I tried to run my first container. I spent a good three hours convinced I had botched the entire installation because every single command I typed threw a "permission denied" error at me, and honestly, I nearly wiped the partition out of pure frustration. It’s one of those rites of passage every developer goes through, but once you realize it's just a simple group management issue, you’ll never look back.

The reason you’re running into this is that the Docker daemon binds to a Unix socket rather than a TCP port by default. Because that socket is owned by the root user, you usually need sudo privileges to interact with it. When you attempt to run a command as your standard user, the Docker client lacks the necessary permissions to talk to the daemon, resulting in that annoying "Permission denied" wall. It’s a security feature designed to keep unauthorized users from spinning up containers, but it gets old fast when you’re trying to iterate quickly.

To fix this, I simply add my current user to the docker group, which is created automatically when you install the engine. I run the following command in my terminal to make that happen:


sudo usermod -aG docker $USER

After running that, the change won't take effect immediately because your shell session needs to pick up the new group membership. You can either log out and log back in, or just run this command to apply the group changes to your current session without a reboot:


newgrp docker

Once you’ve done that, try running docker run hello-world again. If it prints the success message without needing sudo, you’re all set.

The best way to prevent this from ruining your flow in the future is to make sure you handle group permissions immediately after a fresh Docker install. If you’re setting up a new machine, I always include this step in my setup.sh script so I never have to deal with the sudo prompt for Docker commands again. It saves me endless keystrokes and keeps my terminal sessions looking clean.

Hope this clears up the headache and gets you back to shipping code. Happy containerizing!

Docker 老是跳 Permission denied？別再無腦加 sudo 了！

來源：Stack Overflow ↗ · 1420 票

記得剛踏入 Linux 世界那陣子，我滿心期待地裝好 Docker，想著終於可以開始玩容器化部署了，結果第一次跑 docker run hello-world 就直接給我噴出一大串紅通通的錯誤訊息。當時我整個人愣住，心想「明明官網教學就是這樣寫的啊，為什麼會報錯？」當下真的是差點崩潰，為了趕專案進度，我乾脆直接在每個指令前面都加上 sudo，結果後來只要打長指令就忘記加，看著那行該死的 Got permission denied 出現，真的會讓人氣到想把鍵盤摔了。

其實會發生這種狀況，是因為 Docker 的守護程序（daemon）預設是用 root 權限在運行的，而那個跟它溝通的 Unix socket 檔案 /var/run/docker.sock，預設權限也只開放給 root 使用。簡單說，你的系統帳號因為不是 root，所以想要呼叫 Docker 時，系統就會跳出來擋人，說「你沒權限，滾開」。每次都要打 sudo 不僅繁瑣，還很容易因為權限管理搞得一團亂，這根本不是現代工程師該有的工作效率。

後來我學乖了，與其每次都跟系統對抗，不如直接把自己的帳號加進 docker 這個使用者群組。做法其實很簡單，你只需要在終端機輸入這兩行指令：


# 建立 docker 群組（通常安裝時已經有了，但跑一下不吃虧）
sudo groupadd docker

# 把你目前的帳號加入這個群組
sudo usermod -aG docker $USER

重點來了，這步做完後，你必須先「登出再登入」或者直接重啟一下電腦，讓群組權限生效。如果你跟我一樣懶，不想重啟，也可以用 newgrp docker 這個指令來臨時重載群組設定，這樣你就可以直接在當前的終端機視窗試試看 docker run hello-world，保證馬上就能跑起來，那種不用加 sudo 的快感真的會讓人心情瞬間變好。

至於要怎麼預防下次再被這種權限問題搞到心累？其實最好的習慣就是安裝完任何服務後，先花兩分鐘看一下官方文件關於使用者權限的建議，不要只為了急著跑起來就忽略了設定。還有，養成定期檢查群組權限的習慣，或者是乾脆設定好你的開發環境腳本，把這些瑣碎的配置自動化，這樣以後換電腦或是重灌系統時，就不會再被這種小問題絆住腳步啦。

好了，現在你的 Docker 應該能順暢運作了，趕快去寫你的 Code 吧，別讓這種小 bug 耽誤了你原本的開發節奏！
