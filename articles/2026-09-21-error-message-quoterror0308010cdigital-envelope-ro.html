How to Fix the "error:0308010C:digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I upgraded my local Node.js version and suddenly my entire development workflow ground to a halt. I had a demo due for a client in two hours, and instead of working on features, I spent a solid forty minutes staring at this cryptic OpenSSL error while my terminal screamed at me in red text. It’s one of those classic "everything was fine ten minutes ago" moments that makes you want to throw your keyboard out the window.

The reason you’re seeing this error is actually quite straightforward, even if the error message itself is a nightmare. When Node.js bumped from version 16 to 17, they upgraded the underlying OpenSSL engine to version 3.0. This new version is much stricter about the algorithms it allows for hashing. Since many older React projects—and the dependencies they rely on—use legacy algorithms like MD4, OpenSSL 3.0 basically refuses to run them, resulting in that "digital envelope routines" error. It's essentially a security conflict between your modern environment and your older project dependencies.

To fix this, you don't actually need to downgrade your entire Node installation; you just need to tell Node to allow the legacy OpenSSL provider. If you're on a Mac or Linux machine, you can patch this in your terminal by setting an environment variable before you run your start command. You’ll want to run this in your terminal:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you're on Windows, the command is slightly different because of how the shell handles variables. Open up your Command Prompt or PowerShell and run:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

If you want to make this permanent so you don't have to type it every single time you spin up your server, just head over to your package.json file. You can modify the scripts section to include the prefix automatically, which saves you from that manual headache every time you open a new terminal tab:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

Moving forward, the best way to prevent this is to stop pinning your projects to the latest Node version without checking your dependencies first. I’ve started using a version manager like nvm (Node Version Manager) for every single project. By creating a .nvmrc file in the root of your project directory with the specific Node version you’re using, you ensure that you or anyone else working on the code will automatically use the correct, compatible environment.

Hope this saves you from the same headache I had! Happy coding, and may your builds stay green today.

React 專案啟動就報錯？搞定那該死的 digital envelope routines 錯誤

來源：Stack Overflow ↗ · 2572 票

那天我剛換了一台筆電，想說把手邊的舊專案重新 npm install 跑起來練練手，結果信心滿滿地敲下 npm start，終端機居然直接噴出一大串紅通通的 error:0308010C:digital envelope routines::unsupported。那一刻我真的差點崩潰，明明程式碼一行都沒動，環境也裝好了，怎麼連讓開發伺服器跑起來都這麼難？當時盯著螢幕上那一長串天書，心裡只想著「這到底是什麼鬼東西」，甚至懷疑是不是自己電腦設定壞了。

其實這背後的原因一點都不神秘，單純是因為 Node.js 升級到了 v17 以上的版本。Node.js 從那個版本開始，為了資安考量，預設改用了 OpenSSL 3.0，而舊版的 Webpack 或一些依賴套件還在用舊的加密演算法，兩邊兜不起來，自然就報出這個「不支援」的錯誤。簡單來說，就是你的工具太新，但你的專案架構還活在過去，兩者溝通出了代溝。

當初我發現這個問題時，試過各種網路上的偏方，最後發現最直接的解法其實就是告訴 Node.js：「嘿，請你暫時放寬心，用回舊版的加密模式吧！」如果你是用 Mac 或 Linux，只要在啟動指令前面加上環境變數設定就行了。像我平常開發都是直接修改 package.json 裡的 scripts，把啟動指令改成這樣：


"scripts": {
  "start": "NODE_OPTIONS=--openssl-legacy-provider react-scripts start",
  "build": "NODE_OPTIONS=--openssl-legacy-provider react-scripts build"
}

改完之後再跑一次 npm start，世界就瞬間清淨了。如果你是用 Windows 的 PowerShell，可能需要用 $env:NODE_OPTIONS = "--openssl-legacy-provider" 先設定環境變數，或者乾脆裝一個 cross-env 套件來統一處理，這樣以後換作業系統也不會再卡關。

要避免這種狀況再次發生，我現在學乖了，養成了一個習慣：盡量讓專案的 Node.js 版本跟團隊保持一致。我強烈建議在專案根目錄放一個 .nvmrc 檔案，裡面寫上適合該專案的 Node 版本號（比如 16.14.0），這樣每次換電腦或接手舊專案時，只要用 nvm use 就能一鍵切換到對的版本，不用再在那邊苦惱那些加密演算法的相容性問題。

搞定這個之後，終於可以繼續寫程式了，希望這招能幫你也省下那寶貴的幾小時開發時間。
