Troubleshooting "error:0308010C:digital envelope routines::unsupported" in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the first time this error popped up on my screen; I had just upgraded my Node.js version to v17, grabbed a coffee, and sat down to start a fresh project in IntelliJ. I expected a clean "Hello World" but was greeted with a wall of red text instead, and I spent a solid two hours convinced I’d somehow corrupted my entire global environment. It’s one of those infuriating errors that makes you feel like you’ve broken your computer just by clicking "create project," but don’t worry, you aren't alone in this.

The reason you’re seeing this is that Node.js v17 and later updated the OpenSSL version to 3.0. This update introduced stricter security constraints that aren't compatible with older versions of Webpack, which many React projects—especially those created via older create-react-app templates—rely on. Basically, your build tool is trying to use an outdated hashing algorithm that Node now considers insecure, so it simply slams the door in your face. It's a classic case of a breaking change in the underlying ecosystem that leaves legacy build scripts stranded.

I found that the quickest way to fix this without spending all day messing with package dependencies is to force Node to use the legacy OpenSSL provider. You can do this by setting an environment variable before you run your start script. If you're on a Mac or Linux machine, you just need to prepend the variable to your command in the terminal like this:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, you’ll need to set it a bit differently in your command prompt:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

For those of you who want a permanent fix, you can modify the scripts section inside your package.json file. Just update the start command so it automatically applies the flag every time you fire up your dev server:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To prevent this from haunting you in the future, my best advice is to keep your development environment aligned with the project's actual requirements by using a version manager like nvm (Node Version Manager). Instead of globally installing the latest version of Node and hoping for the best, you can switch to an LTS (Long Term Support) version that matches what your project expects. It saves you from these "upgrade-induced" headaches and keeps your local setup much cleaner.

Hope that gets your project back on track and lets you get back to actually coding. Let me know if you run into any other weird build errors!

當 React 遇上 Node.js 版本地獄：解決 error:0308010C 的崩潰經驗

來源：Stack Overflow ↗ · 2572 票

那天我剛接手一個舊專案，原本想說只是開個環境跑跑測試，結果一執行 npm start，終端機直接噴出一大串紅色錯誤，那個 error:0308010C:digital envelope routines::unsupported 簡直像是在嘲笑我。我當時真的差點把鍵盤砸了，心想「不是啊，這程式碼明明昨天還能跑，怎麼過了一夜就跟我鬧脾氣？」

其實這問題的兇手就是 Node.js 的版本升級。簡單來說，Node.js 在 v17 之後引入了 OpenSSL 3.0，這玩意兒對加密演算法的安全性要求變高了，偏偏很多舊版的 Webpack 或者一些依賴套件還在用舊的演算法，兩邊一搭不上線，加密過程就直接拋出錯誤。這就是典型的「為了安全，結果把舊專案給搞死了」的案例，那種看著螢幕發呆、懷疑是不是自己電腦中毒的痛苦時刻，相信很多開發者都經歷過。

要解決這個問題，最快速的方法就是讓 Node.js 稍微「退讓」一下，允許使用舊版的加密演算法。如果你是在 macOS 或 Linux 上，直接在終端機輸入這行指令：


export NODE_OPTIONS=--openssl-legacy-provider

如果是 Windows 的使用者，可以在 PowerShell 執行：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

但說實話，每次開終端機都要打這串實在太累了，最推薦的做法還是直接寫進你的 package.json 裡。找到 scripts 區塊，把 start 和 build 的指令改一下，像這樣：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

這樣以後不管誰拉你的專案下來，都不用擔心環境設定的問題。為了避免以後再被這種環境問題搞到懷疑人生，強烈建議大家一定要用 nvm (Node Version Manager) 來管理 Node.js 版本。在專案根目錄放一個 .nvmrc 檔案，寫入你專案開發時用的版本號，這樣每次進入專案資料夾時，只要打個 nvm use 就能切換到正確的版本，從源頭避開這些奇怪的相容性地雷。

搞定這個之後，看著熟悉的 React 啟動畫面，真的會覺得世界又變美好了，大家趕快去試試看吧！
