How to Check if a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7352 votes

Back when I was a junior developer, I remember writing a script to process thousands of log files for a server migration. I was obsessed with using try-except blocks for everything, and my code ended up looking like a nested nightmare that was impossible to read. I spent three hours debugging a simple file-check function because I was catching exceptions that weren't even related to the file's existence, and honestly, I felt like a total amateur when I realized there were cleaner, more "Pythonic" ways to handle this.

The reason people usually get tripped up here is that Python’s philosophy is often "easier to ask for forgiveness than permission" (EAFP), which encourages using try-except blocks. While that’s generally solid advice for handling race conditions, sometimes you just need to verify a path exists to decide which branch of logic to follow. If you’re just checking a file's state to log a message or skip a routine, wrapping everything in an exception handler creates unnecessary overhead and makes your code look like a cluttered mess of boilerplate.

When I need a clean, readable way to check for a file without the baggage of exception handling, I reach for the pathlib module. It’s been the standard since Python 3.4, and it makes your code feel much more modern. You can simply create a Path object and call the exists() method. It’s incredibly straightforward and avoids those clunky os.path calls that used to plague my early scripts.


from pathlib import Path

file_path = Path("my_data_file.txt")

if file_path.exists():
    print("The file exists, let's get to work!")
else:
    print("File not found, skipping this step.")

If you’re working with older legacy systems or just prefer the classic approach, os.path.isfile() is the other tool in my belt. It does exactly what it says on the tin—it returns a boolean value, so you don't have to worry about catching FileNotFoundError.


import os

if os.path.isfile("my_data_file.txt"):
    print("File is right where we left it.")

The best way to prevent these headaches is to always consider your specific use case. If you’re planning to open the file immediately after checking it, just use try-except with FileNotFoundError anyway, because a file could technically be deleted by another process between your check and your open call—that’s the classic "Time-of-check to time-of-use" bug. If you’re just doing a quick existence check for logging or flow control, stick to pathlib for the cleanest code.

Keep your logic simple and your imports clean, and you'll save yourself a lot of frustration down the road. Happy coding!

別再為了檢查檔案存不存在寫 try-except 了：Python 的優雅解法

來源：Stack Overflow ↗ · 7352 票

記得幾年前剛開始寫 Python 自動化腳本時，為了處理一堆雜亂的 log 檔，我整個人簡直快崩潰。當時我寫了一個非常直覺的 try-except 區塊，想說如果檔案不存在就捕捉 FileNotFoundError，結果寫到最後，整個程式碼裡充斥著這種防禦性程式碼，看起來不僅臃腫，重點是當我不小心在 try 區塊裡寫錯其他變數名稱時，那個錯誤被無情地吞掉，我在除錯時整整花了兩小時才發現自己是在跟空氣對話，那種「我到底寫了什麼垃圾」的挫折感，真的會讓人想直接關電腦下班。

其實會發生這種問題，是因為我們習慣了 Python 那種「請求原諒比請求許可更容易」（EAFP）的哲學，導致大家把所有檢查都往 try-except 裡塞。但在處理檔案系統時，有時候我們只是想單純地判斷一下「這東西在不在」，根本不想觸發異常處理機制。如果你的邏輯只是要根據檔案存不存在來決定下一步，硬是用異常捕捉來寫，反而會把正常的程式流程搞得像是在玩猜謎遊戲。

後來我學乖了，直接改用 pathlib 模組，這簡直是救贖。pathlib 在 Python 3.4 之後就內建了，它把路徑當作物件來處理，使用起來非常直觀。你只需要建立一個 Path 物件，然後呼叫 .exists() 方法，它會直接回傳一個布林值，乾淨俐落，完全不用擔心會噴出什麼惱人的例外。


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.exists():
    print("檔案還在，可以安心工作！")
else:
    print("檔案不見了，趕快去檢查你的路徑。")

如果你是在維護一些超級舊的專案，沒辦法用 pathlib，那 os.path 也是個老牌但穩定的選擇，寫法大同小異，一樣能達到不使用例外處理的效果。

至於怎麼預防這種地獄重演？我覺得最核心的一點就是「預判與權限分離」。很多時候我們檢查檔案，其實是因為我們對環境不夠有信心。建議大家在開發時，養成習慣把「檔案檢查」跟「檔案存取」分開來想。如果你的程式邏輯非常複雜，請務必在操作前先用 pathlib 檢查狀態，而不是等著程式崩潰了才去救火。這樣你的程式碼看起來會清爽很多，未來的你也會感謝現在的你，至少不用再盯著滿滿的 try 區塊發呆。

好了，現在趕快去把那些多餘的 try-except 刪掉吧，生活會變得輕鬆不少的！
