How to Check If a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7352 votes

Back when I was still cutting my teeth on Python, I remember writing a script to automate log cleanup on a production server. I wrapped every single file operation in a massive, ugly try-except block because I was terrified of a FileNotFoundError crashing my process, but it ended up looking like a labyrinth of spaghetti code that took me three hours to debug. It was one of those moments where I stared at my screen wondering why I was making life so difficult just to verify a simple file path.

The reason we run into this is that Python’s philosophy is deeply rooted in EAFP—"Easier to Ask for Forgiveness than Permission." The language designers generally prefer you to just try an action and handle the error if it fails. However, sometimes you're building a CLI tool or a monitoring script where you just need a quick boolean check to decide whether to trigger a workflow, and the overhead of catching exceptions feels like overkill. You don't want to clutter your logic with error handling if you just need to know if a config file is sitting in the directory.

When I need to keep things clean, I reach for the pathlib module. It’s been the standard since Python 3.4, and honestly, it makes file handling feel like a modern, object-oriented experience. Instead of importing os and dealing with clunky string paths, you just create a Path object and call the .exists() method.


from pathlib import Path

file_path = Path("config.json")

if file_path.exists():
    print("File found, proceeding with the update.")
else:
    print("File missing, skipping this step.")

If you’re working on a legacy codebase or you just prefer the classic approach, the os.path module is your fallback. It’s what most of us grew up with, and it’s still perfectly reliable for simple existence checks. You’d use os.path.isfile() to ensure it’s actually a file and not a directory, which is a common oversight that has bitten me more than once.


import os

if os.path.isfile("config.json"):
    print("The file exists and is ready for reading.")

To prevent these kinds of headaches in the future, my biggest tip is to stop relying on existence checks as a primary way to control flow. In multi-threaded or high-concurrency environments, checking if a file exists and then trying to open it creates a "Time-of-check to time-of-use" (TOCTOU) race condition. Even if your check returns True, another process could delete the file a millisecond later. Always try to open the file directly and handle the potential error—it’s actually the safer, more robust way to handle files, even if checking first feels more intuitive at the start.

Hope this saves you some of the frustration I dealt with back in the day. Happy coding!

別再瘋狂 try-except 了！檢查檔案是否存在其實可以很優雅

來源：Stack Overflow ↗ · 7352 票

當年我剛接手一個處理大量日誌文件的爬蟲專案時，心態簡直要崩潰。那時候我寫了一大堆 try-except FileNotFoundError 來判斷檔案在不在，結果程式碼看起來臃腫得像一坨義大利麵，最慘的是，有一次我因為沒處理好權限問題導致例外被攔截後的邏輯全跑偏，硬是讓我在公司加班到半夜三點，看著螢幕上的錯誤代碼差點把鍵盤砸了。那種「我明明知道檔案不存在，卻還要強行拋出例外再接住」的虛耗感，真的會讓人懷疑人生。

其實這背後的根本原因，是很多新手（包括當年的我）誤以為在 Python 裡只有 try-except 才是處理錯誤的唯一途徑。其實這種做法不但效能低，而且讓程式碼邏輯變得支離破碎。當我們只是想確認一個檔案是否存在時，並不需要大費周章地製造一個例外，因為檔案系統檢查本身就是一個常見的邏輯判斷，Python 的標準庫其實早就幫我們準備好了更直接的方法。

我後來學乖了，直接改用 pathlib 這個現代化的模組。它處理路徑的方式真的優雅太多，只要一行程式碼就能解決。你可以這樣寫：


from pathlib import Path

file_path = Path("your_file.txt")

if file_path.exists():
    print("檔案就在這，安心服用！")
else:
    print("檔案消失了，別再找了。")

如果你是因為習慣舊有的 os 模組，不想改寫太多程式碼，用 os.path.exists() 也是完全沒問題的。我個人現在習慣用 pathlib 是因為它物件導向的特性用起來更順手，而且在處理路徑拼接時不會有奇奇怪怪的斜線錯誤。

至於要怎麼預防這種「過度防禦」的壞習慣再次出現，我建議大家在寫程式時多問自己一句：「這真的是一個異常情況嗎？」如果檔案不存在是你業務邏輯中會預期發生的分支，那就用 if 判斷；只有當你真的無法預測、無法控制的情況（例如磁碟突然掛掉或權限被鎖死）才需要動用 try-except。把例外處理留給真正的意外，你的程式碼會乾淨很多，以後維護起來也不會想殺了當年的自己。

希望這招能拯救你的專案結構，趕快去把那些多餘的 try 區塊刪掉吧！
