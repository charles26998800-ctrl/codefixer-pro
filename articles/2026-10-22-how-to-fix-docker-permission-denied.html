How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1420 votes

I still remember the first time I set up Docker on a fresh Ubuntu server. I was convinced I’d botched the installation because every time I tried to spin up a container, I was met with that dreaded "permission denied" error. I spent an embarrassing three hours digging through documentation and reinstalling the engine, only to realize I was just being lazy and didn't want to type sudo every single time. It’s a rite of passage for every developer, so if you're hitting this wall, don't sweat it—you're definitely not alone.

The reason you're seeing this error is that the Docker daemon binds to a Unix socket rather than a TCP port by default. Because that socket is owned by the root user, you need elevated privileges to communicate with it. When you run a command without sudo, your current user account simply doesn't have the necessary permissions to access /var/run/docker.sock. Essentially, Docker is playing the role of a strict bouncer, and your user account isn't on the guest list yet.

To fix this, you need to add your user to the docker group, which grants you the same permissions as the root user when interacting with the daemon. First, create the group if it doesn't already exist by running sudo groupadd docker. Once that's set, add your current user to the group using this command:


sudo usermod -aG docker $USER

After you’ve run that, you can't just jump back in immediately. You’ll need to refresh your group membership. You can either log out and log back in, or run newgrp docker to apply the changes to your current terminal session. To verify it worked, just run docker run hello-world without the sudo prefix. If you see the "Hello from Docker!" message, you’re officially in the clear.

Moving forward, the best way to prevent these permission headaches is to always double-check your group assignments whenever you set up a new environment. I’ve started adding the usermod command to my automated setup scripts, which saves me from having to remember the syntax every time I provision a new machine. It’s a tiny bit of upfront work that saves you from a massive headache down the line.

Hope this gets you back to building containers without the constant sudo-ing. Happy coding!

為什麼 Docker 老是嫌我權限不足？別再傻傻加 sudo 了！

來源：Stack Overflow ↗ · 1420 票

記得我剛開始接觸 Docker 時，為了趕一個專案進度，在那邊瘋狂測試各種容器，結果每次敲完指令都要補上一個 sudo，打到手都快抽筋了。最崩潰的是，有一次我寫了一個自動化部署腳本，因為忘記在每個 Docker 指令前加 sudo，導致腳本跑一半直接噴出一堆紅字報錯，當下看著那個 Permission denied 的錯誤訊息，真的差點把鍵盤砸了，那種「我明明就是這台電腦的擁有者，為什麼你還要擋我」的無力感，相信很多人都懂。

其實這個問題會發生，是因為 Docker 在安裝時預設會建立一個叫做 docker 的 Unix 群組。問題在於，Docker Daemon 預設是透過一個位於 /var/run/docker.sock 的 Socket 檔案來通訊，而這個檔案的權限通常只有 root 和 docker 群組的成員才能存取。當你沒加 sudo 時，你的普通使用者帳號根本沒有權限去碰這個 Socket，Docker 守護進程當然會直接把你拒於門外，這就像是你拿著普通員工識別證，想硬闖總經理辦公室一樣，系統不報錯才怪。

解決這個問題的方法其實很簡單，就是把你自己的使用者帳號加入到那個 docker 群組裡。你可以先用 sudo groupadd docker 確保群組存在，接著執行 sudo usermod -aG docker $USER 把自己加進去。不過要注意喔，這時候你直接跑指令通常還是會失敗，因為系統需要重新讀取你的群組權限，最快的方法就是直接登出再登入，或者更暴力一點直接重啟電腦。如果你不想重啟，也可以試試看用 newgrp docker 這個指令來即時更新當前終端機的群組權限，這樣就不用在那邊登出登入半天了。

為了預防以後再被這個權限問題搞到心態爆炸，我建議大家在每次安裝完 Docker 後，第一件事就是養成把當前使用者加入 docker 群組的習慣。另外，記得平時也要檢查一下 /var/run/docker.sock 的權限設定，不要手癢去改動它的所有權，否則可能會引發更嚴重的資安風險。

好了，現在你可以試試看直接執行 docker run hello-world，如果看到那串熟悉的成功訊息，恭喜你，終於告別那個煩人的 sudo 惡夢了。
