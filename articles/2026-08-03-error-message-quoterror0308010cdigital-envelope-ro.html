How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the day I upgraded my Node.js version to 17, feeling all smug about having the latest tools, only to have my entire React project blow up in my face the second I hit npm start. I spent a solid two hours digging through dependency trees and questioning my life choices before realizing it was just a simple compatibility mismatch, and honestly, I felt like a complete amateur for not seeing it sooner.

The reason you’re seeing this error:0308010C:digital envelope routines::unsupported message is that Node.js version 17 and later updated the OpenSSL library to version 3.0. This new version is significantly more secure, but it also tightened the rules on cryptographic algorithms. Older versions of Webpack, which many React projects rely on for bundling, were still trying to use legacy algorithms that OpenSSL 3.0 now flags as insecure. Basically, your build tool is trying to use an old-school cryptographic lock that Node just isn't willing to open anymore.

Fixing this is luckily straightforward, and you don't need to rebuild your whole project. The quickest way to get back to coding is to tell Node to use the legacy OpenSSL provider by setting an environment variable. If you're on a Mac or Linux machine, you can just run this in your terminal before starting your app:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you're stuck on Windows using PowerShell, you'll want to use this command instead:


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

For those of you who don't want to type that every single time you spin up your project, just update the scripts section in your package.json file. It’s a permanent fix that saves you the headache of remembering the command every morning:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To keep this from biting you again, the best habit I’ve picked up is using a version manager like nvm (Node Version Manager) for all my projects. It lets me switch back to Node 16 for older legacy projects while keeping the latest version for my newer work. If you stick to using a .nvmrc file in the root of your repositories, you’ll never have to worry about accidentally running a project on an incompatible Node version again.

Hope this gets your dev environment back in gear so you can get back to building cool stuff. Happy coding!

救命！React 專案突然報錯：Error: error:0308010C:digital envelope routines::unsupported

來源：Stack Overflow ↗ · 2572 票

上禮拜我剛接手一個舊專案，想說先在本地跑起來檢查一下環境，結果 npm start 才剛敲下去，終端機就噴出一大串紅字，那個 digital envelope routines::unsupported 看得我一頭霧水。當時我真的差點崩潰，明明昨天還能跑的程式碼，換個環境就直接罷工，那種看著螢幕發呆、懷疑是不是自己電腦壞掉的心情，真的是軟體工程師最想原地離職的時刻。

其實這個錯誤會出現，主要是因為我們升級了 Node.js 版本（通常是從 v16 升到 v17 以上）。Node.js 在比較新的版本中更新了 OpenSSL，它對加密演算法的要求變嚴格了，但很多舊版的 Webpack 還是依賴著舊的演算法，兩邊兜不起來，它就直接在啟動時報錯給你看了。說穿了，就是新版本的 Node 太「嚴謹」，不吃舊專案那一套。

當時我查了一下，最快的方法就是告訴 Node.js：「嘿，別管那麼多，先照舊的規則跑就好」。只要在執行指令前設定環境變數 NODE_OPTIONS 就可以了。如果你是 Mac 或 Linux 使用者，在終端機輸入這行就能解決：


export NODE_OPTIONS=--openssl-legacy-provider

如果是 Windows 的 PowerShell，則是用這行：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

如果你懶得每次重開終端機都要打一次，直接把這段加到 package.json 的 scripts 裡面會更省事。例如把 start 改成這樣：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

這樣改完之後，不管你是誰、在哪個環境跑，它都會乖乖聽話。至於要怎麼預防下次再遇到這種鳥事？最好的辦法其實是養成使用 .nvmrc 或 .node-version 檔案的習慣。只要在專案根目錄放一個檔案，記錄開發該專案時使用的 Node 版本，之後不管是自己還是同事，只要透過 nvm use 就能快速切換到對應的版本，直接從源頭避開這種環境不相容的坑。

雖然這個解法有點像是在「繞過」問題，但對付這種歷史共業，這確實是成本最低且最有效的方法。希望這能幫你省下寶貴的除錯時間，趕快回去寫程式吧！
