How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1416 votes

I remember the first time I set up Docker on a fresh Ubuntu install back when I was still junior. I was so excited to containerize my local dev environment that I didn't even notice the sudo requirement until I tried to script a quick deployment test and my CI pipeline kept falling over. I spent a good two hours convinced I’d somehow corrupted my entire Linux installation, only to realize I was just fighting a simple group permission setting the whole time.

The reason you’re running into this annoying "permission denied" error is actually pretty straightforward. By default, the Docker daemon binds to a Unix socket located at /var/run/docker.sock instead of a TCP port. Because this socket is owned by the root user, only users with root privileges—or those who explicitly use sudo—can talk to the daemon. When you run a command without sudo, your standard user account simply doesn't have the security clearance to read or write to that socket, so Docker shuts you down immediately.

The fix is luckily very simple: you just need to add your user to the docker group. Once you’ve done this, the system will recognize your user as having the authority to interact with the daemon without needing to type sudo every single time. First, you’ll want to create the group if it doesn't already exist:


sudo groupadd docker

Next, add your current user to that group by running the following command:


sudo usermod -aG docker $USER

After you run that, you can't just jump back into your terminal and expect it to work immediately. You need to tell the system to refresh your group memberships, which usually requires a quick logout and login. If you’re in a rush, you can activate the changes for your current shell session by running newgrp docker. Once that's settled, verify it worked by running docker run hello-world without the sudo prefix. If the hello message pops up, you're golden.

To keep this from biting you again, just remember that whenever you provision a new VM or set up a new dev box, adding your user to the docker group should be one of the very first things on your setup checklist. It’s a small bit of configuration that saves you from thousands of keystrokes and endless frustration down the line.

Hope this saves you some time today—happy coding!

被 Docker 權限搞到心累？別再一直加 sudo 了！

來源：Stack Overflow ↗ · 1416 票

記得剛開始碰 Docker 的時候，我正趕著要在本地端架一個測試環境，想說把 Docker 安裝好就沒事了，結果每次打指令都要加個 sudo，打到後來真的覺得超煩，甚至有幾次因為忘了加，導致腳本跑一半噴出 Permission denied 的錯誤，當下真的心態直接炸裂，覺得開發體驗爛透了。

其實這背後的原因很單純，Docker 預設會透過一個 Unix socket (/var/run/docker.sock) 來跟後台的 daemon 溝通，但為了安全起見，這個檔案的權限被鎖死在 root 使用者和 docker 群組手上。簡單說，除非你是 root，不然系統根本不讓你碰那個 socket，這就是為什麼你沒加 sudo 就會被拒絕存取。

後來我學乖了，與其每次在那邊跟 sudo 對抗，不如直接把自己加入 docker 群組。解決方式很簡單，先建立一個群組（通常安裝 Docker 時就有了），然後把自己塞進去就行了。你可以照著下面這幾行指令操作：


# 建立 docker 群組（通常裝完已經有，但跑一下沒壞處）
sudo groupadd docker

# 把目前的使用者加入 docker 群組
sudo usermod -aG docker $USER

這步做完還沒結束喔，這是很多新手會卡住的地方：你必須要「登出再登入」或是重開機，讓系統重新讀取你的群組權限，不然你會發現怎麼改了還是沒用。如果懶得重登，也可以先用 newgrp docker 強制讓當前的 shell 生效，這招真的省下不少時間。

說到怎麼預防這種鳥事再發生，其實最好的習慣就是剛裝好 Docker 的當下，就把這組指令寫進你的「環境安裝筆記」裡。每次換新電腦或是重灌系統時，第一件事就是把這行加上去，把它當成開發環境設置的標準流程，以後就再也不用為了解決權限問題而搞到崩潰了。

現在總算能順順跑 Docker 指令，不用再被 sudo 煩了，祝大家開發順利，少踩點坑！
