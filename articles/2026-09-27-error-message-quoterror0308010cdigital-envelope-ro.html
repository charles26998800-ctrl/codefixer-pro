How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I remember the exact moment I first hit this wall. I had just upgraded to Node.js v17 for a side project, feeling pretty smug about keeping my environment updated, when I tried to spin up my local dev server and was greeted by a wall of red text ending in error:0308010C:digital envelope routines::unsupported. I spent a solid two hours convinced I’d somehow corrupted my entire node_modules folder, deleting and reinstalling packages like a madman before I realized it had absolutely nothing to do with my code.

The reason this happens is actually quite straightforward, even if the error message makes it sound like your computer is having a meltdown. When Node.js bumped up to version 17, they upgraded the underlying OpenSSL library to version 3.0. This new version is much stricter about the algorithms it allows, and a lot of older Webpack versions or build tools rely on legacy algorithms like MD4. Essentially, your project is trying to use an old hashing method that Node 17+ now considers insecure, so it just shuts the whole process down to keep you safe.

To fix this, I usually just tell Node to allow those legacy algorithms by setting an environment variable called NODE_OPTIONS. If you’re on a Mac or Linux machine, you can run this right in your terminal before starting your project:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re stuck on Windows, the syntax is a bit different, so you’ll want to run this in your PowerShell or Command Prompt:


$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm start

If you want to make this change permanent so you don't have to type it every single time you open your terminal, you can just tweak your package.json file. Find the scripts section and modify your start command to include the flag directly:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

The best way to prevent this kind of headache in the future is to use a version manager like nvm (Node Version Manager). It allows you to switch between different Node versions on a per-project basis, so when you’re working on an older legacy codebase, you can just drop back to Node 14 or 16 without breaking your global environment. It’s saved me from countless dependency nightmares and keeps my workflow much cleaner.

Hope this gets you back to coding without any more cryptic errors. Good luck with the build!

遇到「digital envelope routines::unsupported」別慌，這只是 Node.js 版本在搞你

來源：Stack Overflow ↗ · 2572 票

那天早上我剛接手一個舊專案，想說先跑個 npm start 暖暖身，結果終端機直接噴出一大串紅字，那個 error:0308010C:digital envelope routines::unsupported 簡直像是在跟我宣戰。我當時盯著螢幕看了五分鐘，咖啡都涼了，心裡還在想：「我昨天明明還好好的，這專案是怎麼了？」那種明明什麼都沒改，專案卻突然原地爆炸的絕望感，真的會讓人懷疑人生，甚至開始懷疑是不是電腦中了什麼詭異的病毒。

其實這問題的兇手就是 Node.js 的版本升級。Node.js 在 v17 之後導入了 OpenSSL 3.0，這傢伙對於加密演算法的安全要求變嚴格了，但很多舊版的 Webpack 或是其他的套件還在用舊的演算法，兩邊兜不起來，OpenSSL 就會覺得「這東西不安全」然後直接拒絕執行。簡單來說，就是你的新環境太嚴格，而舊專案還停留在「隨便用也沒關係」的年代。

解決這個問題其實很簡單，你不需要去改那些複雜的 node_modules。最快的方法就是告訴 Node.js：「嘿，別管那麼多，先讓我把這個環境跑起來」。如果你是用 Mac 或 Linux，直接在終端機輸入這行指令：


export NODE_OPTIONS=--openssl-legacy-provider

如果是 Windows 的 PowerShell 使用者，則是輸入：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

只要執行完這行，再重新 npm start，通常就能看到那熟悉的編譯進度條開始跑了。如果你不想每次開終端機都打一次，直接把它加進 package.json 裡的 scripts 區塊，像是這樣：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

這樣一來，以後不管誰接手這個專案，都不會再被這個錯誤卡住。

至於怎麼預防這種鳥事再發生？我覺得最根本的還是要學會用 nvm (Node Version Manager) 來管理環境。每個專案在開發初期，最好都在根目錄放一個 .nvmrc 檔案，註明這個專案適合的 Node.js 版本。這樣下次當你換了一台電腦，或者過了一年再回來寫這支程式時，只要切換一下版本，就能避開這些因為環境升級而產生的莫名奇妙問題。

好啦，希望這招能幫你從崩潰邊緣救回來，趕快把專案跑起來繼續搬磚吧！
