How to Fix "RuntimeError: Input type and weight type should be the same" in PyTorch

Source: Stack Overflow ↗ · 202 votes

I still remember the first time I ran into this error back when I was training my first CNN. I had spent nearly three hours debugging my data pipeline, convinced that my dataset was corrupted or that my CUDA drivers were acting up, only to realize I’d completely forgotten to move my input tensors to the GPU. It’s one of those classic PyTorch "gotchas" that makes you want to throw your keyboard across the room, but once you understand what’s happening under the hood, it becomes second nature to avoid.

The reason you’re seeing this RuntimeError is actually pretty straightforward once you stop to think about how PyTorch manages memory. Your model is living on the GPU because you called .to(device) on it, but your input data is still sitting comfortably in your machine's CPU RAM. PyTorch is incredibly strict about hardware parity; it refuses to perform matrix multiplication if the weights and the inputs don't reside on the same device. It’s essentially a security guard standing at the gate of your GPU, preventing the CPU-based data from interacting with the GPU-based model parameters.

To fix this, you just need to ensure that your input tensors are explicitly moved to the same device as your model inside your training loop. I usually handle this right after I pull the data from the dataloader. You’ll want to update your loop to look something like this:


device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model.to(device)

for data in dataloader:
    # Move inputs and labels to the device before passing them to the model
    inputs, labels = data
    inputs = inputs.to(device)
    labels = labels.to(device)
    
    outputs = model(inputs)
    # ... rest of your training logic

If you’re working with multiple tensors or complex custom datasets, it’s easy to miss one. To prevent this from becoming a recurring headache, I always adopt a "device-agnostic" coding style. I define a constant device at the top of my script and then I consistently use .to(device) whenever I initialize a new tensor or pull a batch from my loader. If you get into the habit of writing inputs = inputs.to(device) every single time you define a training step, you’ll stop seeing this error for good.

Hope this saves you a few hours of frustration today. Happy coding, and may your gradients always converge!

PyTorch 報錯：RuntimeError: Input type and weight type should be the same 該怎麼救？

來源：Stack Overflow ↗ · 202 票

還記得那是個趕專案進度的深夜，我把模型好不容易搬到 GPU 上跑，興致勃勃地按下執行鍵，想說應該能順利看到 Loss 下降。結果螢幕一閃，啪的一聲直接噴出 RuntimeError: Input type (torch.FloatTensor) and weight type (torch.cuda.FloatTensor) should be the same，當下我真的差點要把鍵盤給砸了，明明都已經寫了 .to(device)，為什麼 PyTorch 還是這麼不領情？

其實問題的核心很簡單，就是我的模型已經乖乖地搬到 GPU 上了，但我的資料（Input）還留在 CPU 的記憶體裡「納涼」。PyTorch 的規則很嚴格，模型在 GPU，資料就必須跟著在 GPU，兩者就像是在不同平行時空的住戶，根本沒辦法溝通。那種感覺真的很無力，就像是你準備好了一桌滿漢全席，結果食材卻還留在樓下的便利商店沒拿上來，程式當然會直接罷工給你看。

要解決這個問題，其實只要在迴圈裡多加一行指令就好。我們必須在讀取資料後，手動把 inputs 和 labels 也丟到對應的 device 上，這樣它們才會跟模型在同一個頻率。修改後的程式碼長這樣：


device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model.to(device)

for data in dataloader:
    # 關鍵在這裡，把資料也搬到 GPU
    inputs, labels = data
    inputs = inputs.to(device)
    labels = labels.to(device)
    
    outputs = model(inputs)
    # 後續計算 Loss 的時候，labels 也要記得在 GPU 上喔！

至於要怎麼預防這種慘劇再次發生？我現在養成了一個習慣，就是寫 DataLoader 相關的邏輯時，直接封裝成一個小工具函式，或者在寫測試時強制檢查 next(model.parameters()).device 跟資料的 device 是否一致。只要心裡多留個心眼，確認「模型跟資料在同一個房間」，基本上就不會再被這個錯誤搞到心態崩潰了。

搞定這個之後，就能安心去泡杯咖啡，看著模型跑起來的那種成就感，真的是工程師最大的小確幸啦。
