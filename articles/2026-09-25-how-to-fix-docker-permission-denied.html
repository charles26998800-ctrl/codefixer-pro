Docker Permission Denied: The Quick Fix for Your Ubuntu Setup

Source: Stack Overflow ↗ · 1419 votes

I vividly remember the first time I set up Docker on a fresh Ubuntu box; I was ready to deploy my first containerized app, feeling like a total pro. I ran docker run hello-world with a flourish, only to be met with a wall of "Permission denied" errors that made me feel like an absolute amateur. I spent a good hour double-checking my installation logs and questioning my sanity before I realized that, of course, I didn't have the right group permissions.

The reason you're hitting this wall is that the Docker daemon binds to a Unix socket rather than a TCP port by default. This socket is owned by the root user. Unless you’re running as root—which is why sudo works—your standard user account simply doesn't have the required permissions to talk to that socket. It's a security feature designed to keep your system safe, but it sure is annoying when you're just trying to get a quick container up and running.

To fix this, you need to add your user to the docker group, which grants you the necessary access without needing to type sudo every single time. First, you'll want to create the docker group if it doesn't already exist:


sudo groupadd docker

Next, add your current user to that group so your system recognizes you as a member authorized to manage the daemon:


sudo usermod -aG docker $USER

Once you've done that, the changes won't take effect immediately. You either need to log out and log back in, or run this command to refresh your group membership right now:


newgrp docker

To verify it worked, just run docker run hello-world without the sudo prefix. If you see the "Hello from Docker!" message, you're officially back in business.

To prevent this from ever being an issue on future machines, I always make it a habit to add the docker group creation and user assignment to my initial system setup script. If you're building out a new environment, just bundle those commands into your bootstrap process, and you’ll never have to deal with this headache again.

Hope this helps you get back to shipping code without the constant sudo prompts. Happy containerizing!

每次跑 Docker 都要打 sudo？教你如何優雅地告別 Permission denied

來源：Stack Overflow ↗ · 1419 票

記得剛開始碰 Docker 的時候，我正趕著要把一個專案部署上線，結果一執行指令就噴出 Got permission denied 的錯誤訊息，當時我整個人原地傻眼。明明 sudo 一下就能跑，但每次都要加個 sudo 實在有夠煩，更慘的是，當我寫腳本自動化部署時，那個權限問題簡直像個幽靈一樣，搞得我連續幾個晚上都在跟終端機搏鬥，差點就把鍵盤給砸了。

其實會發生這種狀況，是因為 Docker 的守護行程（daemon）預設是用 root 權限在跑的，而 /var/run/docker.sock 這個 Socket 檔案的擁有者也是 root。當你不用 sudo 去執行指令時，你的使用者帳號根本沒有權限去敲這個 Socket 的門，就像是你去高級俱樂部沒帶會員證，保全當然把你擋在門外。

解決這個問題的方法其實很簡單，就是把你的使用者帳號加入到 docker 這個群組裡。只要打開你的終端機，執行底下這幾行指令就能搞定：


# 建立一個 docker 群組（通常安裝完就有，但檢查一下比較保險）
sudo groupadd docker

# 把你目前的帳號加入到這個群組
sudo usermod -aG docker $USER

不過，執行完這些指令後，你千萬別急著狂敲 docker run，因為系統的群組變更不會馬上生效。你必須要先登出再重新登入，或者更暴力一點直接重開機，讓系統重新讀取你的權限設定。如果你懶得重開機，也可以在終端機輸入 newgrp docker，這樣就能讓當前的 Shell 視窗馬上吃到新的群組權限，省去重新登入的麻煩。

為了預防下次換了電腦又遇到這種鳥事，我建議大家以後安裝完 Docker 的第一件事，就是先把這段設定加入你的「裝機腳本」裡。像我現在設定新環境時，都會直接把這行寫進備忘錄，裝好 Docker 就順手跑一次，徹底擺脫這種因為權限問題而中斷開發節奏的痛苦。

搞定之後，現在跑 Docker 指令終於可以不用再打那該死的 sudo 了，心情瞬間舒暢很多。希望這篇筆記能幫你省下不少找資料的時間，趕快回去寫 code 吧！
