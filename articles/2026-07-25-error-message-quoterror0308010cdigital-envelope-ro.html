How to Fix the "error:0308010C:digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2573 votes

I still remember the day I upgraded my local development machine and thought I was being proactive by installing the latest Node.js version. I sat down to spin up a quick React project in IntelliJ, only to be greeted by a wall of red text screaming about "digital envelope routines" the moment I hit npm start. I spent three hours spiraling down a rabbit hole of reinstalling dependencies and clearing my cache, feeling like a complete amateur before I finally realized it was just a version mismatch.

This error pops up because of a significant change in how Node.js handles security. Starting with Node v17, the developers switched to OpenSSL 3.0, which enforces stricter security standards. A lot of the older build tools and libraries—especially those used in Create React App—rely on legacy algorithms that OpenSSL 3.0 now considers insecure. When your build process tries to use one of these algorithms, Node effectively shuts it down to protect you, leaving you with that cryptic error message instead of a running development server.

If you’re stuck, the quickest way to get back to work is to tell Node.js to stop being so strict by using the NODE_OPTIONS environment variable. You’re essentially telling the system to use the legacy OpenSSL provider, which allows those older React build scripts to function as expected. If you're on a Mac or Linux machine, you can run this command in your terminal before starting your project:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the syntax is a little different. You’ll want to run this in your command prompt:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

For a more permanent fix so you don't have to type that every single time, I usually just add it directly to my package.json file. Find the "scripts" section and update the start command like this:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To prevent this headache in the future, my best advice is to use a tool like nvm (Node Version Manager) to manage your environments. Whenever I start a new project or inherit an older codebase, I check the engines field in the package.json or consult the project’s documentation to see which Node version was intended for that build. Keeping your tools consistent with the project requirements saves you from these "modern vs. legacy" traps every single time.

Hopefully, this saves you those three hours of frustration I lost. Happy coding!

遇到 Node.js 的那個惡夢錯誤：Error: error:0308010C:digital envelope routines::unsupported

來源：Stack Overflow ↗ · 2573 票

那天我正準備快速刻個 React 小專案來測試新想法，剛用 IntelliJ 把環境建好，滿心期待地打下 npm start，結果螢幕直接噴出一大串紅字，那個 digital envelope routines::unsupported 簡直像是在跟我唱反調。我當時真的差點原地崩潰，心想：「我什麼都還沒寫啊，連個 Hello World 都還沒出來，環境就先給我陣亡是怎樣？」那種好不容易想到的靈感，卻被這種莫名其妙的環境錯誤卡住的感覺，真的會讓人想把鍵盤直接丟出窗外。

其實這問題的兇手是 Node.js 的版本更新。簡單來說，Node.js 在 17 版之後升級了底層的 OpenSSL 函式庫，預設採用了更嚴格的加密標準。而我們很多舊的 React 專案（或是那些依賴 Webpack 4 的老套件）還在用舊版的演算法，兩邊一搭上，Node.js 就覺得：「你這東西太舊太危險，我拒絕執行。」這就是為什麼你明明程式碼沒改動，換個電腦或升級個 Node 之後，世界就變了。

解決方法其實意外地單純，我們只需要告訴 Node.js：「嘿，別那麼嚴格，讓我用舊版的演算法跑一下吧。」最快的做法就是設定一個環境變數 NODE_OPTIONS。如果你是用 Mac 或 Linux，直接在終端機輸入這行指令：


export NODE_OPTIONS=--openssl-legacy-provider

設定好之後再執行 npm start，通常就能順利跑起來了。如果你是用 Windows 的 PowerShell，語法會稍微變一下：


$env:NODE_OPTIONS = "--openssl-legacy-provider"

當然，如果你不想每次開終端機都要敲一次，最推薦的做法是直接改 package.json 裡的 scripts。把 start 的部分改成這樣：


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

這樣一來，不管你是誰、在哪個環境跑，設定都會自動帶上去，省得以後還要為了這個錯誤懷疑人生。

如果要說怎麼預防，最好的建議就是養成使用 nvm (Node Version Manager) 的習慣。每次要接手舊專案時，先確認一下該專案建議的 Node 版本，用 nvm use 切換到對應的版本，通常就能避開這類升級帶來的相容性地獄。畢竟把時間花在寫程式邏輯上，總比花在修這種環境錯誤來得划算多了。

希望這招能救你脫離苦海，趕快把專案跑起來去喝杯咖啡吧！
