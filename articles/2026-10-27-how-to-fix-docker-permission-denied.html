How to Fix the "Docker: Permission Denied" Error on Ubuntu

Source: Stack Overflow ↗ · 1420 votes

I still remember the first time I set up Docker on a fresh Ubuntu install. I was feeling pretty productive, ready to spin up a containerized environment, but every time I typed docker ps I was greeted with that stinging "permission denied" error. I spent a solid 30 minutes convinced I’d somehow broken my entire Linux installation, constantly typing sudo out of pure habit until I finally realized I was just dealing with standard Unix group permissions.

The reason you’re running into this is that the Docker daemon binds to a Unix socket rather than a TCP port. By default, that socket is owned by the root user. If you aren't running as root, you don't have the necessary access to talk to the daemon, which is why sudo makes it work—you're effectively telling the system to run the command with elevated privileges. It's a security feature, not a bug, but it gets old fast when you’re trying to run quick commands without constantly typing your password.

To fix this for good, you need to add your current user to the docker group. This grants your user account the authority to communicate with the Docker daemon without needing root access every single time. Open your terminal and run these commands to get it sorted:


# Create the docker group if it doesn't already exist
sudo groupadd docker

# Add your current user to the group
sudo usermod -aG docker $USER

Once you’ve run those, the changes won't take effect immediately. You’ll need to either log out and log back in, or run newgrp docker to refresh your group membership in your current terminal session. After that, go ahead and test it with docker run hello-world. If everything went according to plan, it should pull and run the container instantly, no sudo required.

To prevent this from becoming a recurring headache, just make it a part of your standard "new machine" setup script. Whenever I provision a new dev environment, I always include that usermod command in my shell script so I never have to deal with permission errors on day one.

Hope this saves you some time so you can get back to building cool stuff. Happy coding!

為什麼執行 Docker 指令老是卡在 Permission denied？教你一招徹底擺脫 sudo

來源：Stack Overflow ↗ · 1420 票

記得剛開始學 Docker 那會兒，我為了趕專案進度，在終端機裡瘋狂輸入指令。當時每打一次指令就得補一個 sudo，搞得我煩躁到不行，甚至有好幾次因為忘記加 sudo，導致腳本跑一半直接報錯中斷，看著滿螢幕紅通通的「Permission denied」，我真的差點要把鍵盤給砸了。最痛苦的是，當你寫好一段複雜的 docker-compose 腳本，以為可以一鍵啟動服務，結果因為權限問題卡死，那種「明明程式沒錯，卻被作業系統擋在門外」的無力感，真的是工程師職涯中的一大陰影。

其實這問題的根本原因很單純，就是 Docker 預設是透過 Unix Socket 來進行溝通的，而這個 /var/run/docker.sock 檔案的擁有者是 root。當我們沒有用 sudo 執行指令時，我們只是以一般使用者的身份在呼叫它，系統基於安全考量，當然會直接賞你一個「拒絕存取」。簡單來說，就是你的帳號沒有權限去觸碰那個核心的通訊檔案，所以才會一直鬧脾氣。

要解決這個問題，其實不用每次都跟 sudo 硬槓，我們只需要把自己的使用者帳號加入到 docker 這個群組裡就好。你可以先試著執行 sudo groupadd docker 確保群組存在，接著用 sudo usermod -aG docker $USER 把自己加進去。搞定之後，最關鍵的一步來了：你必須登出再重新登入，或者直接執行 newgrp docker 來重新整理群組權限，不然系統是不會認帳的。你可以試著打 docker run hello-world 測試一下，只要沒報錯，恭喜你，以後再也不用忍受那該死的 sudo 了。

至於要怎麼預防下次又踩坑？最簡單的方式就是養成習慣，在剛裝好 Docker 的當下，就把這行設定加進你的安裝腳本裡。以後不管是換了新電腦，或是要幫同事部署環境，只要這行指令跑過，就再也不會被權限問題搞到心態崩潰。

現在終於可以打一行簡潔的指令就讓容器跑起來，這種清爽的感覺真的太棒了，祝大家開發順利，少點 bug 多點咖啡！
