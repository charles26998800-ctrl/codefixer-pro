How to Check if a File Exists in Python Without Using Try-Except

Source: Stack Overflow ↗ · 7352 votes

Early in my career, I was building a log-parsing script that had to scan thousands of directories, and I went through a phase where I was obsessed with using try-except blocks for everything. I vividly remember spending three hours debugging a performance bottleneck because I was catching FileNotFoundError exceptions inside a tight loop, which turned out to be incredibly expensive in terms of CPU overhead. I felt like a total amateur when I realized I was essentially using an error-handling mechanism as basic control flow, which is a classic "don't do this" trap that makes your code sluggish and harder to read.

The root cause of why this feels tricky is that Python’s philosophy is "easier to ask for forgiveness than permission" (EAFP). Many developers default to try-except because it’s the idiomatic way to handle race conditions—where a file might exist when you check, but disappears a millisecond later before you open it. However, if you're just doing a quick configuration check or verifying an asset before a batch process, the overhead of creating and catching an exception object is totally unnecessary. You don't need to wrap every single file check in a massive block when the standard library provides cleaner, more performant tools for simple existence checks.

My go-to solution now is the pathlib module, which has been the standard way to handle file system paths since Python 3.4. It’s object-oriented, readable, and much more intuitive than the old os.path methods. If I need to check if a file exists, I simply create a Path object and call the .exists() method. It’s clean, it’s fast, and it doesn't trigger the exception handling machinery at all.


from pathlib import Path

file_path = Path("config.json")

if file_path.exists():
    print("The file is right where it belongs.")
else:
    print("File not found, skipping...")

If you’re working on a legacy codebase that hasn't migrated to pathlib yet, you can still use the older os.path module, which is perfectly functional for quick checks. It’s not as elegant, but it gets the job done without any extra fluff:


import os

if os.path.exists("config.json"):
    print("Found it!")

To prevent this from becoming a headache in your own projects, my best advice is to distinguish between *checks* and *actions*. If you are just checking for the existence of a file to decide on a simple branch in your logic, use pathlib. But if you are about to perform an operation like opening or reading that file, stop trying to pre-check existence entirely. Just use the try-except block around the operation itself. That way, you handle the actual failure—like a permission error or a disk read issue—instead of just checking if the file is there and then getting blindsided by a different error a moment later.

Happy coding, and I hope this saves you those three hours of debugging that I had to go through!

別再用 try-except 檢查檔案存不存在了：Python 檔案處理的優雅解法

來源：Stack Overflow ↗ · 7352 票

記得幾年前剛開始寫 Python 爬蟲時，為了檢查下載後的圖片檔有沒有存進資料夾，我傻傻地寫了一大堆 try-except 包在迴圈裡。結果有次跑一個幾萬張圖的腳本，程式跑一半突然報錯，那一瞬間我真的差點崩潰，滿腦子想著：「我只是想確認檔案在不在，為什麼要搞得像在拆炸彈一樣？」那種為了檢查一個簡單狀態，卻讓程式碼變得又臭又長、邏輯斷層的痛苦，相信很多工程師都懂。

其實會發生這種困擾，是因為 Python 的哲學裡有個很有名的原則叫 EAFP（Easier to Ask for Forgiveness than Permission），也就是「先做再說，出錯了再處理」。這在處理複雜併發或多執行緒時很強大，但放在單純的檔案檢查上，就顯得有點殺雞用牛刀。很多人誤以為 Python 檢查檔案只能透過「嘗試打開它」來判斷，一旦檔案被鎖定或是權限不足，錯誤堆疊（Traceback）就會跳出來嚇人，這真的會讓代碼的可讀性降到冰點，甚至還會因為頻繁的例外處理拖慢執行效率。

後來我學乖了，直接擁抱 pathlib 這個模組，這簡直是 Python 界的神器。如果你還在用舊版的 os.path.exists，真的強烈建議換掉。現在我檢查檔案是否存在，只需要一行程式碼就能搞定，乾淨又漂亮。你可以直接這樣寫：


from pathlib import Path

file_path = Path("my_data.txt")

if file_path.is_file():
    print("檔案就在這，安心服用！")
else:
    print("檔案不見了，別再找了。")

這不僅邏輯清晰，而且 pathlib 把檔案路徑當作物件處理，比起字串拼接要穩得多。如果你是要檢查資料夾，只要改成 is_dir() 就行，完全不用擔心那些惱人的例外處理會干擾你的業務邏輯。

為了避免以後又踩到這種雷，我現在養成一個習慣：只要涉及到檔案系統的操作，統一採用「宣告式」的檢查風格，也就是先判斷狀態再執行動作。另外，盡量不要在迴圈內部做過多的 IO 檢查，如果檔案很多，最好先在迴圈外把路徑清單抓出來一次處理，這樣不僅程式跑得快，維護起來也輕鬆不少。

寫程式嘛，能讓邏輯簡潔一點，心情就會好一點。下次遇到類似的情境，試試看 pathlib 吧，你會回來感謝我的！
