How to Fix the "digital envelope routines::unsupported" Error in React

Source: Stack Overflow ↗ · 2572 votes

I still remember the first time I ran into this error. I had just upgraded my Node.js version to v17, sat down with a fresh coffee, and fired up an old project I hadn't touched in a few months. Instead of seeing my dev server spin up, my terminal exploded with a wall of red text ending in that cryptic digital envelope routines::unsupported message. I spent a good hour convinced I’d somehow corrupted my entire node_modules folder before I realized it was just a mismatch between my environment and my dependencies.

The reason this happens is actually quite straightforward once you dig into the OpenSSL changes. When Node.js bumped up to version 17 and beyond, they updated to OpenSSL 3.0. This new version of OpenSSL is much stricter about the algorithms it allows. A lot of older React projects—specifically those using Webpack 4 or older versions of react-scripts—rely on legacy hashing algorithms that OpenSSL 3.0 effectively blacklisted for security reasons. It’s basically the software equivalent of trying to plug a modern USB-C cable into a floppy disk drive; the underlying tech just isn't speaking the same language anymore.

The quickest way I’ve found to resolve this is by telling Node.js to use the legacy OpenSSL provider, which essentially patches the issue without needing to rewrite your entire project’s configuration. If you’re on a Mac or Linux machine, you can fix this in your terminal by running the following command before you start your project:


export NODE_OPTIONS=--openssl-legacy-provider
npm start

If you’re working on Windows, the command is slightly different since you’re likely using Command Prompt or PowerShell. For Command Prompt, you can use:


set NODE_OPTIONS=--openssl-legacy-provider
npm start

If you want a more permanent fix that doesn't require you to type that command every single time you start your day, just head over to your package.json file. You can modify your scripts section to bake the environment variable right into the start command:


"scripts": {
  "start": "react-scripts --openssl-legacy-provider start",
  "build": "react-scripts --openssl-legacy-provider build"
}

To prevent this kind of headache in the future, my best advice is to keep your development environment synchronized with your team using a tool like nvm (Node Version Manager). By keeping a .nvmrc file in the root of your project, you ensure that everyone working on the repo is using the exact same Node version. It saves you from those "it works on my machine" moments and keeps these version-specific breaking changes from ruining your morning.

Hope this gets your build back on track so you can get back to shipping code. Happy coding!

崩潰！啟動 React 專案卻噴出 Error: 0308010C？別怕，這只是 Node.js 的版本代溝

來源：Stack Overflow ↗ · 2572 票

那天我正準備接手一個舊專案，自信滿滿地敲下 npm start，結果螢幕直接噴出一大串紅通通的錯誤訊息，那個 digital envelope routines::unsupported 真的讓我當場傻眼，心想：「這不是才剛 clone 下來的專案嗎？難道是我的環境設定跟這台電腦犯沖？」那種明明只是想跑個程式，卻被環境設定卡死在第一關的無力感，相信每個工程師都經歷過，真的會讓人想直接把鍵盤收一收下班。

其實會發生這個問題，是因為 Node.js 在 v17 版本之後升級了 OpenSSL，改用了全新的加密演算法，結果很多舊版的 Webpack 或是一些依賴套件還在用舊的那套加密標準，導致兩邊「語言不通」。簡單說，就是你的 Node.js 太新，但專案用的工具太老，這兩位老兄撞在一起就吵架了。

要解決這個問題，其實不用把整個 Node.js 砍掉重練。最快的方法就是告訴 Node.js：「嘿，請暫時回到舊的加密模式」。如果你是用 Mac 或 Linux 的朋友，只要在啟動專案前，設定一下環境變數 NODE_OPTIONS 就可以了。我當時是直接在 terminal 輸入這行：


export NODE_OPTIONS=--openssl-legacy-provider

設完之後再跑一次 npm start，那個熟悉的瀏覽器啟動畫面就跳出來了，當下真的差點感動到哭出來。如果你是用 Windows 的話，要在命令提示字元輸入：


set NODE_OPTIONS=--openssl-legacy-provider

為了不想每次開新終端機都要重打一次，我後來乾脆直接把這行寫進 package.json 的 scripts 裡面，把啟動指令改成這樣：


"scripts": {
  "start": "NODE_OPTIONS=--openssl-legacy-provider react-scripts start",
  "build": "NODE_OPTIONS=--openssl-legacy-provider react-scripts build"
}

這樣一來，不管誰來跑這個專案，都不用再煩惱這個版本問題了。

至於要怎麼預防下次又踩進同一個坑？建議大家養成用 nvm (Node Version Manager) 來管理 Node.js 版本的習慣。每個專案都有它適合的「體質」，如果你能在專案資料夾裡放一個 .nvmrc 檔案，記錄下該專案建議的 Node 版本，下次換電腦或是接手新任務時，只要切換一下版本就能省下大把除錯時間，再也不用為了這種環境問題瞎忙半天。

搞定這些小毛病之後，趕快去寫程式吧，別讓這種環境設定毀了你的一天！
